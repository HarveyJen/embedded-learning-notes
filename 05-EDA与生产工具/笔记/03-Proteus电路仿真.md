# 03 · Proteus 电路仿真

> 定位：一块"电子飞行模拟器"——没买硬件之前，先在电脑里把整块单片机板子搭出来、烧进去、跑起来。

**先说人话**：本篇讲 Proteus 这款软件是什么、怎么装、界面长什么样，然后用一个 51 单片机流水灯从头到尾走一遍完整仿真流程，最后告诉你虚拟仪器怎么用、STM32 仿真有哪些局限。学完你能：独立完成一个"原理图 + 单片机程序"的联合仿真项目，在不花一分钱硬件费的情况下验证自己的电路思路和代码逻辑。

---

## 一、Proteus 是什么：飞行模拟器之于飞行员

Proteus 是英国 Labcenter Electronics 公司出品的**电路 + 单片机联合仿真软件**：它既能画电路原理图，又能仿真电路的电气行为，还能让单片机芯片模型真正"执行"你编译好的程序——电路和代码在电脑里联起手来跑。

类比：飞行员上真飞机之前先在飞行模拟器里练，摔一千次也不用赔一架飞机。Proteus 就是电子爱好者的飞行模拟器——你把 LED 接反了、电阻选小了、程序写死循环了，顶多屏幕上的小灯不亮，一分钱不亏，点一下重置键重新来。

它最独特的卖点叫"联合仿真"：普通电路仿真软件（如 Multisim）主要仿真模拟电路行为，而 Proteus 里跑的是**真代码**——你把 Keil 编译出的 .hex 文件加载给虚拟单片机，单片机按程序控制引脚，引脚电平变化再驱动虚拟电路。这是学单片机前期最有价值的玩法。

## 二、版本与获取：付费软件，先用起来再说

Proteus 是**商业付费软件**，官方提供试用版；国内高校的电子类机房普遍装有授权版本，"学校机房常装"是它的国民度来源。

- 官方网站：labcenter.com（版本信息、功能对比、试用下载以官网为准）。
- 本文不提供、也不建议寻找盗版渠道：一是法律风险，二是破解版经常缺元件库、仿真库损坏，新手排查半天以为是自己的问题，其实是软件被阉割了。
- 新手务实路径：先用学校机房版本跟着本篇练手；确认自己长期要用，再考虑官网正版或培训机构的授权方案。

版本号隔几年会变（8.x 之后按 Proteus 8 / 9 / 9+ 等命名），各版本界面大同小异，本篇流程对 8.x 系列通用，个别菜单位置以你手上的实际版本为准。

## 三、界面分区：一张大画布 + 左侧工具箱

打开 Proteus 主界面别慌，它本质上就是"一张画布 + 一排工具箱"。界面分四大块：

| 区域 | 位置 | 白话理解 |
| --- | --- | --- |
| 菜单栏/工具栏 | 最顶部 | 文件操作、缩放、撤销，和 Office 软件一个逻辑 |
| 元件选择区 | 左上 | 搜索框 + 元件列表：你"捡进购物车"的元件都躺在这 |
| 绘图工具区 | 左侧竖排 | 一排小图标：选元件模式、终端模式（电源/地）、虚拟仪器模式等，点一下切换"手上的工具" |
| 原理图编辑区 | 中央大区域 | 白色画布，往这放元件、连线 |

三个新手必会的小图标（左侧绘图工具区）：

1. **Selection Mode（箭头）**：默认模式，用来点选、拖动元件。
2. **Component Mode（芯片小图标）**：切到这个模式，才能从左上角列表里把元件放到画布上。
3. **Terminals Mode（小端子图标）**：提供 POWER（电源，标 VCC/VDD）和 GROUND（地）符号，画电源轨必用。

另外记住两个字母按钮：元件列表上方的 **P**（Pick from Libraries，打开元件库搜索）和 **L**（库管理，暂用不到）。

## 四、完整仿真流程：六步走

这一节是本篇的主干。任何 Proteus 仿真项目，不管多复杂，流程都是这六步：

**第 1 步：新建工程。**
菜单 File → New Project，按向导填工程名、选存放路径，一路默认（原理图图纸选默认 A4 即可）。新手工程单独建文件夹存放，别堆在桌面。

**第 2 步：搜元件（关键词技巧）。**
点元件列表区的 **P** 按钮，弹出元件库搜索框，在 Keywords 里输入关键词。搜索技巧直接决定你的效率：

- 电阻：`RES`；排阻：`RESPACK`
- 发光二极管：`LED`（选 LED-YELLOW 等带颜色的具体型号）
- 无极性瓷片电容：`CAP`；电解电容：`CAP-ELEC`
- 晶振：`CRYSTAL`；按键：`BUTTON`
- 蜂鸣器：`BUZZER` / `SOUNDER`；数码管：`7SEG`；三极管：`NPN` / `PNP`
- 单片机直接搜型号：`AT89C51`、`STM32F103` 等
- 搜出来的列表双击元件名即加入左侧"购物车"，放完元件点 OK 关闭窗口

搜索兜底技巧：

- 搜不到时换更短的词根：库命名常有缩写习惯，`RES` 比 `RESISTOR` 命中率高。
- 换词仍无结果，清空关键词按类别（Category）浏览，逐层缩小范围。
- 同名元件注意参数与封装差异，放购物车前看一眼预览图确认。

**第 3 步：放置元件。**
切到 Component Mode，在左上角列表选中元件，到画布上单击放置；右键单击元件可旋转/删除，双击元件弹出属性框改参数（电阻值、电容容量等）。

**第 4 步：连线。**
把鼠标移到元件引脚的红色小方块端点，光标变成绿色铅笔状时单击，拖到目标引脚再单击即完成连线。电源和地用 Terminals Mode 里的 POWER / GROUND 符号接入。

**第 5 步：给单片机加载程序（.hex）。**
这是联合仿真的灵魂一步：**双击单片机**，弹出属性对话框——

- 在 **Program File** 一栏点文件夹图标，浏览选中 Keil 编译生成的 .hex 文件；
- 在 **Clock Frequency** 一栏填上和电路里晶振一致的频率（如 12MHz）；
- 点 OK 保存。

**第 6 步：运行仿真。**
画布**左下角**有一排播放器式按钮：**Play（播放）**运行、Pause 暂停、Stop 停止。点 Play 后，电路通电，单片机开始执行程序——LED 亮灭、数码管跳动都是真实的程序输出。想改程序？Stop → 回 Keil 重新编译 → 双击单片机换新 hex → 再 Play。

## 五、51 流水灯仿真全步骤：把第一节"课"上完

流水灯是单片机界的"Hello World"：8 个 LED 排成一排轮流点亮，考察最小系统、GPIO 输出、延时程序三件事。我们把它在 Proteus 里完整走一遍。

**电路侧（Proteus）：**

1. 按第四节流程新建工程，从元件库搜出：`AT89C51`、`LED-YELLOW` ×8、`RES`（220Ω 限流电阻 ×8）、`CRYSTAL`（12MHz 晶振）、`CAP`（30pF 瓷片电容 ×2）、`CAP-ELEC`（10μF 复位电容）、`RES`（10kΩ 复位电阻）、`BUTTON`（复位按键）。
2. 搭最小系统（详细原理见 [01-概述与最小系统](../../06-51单片机/笔记/01-概述与最小系统.md)）：
   - 晶振两端接 AT89C51 的 XTAL1、XTAL2 引脚，晶振两侧各对地接一个 30pF 瓷片电容；
   - 复位电路：RST 引脚经 10μF 电容接 VCC，经 10kΩ 电阻接 GND，按键并联在电容上（上电复位 + 手动复位）；
   - EA 引脚接 VCC（用片内程序存储器）。
3. 接 LED：P1.0～P1.7 每个引脚 → LED 阳极 → LED 阴极 → 220Ω 电阻 → GND（单片机引脚输出高电平点亮；若把 LED 接成灌电流方式则低电平点亮，注意程序取反）。

**点 Play 之前的自检清单：**

- 电源和地有没有接反？VCC、GROUND 终端逐个核对。
- 晶振两侧的 30pF 电容是否真的接地了？（新手最容易漏的一根线）
- EA 引脚是否已接 VCC？
- 8 路限流电阻是否都串进去了？有没有一路偷懒直连？
- hex 是否已加载、Clock Frequency 是否填了 12MHz？

**程序侧（Keil 联动）：**

1. Keil uVision 新建工程，芯片选 Atmel 的 AT89C51（与 Proteus 中型号一致）；
2. 新建 main.c，写入流水灯逻辑（寄存器写法详见 [02-GPIO与寄存器思维](../../06-51单片机/笔记/02-GPIO与寄存器思维.md)）：

```c
#include <reg51.h>
#include <intrins.h>

void delay(unsigned int t) {          // 粗略软件延时
    while (t--);
}

void main(void) {
    unsigned char led = 0xFE;         // 1111 1110，P1.0 先亮
    while (1) {
        P1 = led;                     // 状态送到 P1 口
        delay(30000);
        led = _crol_(led, 1);         // 整体循环左移一位
    }
}
```

3. 菜单 Project → Options for Target → Output 选项卡 → 勾选 **Create HEX File** → 编译（Rebuild），输出目录得到 .hex 文件；
4. 回到 Proteus，双击 AT89C51，Program File 选这个 .hex，Clock Frequency 填 12MHz；
5. 点左下角 Play——8 个 LED 应依次流水点亮。不亮？按第四节第 6 步的循环去排查：hex 没加载？晶振频率没填？LED 极性接反？

仿真通过只代表"逻辑和接线没大错"，真板上的驱动能力、干扰问题 Proteus 帮不了你，这一点第七节细说。

## 六、虚拟仪器实测：给虚拟电路挂上"仪表"

Proteus 自带一排虚拟测量仪器，相当于把实验室的仪表台搬进了软件。位置在左侧绘图工具区的 **Virtual Instruments Mode**（仪表小图标），点开后可选：示波器（Oscilloscope）、逻辑分析仪（Logic Analyser）、计数器/定时器（Counter Timer）、信号发生器（Signal Generator）等；直流电压表（DC VOLTMETER）、直流电流表（DC AMMETER）则在元件库搜索 `VOLTMETER` / `AMMETER` 可以找到。

- **虚拟示波器**：从仪器栏拖出示波器图标，把它的 A/B 通道探针接到被测点（比如晶振引脚、P1 口任一引脚），运行仿真后弹出示波器面板，调节时基和幅度旋钮即可看到波形。看 PWM、看晶振起振都靠它。
- **虚拟逻辑分析仪**：多通道同时抓数字信号，适合看 8 位并口或串行时序。把多个通道接到 P1.0～P1.7，流水灯的时序图一目了然——这是"用眼睛看见程序"的最直观方式。
- **电压表/电流表**：像放电阻一样放到画布上，串联进电路量电流、并联在元件上量电压，运行时直接读数。验证"限流电阻取值是否合理"就用它：量 LED 支路电流是否在几毫安到十几毫安的正常范围。
- **虚拟信号发生器**：给电路注入正弦波/方波信号，比如给放大电路的输入端送 1kHz 正弦波，再用示波器看输出——模电实验的标准姿势。

四件仪器的共同"上手提示"：先接探针再点 Play，边运行边在仪器面板上调旋钮；量程/时基不对时波形可能只是"挤成一条线"，别误以为没信号。

用虚拟仪器的好处：不怕烧表、探头随便怼、量程随便切。养成"跑仿真必挂仪表"的习惯，以后上真板用真仪器就不怵了。

## 七、STM32 仿真的现实：能练逻辑，不能替真板

Proteus 对 STM32（以 F1 系列为代表）提供了一定的仿真支持，可以配合 Keil 做程序级联调——把编译好的固件加载进虚拟 STM32F103，验证 GPIO、部分定时器、串口收发这类基础外设的逻辑。

但必须把话说透，新手在这里栽跟头的最多：

- **外设模型覆盖不全、更新滞后**：芯片外设众多，Proteus 只实现了常用子集，一些较复杂或较新的外设根本没有模型，搭上去就是"假件"。
- **时序类外设仿真失真**：凡是依赖精确时序、高频时钟、模拟特性的东西（高速通信、精密 ADC、DMA 高吞吐场景等），仿真结果和真板行为可能有明显出入。
- **仿真通过 ≠ 实物能跑**：时钟树配置错误、供电问题、干扰、焊接问题，仿真里统统不存在。

所以 STM32 阶段的正确姿势：Proteus 用来**入门练逻辑**——理解引脚电平、简单外设的工作流程、验证代码思路；一旦进入定时器精调、通信协议、低功耗这类"吃时序"的内容，**直接上真板**。Proteus 是入门的脚手架，不是替代真板的捷径，这个定位务必刻在脑子里。

## 八、Proteus vs 真板：取舍表

| 维度 | Proteus 仿真 | 真实开发板 |
| --- | --- | --- |
| 成本 | 软件之外零硬件成本，元件随便"烧" | 板子 + 元件 + 工具都要花钱 |
| 试错 | 改错即重来，一键 Reset | 焊错可能烫坏板子、烧元件 |
| 时序真实性 | 高速/精确时序会失真 | 与真实产品一致 |
| 外设真实性 | 模型有限，部分外设缺失 | 外设全部真实存在 |
| 工程能力训练 | 焊接、排障、仪器操作练不到 | 全流程实战，接近岗位要求 |
| 最佳用途 | 前期验证逻辑、课堂演示、无硬件应急 | 任何准备投实物使用的功能 |

结论一句话：**学习前期用仿真建立直觉，学习后期必须回到真板**。两条腿走路，别瘸。

一个务实建议：把"仿真验证 + 真板验证"当成固定的两步流程写进你的项目习惯——仿真过的电路上真板还出问题，问题多半出在仿真覆盖不了的部分（供电、时序、干扰、焊接），排查方向立刻清晰一半。

## 常见坑（新手必看）

1. **双击单片机忘了加载 hex**，点 Play 后一切安安静静——Proteus 不会弹窗提醒你程序是空的，这是"仿真没反应"的头号原因。
2. **Clock Frequency 没填或与晶振不符**：单片机属性里的频率以属性框设置为准（不与电路图自动同步），填错会导致串口波特率等时序全乱。
3. **Keil 忘了勾选 Create HEX File**：编译通过但没有 .hex 生成，Proteus 加载时找不到文件。
4. **LED 长亮或长灭分不清驱动极性**：接成灌电流（低电平点亮）还是拉电流（高电平点亮），程序电平取反要配套，改电路不改程序是最常见的"灯不听话"。
5. **搜元件用中文关键词**：元件库是英文命名，`发光二极管` 搜不到东西，要搜 `LED`、`RES`、`CRYSTAL`。
6. **以为仿真通过就能焊板子**：仿真验证不了驱动能力、电磁干扰、焊接质量，直接照仿真图打样仍有翻车可能。
7. **用破解版遇到元件库缺失**，误以为自己操作错了——优先用学校机房正版，遇到疑似软件问题先换一台机器验证。
8. **连线时只看"线画上了"没看端点**：线没落在引脚端点上其实是悬空，运行时引脚电平不会变化；放元件前把画布放大（滚轮缩放）看得更清楚。

## FAQ

1. **Q：Proteus 有免费版吗？** A：官方提供试用/评估版本（功能与期限以官网为准），完整版是付费的。学生最现实的路径是学校机房授权版。
2. **Q：仿真时单片机引脚上的小方块颜色变化是什么？** A：那是引脚逻辑电平指示，Proteus 用不同颜色区分高、低电平与悬空状态（具体配色随版本略有差异），是快速判断程序有没有跑起来的利器。
3. **Q：学 51 必须用 Proteus 吗？** A：不是必须，但强烈推荐。它让你在买开发板之前先理解"程序如何控制电路"，还能在真板异常时提供一个"标准答案"做对照。
4. **Q：为什么我按教程搭的 STM32 仿真点不亮外设？** A：先确认该外设在 Proteus 中是否有仿真模型（很多没有）；再检查固件是否用对了芯片型号。STM32 仿真支持有限，重要功能请上真板验证。
5. **Q： Proteus 能替代 Multisim 学模电吗？** A：不替代。模电的精细仿真（运放、滤波器频响）建议用 Multisim 或 LTspice，见 [04-其他常用开发工具速查](04-其他常用开发工具速查.md) 的仿真选型对比。
