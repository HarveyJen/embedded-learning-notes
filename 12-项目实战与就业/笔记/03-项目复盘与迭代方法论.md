# 03 · 项目复盘与迭代方法论

> 定位：**全模块的"转换器"**——01 篇教你把项目"展示"出来，02 篇教你"应对"考核，本篇教你把做完的项目"榨出"能力、资产和面试素材。触发点：**每完成一个阶段项目必走一遍**（和 04-选题库配套：选题 → 实现 → 复盘 → 下一题）。

**先说人话**：本篇讲什么，学完能做什么——

不复盘的项目三个月后只剩一句"我做过"，细节全忘、面试露馅。本篇给一套可执行的复盘流水线：四步复盘法（回顾目标→评估结果→分析原因→总结经验）、技术复盘三清单（架构决策/坑清单/量化数据）、资产沉淀动作（Git/文档/BOM 版本化）、v2 迭代计划方法、以及"复盘产出直接变简历与面试答案"的转化句式。学完你能对刚做完的项目产出一份一页纸复盘，并在下次面试把"坑清单"讲成加分项。

一句话定位：**写代码是你和项目的事，复盘是你和"下一个自己"的事。**

## 1. 为什么必复盘：不复盘 = 只做了 50% 的项目

类比：健身不记录重量、不拍体型——练一年也说不清进步在哪。项目同理：**"做过"和"会了"之间隔着一次复盘。**

复盘给你三样东西：

| 产出 | 内容 | 流向哪里 |
|------|------|----------|
| 经验 | 坑与解法、决策依据 | 下一个项目少踩（能力复利） |
| 资产 | 代码/文档/硬件版本化 | 作品集（01 篇的原材料） |
| 故事 | "问题→定位→解决→结果"的完整叙事 | 简历与面试（02 篇的弹药） |

反面清单（对号入座）：做完直接开下一题、仓库半途的提交信息全叫 "update"、原理图有三个版本不知道哪个是最终版、面试被问"你遇到最难的问题"当场哑火——全是没复盘的症状。

## 2. 四步复盘法（通用框架）

> **这是什么**：源自 PDCA/复盘方法论的通用四步，每步都有对应动作，不是鸡汤。

| 步骤 | 核心问题 | 动作 | 产出 |
|------|----------|------|------|
| ① 回顾目标 | 当初要做成什么样？ | 翻出 04-选题库选题卡的需求与验收标准逐条对照 | 目标清单 |
| ② 评估结果 | 实际做到什么样？ | 达标项/未达标项分列，能量化的全量化 | 结果对照表 |
| ③ 分析原因 | 差距/成功各为什么？ | 技术决策、流程问题、时间估算分开归因（第 3 节三清单） | 归因记录 |
| ④ 总结经验 | 下次怎么做得更好？ | 可复用规律 + 明确的行动项（写进下一题的选题卡） | 行动项列表 |

纪律：**只对着"当初的目标"评估，不临时改靶心**——复盘大忌是"其实我本来就想做成这样"。

## 3. 技术复盘三清单

### 3.1 架构决策记录（为什么这么设计）

把项目里的关键分叉口记下来，格式一句话一条：

```
决策：采集任务用 RTOS 周期任务，不用裸机定时器轮询
原因：采集/显示/通信三路并发，裸机轮询时序已互相拖累
代价：多占 1KB 栈 + 学习成本
验证：三任务独立节拍实测稳定
```

面试官问"你的架构为什么这么设计"，答案就从这来——**有对比、有代价、有验证**的决策才是"设计"，其余叫"照抄"。

### 3.2 坑清单（面试 gold，直接背）

每条坑按五段式记录：**现象 → 定位过程 → 根因 → 解法 → 预防**。

示例（格式演示）：

```
现象：继电器吸合瞬间 ADC 读数跳 20%
定位：示波器看地线电压 → 吸合瞬间有共模跳动；断开负载复现消失
根因：触点侧无吸收，电弧干扰经地耦合进模拟前端
解法：触点并联 RC 吸收 + 模拟前端采样滑动平均（防护详见 14/07 EMC 篇）
预防：带继电器的板子，触点吸收与分区布板列入设计评审项
```

这套五段式正是面试官最爱追问的"你怎么定位的"标准答案结构——平时积累、考前白捡。

### 3.3 量化数据（用数字说话）

| 指标 | 怎么记 | 用途 |
|------|--------|------|
| 时间预算偏差率 | （实际天数 − 计划天数）÷ 计划天数 | 校准下次估算 |
| 返工次数 | 因设计失误推倒重来的模块数 | 反映前期设计质量 |
| 缺陷计数 | 自测+联调抓到的 bug 数与分布 | 找出你的薄弱层 |
| 关键性能 | 实测采样率/误码率/精度 vs 目标 | 简历数字来源 |

时间预算偏差率代入算例：计划 5 天、实际 8 天 → 偏差率 =（8−5）÷5 = **+60%**。单次超支可能是意外；**连续两个模块都超 50% 以上就是系统性低估**——下次估算直接给"直觉值 ×1.5~2"（经验值），比硬扛诚实得多。

## 4. 资产沉淀：做完当天就做，拖一周就烂尾

| 资产 | 动作 | 标准 |
|------|------|------|
| 代码仓库 | 整理分支、清理调试残码、打 tag（v1.0） | README 按 [01-作品集打造与简历项目化](01-作品集打造与简历项目化.md) 规范重写；commit 信息可读 |
| 硬件文档 | 原理图导 PDF、BOM 定稿、加版本号 | 明确"哪个是最终版"，接单/复刻可直接用 |
| 调试记录 | 坑清单（3.2）归档进仓库 docs/ | 和代码同版本管理，别散在聊天记录里 |
| 数据曲线 | 关键测试的波形/曲线截图入库 | 面试时"口说无凭"的实证 |

版本化是底线：**"最终版-真最终版-打死不改版"不是版本管理**——统一用 v1.0/v1.1 递进 + 一行变更说明。

## 5. v2 迭代计划：复盘的落地形态

- **优先级排序**：稳定性修复 > 体验/功能完善 > 花活新特性——工程常识，v2 先还 v1 的债再长新肉；
- **每项写验收标准**：不是"优化通信"，而是"连续 72h 通信零误码"——可验证才可收工；
- **不追新**：v2 聚焦 v1 痛点，别顺手引入没学过的新框架/新芯片——那是新项目，不是迭代；
- **小步快跑**：v2 拆成 ≤3 个可独立验收的小步，避免"大重构两个月"烂尾。

## 6. 求职转化：复盘产出直接变面试答案（衔接 01/02 篇）

**简历句式**（从坑清单自动生成）：

```
弱写法：负责温控模块，实现了 PID 温控。
强写法：发现温控超调达 8°C → 定位为积分饱和 + dt 口径不一致 →
       引入积分限幅并统一采样节拍 → 超调降至 1°C 内（±0.5°C 稳态）。
```

"发现→定位→解决→量化结果"四段式，就是 3.2 坑清单的直接投影。

**面试 STAR 法**（通用面试叙事框架）：Situation（项目背景）→ Task（你的任务）→ Action（具体怎么做）→ Result（量化结果）——你的复盘材料正好填满四格，且全是真话。

**面试官最爱三问与复盘的对应**：

| 问题 | 用复盘哪份材料答 |
|------|------------------|
| "项目里最难的问题是什么？" | 坑清单挑最深的一条（五段式完整讲） |
| "你怎么定位的？" | 坑清单的"定位过程"段 |
| "如果重来一次会怎么做？" | 架构决策记录 + v2 计划 |

面试前把这些材料过一遍，等于带着小抄赴考（面试整体备战见 [02-面试实战与方向选择](02-面试实战与方向选择.md)）。

## 8. 与选题库闭环：复盘决定下一题

选题 → 实现 → **复盘** → 反哺选题，四级流水：

- v1 达标率高 + 坑清单深度够 → 下一题**升一级难度**（04-选题库下一阶段）；
- 达标率低 + 返工多 → 下一题**同级换方向巩固**，把同类坑再踩一遍但这次踩赢；
- 复盘中的 v2 行动项，本身就是下一题候选——带着明确痛点的选题比"随便挑一个"学习效率高一个量级。

## 工程实操任务

- [ ] 把刚完成（或搁置已久）的一个项目用第 7 节模板完整复盘一遍，产出真正的一页纸；
- [ ] 给该项目仓库打 v1.0 tag，重写 README，坑清单归档到 docs/（对照 01 篇规范）；
- [ ] 用"发现→定位→解决→量化结果"句式，把这个项目写进简历的项目描述（对照 [01-作品集打造与简历项目化](01-作品集打造与简历项目化.md) 检查）；
- [ ] 算一算你最近两个项目的时间偏差率，若都超 50%，下个项目估算强制 ×1.5 并记录实际偏差验证；
- [ ] 按 3.2 的五段式，把一次你印象最深的 debug 过程完整写出来——这就是你面试的"最难问题"底稿。

## 常见坑（新手必看）

1. **复盘写成流水账**："第一天做了 A，第二天做了 B"——复盘只回答"为什么"和"下次怎么办"，日程表不是复盘；
2. **只总结成功不解剖失败**：失败案例的信息密度远高于成功案例——坑清单里失败必须是主角；
3. **没有行动项**：分析了三大页，落地为零——每条经验必须转成"下一题的验收标准"才算闭环；
4. **复盘拖到遗忘**：做完当天至多三天内完成记忆复盘，文档整理可延，脑子里的 fresh 数据不等人；
5. **资产不版本化**：README 空白、原理图无版本号——作品集环节（01 篇）要花双倍时间返工；
6. **把复盘当检讨**：复盘是机制分析不是自我批评——"我太菜了"不是归因，"估算方式系统性偏低"才是；
7. **跳过复盘直接开新题**：项目→能力的转化率直接腰斩，四步法总共也就一两个小时，别省这一步。

## FAQ

**Q：项目做失败了也要复盘吗？**
A：**尤其是**。失败项目的归因最值钱：是需求定大了、技术路线选错还是执行崩了？写清楚，它就是你面试里"讲一个失败经历"的最佳素材——面试官考察失败经历的点恰是复盘能力本身。

**Q：多久复盘一次？**
A：项目级复盘"做完必做"（本篇主线）；日常级可以每周五花 15 分钟记录本周踩的坑（只记五段式一句话版），项目复盘时直接汇总——两者是汇总关系不冲突。

**Q：小组项目怎么复盘？**
A：四步法不变，第②步评估加"协作维"（接口联调、分工均衡），第④步行动项落实到人——小组复盘的产出（分工机制问题）往往比技术问题对下一项目影响更大。

**Q：复盘和 git commit message 有什么关系？**
A：commit 是"实时流水"，复盘是"定期结算"——commit 信息写得规范（what+why），复盘时翻 log 就能还原决策时间线；反过来，本次复盘发现 commit 信息读不懂，就是下次要改的习惯。
