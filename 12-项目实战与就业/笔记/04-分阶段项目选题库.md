# 04 · 分阶段项目选题库

> 定位：路线要求**求职前攒满 3 个完整项目**，本篇就是选题菜单——每阶段做完 1 个再进下一阶段，作品集的 3 个项目从不同阶段各挑一个即可。每个选题配齐七要素：需求 / 硬件清单 / 架构 / 坑预告 / 验收标准 / 加分项 / 工作量，照单开工。

**先说人话**：看教程像"看别人游泳"，做项目才是"自己下水"。下水最怕两件事：不知道游去哪（没需求），半途呛水放弃（没规划）。本篇把 4 个阶段的 9 个选题做成点菜单——每个都小到 1~2 周能做完，大到能写进简历。别贪多：**每阶段选 1 个，做完、写好 README、打上 tag，再进下一阶段**。

## 2. 06-51 阶段选题（入门：把定时器、数码管、串口拼成系统）

**选题 51-1 · 交通灯（定时器 + 数码管）**
- **需求**：①主干道/支路红黄绿灯按"绿 12s→黄 3s→红"轮转；②四位数码管显示当前方向倒计时；③紧急按键：一键全红 5s 后自动恢复；④夜间模式：黄灯双闪
- **硬件**（约 40 元）：51 最小系统板约 20 元；四位一体数码管约 5 元；红黄绿 LED 各 2 约 2 元；轻触按键约 1 元；面包板+杜邦线约 10 元
- **架构**：模块 = 定时节拍（定时器 1ms 中断）→ 交通状态机 → 显示刷新（LED 直驱 + 数码管动态扫描）+ 按键处理。数据流：`定时器中断 → 秒计数 → 状态机 → 段码/位选缓冲 → 扫描输出`
- **坑预告**：①动态扫描换位不消影（先关位选再送段码）导致重影；②倒计时与灯态不同步——状态机是唯一真相源，显示只读状态；③把扫描放主循环、却在中断里长延时，导致显示闪烁、按键失灵
- **验收标准**：[ ] 四状态轮转时序正确 [ ] 倒计时无重影无闪烁 [ ] 紧急/夜间模式可进可出 [ ] 连续运行 1 小时无死机
- **加分项**：状态机转移图画进 README；用逻辑分析仪实测扫描周期并记录
- **预计工作量**：3~5 天（每天 2~3 小时）

**选题 51-2 · 简易计算器（矩阵键盘 + LCD1602）**
- **需求**：①4×4 矩阵键盘输入 0~9 与加减乘除；②LCD1602 显示算式与结果；③支持连续运算与清除键；④除零/溢出给出错误提示
- **硬件**（约 35 元）：51 最小系统板约 20 元；4×4 薄膜键盘约 5 元；LCD1602 约 8 元；对比度电位器约 1 元
- **架构**：模块 = 键盘扫描（状态机消抖）→ 输入解析（操作数/运算符缓冲）→ 计算核心 → LCD 刷新。数据流：`键盘 → 输入缓冲 → 解析器 → 计算状态机 → 显示缓冲 → LCD`
- **坑预告**：①按键抖动与连击——消抖状态机，长按只算一次；②LCD 时序延时不足导致花屏（按手册延时或查忙标志）；③负数/溢出显示错乱——先想清楚数值范围（如 16 位有符号）再写运算
- **验收标准**：[ ] 四则运算结果全对 [ ] 连续运算正确 [ ] 除零有提示不死机 [ ] 乱按一通不跳键不卡死
- **加分项**：定点小数实现（讲清精度取舍）；按键提示音
- **预计工作量**：4~6 天

**选题 51-3 · 双机串口通信（UART 收发 + 协议帧）**
- **需求**：①两块 51 板互发数据（A 机按键 → B 机 LED/数码管响应）；②自定义协议帧：帧头+长度+命令+数据+校验和；③校验失败丢弃并回错误帧；④串口助手可当上位机查收发日志
- **硬件**（约 55 元）：51 最小系统板×2 约 40 元；USB 转 TTL（CH340 类）约 8 元；杜邦线若干
- **架构**：发送侧 = 组帧器 → UART 发送；接收侧 = UART 接收中断 → 环形缓冲 → 主循环解析状态机（找帧头→收长度→收数据→验校验）→ 执行命令。数据流：`按键 → 组帧 → TX；RX → 环形缓冲 → 解析状态机 → 命令执行`
- **坑预告**：①不找帧头直接读，上电就乱码——解析从"等帧头"状态开始；②在中断里解析整帧——ISR 只进缓冲，主循环解析；③两机没共地——TX/RX/GND 三根缺一不可
- **验收标准**：[ ] 连发 1000 帧 0 丢帧（串口助手统计）[ ] 错误帧被识别丢弃 [ ] 一端断电重启后通信自动恢复
- **加分项**：CRC8 校验；命令表用函数指针分发（面试高频写法）
- **预计工作量**：5~7 天

> 三选题配套：分别练定时器/数码管、键盘/LCD、串口协议，正好覆盖 04 阶段三大主线（详见 [06-51 的串口与综合项目篇](../../06-51单片机/笔记/05-串口与综合项目.md)）。

## 3. 07-STM32 裸机选题（进阶：外设综合 + 模块化架构）

**选题 STM32-A · OLED 万年历时钟（RTC + 按键设置）**
- **需求**：①OLED 显示年月日时分秒；②RTC 掉电走时（VBAT 供纽扣电池）；③按键设置时间：短按切换字段、长按进入/退出设置；④设置中光标闪烁指示
- **硬件**（约 40 元）：STM32F103C8T6 最小系统板约 15 元；0.96 寸 I2C OLED 约 12 元；CR2032 电池座约 5 元；轻触按键 3~4 个约 2 元
- **架构**：模块 = RTC 驱动（秒中断/读时间）→ 设置状态机（按键扫描）→ OLED 显示刷新。数据流：`RTC → 时间缓存 → 格式化 → OLED；按键 → 设置状态机 → 时间缓存`
- **坑预告**：①每次复位都初始化 RTC 导致时间回跳——用备份寄存器存标志，仅首次上电初始化；②I2C 无响应死等卡死——所有 I2C 操作加超时；③设置态与刷新逻辑纠缠——统一由显示节拍驱动闪烁
- **验收标准**：[ ] 断电 24h 后走时误差实测记录 [ ] 全字段可设置可保存 [ ] 复位不丢时间 [ ] 连续运行无花屏
- **加分项**：设置项也存备份寄存器；记录走时误差数据（量化习惯）
- **预计工作量**：5~7 天

**选题 STM32-B · 温湿度记录仪（DHT11/SHT30 + Flash + 串口导出）**——本篇主角，第 4 节升级它
- **需求**：①周期采集温湿度（DHT11 便宜精度一般；SHT30 走 I2C 精度更好，二选一）；②SPI Flash（W25Q64 类）按记录循环存储；③串口命令导出 CSV；④按键切换"实时显示/记录中"状态
- **硬件**（约 40 元）：F103 最小系统板约 15 元；DHT11 约 5 元（或 SHT30 模块约 10 元）；W25Q64 模块约 6 元；OLED 约 12 元
- **架构**：模块 = 传感器驱动（定时触发采集）→ 记录管理（定长结构体+时间戳）→ Flash 驱动（页编程/扇区擦除）→ 环形存储（写指针+容量回卷）+ 串口命令解析。数据流：`定时采集 → 记录缓冲 → Flash 环形写入；串口命令 → 解析 → 导出/擦除`
- **坑预告**：①DHT11 微秒级时序对延时敏感——用逻辑分析仪实测，别信循环次数；②Flash 擦除粒度大于写入粒度——先设计环形区/磨损策略再写代码；③导出中途断电——每条记录带序号，续传不重不漏
- **验收标准**：[ ] 连续记录 24h 无坏点 [ ] 导出 CSV 用表格软件能画曲线 [ ] 掉电重启续记不覆盖旧数据 [ ] 存满回卷正常
- **加分项**：采样间隔可配置存参数区；导出耗时实测数据；坏块处理思路写进 docs
- **预计工作量**：7~10 天

**选题 STM32-C · 超声波测距倒车雷达（HC-SR04 + 蜂鸣器分级）**
- **需求**：①HC-SR04 循环测距并在 OLED/数码管显示；②蜂鸣器分级：距离远慢响、中等快响、小于阈值长鸣；③阈值可调；④无回波超时按无效处理不卡死
- **硬件**（约 30 元）：F103 最小系统板约 15 元；HC-SR04 约 4 元；蜂鸣器+三极管驱动约 3 元（OLED 可复用上一题）
- **架构**：模块 = 触发（定时器出约 10μs 触发脉冲，以手册为准）→ 输入捕获测回响脉宽 → 换算距离（声速×时间/2）→ 分级逻辑 → PWM 驱蜂鸣器。数据流：`触发 → 捕获 → 距离值 → 报警状态机 → 蜂鸣器/显示`
- **坑预告**：①回响脉宽无超时兜底，一次异常就卡死；②温度影响声速、多径反射影响读数——记录实测偏差比假装没有强；③蜂鸣器直推电流不足——三极管驱动
- **验收标准**：[ ] 与卷尺对比的误差数据记录在案 [ ] 三级报警切换正确 [ ] 遮挡/超程不卡死 [ ] 连续运行稳定
- **加分项**：无源蜂鸣器 PWM 变调（音调随距离连续变化）；温度补偿声速
- **预计工作量**：4~6 天

## 4. 08-FreeRTOS 版：同一个项目，两种含金量

**重点：同项目升级思想**。裸机版温湿度记录仪（STM32-B）做完后，**不要新开项目，直接升级成 RTOS 版**。原因三条：

1. 面试必问"为什么用 RTOS、任务怎么划分、优先级怎么定"——同一个需求两个版本，你能拿出第一手对比答案，比多堆一个新项目有说服力得多；
2. 驱动代码已验证过，学习成本集中在调度与任务间通信本身，升级 5~8 天即可完成；
3. 作品集里"裸机 v1.0 → RTOS v2.0"两条 tag 的演进记录本身就是深度证据，直接回应 [01 篇的面试五连问](01-作品集打造与简历项目化.md)。

**选题 RTOS-A · 温湿度记录仪多任务版（采集/显示/存储/上报四任务）**
- **需求**：在裸机版需求之上增加：①串口（或 ESP8266 AT）周期上报数据；②串口命令在线改采样间隔；③输出任务栈水位等运行统计
- **硬件**：与 STM32-B 完全相同（做上报再加 ESP8266-01S 模块约 10 元）
- **架构**：四任务划分 + 队列/信号量交互。数据流：`采集任务 --采样队列--> 存储/上报任务；显示任务读最新值；互斥量保护 I2C/SPI/串口`

  | 任务 | 优先级建议 | 职责 | 交互 |
  |------|------|------|------|
  | 采集 | 高 | 定时采样传感器 | 采样队列发给下游 |
  | 存储 | 中 | 收记录写 Flash | 收队列；SPI 互斥量 |
  | 上报 | 中 | 组帧串口/WiFi 上报 | 收队列；串口互斥量 |
  | 显示 | 低 | 刷 OLED | 读最新值（消息或共享+互斥） |
- **坑预告**：①共享总线用二值信号量引发优先级反转——改用互斥量（优先级继承）；②采集任务里同步写 Flash 阻塞采样——队列解耦，存储慢不拖采样；③栈大小拍脑袋——用栈水位 API 实测再调整
- **验收标准**：[ ] 四任务按设计节拍运行互不拖累 [ ] 采样抖动实测并记录 [ ] 上报断连自动恢复 [ ] 栈水位报告写进 docs
- **加分项**：给出裸机 vs RTOS 的采样抖动对比数据（数字说话）；用事件组做整点归档
- **预计工作量**：5~8 天（驱动已就绪，聚焦架构）

> 配套理论：任务划分/队列/信号量/互斥量分别见 08-FreeRTOS 的 01/02/03 篇，综合示范见 [08-FreeRTOS 综合项目篇](../../08-FreeRTOS/笔记/06-综合项目.md)。

## 5. 09-Linux 方向选题（毕业级：联网与系统编程）

**选题 Linux-A · 串口采集网关（MQTT 上报）**
- **需求**：①从下位机串口收数据帧（直接复用 51-3 的协议，下位机可用 05 阶段记录仪）；②解析后以 MQTT 发布到本地 Broker（mosquitto）；③断线缓存、恢复后补发；④串口参数与主题写在配置文件里
- **硬件**（约 200~500 元）：任一能跑 Linux 的板子（i.MX6ULL 类开发板或树莓派；具体型号价格波动大【待查证】以官网为准）。**没板子先用 PC + USB 转 TTL 完成全部软件逻辑**，再移植
- **架构**：模块 = 串口收发线程（termios raw 模式+环形缓冲）→ 帧解析（状态机）→ 数据队列 → MQTT 客户端线程（发布+遗嘱+指数退避重连）。数据流：`串口 → 环形缓冲 → 解析 → 队列 → MQTT publish`
- **坑预告**：①termios 配置不全（raw 模式、VTIME/VMIN）导致 read 行为诡异；②串口粘包/半包——帧状态机解析（51-3 的经验直接迁移）；③MQTT 重连风暴——指数退避
- **验收标准**：[ ] MQTTX 订阅端看到连续数据流 [ ] 断网恢复后自动重连并补发 [ ] 改配置文件无需改代码 [ ] 72h 长跑稳定
- **加分项**：对接 Modbus RTU 下位机；讲清遗嘱消息与 QoS 等级的取舍
- **预计工作量**：7~10 天

**选题 Linux-B · 简易 Web 控制灯（socket + HTTP）**
- **需求**：①浏览器开关板载 LED（GET /led?state=on）；②返回状态页显示 LED 与系统信息；③支持多个连接并发；④非法请求返回 400/404
- **硬件**：同 Linux-A（也可先在 PC 上用"虚拟 LED"跑通逻辑再移植）
- **架构**：模块 = socket 监听 → accept（多线程或 epoll）→ HTTP 请求解析（请求行+头部）→ 路由表（函数指针分发）→ GPIO 控制 → 组 HTTP 响应。数据流：`浏览器 → TCP → 解析 → 路由 → GPIO → 响应`
- **坑预告**：①TCP 粘包——按 HTTP 报文边界（头结束+Content-Length）解析；②不处理 Connection: keep-alive 导致读阻塞；③GPIO 设备权限与占用释放
- **验收标准**：[ ] 浏览器开关即时生效 [ ] 两个浏览器同时访问不串 [ ] 异常请求不崩溃 [ ] 循环压测 1 万次内存无泄漏（观察记录）
- **加分项**：epoll 版 vs 多线程版的性能对比数据；加简单鉴权
- **预计工作量**：5~8 天

> 配套：网关思路与板级环境见 [09-Linux 综合项目篇](../../11-嵌入式Linux/笔记/05-综合项目智能网关.md)。
>
> **没板子不挡路**：两个选题的软件逻辑都能先在 PC（虚拟机/WSL + USB 转 TTL）上跑通验证，板子晚到只影响移植这一步——硬件不要阻塞软件进度。

## 6. 项目开发五步流程（每步有产出物，没产出 = 没做）

怎么读这张表：顺序执行不跳步；第 1 步产出就是你写代码前唯一要交的"作业"。

| 步骤 | 干什么 | 产出物 |
|------|------|------|
| 1 需求 | 把"我想要个 XX"写成 3~5 条可验证的功能 | 需求清单+验收标准（本篇每选题已给好） |
| 2 方案 | 模块划分、数据流、器件选型 | 一页架构图+硬件清单（对照本篇改） |
| 3 开发 | 最小闭环 → 逐模块加功能，小步提交 | 可运行固件 + 整洁的 Git 记录 |
| 4 测试 | 按验收标准逐条勾，做长跑与边界测试 | 测试记录表（勾选+截图/数据） |
| 5 文档 | README 五段式 + 排障记录 | 仓库 docs/（模板见第 7 节） |

## 8. 作品集加分技巧

- **Git 提交整洁**：feat/fix/docs 前缀，一次提交只做一件事，里程碑打 tag（v1.0-bare-metal / v2.0-rtos）——"一坨 final 提交"是明显减分项；
- **过程比成功值钱**：docs/debugging.md 用"问题→排查→解决"三段式，串口日志、波形截图全部存档——完整的排障记录证明你能独立救火，"一次做对"只证明你会抄；
- **能量化就量化**：抖动、误差、长跑时长、内存占用——能测的都测，简历项目段直接引用（呼应 [02 篇的面试题库](02-面试实战与方向选择.md)）。

## 常见坑

1. **选题贪大求全**：一上来做"智能家居系统"必烂尾——从本篇菜单里挑，每个都被设计成 1~2 周能闭环；
2. **只堆功能不做记录**：不做 Git 提交、不写排障记录，两周后自己都复现不了；
3. **照抄例程不改架构**：代码全在一个 main.c 里、变量名是例程原名——典型的"课程作业感"；
4. **硬件一次买齐**：先按选题清单买最小集，缺啥补啥，避免抽屉里一堆吃灰模块；
5. **卡住就死磕**：违反 48 小时原则（见 FAQ），死磕三天不如降级方案+记录原因。

## FAQ

**Q1：做项目卡住怎么办？**
先写下来：现象、预期、已试过什么——写清的过程常自己就想通。然后：换关键词搜报错原文、查器件手册对应章节；**48 小时仍无进展就降级**（换器件/砍功能/简化协议），并把降级原因记进 debugging.md——降级决策也是工程能力。

**Q2：买什么板子？**
04 阶段：51 最小系统板或配好外设的 51 学习板；05 阶段：STM32F103C8T6 最小系统板 + 传感器模块拼装（学得最多）；06 阶段：不买新板；09 方向：能跑 Linux 的开发板。原则：**最小系统 + 模块拼装优先，大而全的学习板可做第二块**。

**Q3：要不要做 PCB？**
求职作品集阶段不强求——面包板/洞洞板 + 清晰接线图完全够用。想练手：挑最熟的一个项目用立创 EDA 画板打样（流程见 05 模块），一次打样费用不高，还能多一个"会画板"的谈资。

**Q4：项目烂尾了怎么办？**
烂尾也是素材：把已完成部分收敛成 v0.1 提交，README 里诚实写"做到哪、为什么停、下一步是什么"。**一个诚实的 80 分项目，好过一个吹牛的 100 分项目**——面试官追问两句就露馅的才是真的减分。

**Q5：能复现别人的开源项目吗？**
可以，但必须改：换器件、加功能、换架构任选其一，README 写清"与原版的差异"。原样搬运不是作品，改造+记录才是。
