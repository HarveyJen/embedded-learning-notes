# 01 · 作品集打造与简历项目化

> 目标：把路线里的毕业项目（07-STM32 多传感器系统、08-FreeRTOS 重构版、07-联网上报、10-Bootloader与OTA、11-嵌入式Linux网关）提炼成"面试官 3 分钟看懂"的作品集。

## 1. 好作品集的三个标准

**这是什么/解决什么问题**：作品集是你唯一能"提前递到面试官手上"的证据——简历上的每一句话它都替你作证。三个标准解决的是学生项目最普遍的三个死穴：跑不起来（不可运行）、课程作业感（没深度）、说不清（没故事）。

1. **可运行**：clone 下来能编能烧（README 一条龙命令）；
2. **有深度痕迹**：看得见架构分层、排障记录、测试数据——不是"课程作业感"；
3. **讲故事**：每个项目能回答"为什么这么设计、遇到什么坑、怎么量化收益"。

**数量原则**：2~3 个精项目 > 10 个烂项目。推荐组合（按求职方向二选一）。

怎么读这张表：先定求职方向（02 篇第 3 节有四方向对比），再按行取"项目套餐"——每行就是一条完整的作品集配置，不必全做：

| 方向 | 项目组合 |
|------|----------|
| 单片机/RTOS | STM32 多传感器采集（裸机+RTOS 双版本对照）+ OTA 升级系统 + Modbus 仪表 |
| Linux/IoT | 智能环境网关 + LED/按键字符驱动 + Buildroot 构建系统 SOP |

## 2. GitHub 仓库规范（作品集的门面）

```
gateway/
├── README.md            ← 面试官只看这个（3 分钟规则）
├── docs/
│   ├── architecture.md  ← 架构图（任务/线程、数据流）
│   ├── debugging.md     ← 排障手册（3+ 真实案例）
│   └── test-report.md   ← 长跑/压力测试数据
├── src/ include/        ← 分层清晰的代码
├── driver/              ← （Linux 方向）驱动与设备树
└── CMakeLists.txt / Makefile
```

**README 五段式**（直接套）：
1. 一句话：这是什么（配架构图）；
2. 功能清单（带截图/GIF 演示）；
3. 技术要点：3~5 条硬货（"osDelayUntil 保证采样抖动<1ms""双分区 OTA + 断电回滚验证"）；
4. 快速开始：环境/编译/烧录/测试命令；
5. 排障与测试：指向 docs。

**Git 卫生**：有意义的 commit message（feat/fix 前缀）、tag 版本点（v1.0-rtos）、无大二进制、无密钥泄漏。

## 3. 简历项目段怎么写（STAR 变体）

**这是什么/解决什么问题**：简历项目段是全简历被读得最细的地方。写法公式一句话：**动词 + 技术 + 量化结果**——每句话都要"做了什么、用了什么、效果多大"。先看反例与正例的对比，再照正例的结构改写自己的。

（标题里的 STAR=情境 Situation—任务 Task—行动 Action—结果 Result 的叙事框架，本篇把它压缩成一行式"动词+技术+量化结果"，是同一件事的简历版。）

**反例**（空话，全是"会过什么"，没有"做出了什么"——面试官无法验证也无法追问）：
> 熟悉 STM32 与 FreeRTOS，完成了数据采集系统，掌握 Modbus、MQTT 协议。

**正例**（量化+技术决策，每条都能追问出深度）：
> **多传感器数据采集系统**（STM32F103 + FreeRTOS + MQTT）
> - 五任务架构：DMA+定时器触发采样，osDelayUntil 周期对齐，采样抖动 <1ms（示波器实测）
> - 通信：自研 Modbus RTU 主站（CRC16 查表），MQTT 上云，断线指数退避重连
> - 可靠性：分布式看门狗（事件组打卡），双分区 OTA 支持断电回滚，72h 零故障
> - 仓库：github.com/xxx/gateway（含架构图/排障手册/测试报告）

**公式：动词 + 技术 + 量化结果**。每个 bullet 都该经得起面试追问（写了抖动<1ms 就要会讲怎么测的）。

## 4. 技能清单自我盘点（对照路线）

**这是什么/解决什么问题**：写"精通 C 语言"之前，先用这张表照照镜子——左列是层级，右列是"能写进简历的最低线"，达不到最低线就降级措辞（精通→熟悉→了解）。

怎么读这张表：逐行自问"右列的每一条我现在能做吗"，能做才可写；这张表同时也是面试复习的总目录（每行都对应路线里的具体笔记）。

| 层级 | 达标表现（能写进简历的最低线） |
|------|------|
| C 语言 | 手写环形缓冲/链表，讲清 volatile/static/内存对齐 |
| 单片机 | 寄存器级理解 GPIO/定时器/串口；HAL+寄存器双修 |
| RTOS | 任务划分原则、优先级反转与解法、栈溢出排查实战 |
| 通信 | Modbus 全栈实现、MQTT 断线重连、485/USB 调试经验 |
| OTA | 双分区+回滚+固件校验完整落地 |
| Linux | 系统编程+交叉编译+驱动入门+Buildroot 全流程 |
| 工具 | Git 工作流、ST-Link/JLink 调试、示波器/逻辑分析仪 |

**诚实原则**：每一条都要能扛住 20 分钟追问。写"了解"的水平就别用"精通"。

## 5. 项目深挖预备（面试官必问的五个为什么）

**这是什么/解决什么问题**：二面必考"项目深挖"——面试官拿你的项目连环追问为什么。这五个问题是最高频的追问点，提前自问自答写进 docs，面试时就是在"背自己的答案"。

对每个项目自问自答写进 docs（答案已在对应笔记里）：
1. 为什么任务/线程这么划分？（08-FreeRTOS 01/06 篇）
2. 优先级反转怎么防的？（08-FreeRTOS 03 篇）
3. 为什么用 MQTT 不用裸 TCP？（07-通信 07 篇思考题）
4. 升级失败怎么办？（10-Bootloader与OTA 回滚设计）
5. （Linux）为什么这个放驱动那个放用户态？（11-嵌入式Linux 05 篇思考题）

## 课后思考题

1. 面试官看 GitHub 时最先看什么？你该优化什么？（README 首屏+commit 曲线——假日期间刷 commit 没用，把 README 的"3 分钟可懂度"做到极致）
2. 项目里"踩过的坑"为什么比"实现的功能"更值钱？（功能证明会抄会拼；排障记录证明理解底层+工程方法论——面试官招的是"能独立救火的人"）
3. 没有企业级经验，怎么弥补"产品感"？（在作品集里补：OTA 安全分级、日志轮转、鉴权、长跑测试——这些"demo 不会做但产品必须有"的东西，恰恰是学生与工程师的分水岭）
