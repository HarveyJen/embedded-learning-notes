# 03 · 数码管与按键：动态扫描与消抖

> 目标：掌握"分时复用"思想（动态扫描）与"机械开关不可信"思想（消抖）——两者都是嵌入式基本功。

**开篇大白话**：这一篇解决两个"输入输出不老实"的问题——数码管太多位、IO 不够用（用"快速轮流点亮"骗过眼睛解决），按键会弹跳、一次按变多次（用"等一等再确认"解决）。两个解法背后是同一个思想：硬件不完美，用软件智慧补。

## 1. 数码管：8 个 LED 的组合拳

**这一节说什么**：先认识显示器件本身——数码管就是把 8 个 LED 摆成"8"字形，点亮不同的 LED 组合出 0~9。会"推段码"比会"背段码"重要。

一位数码管 = 8 个 LED（a~g 七段 + dp 小数点）排成"8"字形。**共阴**（所有 LED 阴极并接公共端，公共端接低、段给高点亮——"阴"指公共端是负极）与**共阳**（反过来，公共端接高、段给低点亮）两种，段码表互为取反。

**段码**这个词的意思：8 个 LED 对应 8 个二进制位，"显示某个数字需要点亮哪些段"拼成一个字节，这个字节就叫该数字的段码。

常用段码（共阴，0x 开头）：

```
0:3F  1:06  2:5B  3:4F  4:66
5:6D  6:7D  7:07  8:7F  9:6F
```

**怎么记住而不是背**：段码 = 把 dp g f e d c b a 依次当二进制的 7~0 位。例如"1"点亮 b、c 两段 → 0b0110_0110 → 0x06。需要新字形时自己推，不用查表死记。

**顺手推一个**："8"要点亮全部 7 段（dp 不亮）→ dp g f e d c b a = 0 1111 111 → 0b0111_1111 → 0x7F。共阳数码管？全部取反：0x7F → 0x80，0x06 → 0xF9——这就是"互为取反"的意思。

## 2. 静态 vs 动态扫描（核心思想：分时复用）

**这一节说什么/解决什么问题**：IO 引脚不够用的经典对策。先看静态方案为什么行不通，再学动态扫描怎么用"时间换空间"——它是嵌入式里"一根线干多件事"思想的第一次亮相。

**静态显示**：每一位数码管配独立的 8 个 IO 锁存段码 → 4 位就要 32 个 IO，51 的 32 个 IO 全搭进去还嫌不够。

**动态扫描**：所有位的**段选线并联**（共用一组 8 个 IO），**位选线**各自独立控制公共端。这两个新词先解释：
- **段选**：控制"显示什么字形"的那 8 根线（对应段码）；
- **位选**：控制"哪一位数码管通电"的那几根线（相当于每位数码管的"总闸"）。

每一时刻只点亮一位，但快速轮流切换：

```
第1ms：选通位1，送位1的段码
第2ms：选通位2，送位2的段码
……轮流往复，每位每秒被点亮几十次
```

**为什么看起来是"同时亮"**：人眼视觉暂留约 0.05~0.1s——电影 24 帧/秒就骗过眼睛，数码管每位刷新 >50Hz（8 位轮一圈 ≤20ms，每位亮 2ms）就"看起来全亮"。**算一遍**：8 位 × 2ms/位 = 16ms 轮一圈 → 刷新率 = 1 ÷ 0.016s = 62.5Hz > 50Hz，达标；若每位拖到 5ms，一圈 40ms → 25Hz，肉眼就能看出抖动。

类比：一桌人吃饭只有一双筷子（一组段选 IO），服务员飞快轮流给每人夹一筷子菜（分时点亮），速度快到每人都觉得自己一直在吃。

**代价与收益**：IO 从 4×8=32 降到 8+4=12 个；亮度打折（每位只有 1/8 时间通电）→ 位驱动常用三极管/专用芯片补电流。

### 硬件上的老朋友

段选/位选电流不够时，经典外扩方案就是 **74HC245（总线缓冲）/ 74HC573（锁存）**，位选多时用 **74HC138（3-8 译码）**——这些正是 [LX-750PLUS BOM](../../02-电路基础/笔记/08-真实工业产品BOM案例-LX750PLUS线材测试仪.md) 里"逻辑 IC"一栏的常客：51 时代的外扩套路在工业设备里活得好好的。

### 扫描代码模板（必须吃透）

**这段代码做什么**：在指定位置显示指定数字。它一次只负责"一位"，主循环轮流调用它就把整屏点亮了。

```c
unsigned char code segTable[] = {0x3F,0x06,0x5B,0x4F,0x66,0x6D,0x7D,0x07,0x7F,0x6F};
// code 关键字：把表放进 Flash。51 只有 512B RAM，常量表坚决不占 RAM

void DisplayOne(unsigned char pos, unsigned char num)  // pos:0~7 位, num:0~9
{
    /* 段选、位选的具体 IO 按你的开发板原理图对应（普中典型：P0 段、P2 位）*/
    P2 = ~(1 << pos);      // 位选：低电平选通（共阴位选经驱动管）
    P0 = segTable[num];    // 段选：送出字形
    DelayMs(2);            // 点亮 2ms：8 位轮一圈 16ms ≈ 62Hz > 50Hz 不闪
    P0 = 0x00;             // 【消隐】切走前先熄灭段码
}
// 主循环里 for(pos=0..7) 轮流调用，每次显示各自的数字
```

**关键行拆解**：
- `unsigned char code segTable[]`——把 0~9 的段码做成"查表"（数组下标=数字，表里存的值=段码），显示时 `segTable[num]` 一步取到，不用 switch-case 九九八十一次；
- `P2 = ~(1 << pos);`——**拆一位看**：pos=2 时，`1<<2` = `0000 0100`，取反 = `1111 1011` → 8 个位里只有 bit2 是 0 → 只有 2 号位的"总闸"打开。这个"1 左移再取反"是"从 N 个里挑 1 个"的通用写法，矩阵键盘还会再见；
- `P0 = segTable[num];`——段选线是并联的，此刻只有位选打开的那一位能看到段码，其他位"看得到够不着"（不通电）；
- `P0 = 0x00;`（消隐）——见下方说明。

**消隐为什么必须**：位选切换到下一位的瞬间，上一位的段码还挂在段选线上 → 下一位会"错误地亮出上一位的字形一瞬间"→ 肉眼看到**串影**（两个影子叠着）。先清段码再切位选，影子消失。类比：黑板擦干净了再给下一个人写，不然两个人的字叠在一起。

## 3. 按键：机械开关不可信

**这一节说什么/解决什么问题**：按键读数"一次按下被当成好几次"的病根与药方。学完你就知道为什么简单的 `if(按键==0)` 在工程里不够用，以及三种档位的消抖方案各用在什么场合。

### 抖动从哪来

金属触点闭合瞬间会弹跳 5~10ms，电平在 0/1 间反复横跳——一次按下可能被读成 3~10 次。类比：往床上扔枕头，枕头会弹几下才躺稳。

### 消抖三板斧

| 方案 | 做法 | 适用 |
|------|------|------|
| 软件延时确认 | 检测到按下→延时 10ms→再读一次确认 | 最常用，笔记02 已用 |
| 硬件 RC | 按键并联 100nF + 串联 10k 构成低通滤掉毛刺 | 对应[滤波器笔记](../../04-模拟电路基础/笔记/03-滤波器与频率响应.md) 4.3 节 |
| 状态机扫描 | 定时器每 10~20ms 采一次键，连续 2 次相同才确认 | **工程首选**，不吃主循环时间，长按/连击轻松扩展 |

**状态机**这个词在此处的含义：给按键定义几个"状态"（松开/抖动/按下确认/长按），每隔一段时间采样一次，按"当前状态+本次采样结果"跳到下一个状态——像流水线质检，每次来料按规矩走流程，不靠"等一等"这种笨办法。定时器哪来？笔记04 讲完定时器你就有资格用它了。

### 矩阵键盘（4×4=16 键只用 8 个 IO）

**为什么这么设计**：16 个键如果每个键一个 IO 要 16 根线；把键摆在行列交叉点上，行 4 根 + 列 4 根只要 8 根——n 行 m 列能装 n×m 个键，这是"分时复用"的又一次胜利。

行 4 根 + 列 4 根交叉，按键在交叉点上（不按=断路）。**行反转扫描法**：

```
① 行线输出 0，列线读入 → 有键按下则某列读到 0 → 定位"列"
② 列线输出 0，行线读入 → 定位"行"
③ 行号×4+列号 = 键值
```

**走一遍例子**：按下第 2 行第 3 列的键（行列都从 0 数）。第一步行线全 0，电流从列线的上拉电阻经按键流进行线 → 列线 3 读到 0 → 锁定"列 3"；第二步列线全 0 → 行线 2 读到 0 → 锁定"行 2"；键值 = 2×4+3 = 11。两次"主动出击+听回音"就把 16 个键压缩成 8 根线——又是分时复用思想。

## 4. 常见坑

**这一节说什么**：动态扫描的所有"显示难看"问题（闪、影、卡）都指向同一个根源——主循环被占住。先看现象，末尾的"深层教训"是本篇真正的考点。

| 坑 | 现象 |
|----|------|
| 没消隐 | 相邻位显示"叠影" |
| 每位延时 10ms+ | 整屏明显闪烁（刷新率掉到 12Hz 以下） |
| 扫描函数里塞了长延时操作 | 显示闪、按键迟钝（主循环被霸占） |
| 共阴共阳没分清 | 段码全反，显示乱码 |
| 长按一直触发 | 没写"等待释放"逻辑，或状态机没做连击间隔 |

**深层教训**：动态扫描的显示质量 = 主循环的执行节奏。主循环一旦被延时/长任务卡住，显示立刻花——这个"轮询架构的天然缺陷"正是笔记04 引入**定时器中断扫描**的理由，也是将来引入 RTOS 的动机。

## 5. 章节小结

- 段码 = 二进制位对应段，共阴共阳互为取反
- 动态扫描 = 分时复用 + 视觉暂留，>50Hz 不闪，消隐防串影
- 消抖 = 延时确认（入门）/ RC（硬件）/ 定时器状态机（工程首选）
- 矩阵键盘行反转：16 键 8 线
- 显示质量绑死主循环节奏 → 为中断扫描埋伏笔

## 课后思考题

1. 扫描每位 2ms、8 位共 16ms，为什么说刷新率约 62Hz？换成 16 位数码管会有什么问题？（16 位轮一圈 32ms≈31Hz，接近闪烁边缘——说明"扫描位数有限"，更多位要换锁存器静态方案或专用驱动芯片）
2. 行反转法为什么要求行列线都能"推 0 也能读"？（准双向口写 1 后可读外部，两步各扮演一次输出/输入——同时是"读前写 1"铁律的活用）
3. RC 消抖的 10k+100nF 时间常数约 1ms，为什么能对付 5~10ms 抖动？不够时怎么办？（RC 只压制快速毛刺，深抖动要更大 C 但会拖慢响应 → 混合方案：RC 粗滤 + 软件二次确认）
