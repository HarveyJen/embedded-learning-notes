# 02 · GPIO 与寄存器思维

> 目标：理解"写寄存器=控制硬件"，掌握准双向口特性、位操作三件套，独立写出流水灯与按键控制。

**开篇大白话**：这一篇回答"程序怎么摸得到外面的世界"——CPU 不能直接伸手去掰引脚，它只能往一些"有编号的格子"里写数字，硬件自动把这些数字变成引脚上的高低电平。看懂这个机制，你就掌握了嵌入式开发的一半。

## 1. 寄存器思维（本笔记的灵魂）

**这一节说什么/解决什么问题**：建立"控制硬件的唯一入口是寄存器"这个核心观念——以后你接触的每一个外设（定时器、串口、STM32 的一切），都遵循同一套玩法：查地址→写寄存器→硬件动作。

单片机控制外设的唯一方式：**读写特殊功能寄存器（SFR）**——CPU 地址空间里 0x80~0xFF 那一段，每个地址对应一个硬件功能。寄存器（Register）这个词先记住它的通俗含义：**CPU 眼里有固定编号的一格存储空间，写它=发命令，读它=问状态**。

```
你写 P1 = 0xFE;
      ↓ 本质
向地址 0x90 写入 0xFE
      ↓ 硬件自动
P1.0 引脚变低电平 → LED 亮
```

类比：寄存器是**一排带编号的开关面板**——每个面板（寄存器）有固定门牌号（地址），上面每个拨杆（位）连着一盏灯/一台设备。你不需要懂电路怎么走线，只要查"通讯录"（datasheet）找到面板号和拨杆位，拨对了设备就动。**嵌入式工程师的日常 = 查手册 + 拨开关**，这个感觉从 51 开始建立。

两个方向都要会：
- **写寄存器**=下命令（"P1.0 给我输出低电平"）；
- **读寄存器**=查状态（"引脚现在是高是低？"——按键检测读的就是它）。

C51 语法（reg52.h 已定义好）——**先认识这两个关键字**，它们是 C51 专门为"给地址起名字"造的：

```c
sfr P1 = 0x90;        // "P1 这个名字 = 地址 0x90 的 8 位寄存器"
sbit LED1 = P1^0;     // "LED1 = P1 寄存器的第 0 位"，可以单独读写
```

**这两行拆开看**：`sfr`（Special Function Register 声明）相当于在通讯录上登记"门牌号 0x90 的面板叫 P1"；`sbit` 相当于登记"这个面板上的 0 号拨杆叫 LED1"。之后写 `LED1 = 0;` 编译器就知道是"把地址 0x90 里 bit0 写成 0"。名字随便起（叫 LED1 还是叫 K1 都行），**地址才是硬件身份**。

## 2. 准双向口：51 IO 的特殊脾气

**这一节说什么/解决什么问题**：51 的 IO 引脚不是"想输出多强就多强"的万能脚——它输出 0 很有力、输出 1 很没劲。搞懂这个脾气，你就明白为什么 LED 要低电平点亮、为什么读按键前要先写 1，少踩一半的新手坑。

P1/P2/P3 是**准双向口**（"准"字的意思：能输入也能输出，但输入前有个前置动作），内部结构 ≈ 一个锁存器 + 一个弱上拉电阻：
- **锁存器**是什么：引脚内部的一个"记忆格"，你写的值先存在这里，它再驱动引脚——所以写 1 之后哪怕程序去干别的，引脚也保持 1；
- **弱上拉电阻**：一根很细的内部"弹簧"，没别的力作用时把引脚轻轻拉在高电平（拉力弱到只能维持电平，带不动负载）。

- **输出 0**：内部 MOS 导通，引脚被**强拉到地**（灌电流能力强，可到十几 mA）；
- **输出 1**：内部 MOS 断开，引脚只被**弱上拉**到高（只能输出几百 μA，推不动负载）。类比：强拉 0 像"用手把门按死"，弱拉 1 像"用一根橡皮筋把门拉住"——挡风可以，顶人不行；
- **读引脚**：读到的是引脚真实电平。

由此推出两条铁律：

1. **读按键前，先把该引脚写 1**。若上次写了 0（强拉到地），引脚永远是 0，读什么都是"按下"。**为什么**：准双向口的"读"读的是引脚实际电压，你自己的 0 把它钉死在地上，外部按键再怎么按也改变不了；
2. **LED 用"低电平点亮"**（灌电流）：LED 阳极经限流电阻（220Ω~1k）接 VCC，阴极接 IO——IO 输出 0 强灌电流点亮。高电平"拉"太弱点不亮。这就是 51 板"低电平有效"传统的由来，STM32 开发板也延续了这个习惯。

**P0 特殊：开漏输出，连弱上拉都没有**——输出 1 = 高阻态（引脚既不接电源也不接地，电平谁也定不了）！所以 P0 做 IO 必须外接上拉电阻（10k 排阻）；当年 P0 的本职是外扩存储器时的"地址/数据总线"。

## 3. 位操作三件套（贯穿整个嵌入式生涯）

**这一节说什么/解决什么问题**：一个 8 位寄存器上往往"有的位在忙、有的位不能动"——需要只改某一位而不碰其他 7 位的手法。这三招从 51 一直用到 STM32，是位运算知识（C 语言笔记10）在硬件上的第一次实战。

```c
P1 |=  0x01;    // 置位 P1.0（其余位不变）：与 1 或 = 置 1
P1 &= ~0x01;    // 清零 P1.0（其余位不变）：与 0 与 = 清 0
P1 ^=  0x01;    // 翻转 P1.0：异或取反
```

口诀（对照 C 语言笔记10 位运算）：**"或一置一，与零清零，异或翻转"**。

**一步步算给你看**（假设 P1 当前是 `0xF6 = 1111 0110`，即 P1.0=0、P1.1=1、其余全 1）：

```
① 置位 P1.0：  1111 0110   (P1)
             |  0000 0001   (0x01)
             =  1111 0111   → P1.0 变 1，其他位原样

② 清零 P1.0：  1111 0111   (P1)
             &  1111 1110   (~0x01，注意是掩码取反)
             =  1111 0110   → P1.0 变 0，其他位原样

③ 翻转 P1.0：  1111 0110   (P1)
             ^  0000 0001   (0x01)
             =  1111 0111   → 与 1 异或=取反，与 0 异或=不变
```

**为什么要绕这么一圈**：C 语言里没有"直接改某一位"的语句，只能用"位掩码"参与运算——`0x01` 是只挑 0 号位的"筛子"。想操作第 3 位？把筛子换成 `0x08`（0000 1000）即可，套路完全一样。

## 4. 实战代码

### 4.1 流水灯

**这段代码做什么**：8 个 LED 依次点亮，看起来像一盏灯从 P1.0"流"到 P1.7 再回头。核心技巧：用一个变量保存"当前亮灯位置"，每 200ms 循环左移一位。

```c
#include <reg52.h>
#include <intrins.h>          // _crol_ 循环左移函数在这里

void DelayMs(unsigned int ms);

void main(void)
{
    unsigned char led = 0xFE; // 1111 1110：只有 P1.0 是 0 → LED0 亮
    while (1)
    {
        P1 = led;             // 整个端口一次写 8 位（寄存器思维）
        led = _crol_(led, 1); // 0 循环左移一位：亮灯位置顺次移动
        DelayMs(200);         // 人眼能看清的速度
    }
}

void DelayMs(unsigned int ms)     // 粗略延时 @12MHz 12T
{
    unsigned int i, j;
    for (i = 0; i < ms; i++)
        for (j = 0; j < 123; j++); // 内圈约 1ms，凭经验凑的
}
```

**关键行拆解**：
- `unsigned char led = 0xFE;`——0xFE = 二进制 `1111 1110`。51 板 LED 低电平点亮，8 位里唯一的 0 落在 bit0 → 只有接 P1.0 的灯亮。**记住这个思路：先在纸上写出 8 个二进制位，看 0/1 落在哪些位，再换算成十六进制**；
- `led = _crol_(led, 1);`——`_crol_` 是"循环左移"：所有位整体左移一格，最高位绕回最低位。`1111 1110` → `1111 1101` → `1111 1011`……那个 0 像接力棒一样往高位跑，亮灯位置就动了。为什么不用 `led <<= 1`？普通左移会把最高位丢掉、最低位补 0，移满 8 位后灯全灭，接不上力；
- `for (j = 0; j < 123; j++);`——空循环拖时间。**为什么内圈是 123**：12MHz 12T 下一条空循环指令约 8 个机器周期，123 次×8μs≈1ms——这是"凑"出来的经验值，换个编译器/优化等级就不准了。

注意：`DelayMs` 是**不精确延时**（编译器、指令周期都会影响），精确计时必须用定时器（笔记04）——先知道有这个缺陷，后面补上。

### 4.2 按键控制 LED（含消抖雏形）

**这段代码做什么**：每按一次按键，LED 翻转一次（亮↔灭）。用"检测→延时→再确认"三步躲过机械抖动。

```c
sbit KEY1 = P3^2;    // 开发板按键一般接 P3.2/P3.3（恰好是外部中断引脚）
sbit LED1 = P1^0;

void main(void)
{
    KEY1 = 1;                       // 铁律：读之前先写 1（准双向口）
    while (1)
    {
        if (KEY1 == 0)              // 检测到低电平（按下拉地）
        {
            DelayMs(10);            // 粗延时跳过机械抖动（5~10ms）
            if (KEY1 == 0)          // 二次确认：还是低才是真按下
            {
                LED1 = !LED1;
                while (KEY1 == 0);  // 等待松手，避免长按连翻转
            }
        }
    }
}
```

**关键行拆解**：
- `KEY1 = 1;`——**为什么读前先写 1**：见第 2 节铁律。这一句把引脚交还给"弱上拉+外部按键"决定电平，程序自己别插手；
- `if (KEY1 == 0)`——按键一端接 IO、另一端接地，按下=引脚被拉到地=读到 0。这就是"读寄存器=查状态"的实际应用；
- `DelayMs(10); if (KEY1 == 0)`——第一次读到 0 可能是抖动的"假信号"，等 10ms 抖动结束再确认一次，还是 0 才算数；
- `while (KEY1 == 0);`——按住不放就原地等。**为什么**：不加这句，按一次 0.5 秒会被主循环判成几百次按下，LED 疯狂翻转。代价是按住期间主循环啥也干不了——这个缺陷由笔记03/04 的状态机与中断解决。

消抖原理详述在笔记03，这里先建立"检测→延时→再确认"肌肉记忆。

## 5. 常见坑

**这一节说什么**：下面的坑全都源自第 2 节"准双向口脾气"——现象千奇百怪，根因就那么几个，对照"原因"列反过来理解第 2 节效果最好。

| 坑 | 现象 | 原因 |
|----|------|------|
| P0 没上拉 | 接 P0 的 LED/数码管全无反应 | 开漏无上拉，输出 1 = 高阻 |
| 读按键前没写 1 | 按键永远"已按下" | 引脚被自己上次写的 0 强拉到地 |
| LED 接法反了 | 只有 1 颗亮或不亮 | 低电平点亮 vs 高电平点亮没搞清 |
| 用 sbit 名字直接 = 0xFE | 编译报错 | 位只能赋 0/1，字节才能赋 0xFE |
| 延时太短 | 流水灯像"常亮微闪" | 人眼分辨极限 ~24Hz，间隔至少 50ms |

## 6. 章节小结

- 写寄存器 = 写地址 = 控硬件；sfr 定字节、sbit 定位
- 准双向口：输出 0 强、输出 1 弱 → 读前写 1、LED 低电平点亮；P0 开漏必须上拉
- 位操作三件套 `|= / &=~ / ^=` 沿用到 STM32
- 软件延时不精确，精确时序交给定时器

## 课后思考题

1. 为什么"输出 1 弱、输出 0 强"反而适合点灯？（LED 接 VCC 侧用灌电流：强灌能提供点亮电流；若靠弱拉高驱动 LED，电流不足且电压不达标）
2. `P1 |= 0x01` 这句 CPU 实际做了几步？（读 P1 → 与 0x01 或 → 写回 P1，即"读-改-写"三步——这也解释了为什么要防止对锁存器为 0 的引脚做读改写）
3. 如果 8 个 LED 全接 P0 又不想用排阻，有什么办法？（P0 恢复本职：接 74HC245/573 缓冲芯片——正是 LX-750PLUS BOM 里的总线缓冲方案，也是很多 51 开发板数码管电路的标准做法）
