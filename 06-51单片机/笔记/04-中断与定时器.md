# 04 · 中断与定时器（本阶段核心）

> 目标：建立"事件驱动"思维——让硬件替你盯着时间与事件，CPU 只在被叫到时才干活。这章的概念 100% 原样迁移到 STM32/任何 MCU。

**开篇大白话**：前面所有程序都在"死等"——延时凑时间、轮询查按键，CPU 大部分生命耗在空转上。这一篇给 CPU 装上"闹钟"（定时器）和"门铃"（中断）：时间到了、事件来了，硬件主动喊 CPU，平时它该干嘛干嘛。这两件东西是所有单片机程序的心脏。

## 1. 中断：从"死盯"到"呼叫"

**这一节说什么/解决什么问题**：轮询架构的 CPU 利用率极低，而且"查得慢了就漏事"。中断机制让硬件在事件发生的第一时间主动通知 CPU——这是从"傻循环"迈向"工程程序"的分界线。

**轮询**（前面所有程序的方式）：主循环反复查"按键按了吗？时间到了吗？"——像站在锅边死盯水开，什么都干不成。

**中断**：平时主循环干正事，事件发生时硬件**自动暂停主程序、跳去执行你的服务函数（ISR）、干完回来接着跑**——像装了烟雾报警器，你放心睡觉，着火才叫你。更日常的版本：在家做饭（主循环）时门铃响了（中断事件），你先把火关小记住锅的状态（硬件保存现场），开门应付两分钟（执行 ISR），回来接着炒菜（恢复现场继续跑）——**一顿饭没耽误，客人也没被晾着**。

### 51 的 5 个中断源 + 向量表

**中断源**这个词：能触发中断的事件种类。51 有 5 个"门铃按钮"，每个按钮在 Flash 里对应一个固定门牌（向量地址）。

| 中断源 | 触发条件 | 中断号（C51 关键字用） | 向量地址 |
|--------|----------|:---:|------|
| INT0 外部中断 0 | P3.2 引脚出现有效电平/边沿 | 0 | 0003H |
| T0 定时器 0 | 计数溢出 | 1 | 000BH |
| INT1 外部中断 1 | P3.3 引脚 | 2 | 0013H |
| T1 定时器 1 | 计数溢出 | 3 | 001BH |
| UART 串口 | 收/发完一字节 | 4 | 0023H |

**向量表**：每个中断在 Flash 里预留一个固定入口地址，中断发生时硬件自动跳到那里——你不用管怎么跳，只要把 ISR 函数用 `interrupt n` 挂上去（`interrupt 1` 里的 1 就是上表"中断号"列，告诉编译器"我这个函数是 T0 的门铃应答"）。这个机制与 ARM 的向量表、NVIC 一脉相承。

### 控制"门与优先级"的寄存器

**先说为什么需要它们**：中断不能想响就响——你得决定"哪些门铃开着、谁更急"。这三个寄存器就是 51 的"门铃总控台"。

- **IE（Interrupt Enable，中断允许寄存器）**：一排开关。`EA` 是总闸（EA=Enable All），EX0/ET0/EX1/ET1/ES 是各源分开关。**总闸和分闸都闭合，对应中断才通**——**EA 忘写 1 = 所有中断全灭**，头号新手坑；
- **TCON**：定时器/外部中断控制寄存器，这里用到 IT0/IT1 两位——选外部中断触发方式（0=低电平，1=**下降沿**，一般用沿触发防重复）。**为什么用下降沿**：电平触发时引脚只要低着就一直喊人，一次按键喊几百声；下降沿触发只在"从高变低那一瞬"喊一声；
- **IP**：中断优先级寄存器，两级优先级，=1 的高优先级能打断低优先级（中断嵌套——高级 ISR 可以把低级 ISR 按暂停，类似"领导来电可以打断你正在开的会"）。

### ISR 纪律（嵌入式通用军规）

**为什么有军规**：ISR 执行期间，同级/低级中断全部排队、主循环完全停摆——ISR 每多待 1μs，全系统就卡 1μs。

1. **短小快走**：ISR 里严禁长延时/死等——它卡住的是整个系统的响应；
2. **与主循环共享的变量加 `volatile`**，防止编译器优化掉读取（原理：编译器看主循环里 `while(!keyFlag)` 没人改它，就自作主张优化成只读一次——volatile 告诉它"这个变量会被 ISR 偷偷改，每次都要真读"）；
3. 只做"标记/搬运"，判断和显示交给主循环。

**这段代码做什么**：按键接在 INT0（P3.2）上，每按一次（下降沿）触发中断，ISR 只把标志位置 1；主循环看到旗子立起来才做正经工作（如计数+显示）。

```c
volatile unsigned char keyFlag = 0;   // 主循环和 ISR 都碰，必须 volatile

void INT0_ISR(void) interrupt 0        // interrupt 0 = INT0 的中断号
{
    keyFlag = 1;                       // 只立旗子，不干活
}

void main(void)
{
    IT0 = 1; EX0 = 1; EA = 1;          // 下降沿触发、开 INT0、开总闸
    while (1)
    {
        if (keyFlag) { keyFlag = 0; /* 显示计数 +1 等正经工作 */ }
    }
}
```

**关键行拆解**：
- `IT0 = 1;`——TCON 里的触发方式位，1=下降沿触发（按下瞬间触发一次）；
- `EX0 = 1; EA = 1;`——**顺序无所谓，两个都必须有**：EX0 是 INT0 的分闸，EA 是总闸。新手最常见"开了分闸忘总闸"，程序看起来"中断完全无效"；
- `interrupt 0`——查第 1 节的表：中断号 0 = INT0。写错号 = 程序跳进别人的门铃应答，直接跑飞；
- `keyFlag = 1;`——ISR 全身只有这一句，这就是"短小快走"的样板：真正的计数显示留给主循环，中断响应耗时几乎为零。

## 2. 定时器：硬件帮你数心跳

**这一节说什么/解决什么问题**：软件延时不准、还占着 CPU；定时器是独立于 CPU 的"自动数数机"，数满自动报警——它是精确计时、走时钟、PWM、串口波特率的地基，51 和 STM32 上思路完全一样。

### 原理一句话

定时器 = **一个自动 +1 的计数器**，每个机器周期加一次，数到溢出（65536→0）就置标志/触发中断。既然"每跳一下=1μs（12MHz 12T）"，数多少下就是多少时间——**时间测量变成计数问题**。

类比：让一个不知疲倦的人每秒在纸上画一道，画满 65536 道按铃——按铃间隔就是你设的时长。

**涉及的寄存器先点名**（都在管定时器的事）：
- **TMOD**（Timer Mode 定时器模式寄存器）：决定定时器"怎么数"（16 位/8 位自动重装/计数模式等），低 4 位管 T0、高 4 位管 T1；
- **TH0/TL0**：T0 的计数器本体，高 8 位+低 8 位拼成 16 位（从初值一路数到 65536）；
- **TCON 里的 TR0**：T0 的"油门"，TR0=1 才开始数；
- **IE 里的 ET0**：T0 溢出中断的分闸（EA 是总闸）。

### 初值计算（必须手算过关）

**为什么有"初值"这回事**：计数器只会一路 +1 数到 65536 溢出，可你想要的是"数 1000 下就报警"——那就让它**从 65536−1000=64536 开始数**，走 1000 步正好到头。初值就是"起点"，溢出是"终点"。

计数器从**初值**数到 65536 溢出，所以：

```
初值 = 65536 − 计数值        （模式1：16位）
```

**完整算例一：12MHz 定时 1ms（一步步来）**

```
第1步：求机器周期。12MHz、12T 模式 → 机器周期 = 12/12MHz = 1μs
第2步：求要数多少下。定时 1ms = 1000μs → 计数值 = 1000μs ÷ 1μs = 1000
第3步：求初值。65536 − 1000 = 64536
第4步：拆成高低字节（TH0 装 64536÷256 的商，TL0 装余数）：
       64536 ÷ 256 = 252 余 64
       → TH0 = 252 = 0xFC，TL0 = 64 = 0x18
验证：0xFC18 = 252×256+64 = 64536 √（从 64536 数 1000 步正好到 65536）
```

**完整算例二：12MHz 定时 50ms**

```
计数值 = 50ms ÷ 1μs = 50000
初值   = 65536 − 50000 = 15536
拆分：  15536 ÷ 256 = 60 余 176 → TH0=60=0x3C，TL0=176=0xB0
```

**完整算例三：11.0592MHz 定时 1ms（实操任务里的那题）**

```
第1步：机器周期 = 12 ÷ 11.0592MHz = 1.085μs（不是整 1μs！）
第2步：计数值 = 1000μs ÷ 1.085μs ≈ 921（取整，舍掉 0.7μs 的尾巴——这就是走时误差的来源）
第3步：初值 = 65536 − 921 = 64615
第4步：64615 ÷ 256 = 252 余 103 → TH0=0xFC，TL0=103=0x67
```

**模式 1 不会自动重装初值**——ISR 里必须手动把 TH0/TL0 补回去，忘了就"第一次准，之后每次都从 0 数起变成 65ms"（经典故障：走时越走越慢）。（STC 增强款与 STM32 的 TIM 都有自动重装寄存器，就是为了让硬件替你补。）

### 标准例程：1ms 时基

**这段代码做什么**：让定时器 0 每 1ms 溢出中断一次，ISR 里累加变量 ms——这就是给整个程序装了一个"毫秒心跳"，主循环想要任何时间间隔（500ms 闪灯、10ms 扫描）都从 ms 上"取"。

```c
#include <reg52.h>

volatile unsigned int ms = 0;      // 时基计数

void Timer0_Init(void)
{
    TMOD &= 0xF0;                  // 清 T0 的模式位（低4位），不动 T1
    TMOD |= 0x01;                  // T0 模式1：16 位定时
    TH0 = 0xFC; TL0 = 0x18;        // 1ms 初值 @12MHz
    ET0 = 1;                       // 开 T0 中断
    EA  = 1;                       // 开总中断
    TR0 = 1;                       // 启动 T0（TCON 里 T0 的"油门"）
}

void Timer0_ISR(void) interrupt 1
{
    TH0 = 0xFC; TL0 = 0x18;        // 手动重装！
    ms++;
}

void main(void)
{
    Timer0_Init();
    while (1)
    {
        if (ms >= 500)             // 主循环只看"闹钟"，不做精确计时
        {
            ms = 0;
            P1 ^= 0xFF;            // 每 500ms 翻转 → 1Hz 闪灯
        }
    }
}
```

**关键行拆解**：
- `TMOD &= 0xF0; TMOD |= 0x01;`——**为什么两句而不是一句 `TMOD=0x01`**：TMOD 低 4 位管 T0、高 4 位管 T1。直接赋值会把 T1 的配置也清掉（未来 T1 兼职波特率发生器时就是事故）；"先与后或"是位操作三件套（笔记02）的标准应用：`&= 0xF0` 只清低 4 位，`|= 0x01` 只把模式 1 填进低 4 位；
- `TH0 = 0xFC; TL0 = 0x18;`——完整算例一算出的初值 64536，高字节 0xFC、低字节 0x18；
- `ET0 = 1; EA = 1;`——又是"分闸+总闸"双开关；
- `TH0 = 0xFC; TL0 = 0x18;`（ISR 里）——**手动重装，本程序成败手**：溢出后计数器从 0 重新数，不补初值下一次就要数满 65536 才中断（65.5ms 而不是 1ms）；
- `ms >= 500`——主循环把"计时"外包给中断，自己只消费结果。中断每 1ms 把 ms 加 1，主循环攒够 500 就动作，误差最多一个主循环节拍。

这套"**定时器中断造时基 + 主循环查标志**"的架构是 51/STM32/工业裸机通用的骨架——笔记03 末尾的"显示被延时卡死"问题，把数码管扫描搬进这里就解决了。

## 3. 定时器的两个杀手应用

**这一节说什么**：光会"定时中断"还不够，看它怎么变现——用同一套时基造出"占空比可调的方波"（PWM 调光调速）和"频率可调的方波"（蜂鸣器奏乐）。

### ① 软件 PWM（呼吸灯/电机调速）

**PWM 是什么**：快速开关 IO，用"亮的时间占比"（占空比）控制平均亮度/转速——灯其实每秒闪了几十次，但人眼只感觉到"平均亮度"。

**这段代码做什么**：在 1ms 中断里维护一个 0~99 的循环计数（100 拍=一个 PWM 周期），计数值小于 duty 的拍子里点灯，其余时间灭——duty=30 就意味着"每 100 拍里亮 30 拍"。

```c
// 在 1ms 中断里数 100 拍 → PWM 周期 100ms（示意；实用请缩短到 100μs 中断）
volatile unsigned char pwmCnt = 0;
unsigned char duty = 30;               // 占空比 30%

void Timer0_ISR(void) interrupt 1
{
    TH0 = 0xFC; TL0 = 0x18;
    if (++pwmCnt >= 100) pwmCnt = 0;   // 0~99 循环
    LED = (pwmCnt < duty) ? 0 : 1;     // 低电平点亮：前 duty 拍亮
}
```

**关键行拆解**：
- `if (++pwmCnt >= 100) pwmCnt = 0;`——先加再判，pwmCnt 在 0~99 之间循环，100 拍走完归零重来；
- `LED = (pwmCnt < duty) ? 0 : 1;`——PWM 周期 100ms 里前 30ms 亮（占空比 30%）。**算频率**：周期 100ms → 频率 10Hz，人眼能看到闪烁，所以注释提醒"实用请缩短到 100μs 中断"——周期 10ms → 100Hz 就平滑了；
- 主循环里让 duty 在 0↔100 间缓变 = 呼吸灯。

驱动电机时接三极管/MOS（对应[半导体笔记](../../02-电路基础/笔记/03-半导体器件.md)的驱动电路）。占空比思想直通 STM32 硬件 PWM 与 LX-750PLUS 的可控硅调压（调交流"占空比"）。

### ② 无源蜂鸣器发音

- **有源蜂鸣器**：通电就响（内置振荡）——省事；
- **无源蜂鸣器**：要外部喂 **2~5kHz 方波**才响——用定时器每 200μs（对应 2.5kHz）翻转一次 IO。**算一遍**：每 200μs 翻转一次 → 一个完整周期 = 翻转两次 = 400μs → 频率 = 1÷400μs = 2.5kHz，落在发声区间。改翻转间隔=改频率=变音调，能奏《小星星》。这也是"定时器产生频率"的思想（与模电笔记04 的 555 造方波殊途同归）。

## 4. 常见坑

**这一节说什么**：定时器程序的故障都有"规律可查"——先对照这张表自查，每一行都对应前文某条纪律。

| 坑 | 现象 |
|----|------|
| 忘 `EA=1` | 所有中断无声无息 |
| 忘重装初值 | 周期比设定长得多、走时慢 |
| TMOD 直接 `=0x01` | 把 T1 模式顺带清了（要用 `&=` `|=` 保住另一半） |
| ISR 里 DelayMs | 全系统响应卡死 |
| 中断号写错 | 程序跑飞进错误入口 |
| 11.0592MHz 却按 1μs 算初值 | 所有时间慢 8.5% |

## 5. 章节小结

- 中断=硬件呼叫：5 源、向量表、EA 总闸、ISR 短小+volatile
- 定时器=数机器周期：初值 = 65536−计数值；模式 1 手动重装
- 时基架构：定时器造 1ms tick + 主循环查标志 = 裸机程序万能骨架
- 应用：软件 PWM（占空比）与方波发音（频率）——占空比/频率两参数贯穿到 STM32 外设

## 课后思考题

1. 为什么 ISR 里禁止长延时，而主循环里可以？（ISR 打断的是一切——延时期间其他中断也排队，实时性崩塌；主循环慢只影响不紧急任务）
2. 两级优先级的 51 遇到"三个中断同时来"会怎样？（同级按 INT0>T0>INT1>T1>UART 固定自然顺序逐个响应；高级别可打断低级别 ISR——对比 STM32 抢占/响应双维度的灵活性）
3. 为什么说"定时器扫描数码管"比主循环扫描工程质量高？（刷新率由硬件时钟保证、不受主循环业务耗时影响；主循环慢只影响响应速度不影响显示——**时序确定性**是工业程序的命根子）
