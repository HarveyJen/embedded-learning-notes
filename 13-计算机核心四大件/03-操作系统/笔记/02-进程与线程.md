# 02 · 进程与线程

> 定位：OS 四大件第一块硬骨头。学完本篇，Linux 的进程线程和 FreeRTOS 的 Task 就能在同一个脑子里对上号（总对照表见 [01-操作系统-嵌入式视角](01-操作系统-嵌入式视角.md)）。

**先说人话**：本篇讲两个最基础的抽象——**进程**（"一家工厂"，OS 分配资源的最小单位）和**线程**（"厂里工人"，CPU 真正调度的执行单位）。为什么嵌入式工程师需要它：Linux 板子上跑的每个可执行程序都是一个进程；你写过的每套多任务逻辑（pthread 也好、FreeRTOS 任务也好）都是这对概念的变体。搞懂它，Linux 应用开发与 RTOS 开发就打通了。

## 1. 进程：一家工厂

**这是什么**：进程 = **程序的运行实例**。程序是硬盘里的菜谱（静态文件），进程是"正在炒的这道菜"（动态实体）。类比：程序 = 一张工厂设计图纸，进程 = 图纸落地建起的工厂——有厂房（内存）、有设备（打开的文件、外设）、有门牌号（PID，进程号）。

- 进程是 OS **分配资源的最小单位**：内存、文件描述符、信号处理表……都以进程为单位记账；
- 程序 ≠ 进程：一份图纸可以盖三家厂——同一个程序跑三份就是三个独立进程；
- 每个进程有唯一 PID；1 号进程（init/systemd）是所有进程的"祖宗"，专门负责收养孤儿（第 8 节）。

## 2. 线程：厂里的工人

**这是什么**：线程 = **CPU 调度执行的最小单位**，住在进程这间厂房里。类比：进程是工厂，线程是工人——多个工人**共用同一厂房、同一批设备**（共享内存和文件），但每人有**独立工位和记事本**（私有栈和寄存器）。

同一进程内的线程之间：
- **共享**：代码段、全局变量、堆（malloc 来的内存）、打开的文件；
- **私有**：栈（函数调用链）、寄存器组（含程序计数器——"干到第几行了"）。

共享是福利也是祸根：线程间传数据零成本，但"两个工人同时改一张表格"就是下一篇（04 同步互斥）要治的病。

## 3. fork / exec / wait：Linux 创建进程三板斧

**这是什么**：Linux 进程的一生三步——**fork**（照现有厂房克隆一家新厂）、**exec**（给新厂换图纸、改产新产品）、**wait**（老厂等新厂完工并验收）。与"直接新建一个空进程"的思路不同，Linux 的哲学是**先复制、再改造**。

**这段代码要做什么**：父进程克隆出子进程，子进程把自己"换身"成 ls 去列目录，父进程等它完工并取回退出码——shell 执行每条命令用的就是这套流程。

```c
#include <stdio.h>
#include <unistd.h>     /* fork / execlp / getpid */
#include <sys/wait.h>   /* waitpid */

int main(void)
{
    printf("before fork: pid=%d\n", getpid());

    pid_t pid = fork();                 /* 关键一行：调用一次，返回两次 */

    if (pid < 0) {                      /* 失败：进程数超限或权限不足 */
        perror("fork");
        return 1;
    } else if (pid == 0) {              /* 子进程分支：fork 在子进程里返回 0 */
        execlp("ls", "ls", "-l", (char *)NULL);  /* 换图纸：加载 ls 取代自己 */
        perror("execlp");               /* exec 成功就不回来；能走到这说明失败 */
        _exit(127);                     /* 用 _exit，避免把父进程的缓冲区也冲出去 */
    } else {                            /* 父进程分支：fork 返回子进程 PID（>0） */
        int status;
        waitpid(pid, &status, 0);       /* 阻塞等子进程退出，顺便"收尸" */
        if (WIFEXITED(status))
            printf("child exit code=%d\n", WEXITSTATUS(status));
    }
    return 0;
}
```

**fork 为什么"返回两次"**：fork 把当前进程整个复制一份（内存先共享、谁写谁才真正复制，即**写时复制** Copy-On-Write）。复制完系统里有两个几乎一样的进程，**都停在 fork 这一行准备往下跑**——父进程拿到的返回值是子进程 PID，子进程拿到 0。一次调用、两个进程各返回一次，所以"返回两次"。代码靠 if/else 把两条岔路分开。

时间线拆解（A = 父进程，B = 子进程）：

```
t0  A 执行到 fork()
t1  内核复制出 B（代码数据与 A 相同，仅 PID 不同）
t2  A 从 fork 返回，拿到 B 的 PID → 走 else 分支
t3  B 从 fork 返回，拿到 0          → 走 if 分支
t4  B 执行 execlp：全身换成 ls 的代码与数据（PID 不变，"换人不换工牌"）
t5  A 在 waitpid 处睡着等 B
t6  B（现在是 ls）列完目录退出；A 醒来，拿到退出码
```

**API 三问**：
- **fork**：是否阻塞？否（瞬间返回两次）。时间单位？无（返回值是 pid_t）。适用上下文？进程内（多线程程序里 fork 只复制调用线程，慎用）。
- **execlp**：是否阻塞？不适用——成功则**永不返回**（原程序被整体替换）。时间单位？无。适用上下文？进程内（exec 不新建进程，只换内容）。
- **waitpid**：是否阻塞？**默认阻塞**到子进程结束（加 WNOHANG 变非阻塞轮询）。时间单位？无（直到子进程退出）。适用上下文？父进程。

## 4. pthread：线程创建与汇合

**这是什么**：pthread（POSIX 线程）是 Linux 线程的标准接口。类比：厂里**招工人**（pthread_create）进同一间厂房干活，完工后**收工牌、取报表**（pthread_join）。

**这段代码要做什么**：主线程招一个工人线程去干 1 秒活，然后等它收工、取回返回值。

```c
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

void *worker(void *arg)               /* 线程函数签名固定：void *(void *) */
{
    int id = *(int *)arg;             /* 取出启动参数 */
    printf("thread %d start\n", id);
    sleep(1);                         /* 模拟干活 1 秒 */
    return (void *)(long)(id * 100);  /* 小整数可用"指针夹带"传返回值 */
}

int main(void)
{
    pthread_t tid;
    int arg = 7;

    pthread_create(&tid, NULL, worker, &arg);  /* 招工人：立即返回 */

    void *ret;
    pthread_join(tid, &ret);          /* 等收工并取回返回值 */
    printf("thread return %ld\n", (long)ret);
    return 0;
}
```

运行逻辑与易踩坑：
- 编译要带 `-pthread`（链接线程库），否则报 `undefined reference to pthread_create`；
- 参数 `&arg` 是主线程的**栈地址**：本例 main 里 join 了所以安全；若在循环里复用同一个变量传给多个线程，就成竞态——多线程各传各的用数组每线程一格，或 malloc 单独一份；
- 忘了 join：线程资源没人回收，近似进程界的"僵尸"。

**API 三问**：
- **pthread_create**：是否阻塞？否（创建后新线程立即并发跑）。时间单位？无。适用上下文？同一进程内的线程。
- **pthread_join**：是否阻塞？是（等目标线程结束）。时间单位？无超时版本（要限时得用条件变量自己实现）。适用上下文？任意线程等另一线程。

## 5. 进程地址空间：五段布局

**这是什么**：进程眼中的内存不是一锅粥，而是**分区摆放的厂房**：成品区、原料库、扩建区、操作台各归其位。（C 语言层面的分段与存储类别细节见 [08-内存布局与动态内存](../../../01-C语言基础/笔记/08-内存布局与动态内存.md)，本节补"运行中进程"的视角。）

```
高地址 ┌──────────────────────┐
       │ 栈  ↓ 向下生长        │ ← 局部变量、函数调用帧
       │          ...         │ （中间是大片空洞，堆栈相向生长）
       │ 共享库映射区          │ ← libc.so 等加载进来的位置（栈之下、堆之上）
       ├──────────────────────┤
       │ 堆  ↑ 向上生长        │ ← malloc 来的内存
       ├──────────────────────┤
       │ BSS                  │ ← 未初始化全局/static（加载时清零）
       ├──────────────────────┤
       │ 数据段 .data         │ ← 已初始化全局/static
       ├──────────────────────┤
       │ 代码段 .text（只读）  │ ← 机器码、字符串常量
低地址 └──────────────────────┘
```

**这段代码要做什么**：把"什么变量住哪一段"一次记牢——这是面试与踩坑（段错误、爆栈、泄漏定位）的基本功。

```c
int g_init = 10;         /* .data   已初始化全局变量 */
int g_zero;              /* BSS     未初始化全局变量 */
static int s_cnt = 1;    /* .data   已初始化静态变量 */
const char *msg = "hi";  /* msg 本身在 .data；"hi" 字面量在 .text 只读区 */

int main(void)
{
    int local = 0;        /* 栈：函数一返回就自动回收 */
    static int s_zero;    /* BSS：static 变量绝不在栈上！ */
    int *p = malloc(100); /* p 本身入栈；100 字节本体在堆，要手动 free */
    free(p);
    return 0;
}
```

关键记忆点：**栈向下长、堆向上长、中间是空洞**——两者相遇就是内存耗尽；.text 只读，写它 = 段错误（如 `char *s = "hi"; s[0] = 'H';`）。

## 6. 上下文切换：换班交接

**这是什么**：CPU 只有少数几个，任务一大堆——轮换上场时必须**把工位交接清楚**。白话：切换 = 把当前任务的"大脑状态"（所有寄存器 + 程序计数器 + 栈指针）拍照存进它的档案（进程叫 PCB，FreeRTOS 里叫 TCB），再把下一个任务的存档恢复进 CPU。

类比：车间换班——老工人把记事本、半成品、工具箱全部归位登记（保存现场），新工人按登记单一件件领走（恢复现场）；交接不细，活就废了。

**切换成本三来源**：
1. **保存/恢复寄存器 + 切换内核栈**：纯手工活，Cortex-M 上由 PendSV 中断一气呵成，十几微秒量级；
2. **调度器决策**：从就绪队列里挑下一个上场者（算法见 03 篇）；
3. **地址空间切换（仅进程之间）**：换页表基址会让 TLB/Cache 大面积失效，之后一段时间每次访存都变慢——**这是进程切换比线程切换贵的根本原因**；线程共享地址空间，免了这笔账。

嵌入式对应：FreeRTOS 任务切换只做第 1+2 步（无第 3 步——没有 MMU/地址空间概念），所以更便宜。这也回答了"任务为什么不能切太碎"：切换本身是纯开销，切得太密就全在交班、没在干活（切换细节见 [01-裸机到RTOS任务与调度](../../../08-FreeRTOS/笔记/01-裸机到RTOS任务与调度.md)）。

## 7. 三栏对照：进程 / 线程 / FreeRTOS 任务

**这是什么**：三个概念最容易混——一张表钉死。读法：**从左到右 = 隔离越来越弱、切换越来越快**。

| 维度 | Linux 进程 | Linux 线程 | FreeRTOS 任务 |
|------|-----------|-----------|---------------|
| 本质 | 资源分配单位 | 调度执行单位 | 调度执行单位（RTOS 没有"进程"这一层） |
| 地址空间 | 独立虚拟空间，进程间有墙 | 共享所属进程的空间 | 全体共享同一物理空间，无墙 |
| 切换成本 | 最大（含页表切换） | 中（无页表切换） | 最小（只换寄存器 + 栈指针） |
| 一个崩了 | 别的进程无恙 | 整个进程团灭 | 整个系统遭殃 |
| 通信方式 | 管道/消息队列/共享内存等 IPC | 直接共享变量（必须加锁） | 队列/信号量/任务通知 |
| 创建开销 | fork+exec，重 | pthread_create，轻 | xTaskCreate，可纯静态零堆分配 |

一句话结论：**FreeRTOS 任务 ≈ 一个"共享一切"的线程**——好处是通信零成本，代价是没有防火墙，全靠程序员自觉（内存保护对比详见 05 篇）。

## 8. 僵尸进程与孤儿进程

**这是什么**：父子进程"交接手续没办完"的两种事故。类比：僵尸 = **员工离职了人事档案还挂着**（没人办手续）；孤儿 = **公司先倒闭，员工被劳动局接管**（有人兜底，无害）。

- **僵尸进程**：子进程已退出，但父进程一直不调 wait → 内核进程表里残留一条"退出状态"记录，占着 PID。僵尸不耗 CPU，但 PID 是有限资源——攒多了系统就 fork 不出新进程；
- **孤儿进程**：父进程先死，子进程被 1 号进程（systemd/init）收养，退出后由养父代为收尸——天然无害，不用防；
- **防僵尸三板斧**（按常用度）：① 父进程用 wait/waitpid 主动收尸；② 注册 SIGCHLD 信号处理函数，在其中 waitpid；③ `signal(SIGCHLD, SIG_IGN)` 声明忽略子进程退出，让内核自动回收。

嵌入式对应：板子上常写"常驻父进程 + 短命子进程"模型（比如每来一包数据 fork 一个处理进程）——不收尸的话，设备跑几天突然 fork 失败，十有八九是进程表被僵尸塞满了。（想在开发板上跑本篇例程，先过一遍 [01-Linux基础与系统编程](../../../11-嵌入式Linux/笔记/01-Linux基础与系统编程.md)。）

## 章节小结

- 进程 = 资源分配单位（工厂），线程 = 调度执行单位（工人）；线程共享进程的代码/数据/堆，私有栈和寄存器
- Linux 创建进程三板斧：fork 克隆（写时复制）→ exec 换身 → wait 收尸；fork 一次调用返回两次，靠返回值分岔
- pthread_create 立即返回、pthread_join 阻塞等待；线程参数传栈地址要防生命周期与竞态
- 进程地址空间五段：.text / .data / BSS / 堆 / 栈；堆栈相向生长，相遇即内存耗尽
- 上下文切换 = 存档/恢复"大脑状态"；成本 = 寄存器交接 + 调度决策 +（仅进程间）地址空间切换
- 进程切换贵在换页表（TLB 失效）；FreeRTOS 任务 ≈ 共享一切的线程，切换最便宜、隔离最没有
- 僵尸 = 子死父不收尸（占 PID，必须防）；孤儿 = 父死子被 1 号收养（无害）

## 常见问题 FAQ

**Q1：fork 之后父子进程谁先跑？**
A：不保证，看调度器心情。程序必须设计成"谁先跑都对"——父等子就用 waitpid，子等父就用管道/信号同步，不能赌顺序。

**Q2：一个线程崩了，为什么整个进程陪葬？**
A：非法访存是**进程级**的错误（地址空间属于进程），OS 直接杀整个进程，所有线程一起没了——这就是"线程隔离性差"的根源。

**Q3：FreeRTOS 里有没有"进程"概念？**
A：没有。RTOS 所有任务共享同一物理地址空间，相当于一群"线程"直接跑在物理内存上——省了虚拟内存的开销，也拆掉了保护墙。

**Q4：僵尸进程吃 CPU 吗？放着不管行不行？**
A：不吃 CPU，只占进程表的一个坑。平时没事，但 PID 总量有限，耗尽后 fork 失败——常驻型程序必须收尸。

**Q5：exec 之后 PID 变吗？**
A：不变。exec 只换"图纸和内容"（代码/数据/堆栈全换新），进程还是原来那个（PID、打开的文件描述符默认保留）——换人不换工牌。
