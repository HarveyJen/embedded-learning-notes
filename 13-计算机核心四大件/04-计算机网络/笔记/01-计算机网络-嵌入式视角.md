# 04 · 计算机网络（嵌入式视角）

> 定位：四大件之一，**09-通信协议阶段并行食用**。书：《计算机网络：自顶向下方法》前五章 + 湖科大教书匠视频（B 站）。

**先说人话**：计算机网络讲的是"两台机器怎么把一句话准确送到对面"——分层的本质是**快递包装**：应用层写信（数据）、传输层装箱贴单（TCP）、网络层写地址（IP）、链路层找快递站（MAC）。你在 07 篇抓过包、写过 socket，本篇就是给那些"会操作"的技能补上"为什么"。

| 课本层 | 协议 | 你抓过的实物 | 出处 |

| 应用层 | HTTP/MQTT/DNS | Wireshark 里的 GET 请求、MQTT CONNECT | 07-通信 05/07 |

## 2. 五个必精读主题（嵌入式岗高频）

### 2.1 TCP 连接管理（必考之王）

**这是什么**：TCP 建立和断开连接的仪式。类比：三次握手=打电话时的**对话确认**（"听得到吗？""听得到，你呢？""我也听得到"）——双方都确认"我说的话对方能收到"才开聊。

- **三次握手**：SYN→SYN+ACK→ACK——为什么不是两次（防旧连接请求孤儿化服务端资源）；为什么不是四次（合并）；
- **四次挥手**：FIN/ACK×2/FIN + **TIME_WAIT 2MSL**（MSL=报文在网络里的最大存活时间——等满 2MSL，最后的 ACK 丢了还来得及补，且旧连接的报文保证全部死光、不会串进新连接）——"服务器大量 TIME_WAIT"运维题的理论根；
- 半连接队列/全连接队列：SYN Flood 攻击与防御（syncookie）。

### 2.2 TCP 可靠传输

**这是什么**：网络会丢包、乱序、拥堵，TCP 靠"编号+确认+重发+控速"四招把不可靠的网络变成可靠字节流。类比：可靠的**挂号信系统**——每封信念编号、对方回执确认、超时没回执就重寄，还根据"回执速度"控制寄信频率。

**术语白话**：滑动窗口=**不发一封等一封，而是连寄一批**（窗口大小=在途未确认的信件上限）；流量控制=照顾**收件人**的处理速度（他家门口堆不下就少寄）；拥塞控制=照顾**邮路**的承载能力（路上堵了就全体减速）；指数退避=重连间隔**逐次翻倍**（1s→2s→4s），给拥堵的网络喘息时间。

- 序号+确认应答（累积确认）、超时重传（RTT 自适应）、快速重传（丢包后每个后续包都会重复确认丢失处——连收 3 个重复 ACK 就基本断定丢了，不必干等超时）；
- **滑动窗口**：流量控制（对方接收能力）vs **拥塞控制**（网络承载能力）——三招口诀：慢启动=从小窗口指数探路，拥塞避免=过阈值改线性缓增，快恢复=丢包后窗口减半重整再出发；
- 嵌入式关联：MQTT 断线重连的"指数退避"（07-通信 06）就是应用层对拥塞控制的仿生；弱网产品 QoS1 重传（07-通信 07）=TCP 重传思想上浮。

### 2.3 IP 与 ARP

**这是什么**：IP 是"全球邮寄地址"（逻辑定位，可跨网），ARP 是"从逻辑地址查物理门牌"（IP→MAC）。类比：IP=收件人写的**行政区划+街道**，MAC=快递员最后按**门牌号**送到家门口。

**术语白话**：MTU=单件快递的**最大包裹尺寸**（以太网 1500 字节），超了要拆成几件寄（分片）——丢一件整套重寄，所以应用层包别太大；NAT=公司前台**代收代发**——全公司的人对外用一个总机号码（公网 IP），前台记住谁托寄谁收（端口映射），这就是你家设备"在内网上不了外网直连"的根源。

- IP 分片与 MTU（1500）：MQTT 大包踩 MTU → 分片 → 一片丢失全包重传 → **应用层包别太大**（07 篇 64~256B 建议的理论根）；
- ARP：IP→MAC 查询，同网段直达/跨网段走网关——"ping 通了但跨网段不通"（07-通信 05 坑表）的排查依据；
- NAT：私网地址怎么上网——智能家居"内网穿透"问题的根源。

### 2.4 以太网与交换

**这是什么**：局域网里数据帧长什么样、交换机/路由器各按什么转发——这是你插上网线后"物理世界"的一段。

- 帧结构：MAC 目的/源+类型+载荷+FCS(CRC32)；交换机按 MAC 表转发，路由器按 IP 转发——"交换机隔离冲突域、路由器隔离广播域"；
- 差分信号+双绞线抗噪（07-通信 01 RS485 同源思想）。

**术语白话**：交换机=小区**内部信件分拣员**（只看门牌 MAC，在本小区内投递）；路由器=**跨城邮局**（看行政区划 IP，决定往哪个城市发）；FCS/CRC32=包裹上的**封条校验**——拆包时封条破了就整件丢弃。

### 2.5 应用层协议设计思想

**这是什么**：HTTP/DNS 这些"现成协议"背后的设计哲学，以及自己设计协议时的检查清单——嵌入式自定义协议的"必答题"。

- HTTP 的无状态+文本化（07-通信 05"恍然大悟点"）、DNS 递归/迭代查询；
- **自定义协议 checklist**（07-通信 01 模板的理论升华）：帧定界/长度域/校验/序号/应答/超时重传/心跳/版本协商——TCP 保证了字节流可靠，但**粘包/拆包与业务语义必须应用层自理**。

## 4. 常考速答

怎么用这张表：面试前的"急救卡"——每题一句话版先背下来，面试时用一句话起手，再展开细节；每格背后都有本篇对应小节，忘了展开逻辑就回去翻。

| 问题 | 一句话答 |
|------|----------|
| TCP/UDP 区别与选型 | 可靠有序有连接 / 快而简单无连接；遥测可 UDP、命令控制 TCP+应用层确认 |
| 粘包怎么处理 | TCP 是字节流无消息边界——定长/长度域/分隔符三法（状态机解析） |

| 浏览器输入网址发生了什么 | DNS→TCP 握手→TLS→HTTP→渲染（经典串联题，逐层答） |
