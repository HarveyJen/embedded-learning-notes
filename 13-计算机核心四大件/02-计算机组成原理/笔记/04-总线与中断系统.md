# 04 · 总线与中断系统

> 定位：组成原理详解第三篇，回答"芯片内部数据走什么路、硬件出事怎么打断 CPU"。是导读篇 2.3/2.4 节的展开——AHB/APB 分级与 NVIC 全链路，是理解 STM32 时钟树和外设驱动原理的地基。

**先说人话**：本篇讲两件事。**总线**：芯片内部所有部件共用的"高速公路网"——地址、数据、控制三组线各司其职，STM32 的 AHB/APB 分级就是它的实物版。**中断**：硬件"举手打断" CPU 的机制——从火警触发到 ISR 开跑有完整五步时间线，"中断为什么要 12 个周期""ISR 为什么要短"全在这条时间线里。再加一个 DMA：它是总线上"另一个主人"，不用 CPU 亲自搬货。

## 1. 总线：地址、数据、控制三组线

**这是什么**：总线（Bus）= 一组公共导线，所有部件挂在上面"对讲"。类比：快递系统——**地址线是门牌号**（去哪取/送）、**数据线是货物**（搬什么）、**控制线是运单类型**（读还是写、什么时候动手）。没有总线，每个部件都得和每个部件单独拉线，芯片根本画不出来。

- **地址总线**（单向，CPU 发出去）：指定要访问哪里。32 位地址线可寻址 2^32 = 4GB——**Cortex-M3 内存映射为什么是 4GB 空间**，就是这条算术（内存映射图见 [07-STM32 寄存器方式直操外设](../../../07-STM32/笔记/09-寄存器方式直操外设.md)）；
- **数据总线**（双向）：搬运数据本体。32 位数据总线一次搬 4 字节；
- **带宽算例**：32 位数据总线 @ 72MHz，理论极限 = 72,000,000 次/秒 × 4 字节 = **288MB/s**——实际受仲裁、等待周期拖累远达不到。这也提前解释了为什么大块数据搬运（ADC 连续流、图像行数据）要靠 DMA 流水作业，而不是 CPU 一条条搬。
- **控制总线**：发命令和握手——"现在是读""现在是写""数据有效了"。

**代入一次真实传输**：CPU 执行 `GPIOA->ODR |= 0x20` 的写部分——地址线送出 0x4001080C，控制线宣布"写"，数据线送上新值，一拍完成。你在 C 里一行寄存器赋值，就是总线上这三组线的同步动作。

**总线仲裁（Arbitration）**：多人抢路谁先走？

- **主设备（Master）**：能主动发起传输的（CPU、DMA）；**从设备（Slave）**：被动应答的（存储器、外设寄存器）；
- 两个主同时要路，由**仲裁器**按优先级裁决——白话：红绿灯 + 交警。CPU 和 DMA 谁让谁，见本篇第 6 节。

**总线是"分时复用"的**：一条总线一个时刻只能跑一个传输——所有人共用一条路，轮流发言。这正是仲裁存在的原因，也是 DMA 能"接管搬运"的机制基础。想真并行？就得像 02 篇哈佛结构那样**多修几条路**（I-Code/D-Code/System 三总线）。总线数量与带宽，是芯片设计里"布线面积 vs 性能"的永恒权衡。

## 2. AHB/APB：STM32 的分级公路网

**这是什么**：STM32 内部把总线分级——**AHB**（Advanced High-performance Bus，高速主干道）直连 CPU 一侧，**APB1/APB2**（Advanced Peripheral Bus，外设支路）挂外设。主干跑得快、支路跑得慢，各得其所。类比：城市路网——高架（AHB）不设红绿灯，社区路（APB）限速 30，通过"减速匝道"（桥接器）衔接。

```
SYSCLK 72MHz ── AHB ÷1 → HCLK 72MHz（CPU、DMA、SRAM 走主干）
             ├─ APB1 ÷2 → PCLK1 36MHz（低速外设：TIM2~7、USART2/3 等）
             └─ APB2 ÷1 → PCLK2 72MHz（高速外设：GPIO、USART1、ADC 等）
```

**分频算例**（时钟树全貌见 [07-STM32 时钟树](../../../07-STM32/笔记/01-工程建立与时钟树.md)）：

```text
APB1 分频系数 = 2 → PCLK1 = 72MHz ÷ 2 = 36MHz
为什么必须 ÷2：APB1 总线的硬件设计上限就是 36MHz，不是"随手分着玩"——
支路电路简单（省面积省电），代价是跑不了主干的速度
```

- **为什么外设要挂慢总线**：串口、I2C 这些外设的节拍远用不到 72MHz，挂慢总线省电、布线简单；需要快节奏的（GPIO 翻转、ADC 时基）走 APB2；
- 挂钩一个高频笔试题：APB 分频系数 >1 时，其下定时器时钟自动 ×2 补偿（36×2=72MHz）——为的是和 APB2 侧的外设节拍对齐，细节在时钟树篇已拆过；

**AHB 和 APB 之间的"减速匝道"叫桥（Bridge）**：APB 上的读写都由它代理转译——CPU 按主干节拍发请求，桥到慢总线上慢慢办，办完再应答回来。由此得到一个嵌入式常识：**访问 APB 外设寄存器比访问 SRAM 慢好几个周期**——紧循环里高频读写外设寄存器是性能杀手。

**总线视角重看一个老朋友**：01-C 06 篇说过 STM32 的 BSRR 寄存器能"原子"置位/清零——总线视角的原因：`|=` 要"读-改-写"三次总线往返（02 篇反汇编证明它还是三条指令），而写 BSRR 是**单次写传输**直达硬件，中途没有可被插队的窗口。
- 一句话收束：**你配时钟树，就是在给这张公路网逐级设定限速牌。**

## 3. 中断系统全链路：从火警到救火（五步时间线）

**这是什么**：中断 = 硬件事件打断 CPU 当前程序、转去执行专门处理函数（ISR）的机制。类比：你在写报告（主程序），前台电话响（中断请求），你放下笔接电话（进入 ISR），接完回来从停笔处接着写（恢复现场）。"放下笔前要把笔放好"——就是硬件自动压栈。

全链路五步时间线（以"串口收到一个字节"为例）：

```text
① 事件发生：UART 收到字节，硬件把状态寄存器的 RXNE 标志置 1（火警探头触发）
② 请求送达 NVIC：UART 的中断已使能 → 中断请求（IRQ）送到中断控制器（火警线接通中控）
③ NVIC 裁决：比较该中断与当前代码/其他挂起中断的优先级——现在打断，还是排队？
④ CPU 响应：收尾当前指令 → 硬件自动压栈 8 个寄存器（R0~R3、R12、LR、PC、xPSR）
   → 按中断号查向量表拿到 ISR 入口 → 跳转执行
⑤ ISR 返回：硬件自动出栈恢复现场 → 回到被打断处继续跑，像没被打断过
```

两个关键名词的白话：

- **NVIC**（Nested Vectored Interrupt Controller，嵌套向量中断控制器）：Cortex-M3 内置的"中断总调度室"——谁能打断谁、排队顺序、嵌套规则全归它管，CPU 核心外的外设都朝它举手；
- **向量表（Vector Table）**：按编号排列的"分机号码表"——第 n 号中断的 ISR 入口地址放在表里第 n 格。STM32 从 Flash 启动时向量表位于 0x08000000（别名映射到 0x00000000），**表头第 0 格存主栈指针初值、第 1 格存复位入口地址**——你读启动文件时开头那张地址表就是它。

**三层使能开关**（任何一个没开都收不到中断）：外设自己的中断使能位（如 UART 的接收中断使能）→ NVIC 侧的使能 → 全局开关（PRIMASK 等 CPU 级屏蔽）。调试"中断不进来"就按这三层从里往外查。

**和启动流程挂钩**：复位后 CPU 先取向量表第 0 格装入主栈指针、再取第 1 格跳进 Reset_Handler——启动文件开头那张地址表正是本节的向量表本体（启动四步拆解见 [07-STM32 时钟树](../../../07-STM32/笔记/01-工程建立与时钟树.md)）。所以启动文件不是汇编玄学，就是"向量表 + 少量初始化"。

**中断 vs 轮询，一句话分清**：轮询 = 你每隔一分钟看一次门口有没有快递（CPU 主动、及时但全程空耗）；中断 = 快递到了门铃响（硬件通知、CPU 不空转）。嵌入式"低功耗 + 快响应"的标配就是：平时休眠等中断，事件来了再干活。

向量表开头长什么样（节选，数值为示意，以你工程的启动文件为准）：

```text
0x08000000: 0x2000XXXX    ← 第 0 格：主栈指针初值（SRAM 顶部附近，栈从这里向下长）
0x08000004: 0x08000XXX    ← 第 1 格：复位处理函数 Reset_Handler 入口
0x08000008: 0x08000XXX    ← 第 2 格起：NMI、HardFault……再往后是各外设中断
```

验证方法：调试器 Memory 窗口看 0x08000000 的前几个字，和启动文件里那张表逐格对上——向量表从此眼见为实。

## 4. 中断优先级、抢占与嵌套

**这是什么**：优先级决定"谁让谁"；**抢占（Preemption）**= 高优先级中断能打断**正在执行**的低优先级 ISR；ISR 里再进 ISR 就是**嵌套**。类比：急诊（高抢占级）能打断正在问诊的普通门诊（低抢占级）；同级病号不能插队，按取号顺序（响应优先级）受理。

- STM32F103 只实现 4 位优先级 → 共 **16 级**；固件库再把这 4 位按分组切成"抢占位 + 响应位"，例如分组 2 = 2 位抢占 + 2 位响应 → **4 级抢占 × 4 级响应**【各分组位宽以固件库 NVIC_PriorityGroupConfig 文档为准】；
- 固件库约定：**数值越小，优先级越高**；
- 两个词的白话区分：
  - **抢占优先级**：能不能"插队打断别人"——领导特权，决定嵌套；
  - **响应（子）优先级**：同级之间不能插队时，同时挂起的情况下谁先被受理——取号顺序；
- **代入算例**：中断 A（抢占 1）的 ISR 正在跑，中断 B（抢占 0）来了 → B 立刻打断 A，进入 B 的 ISR（嵌套发生）；B 跑完出栈，回到 A 的 ISR 接着跑。若来的是抢占 1 的 C：不能打断 A，C 挂起排队；A、C 都挂起且同时到 → 响应级小的 C 先受理；

**分组代入算例**（以分组 2 为例：抢占 2 位 + 响应 2 位）：

```text
抢占级取值 0~3（0 最高）：能不能打断别人，看这个数字
响应级取值 0~3：同级排队顺序，看这个数字
中断 A（抢占1、响应0）与 B（抢占1、响应2）同时挂起 → A 先受理；但 B 运行时 A 打不断 B
中断 C（抢占 0）→ 无论响应级是几，A、B 谁在跑它一来就打断——抢占级碾压响应级
```

**两个常见配错**：① 只设抢占级、响应级全留默认 0——同级中断互相打不断，实时性莫名变差；② 和 RTOS 的习惯搞混（FreeRTOS 任务优先级数值越大越高）——NVIC 这里恰好相反，**数值越小越高**。两处都栽过跟头的人不在少数。
- 实战挂钩：外部中断（按键）配置走 [07-STM32 GPIO 与外部中断](../../../07-STM32/笔记/02-GPIO与外部中断.md)；中断现场在调试器里怎么看（MSP/PSP、EXC_RETURN）走 [07-STM32 调试实战](../../../07-STM32/笔记/07-调试实战.md)。

## 5. 中断响应延迟：十几个周期花在哪

**这是什么**：中断延迟 = 从"事件发生"到"ISR 第一条指令开始执行"的时间。把这笔账拆开，你才知道"ISR 要短"省的是什么钱、实时性余量留在哪里。

构成拆账（零等待存储器、无更高优先级打断的典型条件）：

```text
① 收尾当前指令 + 识别请求：约 1 个周期量级
② 硬件压栈 8 个寄存器（R0~R3、R12、LR、PC、xPSR）：12 周期总账里的大头
③ 查向量表取 ISR 地址 + 流水线重填（呼应 02 篇的流水线冲刷）
合计：Cortex-M3 典型 12 周期。72MHz 下：12 × 13.9ns ≈ 0.17μs
```

- 若 Flash 有等待周期、总线被 DMA 占着，②③都会拉长——**中断启动时间天然有抖动**；
- **尾链（Tail-chaining）**：一个 ISR 刚结束、另一个中断已挂起 → 硬件跳过"出栈再压栈"，约 6 个周期直接进下一个 ISR——连续中断不走回头路，省掉一半现场开销；
- **返回时的暗号 EXC_RETURN**：进异常时 LR 被硬件塞进一个特殊值（0xFFFFFFF1 / 0xFFFFFFF9 / 0xFFFFFFFD 这类"长得像非法地址"的数），它不是普通返回地址，而是写给异常返回指令的"备忘条"——告诉 CPU"回哪种模式、用哪个栈指针（MSP 还是 PSP）"。调试时看到 LR = 0xFFFFFFFx 别慌，那是硬件的手笔（现场勘查应用见 [07-STM32 调试实战](../../../07-STM32/笔记/07-调试实战.md)）。

**嵌套时间线走一遍**（代入数字，看清代价叠加）：

```text
t0  低优先级 ISR_A 开跑（它自己进入时已花 ~12 周期）
t1  高优先级事件到来 → NVIC 判定可抢占 → 再花 ~12 周期压栈 + 跳转
t2  ISR_B 执行 5μs
t3  B 返回（出栈又 ~12 周期）→ 回到 A 的断点继续
A 的实际完成时间 = 自身耗时 + 12周期 + B耗时 + 12周期
—— 这就是"高优先级中断会拖长低优先级"的定量解释，也是 ISR 要短的账单
```

**实测注意点**：用 GPIO 翻转 + 示波器测中断延迟时，别忘了事件源（如 EXTI 边沿检测）本身有同步采样延迟、翻转 GPIO 也要占总线拍子——你测到的是"全链路"延迟，比裸 12 周期大是正常的，别当成芯片坏了。

**延迟和抖动，哪个更要命**：多数应用怕的是**抖动**——平均 12 周期无所谓，"最坏情形被拖延"才会打崩实时闭环（电机控制、通信超时判断）。所以工程上真正要问的不是"平均延迟多少"，而是"**最坏多少、能不能保证**"。
- "ISR 要短"的硬件级解释：ISR 越长，后面同/低优先级中断的排队时间越不可控——**实时性的敌人不是那 12 周期，是不确定的排队时长**（这条是 08-FreeRTOS 中断纪律的硬件根源）。

## 6. DMA：总线上的"另一主"

**这是什么**：**DMA**（Direct Memory Access，直接存储器访问）= 一个专职搬数据的**总线主设备**。它和 CPU 并列抢总线，CPU 只负责"下单 + 验收"。类比：老板（CPU）把搬运单交给专职搬运工（DMA），自己继续开会——不必亲自把箱子一层层搬上楼。

- 没有搬运工的版本：CPU 用循环逐字拷贝——每搬 4 字节都要"取指 + 读 + 写"，流水线和 CPU 时间全耗在路上；
- 有搬运工：CPU 配一次寄存器（源地址、目的地址、长度），DMA 自己沿总线搬，搬完发中断通知 CPU 验收——全程不占 CPU；
- 仲裁视角：DMA 和 CPU 都向总线仲裁器申请使用权，按传输粒度轮流走——**CPU 让出的是总线拍子，不是整个系统停摆**（这就是第 1 节总线仲裁的日常应用）；
- **CPU 和 DMA 抢同一块 SRAM 会怎样**：总线层面仲裁器按拍子轮流给——DMA 搬运时 CPU 偶尔等一拍，整体仍是双赢。真正的风险在**软件层面：两者同时读写同一缓冲区**（竞态，不是总线问题）——要靠半满/全满中断、双缓冲这类套路划清地盘（详见 [07-STM32 DMA 与 ADC](../../../07-STM32/笔记/05-DMA与ADC.md)）。
- 典型场景：ADC 连续采样进 SRAM、串口大包收发、内存到内存搬运——配置实操见 [07-STM32 DMA 与 ADC](../../../07-STM32/笔记/05-DMA与ADC.md)；

配 DMA 时，寄存器里填的就是这四件事（白话版，具体寄存器名查参考手册）：

```text
① 源地址：从哪搬（外设的数据寄存器？某段 SRAM？）
② 目的地址：搬到哪（SRAM 缓冲区？另一个外设？）
③ 长度与宽度：搬多少个、每次几个字节
④ 触发方式：谁喊开始（外设请求？软件触发？）+ 搬完要不要发中断叫 CPU
```
- 前后呼应：DMA 直接写内存而绕过 CPU——若平台有 Cache，CPU 就可能读到旧值（一致性问题），见本目录 [03-Cache 与存储层次](03-Cache与存储层次.md)。

## 章节小结

- 总线 = 地址线（去哪，32 位 → 4GB 映射）+ 数据线（搬什么）+ 控制线（读/写）
- 主设备发起、从设备应答；多主抢路由仲裁器按优先级裁决
- STM32 总线分级：AHB 72MHz 主干、APB1 36MHz 上限（必须 ÷2）、APB2 72MHz
- 中断五步：事件置标志 → 送 NVIC → 裁决 → 压栈 8 寄存器 + 查向量表跳 ISR → 返回
- 向量表 = 分机号码表，表头是 MSP 初值和复位入口（启动文件开头那张表）
- 优先级两层：抢占级管"能不能插队嵌套"，响应级管"同级排队顺序"，数值越小越高
- 中断延迟典型 12 周期（大头是压栈），尾链 ~6 周期连跳；ISR 短是为了排队时间可控
- DMA 是总线上的另一个主，仲裁轮流走总线；有 Cache 的平台要防读到旧值

## 常见问题 FAQ

**Q1：地址总线和数据总线的"宽度"是什么意思？**
A：就是线的根数。32 根地址线 → 每次能发出 32 位地址 → 2^32 = 4GB 可寻址；32 根数据线 → 一次搬 32 位（4 字节）。宽度决定"一次能指多大空间、一次能搬多少货"。

**Q2：APB1 为什么非得 ÷2？不分会怎样？**
A：APB1 的硬件设计上限是 36MHz——支路电路简单是为了省面积省电，代价就是跑不快。硬喂 72MHz 不符合设计规范，轻则时序不保证，重则工作异常。这不是软件选择，是硬件规格。

**Q3：两个中断同时到达，先跑哪个？**
A：先比抢占优先级，小的赢；抢占级相同再比响应优先级，小的先受理；再相同就看向量表中编号，小的在前。注意"先受理"≠"能打断正在跑的同级 ISR"——同级之间永远不互相打断。

**Q4：NVIC 使能了为什么还是进不了中断？**
A：按三层开关排查：外设自己的中断使能位（最常漏）→ NVIC 的 IRQ 使能 → CPU 全局屏蔽（PRIMASK）。此外标志位没清也可能反复进或进不去——"使能三层 + 标志清除"是中断调试四件套。

**Q5：DMA 搬数据时 CPU 一定要停吗？**
A：不停。DMA 和 CPU 作为两个主设备向仲裁器申请总线，按传输轮流使用——CPU 只是"偶尔让出总线拍子"。所以 DMA 搬运时 CPU 可以继续跑别的代码，这是"解放 CPU"的真正含义。
