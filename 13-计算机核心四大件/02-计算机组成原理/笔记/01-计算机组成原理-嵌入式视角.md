## 2. 核心四模块（精读重点）

### 2.1 指令与流水线

**这是什么**：CPU 执行一条指令分三步（取指→译码→执行），流水线让这三步像**洗衣流程**（洗衣/烘干/熨烫三台机器同时处理不同一批衣服）重叠进行——指令一条接一条"下饺子"，速度成倍提升。

- RISC vs CISC：Cortex-M（RISC 精简、定长指令）vs x86（CISC 变长）——定长指令译码快、流水线友好，但短指令也得占满一个格子，程序体积（代码密度）吃亏；变长指令省空间、一条顶多步，但译码复杂、主频难提——所以 MCU 省体积、PC 拼性能；
- 流水线冒险：分支跳转冲刷流水线 → `while(1)` 内的分支尽量可预测；中断=流水线现场保存（对应 MSP/PSP，07-STM32 07 篇 HardFault 里的 xPSR/PC/LR）；
- **函数调用约定**：参数走 R0-R3、LR 存返回地址——GDB 看调用栈、写汇编启动文件的底气（09-Linux Oops 解析也用它）。

**术语白话**：流水线冒险=洗衣流程里"下一批衣服还没洗完，烘干机就空转等着"——分支跳转让 CPU 猜不准下一条指令，只能清空重排；函数调用约定=**团队交接的暗号**——参数放哪、返回地址存哪，编译器和调试器全按这个暗号办事。

### 2.2 存储层次（嵌入式的命脉）

**这是什么**：存储器越快越贵越小，于是金字塔式分层——顶层快而小、底层慢而大。类比：**书桌（寄存器）→ 书架（Cache）→ 书房（内存）→ 图书馆（Flash/磁盘）**——常用的放手边，越不常用放越远。

```
寄存器(1ns) → L1 Cache(几ns) → SRAM(十几ns) → SDRAM(百ns) → NOR Flash(读快写慢) → NAND/EMMC(最慢)
```

- 为什么外设不 Cache：寄存器读即事件（读 FIFO 取数据）→ **MMIO 区域必须非缓存**（volatile 的硬件级根源，01-C 09 篇闭环）；
- 为什么代码跑 Flash 也快：STM32 有预取缓冲/Cache；性能敏感函数搬 RAM 跑（链接脚本 `__attribute__((section))` 手法）。

### 2.3 中断与异常

**这是什么**：中断=硬件打断 CPU 当前工作的机制——"火警一响，放下手里的活先救火"。这一模块解释了中断的硬件代价，正是"ISR 要短"这条纪律的根。

- 异常向量表、抢占嵌套、尾链（tail-chaining）——NVIC 比 51 强在哪；
- 中断延迟与现场保存成本 → "ISR 要短"的硬件级解释（08-FreeRTOS 05 篇纪律的根）。

**术语白话**：异常向量表=**各科室分诊表**——发生几号异常就去几号地址找处理函数；尾链=连续中断**不走回头路**——一个中断刚退出、硬件直接进下一个，省去恢复现场的来回开销。

### 2.4 I/O 与总线

**这是什么**：CPU 怎么跟外设说话、数据走什么"公路"——总线是芯片内部的公共道路网，I/O 方式决定 CPU 要不要亲自搬货。

- 内存映射 I/O vs 端口 I/O（ARM 全前者）；DMA 为什么解放 CPU（总线仲裁视角，07-STM32 05 篇）；
- CPU/总线/外设频率差 → 时钟树分频的必然性。

**术语白话**：内存映射 I/O=把外设寄存器当"特殊地址的内存"读写（ARM 一统天下的做法）；总线仲裁=多个人抢一条路时**谁先走的裁判规则**；时钟树分频=CPU 跑得快、外设跑得慢，**同一水源按各自需求分流**。

## 4. 实验落地（不悬空的验证法）

**这是什么/解决什么问题**：组原最怕"看懂了但没感觉"——这组实验把教材概念全部搬到你手上那块 STM32 里验证一遍，做完每个概念都有"体感"。

- [ ] Keil 反汇编窗口：写一个函数，对照 ARM 汇编认出 prologue（压栈）/参数传递 R0-R3
