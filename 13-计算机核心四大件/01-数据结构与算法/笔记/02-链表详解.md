# 02 · 链表详解

> 定位：嵌入式数据结构第一名。任务就绪列表、消息缓存、报文重组，底层全是链表——本篇从"节点是什么"一路讲到 FreeRTOS/lwIP 的真实用法（侵入式链表与静态链表）。

**先说人话**：本篇讲透链表。它像**寻宝游戏**——每张纸条上写两样东西："数据本身"和"下一张纸条放在哪"，想找第 100 张只能从第 1 张一张张摸过去。为什么嵌入式工程师必须会它？因为"插删频繁、数量不定"的数据（任务队列、收到的报文）用数组要整体搬家，用链表改一根指针就完事。FreeRTOS 的就绪任务列表、lwIP 的 pbuf 报文链，本质都是本篇的链表。数组版对比可先看 [01-C语言基础 · 11-链表等基础数据结构](../../../01-C语言基础/笔记/11-链表等基础数据结构.md)。

## 1. 单链表：节点定义与内存图

**这是什么**：单链表由一串"节点"串成，每个节点住两部分：数据 + 下一个节点的地址。类比：一节节火车车厢，每节车厢装货（数据域），车尾挂钩连着下一节（指针域），最后一节挂钩空着（NULL）。

```c
typedef struct Node {
    int data;              // 数据域：本节点装的值
    struct Node *next;     // 指针域：下一个节点的地址（尾节点为 NULL）
} Node;
```

内存图（地址是编的，用来看结构）：

```
head ──▶ [10|0x0030](住0x0010) ──▶ [20|0x0020](住0x0030) ──▶ [30|NULL](住0x0020=尾)
```

读图要点：
- `head` 是个指针变量，存第 1 个节点的地址——它是整条链的**唯一入口**，丢了 head 就丢了整条链；
- 节点在内存里**不要求连号**（0x0010 → 0x0030 → 0x0020）——数组靠"连号+算偏移"直达第 n 个，链表只能顺着 next 摸：访问第 n 个要 n 次跳转 O(n)；已知位置插删只改指针 O(1)。

## 2. 头插法与尾插法

**这是什么**：往链表里放新数据的两种姿势。类比：头插法=插队（新来的站最前，O(1) 一步到位）；尾插法=排队（新来的排最后，但要先走到队尾，O(n)）。

**头插法**（返回新头）：

```c
Node *push_front(Node *head, int val) {
    Node *n = (Node *)malloc(sizeof(Node));   // 在堆上申请新节点
    if (n == NULL) return head;               // 分配失败原样返回（嵌入式必须检查！）
    n->data = val;
    n->next = head;   // 新节点指向"原第 1 个节点"——这行必须先执行
    return n;         // 新节点成为新头
}
```

运行逻辑逐段拆解：
- `malloc`：向堆要一块 Node 大小的内存（详见 [01-C语言基础 · 08-内存布局与动态内存](../../../01-C语言基础/笔记/08-内存布局与动态内存.md)），返回值判空是嵌入式铁律；`n->next = head` 必须先执行——先接好"新节点→旧链"，反了旧链首地址被覆盖，整条链成孤儿内存（泄漏）。

**尾插法**（保持先后顺序，适合先来先服务的队列）：

```c
Node *push_back(Node *head, int val) {
    Node *n = (Node *)malloc(sizeof(Node));
    if (n == NULL) return head;
    n->data = val;
    n->next = NULL;                    // 新节点必然是尾：next 置空
    if (head == NULL) return n;        // 空链表：新节点就是头（边界！）
    Node *cur = head;
    while (cur->next != NULL)          // 走到最后一个节点（next 为空那个）
        cur = cur->next;
    cur->next = n;                     // 挂上去
    return head;
}
```

踩坑点：空链表时直接解引用 `head->next` 会崩——所以开头先判 `head == NULL`。若想省去每次 O(n) 找尾，可额外维护一个"尾指针"，代价是多一个要同步更新的变量。

## 3. 按位插入与删除

**这是什么**：在指定位置安插/摘除节点。核心口诀：插入**先接后断**，删除**先跨再释放**——顺序错了必丢链。

```c
// 在第 pos 个位置（从 0 数起）插入 val；pos 太大就插到尾部
Node *insert_at(Node *head, int pos, int val) {
    if (pos <= 0 || head == NULL)          // 插头部或空表：退化为头插
        return push_front(head, val);
    Node *cur = head;
    for (int i = 0; i < pos - 1 && cur->next != NULL; i++)
        cur = cur->next;                   // 走到第 pos-1 个节点（插入点的前驱）
    Node *n = (Node *)malloc(sizeof(Node));
    if (n == NULL) return head;
    n->data = val;
    n->next = cur->next;                   // ① 新节点先牵住"后家"
    cur->next = n;                         // ② 前驱再改指新节点（口诀"先接后断"：反了后半条链丢失）
    return head;
}
```

```c
// 删除第一个值为 val 的节点；返回新头
Node *delete_val(Node *head, int val) {
    if (head == NULL) return NULL;
    if (head->data == val) {               // 情况1：删头
        Node *t = head->next;
        free(head);                        // 释放节点内存（malloc/free 必须成对）
        return t;
    }
    Node *cur = head;
    while (cur->next != NULL && cur->next->data != val)
        cur = cur->next;                   // 停在"待删节点的前一个"
    if (cur->next != NULL) {
        Node *t = cur->next;
        cur->next = t->next;               // 前驱跨过待删节点（先跨）
        free(t);                           // 再释放（后删）
    }
    return head;
}
```

为什么删除要停在"前一个"：单链表节点没有"上一个"的指针，一旦 `cur` 走到待删节点上，就再也回不去它的前驱，链接不回去。想对"任意已知节点"O(1) 删除 → 用双向链表（第 6 节）。

## 4. 反转链表（手推一遍）

**这是什么**：把 1→2→3→NULL 变成 3→2→1→NULL。面试超高频，技巧是**画三个指针的图手推**，别死背代码。

```c
Node *reverse(Node *head) {
    Node *prev = NULL, *cur = head;
    while (cur != NULL) {
        Node *nxt = cur->next;   // 1. 先记住下一个（不然掉头后就找不到了）
        cur->next = prev;        // 2. 当前节点掉头，反指前一个
        prev = cur;              // 3. prev 前进一格
        cur = nxt;               // 4. cur 前进一格
    }
    return prev;                 // 循环结束时 prev 停在原尾节点=新头
}
```

手推过程（1→2→3→NULL，跟踪 prev/cur/nxt 三指针）：

```
初始: prev=NULL cur=1    已反转: 空    剩余: 1→2→3
第1轮: nxt=2; 1→NULL; prev=1; cur=2    已反转: 1
第2轮: nxt=3; 2→1;   prev=2; cur=3    已反转: 2→1
第3轮: nxt=NULL; 3→2; prev=3; cur=NULL → 结束，返回 prev=3（新头）
```

记忆点：第 1 步"先记住下一个"最容易被忘——一旦执行 `cur->next = prev`，原 next 就被覆盖，不先存就断链。

## 5. 快慢指针：找中点与判环（Floyd）

**这是什么**：两个指针一快一慢同走，靠速度差制造信息。类比：操场跑圈，你跑 1 圈的时间同学跑 2 圈——只要他在跑圈（有环），他一定会从背后套住你；如果他跑直线（无环），很快到头。

**找中间节点**：

```c
Node *find_mid(Node *head) {
    Node *slow = head, *fast = head;
    while (fast != NULL && fast->next != NULL) {  // 两个条件缺一不可
        slow = slow->next;         // 慢指针每次走 1 步
        fast = fast->next->next;   // 快指针每次走 2 步
    }
    return slow;                   // 偶数个节点时返回中间偏后那个
}
```

为什么能找中点：快指针速度是慢指针的 2 倍，快指针跑完全程时慢指针正好走到一半。4 个节点：fast 走两轮到 NULL，slow 恰好停在第 3 个（中间偏后）。

**判环（Floyd 判圈算法）**：

```c
int has_cycle(Node *head) {
    Node *slow = head, *fast = head;
    while (fast != NULL && fast->next != NULL) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) return 1;   // 快慢相遇 → 有环
    }
    return 0;                          // fast 先到头 → 无环
}
```

嵌入式对应物：链表节点内存被越界写破坏时，`next` 可能指向自己或前面的节点成环，遍历就**死循环卡死**。生产代码常给遍历加步数上限（超过节点总数就报错退出），原理与判环一致。

## 6. 双向链表

**这是什么**：每个节点多存一个"上一个"的地址，前后都能走。类比：地铁车厢——既能往下一节走也能往上一节走。代价：每节点多一个指针（32 位机多 4 字节）；收益：已知节点时删除 O(1)、可反向遍历。

```c
typedef struct DNode {
    int data;
    struct DNode *prev;    // 前一个节点
    struct DNode *next;    // 后一个节点
} DNode;

// 已知节点 p，删除它自己（不需要找前驱！）
void dnode_remove(DNode *p) {
    p->prev->next = p->next;   // 左邻跳过我，直接连右舍
    p->next->prev = p->prev;   // 右舍跳过我，直接连左邻
    free(p);
}
```

嵌入式对应物：**FreeRTOS 的链表就是"双向环形链表"**——就绪任务按优先级挂在对应链表上，任务随时可能被删除（vTaskDelete），必须 O(1) 摘除，所以用双向；尾部 next 绕回头部成环，从任意节点都能遍历全表。

## 7. 侵入式链表与 container_of（嵌入式重点）

**这是什么**：前面写的链表是"节点专门 malloc、数据搬进去住"（外挂式）；**侵入式链表**反过来：**链表节点内嵌在业务结构体身体里**，结构体自带挂钩。类比：外挂式=仓库统一发周转箱，货物装进箱子；侵入式=每件货物出厂就自带挂环，直接上挂钩排，省箱子的钱和搬运工。

```c
// 业务结构体自带"挂钩"——链表不再额外花内存
typedef struct sensor {
    int     type;                 // 业务数据本身
    float   value;
    struct sensor *next;          // 内嵌的链表指针域
} sensor_t;
```

省了什么：不 malloc 节点（省堆防碎片）、不 memcpy 数据（省 CPU）——这正是 FreeRTOS/lwIP 的选择（lwIP 的 `struct pbuf` 第一个成员就是 `struct pbuf *next`）。更彻底的做法是"通用链表节点 + 反推宿主"，即 **container_of 思想**：

```c
#include <stddef.h>

// 已知成员指针 → 反推宿主结构体首地址
#define container_of(ptr, type, member) \
    ((type *)((char *)(ptr) - offsetof(type, member)))
```

逐符号解释：
- `offsetof(type, member)`：编译期算出 member 在 type 里的**字节偏移**。如 sensor_t 里 next 前面有 int(4B)+float(4B)，则 `offsetof(sensor_t, next)` = 8；
- `(char *)(ptr)` 强转是为了做**字节级**减法（其他类型指针相减按元素大小跳）：成员地址 − 成员偏移 = 宿主首地址，最后强转回 `type *`。

```c
// 遍历时手里只有 next 成员指针（pnext），怎么拿到整个 sensor_t？反推！
sensor_t *host = container_of(pnext, sensor_t, next);  // 得到宿主指针，可访问 host->value
```

这套"通用节点 + container_of"就是 Linux 内核 list_head 的玩法，与 [01-C语言基础 · 06-指针](../../../01-C语言基础/笔记/06-指针.md) 第 9 节"强转指针 + 算术"访问寄存器是同一个思想。

## 8. 静态数组式链表（无 malloc 的嵌入式变体）

**这是什么**：把所有节点放进一个**编译期定长的数组**，next 存"数组下标"而不是内存地址。类比：闭架书库——没有"新书无限加购"（malloc），只在固定书架里腾挪；空位用"空闲链"串起来统一管理。

```c
#define MAX_NODES 8

typedef struct {
    int data;
    int next;              // 存下一个节点的"数组下标"，-1 表示链尾
} snode_t;

static snode_t pool[MAX_NODES];  // 静态池：零 malloc，绝不碎片化
static int head      = -1;       // 数据链头（-1 = 空表）
static int free_head = 0;        // 空闲链头：回收的节点挂这里复用

void pool_init(void) {
    for (int i = 0; i < MAX_NODES - 1; i++)
        pool[i].next = i + 1;        // 初始时全部节点串进空闲链
    pool[MAX_NODES - 1].next = -1;
}

int pool_alloc(void) {               // 从空闲链摘一格
    int idx = free_head;
    if (idx < 0) return -1;          // 池满：申请失败（等价 malloc 返回 NULL）
    free_head = pool[idx].next;
    return idx;
}
void pool_free(int idx) {            // 还回空闲链（头插）
    pool[idx].next = free_head;
    free_head = idx;
}
```

适用场景与代价：内存只有几十 KB 的 MCU、要求"绝不碎片化、行为可预测"时首选；代价是**容量硬上限**（池满要有拒绝策略）、MAX_NODES 过大浪费 RAM。FreeRTOS 的消息队列内部同样是"静态数组 + 下标存取"（见 [08-FreeRTOS · 02-消息队列](../../../08-FreeRTOS/笔记/02-消息队列.md)），思想同源。

## 章节小结

- 单链表节点 = 数据域 + next 指针域；节点内存不连号，访问第 n 个必须 O(n) 逐个跳
- 头插 O(1) 但顺序倒；尾插保序但要走到尾；插入口诀"先接后断"，删除口诀"先跨再释放"
- malloc 判空、free 成对出现防泄漏；反转三指针手推，快慢指针找中点、Floyd 判环
- 双向链表多 4 字节换"已知节点 O(1) 删除"——FreeRTOS 就绪列表的选择
- 侵入式链表：节点内嵌业务结构体，省 malloc 省 memcpy；container_of 由成员地址反推宿主
- 静态数组链表用"下标 + 空闲链"替代 malloc，嵌入式防碎片首选

## 常见问题 FAQ

**Q：链表和数组到底怎么选？**
A：三问定生死——数量固定吗？随机按下标访问多吗？插删频繁吗？数量固定+常按下标取 → 数组；插删频繁/数量不定 → 链表。嵌入式还有第三条：能用静态数组模拟就别上 malloc。

**Q：头插法为什么 O(1)，尾插却 O(n)？**
A：头插只改两根指针（新节点、head）；尾插必须先走到尾（不知道尾在哪）。维护"尾指针"可让尾插也 O(1)，但要多一处同步更新，多一个出错点。

**Q：什么时候该用双向链表？**
A：判据一条：是否需要"已知节点就地删除"或反向遍历。任务系统（随时删任务）、LRU 缓存都需要；单纯 FIFO 缓存单向就够。代价是每节点多 4 字节，节点数量大时是不小的 RAM 开销。

**Q：侵入式链表的优势再总结一下？**
A：三免——免节点 malloc（省堆防碎片）、免数据拷贝（省 CPU）、免容量猜测（有数据才占内存）。代价是业务结构体被"污染"了一个指针域；同一结构体要同时挂多条链时，需要内嵌多个节点域。
