# 05 · 排序与查找算法

> 定位：面试手撕重灾区 + 嵌入式真实会用到的"那几个"。目标：冒泡/插入/选择/快排能手写，二分查找边界零失误，知道"什么数据量该用什么排序"。

**先说人话**：本篇讲排序和查找。**排序**像**整理扑克牌**：把乱序数据排成有序；**查找**像**在字典里找单词**：有序的东西可以"翻一半扔一半"地找。为什么嵌入式工程师要学？一是面试必手撕（冒泡/快排出镜率最高）；二是传感器数据排序、日志查找、ADC 采样取中值，真用得上。本篇还有一张"嵌入式取舍表"——告诉你 n<32 时插入排序反而最快，别盲目上"高级"算法。

## 1. 复杂度速讲（排序前必修）

**这是什么**：复杂度是"操作次数随数据量 n 增长的趋势"，记作 O(?)。逐符号看：O 里装的是**增长趋势**，忽略常数与低阶项——O(2n+3) 写成 O(n)，因为 n 很大时 2 和 3 不影响"数据翻倍、耗时翻倍"这个趋势。

| 记号 | 白话 | n=1000 时 |
|---|---|---|
| O(1) | 次数固定不变 | 1 步 |
| O(log n) | 每步砍一半 | ≈10 步（2^10=1024） |
| O(n) | 挨个过一遍 | 1000 步 |
| O(n log n) | n 遍 × 每遍砍半 | ≈1000×10=10000 步 |
| O(n²) | 两两都比较 | 1000²=1 000 000 步 |

代入感受差距：n=1000 时 O(n²)=100 万步 vs O(n log n)≈1 万步，差 100 倍；n=10000 时 O(n²)=1 亿步 vs ≈13 万步，差约 750 倍——数据量越大，选错算法的代价被指数级放大。嵌入式补充：**实时性看最坏情况**，快排平均 O(n log n) 但最坏 O(n²)，敏感场合要心里有数。

## 2. 冒泡排序

**这是什么**：相邻两个比一比，大的往后换——每一轮"最大值像气泡一样浮到末尾"。类比：体育课排队，老师只说"你和旁边比，高的往右挪"，一整轮下来最高的必站到最右。

```c
void bubble_sort(int a[], int n) {
    for (int i = 0; i < n - 1; i++) {           // 共 n-1 轮：每轮沉底一个
        int swapped = 0;                        // 本轮是否交换过（优化开关）
        for (int j = 0; j < n - 1 - i; j++) {   // 每轮尾部少比一个（已沉好）
            if (a[j] > a[j + 1]) {              // 前比后大 → 交换
                int t = a[j];
                a[j] = a[j + 1];
                a[j + 1] = t;
                swapped = 1;
            }
        }
        if (!swapped) break;                    // 一整轮没交换=已有序，提前收工
    }
}
```

手推一轮（{5,3,8,1}，i=0）：
- j=0：5>3 交换 → {3,5,8,1}
- j=1：5<8 不动 → {3,5,8,1}
- j=2：8>1 交换 → {3,5,1,8}——最大值 8 沉底，下一轮 j 只需走到下标 2。

复杂度：最好 O(n)（已有序 + 优化开关生效），最坏/平均 O(n²)；原地排序额外空间 O(1)；**稳定**（相等元素不换位）。

## 3. 插入排序（嵌入式小数据之王）

**这是什么**：像**理扑克牌**——每摸一张新牌，从右往左跟手上已排好的牌比，插到正确位置。数据"基本有序"时它接近 O(n)，是小数组（n<32）实际最快的常见选择，也是嵌入式排序的默认答案。

```c
void insertion_sort(int a[], int n) {
    for (int i = 1; i < n; i++) {          // 从第 2 张牌开始摸
        int key = a[i];                    // 手里这张待插的牌
        int j = i - 1;
        while (j >= 0 && a[j] > key) {     // 左边比它大的都往右挪一格
            a[j + 1] = a[j];
            j--;
        }
        a[j + 1] = key;                    // 挪出的空位放牌
    }
}
```

手推一轮（{5,3,8,1}，i=1，key=3）：
- j=0：a[0]=5>3 → 挪：{5,5,8,1}，j 退到 −1
- 出循环：a[0]=key → {3,5,8,1}——前两张排好。

为什么"基本有序"就快：每个 key 只需挪一两次就到位置，内层 while 几乎不转——n−1 次外层 ≈ O(n)。传感器数据流（新值总在旧值附近跳动）正是这种形态。

## 4. 选择排序

**这是什么**：每轮从未排序区**选出最小值**，与未排序区头部交换。类比：选队列排头——把全班看一遍记住最矮的，让他站第一个；再看剩下的人……优点是交换次数最少（每轮最多 1 次）。

```c
void selection_sort(int a[], int n) {
    for (int i = 0; i < n - 1; i++) {
        int min = i;                            // 先假设当前位置就是最小
        for (int j = i + 1; j < n; j++)         // 在剩下的人里找真正的最小
            if (a[j] < a[min]) min = j;
        if (min != i) {                         // 找到了别人才交换（只换 1 次）
            int t = a[i]; a[i] = a[min]; a[min] = t;
        }
    }
}
```

手推一轮（{5,3,8,1}，i=0）：min 从 0 出发；j=1 发现 3<5 记 min=1；j=2 的 8 不动；j=3 发现 1<3 记 min=3；最后交换 a[0]、a[3] → {1,3,8,5}——最小值 1 就位。

复杂度恒为 O(n²)（比较次数固定），但交换只有 O(n) 次——**往 EEPROM/Flash 写排序结果时，写次数少 = 磨损少**，这点值得利用。不稳定（相等元素可能被换乱序）。

## 5. 快速排序（挖坑法）

**这是什么**：分治思想——挑一个**基准（pivot）**，把比它小的甩左边、大的甩右边（一趟"分区"），基准归位；再对左右两半递归重复。类比：图书馆分书——先立一根标杆，比它薄的全放左架、厚的全放右架，然后每架内部再各自立标杆细分。

```c
void quick_sort(int a[], int left, int right) {
    if (left >= right) return;               // 递归出口：区间只剩 0/1 个元素
    int i = left, j = right;
    int pivot = a[left];                     // 挖坑：首元素挖出当基准，left 处成"坑"
    while (i < j) {
        while (i < j && a[j] >= pivot) j--;  // ① 从右往左找第一个比基准小的
        a[i] = a[j];                         //    填左坑，j 处成新坑
        while (i < j && a[i] <= pivot) i++;  // ② 从左往右找第一个比基准大的
        a[j] = a[i];                         //    填右坑，i 处成新坑
    }
    a[i] = pivot;                            // ③ i==j 相碰：基准归位（左小右大分界点）
    quick_sort(a, left, i - 1);              // 递归排左半
    quick_sort(a, i + 1, right);             // 递归排右半
}
```

每步解释（{5,3,8,1,4}，pivot=5，坑=i=0）：
1. ① j 从 4 往左：a[4]=4<5 → a[0]=4，数组 {4,3,8,1,4}，**坑转移到 j=4**；
2. ② i 从 0 往右：4≤5、3≤5，走到 a[2]=8>5 → a[4]=8，数组 {4,3,8,1,8}，**坑转移到 i=2**；
3. ① j 从 3 往左：a[3]=1<5 → a[2]=1，数组 {4,3,1,1,8}，**坑转移到 j=3**；
4. ② i 从 2 往右：a[2]=1≤5 → i=3 与 j 相碰，结束；
5. ③ a[3]=5 → **{4,3,1,5,8}**，5 归位；左半 {4,3,1}、右半 {8} 各自递归。

复杂度：平均/最好 O(n log n)（每次对半分，共 log n 层 × 每层 O(n)）；**最坏 O(n²)**（首元素做基准 + 数组已有序，每次分区只分出 1 个元素）；空间 O(log n)（递归栈）。不稳定。

## 6. 归并排序（思路了解）

**这是什么**：也是分治，但方向相反——**先递归拆到最小，再"合并两个有序数组"**。合并像拉链：两边各拿最小的比一比，小的先进新数组。稳定、恒为 O(n log n)，但需要 O(n) 附加数组——嵌入式 RAM 紧张时较难接受，思路了解、能口述"拆→排→合"即可，不要求手写。

```
{5,3,8,1} 拆 → {5,3} {8,1} → 各自排好 → {3,5} {1,8} → 合并 → {1,3,5,8}
```

## 7. 嵌入式取舍表 + qsort 库函数

**这是什么**：算法没有最强只有最合适。嵌入式选型的真实逻辑：数据量、内存、最坏情况、代码量四个约束一起看——这张表就是速查答案。

| 场景 | 首选 | 原因 |
|---|---|---|
| 小数组 n<32 | 插入排序 | 常数小、无递归、代码 10 行，实测常快于快排 |
| 数据基本有序（时间戳流等） | 插入排序 | 接近 O(n)；快排此时反而退化 |
| 大数组且 RAM 富余 | 快排 / qsort | O(n log n) 均摊 |
| RAM 极紧、必须原地 | 选择 / 冒泡 | 额外空间 O(1) |
| 要减少存储器写次数 | 选择排序 | 交换次数最少（每轮 1 次） |
| 实时性严格 | 慎用快排最坏 O(n²) | 改插排（n 小）或预打散数据 |

**qsort 库函数**（C 标准库自带，嵌入式工具链一般都有）：

```c
#include <stdlib.h>

// 比较函数：返回 <0 / =0 / >0 表示 a 应排在 b 前 / 相同 / 后
int cmp_int(const void *a, const void *b) {
    int x = *(const int *)a;        // void* 必须先转回具体类型（见 06-指针）
    int y = *(const int *)b;
    return (x > y) - (x < y);       // 别写 x-y：大数相减会溢出出错
}

int arr[6] = {5, 3, 8, 1, 4, 9};
qsort(arr, 6, sizeof(int), cmp_int);   // 首址、元素个数、单元素大小、比较函数
```

逐参数解释：第 2 参数是**元素个数**不是字节数；第 3 参数告诉它每步跨多大；第 4 参数把"怎么比大小"交给你——所以 float、结构体、字符串都能排，只要会写比较函数。qsort 内部实现各平台不同（多数是"快排+小区间插排"的混合），稳定性与最坏复杂度依实现而定【待查证】。

## 8. 二分查找

**这是什么**：在**有序数组**里找目标——每次看中间那个，砍掉不可能的一半。类比：翻字典找"码"字——不用从 a 翻起，直接翻中间，判断往前还是往后。前提铁律：**数组必须有序**，乱序二分必出错。

```c
int binary_search(const int a[], int n, int target) {
    int low = 0, high = n - 1;              // 闭区间 [low, high]
    while (low <= high) {                   // 易错①：闭区间用 <= 不是 <
        int mid = low + (high - low) / 2;   // 易错②：防溢出写法，别写 (low+high)/2
        if (a[mid] == target) return mid;   // 命中
        else if (a[mid] < target) low = mid + 1;   // 目标在右半 → low 跳过 mid
        else high = mid - 1;                // 易错③：必须 ±1，否则区间不收缩死循环
    }
    return -1;                              // 区间空了=不存在
}
```

代入算例（a={1,3,5,7,9,11}，target=11）：
- 第 1 轮：low=0，high=5，mid=2，a[2]=5<11 → low=3
- 第 2 轮：low=3，high=5，mid=4，a[4]=9<11 → low=5
- 第 3 轮：low=5，high=5，mid=5，a[5]=11 命中，返回 5
- 6 个元素只比 3 次；n=1000 最多 10 次（log₂1000≈10），n=100 万最多 20 次——对数级查找就是这么猛。

三大易错点（面试翻车重灾区）：
1. `low <= high` 写成 `low < high`：只剩最后一个元素时查不到；
2. `(low+high)/2`：两数之和可能超过 int 上限溢出成负数——**16 位 int 的 MCU（如 MSP430）更容易触发**；
3. `low=mid` / `high=mid` 忘了 ±1：区间不收缩，死循环。

## 9. 面试高频：手撕快排/冒泡

**这是什么**：嵌入式面试白板环节的常客。考核点不在"背代码"，而在**边界意识**：空数组？2 个元素？已有序？全相同？先讲思路再动笔。

白板套路（背这个流程）：
1. **先说思路**：快排 = "选基准→分区→递归两半"；冒泡 = "相邻比较，每轮沉底一个最大值"；
2. **主动报复杂度**：快排平均 O(n log n)/最坏 O(n²)，冒泡 O(n²)（加开关最好 O(n)）；
3. **写代码**：函数签名带 n、循环条件想清楚再落笔；
4. **主动补边界**："left>=right 兜住空区间""swapped 开关提前退出"——说出这些就超过八成候选人。

练习验收标准：不看资料 5 分钟写出冒泡（含优化）、10 分钟写出挖坑法快排，且能手推一轮过程讲给面试官听。

## 章节小结

- 复杂度看增长趋势：n=1000 时 O(n²)=100 万步 vs O(n log n)≈1 万步，量级差决定选型
- 冒泡：相邻比、每轮沉底一个；加 swapped 开关最好 O(n)，面试要会讲优化
- 插入排序：理扑克牌；基本有序时接近 O(n)，**n<32 的嵌入式小数组之王**
- 选择排序：每轮选最小、交换 1 次，适合省写次数场景；不稳定
- 快排挖坑法：基准挖坑 → 右找小填左坑 → 左找大填右坑 → 相碰归位 → 递归两半
- 嵌入式取舍：小数据插排、大数据 qsort、RAM 紧原地排、实时敏感防快排最坏
- 二分查找三铁律：数组有序、low<=high、mid 用 low+(high-low)/2 防溢出且 ±1 收缩

## 常见问题 FAQ

**Q：快排已经是 O(n log n)，为什么嵌入式还常用插入排序？**
A：复杂度省略了常数。n<32 时插排的"常数小"（无递归、无分区开销、内存访问连续）占上风；而且嵌入式数据常常"基本有序"，插排能吃满 O(n) 红利。真实工程常二者混合：快排分到小区间后切插排（库函数也这么干）。

**Q：快排最坏 O(n²) 什么时候发生？**
A：首元素做基准 + 数组已（逆）有序时，每次分区只分出 1 个元素，退化成 O(n²)。缓解法：基准取"三者取中"（首/中/尾的中位数）或随机取。面试说出这条是加分项。

**Q：稳定排序是什么意思，为什么有时在意？**
A：相等元素排序后保持原相对顺序。排学生"按分数"时，同分希望保持学号序——就得用稳定排序（插入/归并稳定，快排/选择不稳定）。嵌入式如日志按时间排序，同秒内希望保持原顺序。

**Q：二分查找为什么要求"数组"而不能用链表？**
A：二分要**直接跳到中间**：数组下标 O(1) 直达；链表走到中间要 O(n)，跳一次比线性扫还亏。这正是"有序数组+二分" vs "BST 树"的取舍（见 [04-哈希表与树基础](04-哈希表与树基础.md)）。

**Q：排序会破坏数据的原始顺序吗？**
A：会覆盖原数组。想保留原始数据就先 memcpy 一份再排（注意 RAM 够不够）；或排序"下标数组/指针数组"而不是数据本身，按排好的下标去访问。
