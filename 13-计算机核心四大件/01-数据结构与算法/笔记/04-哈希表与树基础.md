# 04 · 哈希表与树基础

> 定位：两大"跳过线性扫描"的结构。哈希表负责"按名字秒查"（命令表/参数表），树负责"层级组织与有序查找"（文件系统/压缩）。嵌入式重点在哈希，树掌握概念 + 遍历即可。

**先说人话**：本篇讲两个"找得快"的结构。**哈希表**像**寄存包柜**：柜员把你的手机号当场算成一个格子编号，存取都直达——不用挨个翻格子。**树**像**公司组织架构图**：一个老板（根）往下分部门、部门下分小组，查"谁负责某事"顺着层级走就行。嵌入式里：AT 命令/Shell 命令匹配用哈希思想最划算；文件系统目录、字库压缩背后是树。

## 1. 哈希思想：键 → 格子编号

**这是什么**：给每个数据起个"键"（key，如命令名字符串），用**哈希函数**当场把键算成一个数组下标，存取都直达。类比：寄存包柜——报手机号，柜员心算出"12 号柜"直接开柜，绝不上排翻找。

| 存取方式 | 过程 | 复杂度 |
|---|---|---|
| 无序数组 | 从头到尾挨个比对 | O(n) |
| 有序数组 + 二分 | 每次砍一半 | O(log n) |
| 哈希表 | 算出格子号直达 | O(1) 均摊 |

n=1000 时：线性找平均 500 次比较，哈希 1 次就算完——这就是"跳过扫描"的威力。

## 2. 哈希函数：除留取余法

**这是什么**：把任意键映射成"0 ~ 桶数−1"的下标。最常用公式：**index = key % m**（m = 桶总数，取**质数**可减少规律性冲突）。类比：按座位号尾号分班——尾号 0~9 十个班，尾号分布均匀，班班人数差不多。

整数键算例：key=1024，m=13 → 1024 = 78×13 + 10 → index=**10**，放 10 号格。

字符串键（命令名）要先散列成整数再取余——嵌入式常用的 **BKDR 哈希**：

```c
// BKDR 哈希：每个字符乘 131 累加（131 是经验质数，分布较均匀）
unsigned int bkdr_hash(const char *s) {
    unsigned int h = 0;
    while (*s != '\0') {
        h = h * 131 + (unsigned char)(*s);  // 滚动累加：每个字符都影响最终结果
        s++;
    }
    return h;
}
```

算例：`"abc"` → h = 97×131² + 98×131 + 99 = 1 677 554；取 m=13：1 677 554 % 13 = **8**，落 8 号格（97/98/99 是 'a'/'b'/'c' 的 ASCII 码）。

## 3. 冲突解法一：链地址法

**这是什么**：两个键算出同一个格子怎么办？在格子里挂一条链表，都塞进去。类比：一个柜子放不下，柜内挂"袋中袋"，同号的东西串一串。

```c
#define TABLE_SIZE 13

typedef struct hnode {
    char key[16];          // 键（命令名等）
    int  value;            // 值（命令编号等）
    struct hnode *next;    // 撞在同格的节点串成链
} hnode_t;

static hnode_t *table[TABLE_SIZE];   // 13 个桶头指针，初始全 NULL

void h_insert(const char *key, int value) {
    unsigned int i = bkdr_hash(key) % TABLE_SIZE;   // 算格子号
    hnode_t *n = malloc(sizeof(hnode_t));
    if (n == NULL) return;                          // 分配失败直接放弃
    strcpy(n->key, key);
    n->value = value;
    n->next = table[i];    // 头插到该桶链上（先接后断，同 02 篇链表）
    table[i] = n;
}

hnode_t *h_find(const char *key) {
    unsigned int i = bkdr_hash(key) % TABLE_SIZE;
    hnode_t *cur = table[i];
    while (cur != NULL) {                  // 只扫这一条短链
        if (strcmp(cur->key, key) == 0) return cur;
        cur = cur->next;
    }
    return NULL;                           // 走到链尾=没找到
}
```

复杂度：理想（冲突少）O(1)；最坏（全撞一格）退化成链表 O(n)——所以哈希函数分布要匀、桶数要够。

## 4. 冲突解法二：开放寻址法

**这是什么**：不挂链，本格被占就**按规则找下一格**，直到找到空位。类比：车位被占就往前挪一格找空位。优点：全静态数组、零 malloc——更贴嵌入式胃口。

```c
typedef struct {
    char key[16];
    int  value;
    int  used;             // 占位标志：0=空格 1=已占
} slot_t;

static slot_t slots[TABLE_SIZE];

int oa_insert(const char *key, int value) {
    unsigned int i = bkdr_hash(key) % TABLE_SIZE;
    for (int step = 0; step < TABLE_SIZE; step++) {
        if (!slots[i].used) {              // 找到空位：安家
            strcpy(slots[i].key, key);
            slots[i].value = value;
            slots[i].used = 1;
            return 0;
        }
        i = (i + 1) % TABLE_SIZE;          // 被占：线性探测，挪下一格
    }
    return -1;                             // 转一圈没有空位：表满
}
```

注意点：
- 查找也必须沿**同样的探测序列**走，遇到空格才停（说明该键不存在）；
- 删除不能直接清空（会打断探测链），要打"墓碑标记"（格子保留但标记已删）——实现比链地址法麻烦，嵌入式小表用得少，了解即可。

## 5. 装载因子与扩容

**这是什么**：**装载因子 α = 已存元素数 ÷ 桶总数**，衡量"格子有多挤"。类比：停车场停了 8 成车，找空位要转好几圈；停 3 成，一把入位。

- 举例：13 个桶存 6 个元素，α = 6/13 ≈ 0.46；α 越大冲突概率越高；
- 链地址法 α 可以大于 1（链变长变慢而已）；开放寻址法 **α 必须 < 1**（α=1 可能无空位可找）；
- 工程经验：α 超过 0.7 左右就**扩容**——新建 2 倍大的新表，把所有元素**重新哈希**（rehash）搬过去。为什么必须重哈希？index = key % m，m 变了，所有格子号全部重算。

嵌入式提示：命令表通常条目固定（编译期已知），直接把桶数定为"条目数 ÷ 0.7 再取质数"，**免去运行期扩容**——静态内存的嵌入式风格。

## 6. 嵌入式应用：AT/Shell 命令表

**这是什么**：串口收到 "led"，程序要找到对应处理函数去执行。最朴素做法：const 命令表 + 线性扫描——条目少（20 条以内）时它就是最优解（代码短、零冲突、整表放 Flash）。条目几十上百时才升级为哈希表。

```c
typedef void (*cmd_fn)(void);          // 函数指针：指向"命令处理函数"（见 06-指针 第 5 节）

typedef struct {
    const char *name;                  // 命令名
    const char *help;                  // 帮助文本
    cmd_fn      handler;               // 处理函数
} cmd_t;

static void cmd_help(void) { printf("help ver led\r\n"); }
static void cmd_ver(void)  { printf("fw v1.0\r\n"); }
static void cmd_led(void)  { /* 翻转 LED */ }

// const 修饰：整表进 Flash 不占 RAM（const 与 Flash 的关系见 06-指针 第 6 节）
static const cmd_t cmd_table[] = {
    { "help", "list commands", cmd_help },
    { "ver",  "show version",  cmd_ver  },
    { "led",  "toggle led",    cmd_led  },
};
#define CMD_N (sizeof(cmd_table) / sizeof(cmd_table[0]))

void shell_exec(const char *input) {
    for (unsigned int i = 0; i < CMD_N; i++) {
        if (strcmp(input, cmd_table[i].name) == 0) {
            cmd_table[i].handler();    // 命中：通过函数指针调用
            return;
        }
    }
    printf("unknown cmd\r\n");
}
```

升级路线：线性表 → 表内二分（按名字排序后 O(log n)，见 [05-排序与查找算法](05-排序与查找算法.md)）→ BKDR + 拉链哈希（O(1)，条目多时用）。判断依据永远是：**条目数 × 单次比较成本**值不值得引入复杂度。

## 7. 树基础：二叉树概念

**这是什么**：每个节点最多两个孩子（左/右）的层级结构。类比：**锦标赛淘汰图**——冠军（根）在顶上，往下一层层的对阵分支；也是公司组织架构图的原型。

术语速览（白话）：
- **根**：最顶上的节点；**叶子**：没有孩子的末梢节点；
- **深度**：从根走到某节点经过的层数；**高度**：整棵树最深有几层；
- **二叉树**：每节点最多 2 个孩子，且左右有序（左 ≠ 右）。

```c
typedef struct tnode {
    int data;
    struct tnode *left;    // 左孩子
    struct tnode *right;   // 右孩子
} tnode_t;
```

## 8. 二叉搜索树（BST）

**这是什么**：带"排序纪律"的二叉树——**左子树所有节点 < 根 < 右子树所有节点**（对每个节点都成立）。类比：猜数字游戏（1~100 猜一个数）：每猜一次"比 50 大吗"，范围砍半——BST 查找就是这套路。

```c
tnode_t *bst_find(tnode_t *root, int target) {
    tnode_t *cur = root;
    while (cur != NULL) {
        if (target == cur->data) return cur;                  // 命中
        cur = (target < cur->data) ? cur->left : cur->right;  // 小往左，大往右
    }
    return NULL;                                              // 走到空=不存在
}
```

复杂度：树**平衡**（左右层数均匀）时 O(log n)——1000 个节点约 10 层，最多比 10 次（2^10=1024）。**退化警告**：按 1,2,3,...1000 顺序插入会退化成一条"斜树"（形似链表），查找变回 O(n)——这就是大表要用自平衡树（AVL/红黑树）的原因；嵌入式少用，知道即可。

## 9. 三种遍历（递归代码 + 口诀）

**这是什么**：把树上每个节点都访问一遍的三种次序。口诀："**前中后**"说的是**根被访问的时机**——前序 = 根最先，中序 = 根在中间，后序 = 根最后；左右子树永远先左后右。

```c
void preorder(tnode_t *r) {     // 前序：根 → 左 → 右（复制树/打印结构）
    if (r == NULL) return;      // 递归出口：空树直接返回
    printf("%d ", r->data);     // 1. 先访问根
    preorder(r->left);          // 2. 递归走左子树
    preorder(r->right);         // 3. 递归走右子树
}

void inorder(tnode_t *r) {      // 中序：左 → 根 → 右（BST 得升序！）
    if (r == NULL) return;
    inorder(r->left);
    printf("%d ", r->data);
    inorder(r->right);
}

void postorder(tnode_t *r) {    // 后序：左 → 右 → 根（释放树/汇总目录大小）
    if (r == NULL) return;
    postorder(r->left);
    postorder(r->right);
    printf("%d ", r->data);
}
```

记忆钩子：三个函数**代码一模一样，只有 printf 的位置不同**——printf 放最前是前序、放中间是中序、放最后是后序。

手推一遍（树：根 5，左孩子 3，右孩子 8）：
- 前序：5 3 8；中序：3 5 8；后序：3 8 5；
- **中序遍历 BST 输出升序序列**——BST 最重要的性质，面试常考。

## 10. 树在嵌入式中的对应（了解即可）

- **文件系统目录**：FATFS 这类文件系统的**目录层级**就是树——根目录往下挂子目录和文件。前序遍历=打印整个目录树；后序遍历=算目录总大小（先算完所有文件再逐层汇总）；
- **Huffman 压缩**：高频字符编码短、低频字符编码长（树上越深编码越长），点阵字库/固件资源压缩的原理之一——理解"编码 = 从根到叶子的路径"即可，不必手写；
- **XML/JSON 配置解析**：解析结果是一棵节点树，读配置 = 遍历树取值；
- 深度优先遍历（前/中/后序）底层靠**栈**（递归 = 系统帮你压栈，见 03 篇）；层序遍历（一层层扫）靠**队列**。

## 章节小结

- 哈希表 = 哈希函数把键变成格子下标，存取 O(1) 均摊，核心价值是"跳过线性扫描"
- 除留取余 index = key % m，m 取质数；字符串键先用 BKDR（×131 累加）转整数
- 冲突两解法：链地址法（挂链，灵活）与开放寻址法（全静态零 malloc，删除要墓碑）
- 装载因子 α = 元素数 ÷ 桶数，超 0.7 左右扩容重哈希；条目固定的命令表编译期定桶数免扩容
- 嵌入式命令表 20 条以内直接 const 表线性扫，条目多再上哈希
- BST：左 < 根 < 右，平衡时 O(log n)；按序插入会退化成链
- 三种遍历口诀"前中后"= 根的时机；中序遍历 BST 得升序；DFS 靠栈、层序靠队列

## 常见问题 FAQ

**Q：哈希表 O(1) 是绝对的吗？**
A：是"均摊 O(1)"。哈希函数分布均匀 + 装载因子受控时接近 O(1)；极端情况（全撞同一格）退化 O(n)。嵌入式实时性看最坏——所以条目少时线性扫描反而"最坏情况最好"。

**Q：为什么桶数 m 要取质数？**
A：若 m=10 而键都是 10 的倍数，会全部落进 0 号格。质数与数据规律"互质"的概率高，分布更匀。深入原理涉及数论，先记住结论即可。

**Q：链地址法和开放寻址法怎么选？**
A：有堆可 malloc、删除频繁 → 链地址法；要全静态、只增不删（命令表这种）→ 开放寻址法。嵌入式小表两者皆可，关键是容量留够、α 别超 0.7。

**Q：二分查找和 BST 是什么关系？**
A：思想同源——都是"每次排除一半"。有序数组 + 二分 = 隐式的平衡树（mid 就是根）；BST 是把这套逻辑固化成指针结构，代价是多存指针，收益是插删不用搬数组。

**Q：嵌入式什么时候真的需要树？**
A：诚实回答：很少。命令表/参数表哈希足够；层级数据（目录、菜单）深度通常两三层，switch/if 都能对付。面试考 BST 与遍历更多是考递归基本功，别为"用上树"而用树。
