# 08 · 看门狗/低功耗/RTC/Flash 与项目实战

> 收官篇：从"学习板"走向"产品"的系统级功能（看门狗、低功耗、RTC、片内 Flash 读写），最后用毕业项目验收整个阶段。

**开篇大白话**：前面七篇学的是"让功能跑起来"，这一篇学"让它像产品一样活着"——现场没人按复位键、电池要撑一年、断电后参数不能丢。四个系统级功能各救一类场景，最后毕业项目把八篇笔记拧成一件作品。

## 1. 看门狗 IWDG/WWDG（产品的保命符）

**这一节说什么/解决什么问题**：程序在现场跑飞了怎么办？看门狗是"自动重启开关"——它替你盯着程序心跳，心跳停了就强制复位。所有上架产品（家电、仪表、工控）都开着狗，这是"能演示"和"能用"的分水岭。

**问题**：产品在现场跑飞（干扰、栈溢出、死循环）——没人按复位键怎么办？
**看门狗**：一个必须**定期"喂"**的倒计时器，超时没喂 → 强制芯片复位。类比：定时给花浇水，忘了浇园丁（硬件）就重建花园（复位）。

**看门狗超时怎么算（LSI 40kHz，一步步算出 1 秒超时）**：

```
第1步：LSI 时钟 = 40kHz
第2步：预分频 64 → 喂狗节拍 = 40000 ÷ 64 = 625Hz（每 1.6ms 一拍）
第3步：重装载值设 625 → 超时时间 = 625 拍 ÷ 625Hz = 1s
验证：主循环必须每 1 秒内至少喂一次，否则复位 √
（公式：超时 = (重装载值+1) × 分频系数 ÷ LSI 频率——与定时器公式同构）
```

| | IWDG 独立看门狗 | WWDG 窗口看门狗 |
|---|----------------|-----------------|
| 时钟 | LSI 40kHz（主时钟挂了也活着） | APB 派生（受时钟树影响） |
| 喂狗窗口 | 任意时间喂都行 | **太早喂也不行**（防"喂狗代码本身跑飞却在喂"） |
| 用途 | 通用保命 | 精确监控主循环节拍 |

**IWDG 的"独立"二字是关键**：它用 LSI（01 篇时钟树的低速分支）供电计时，主时钟 72MHz 全崩了它照走——**为什么**：要是看门狗跟主程序共用时钟，程序带着时钟一起跑飞，狗也一起死了，保命符就成了摆设。

**工程原则**：
- 喂狗点放**主循环**而不是定时器中断（中断活着≠主循环活着，卡死常发生在主循环）；
- 喂狗前顺手做健康检查（缓冲区水位、关键任务标志）——看门狗从"保命"升级为"看家"；
- 复位后读 RCC 标志判断"我是不是被狗咬的"，上报故障日志（可靠性设计闭环）。

## 2. 低功耗模式（IoT/电池设备的核心技能）

**这一节说什么/解决什么问题**：电池设备要"常年在线"只能靠"平时装死、有事才醒"。三种睡眠深度各有代价——保多少现场、省多少电、醒来付出多少恢复成本。选对模式+避开唤醒坑，才是低功耗工程。

| 模式 | 功耗(F103 量级) | CPU | SRAM/寄存器 | 唤醒源 | 恢复后 |
|------|--------|-----|-------------|--------|--------|
| Sleep | mA 级 | 停 | 保持 | 任意中断 | 从中断处继续跑 |
| **Stop** | ~μA 级 | 停 | **保持** | EXTI/RTC | **从头跑**（时钟被关） |
| Standby | ~2μA | 停 | **丢失** | WKUP/RTC/复位 | 相当于重新上电 |

**选型逻辑**：停多久？多久醒一次？醒了要不要接着干？
- 常醒且要保现场 → Sleep/Stop；
- 睡很久、醒来当新开机 → Standby（RTC 闹钟定时醒采一次数据）。

**类比**：Sleep=上课打了个盹（老师叫一声就醒，笔记还在桌上）；Stop=回家睡觉（RAM 里的"桌面"还保留，但闹钟一响要从头洗漱=重新配时钟）；Standby=彻底退房（RAM 清空，再开房全重来）。**睡得越深越省电，但醒来的"恢复成本"越高**——这是低功耗的根本权衡。

**Stop 模式经典坑**：唤醒后系统时钟回到 HSI——**没重新配 PLL 的设备醒后串口波特率全乱**（时钟树知识的应用）。**为什么会乱**：Stop 把 PLL/HSE 全关了，醒来只剩 8MHz HSI 凑合用；串口波特率是按 72MHz 算的 BRR（04 篇公式），时钟变成 8MHz 后波特率整体缩小 9 倍——乱码。**对策**：唤醒后第一件事重配时钟树再干活。

低功耗三件套（都要做）：降主频/关不用外设时钟、**未用 IO 配模拟输入或带上下拉**（悬空 IO 漏电）、测量唤醒后到睡前的活动时长（串口/GPIO 翻转+功耗计）。

## 3. RTC 与备份域

**这一节说什么/解决什么问题**："断电走时"怎么实现——答案是把 RTC 关进一个"主电源管不到的小院"（备份域），用纽扣电池单独供着。

- **RTC = 用 32.768kHz 走的秒表**（与 51 同款晶振），挂在**备份域**：主电源掉了还有 VBAT 纽扣电池供着——"断电走时"的原理；**为什么是 32.768kHz 这个怪数**：2^15=32768，15 级二分频后正好 1Hz——电路基础笔记05 的分频知识，一个为"数到 1 秒"而生的频率；
- 配置流程：使能 PWR/备份域访问 → LSE 起振等待（32.768kHz 起振慢，等 ~1s 正常）→ 设初值 → 闹钟中断；**为什么要解备份域写保护**：备份域是"重要证件保管室"，默认上锁——PWR/备份域访问使能就是"出示工作证开门"，没解锁写什么都不生效；
- 应用：定时唤醒采集（Standby+RTC 闹钟 = 电池节点标准方案）；校准参数存**备份寄存器**（也是备份域，VBAT 供电）。

## 4. 片内 Flash 读写（掉电保存参数）

**这一节说什么/解决什么问题**：产品断电后校准值、用户设置不能丢——片内 Flash 是免费的非易失存储。但它"先擦后写、按页擦、写时停机"的脾气必须摸清，不然偶发 HardFault 查三天。

需求：保存校准值/用户设置（类比 LX-750PLUS 的校准参数与 LKT4105U 密钥）。
**规则（与 W25Q 同理）**：按**页**擦（F103 中容量 1KB/页）、写只能 1→0、先擦后写；**擦写期间 Flash 被占用——CPU 停摆（代码就在 Flash 里！）**，中断要临时屏蔽。**为什么 CPU 会停摆**：取指令也要访问 Flash，Flash 正忙于擦写时谁给它取指？——所以擦写期间任何中断来了都是事故，先 `__disable_irq()` 再擦写。

```c
HAL_FLASH_Unlock();     // 解锁写保护（同备份域思路：先出示工作证）
/* 擦一页 → HAL_FLASH_Program(TYPEPROGRAM_HALFWORD, addr, data) 逐半字写 */
HAL_FLASH_Lock();
```

**代码关键行拆解**：
- `HAL_FLASH_Unlock()`——Flash 默认锁着防误写（你的程序本体也在这），写参数前必须解锁；对应"KEYR 寄存器按顺序写两把钥匙"的硬件流程；
- `TYPEPROGRAM_HALFWORD`——**为什么按半字（16 位）写**：F103 Flash 写入的最小单位是 16 位（不是 8 位），按字节写会出错——对齐规则知识（C 笔记08）的硬件版；
- `HAL_FLASH_Lock()`——写完重新上锁，防止程序跑飞时误写参数区（同"看门狗防跑飞"的纵深防御思想）。

工程封装：`Param_Save()/Param_Load()` + 写入前校验 + **双备份页**（A 坏用 B，C 笔记08 嵌入式存储策略）。注意 Flash 寿命 ~1 万次擦写——频繁记录用外部 EEPROM/FRAM。

## 5. 毕业项目：多传感器数据采集系统（阶段验收）

**这一节说什么/解决什么问题**：单点知识都会了≠能做产品——毕业项目逼你把八篇笔记的零件装进同一台机器，并处理它们之间的"配合问题"（采样占总线、刷新抢 CPU、命令打断采集）。这是求职作品集的第一块砖。

**题目**：STM32F103 + OLED + MPU6050(姿态) + 光敏/NTC(ADC) + 串口命令行 + 按键菜单，可选温湿度(I2C)。

**功能要求（对照全部笔记）**：

| 模块 | 要求 | 考察笔记 |
|------|------|----------|
| 采集 | ADC 定时器触发+DMA 循环采样，均值滤波 | 05 |
| 姿态 | I2C 读 MPU6050，软件姿态角显示 | 06 |
| 显示 | OLED 界面：数据页/设置页，按键切换 | 02/06 |
| 命令 | 串口命令行：设采样率、读数据、自检 | 04 |
| 可靠性 | IWDG 喂狗+复位原因上报 | 本篇 |
| 调试 | 全程用断点/Watch 排障，提交《调试日志》 | 07 |

**验收标准**：连续运行 24h 无死机（看门狗零触发）；OLED 刷新流畅无闪烁；命令响应 <100ms；能现场回答"某外设时钟挂在哪条 APB"级别的架构问题。

**工程化要求**（求职作品集的标准）：模块化分层（`bsp_xxx.c` 驱动层 / `app_xxx.c` 应用层）；命名统一；每个模块头注释写"功能+接口"；Git 提交记录完整（路线横向要求：每个项目传 GitHub）。

## 6. 常见坑汇总

**这一节说什么**：系统级功能的坑共同特征是"平时看不出来、关键时刻掉链子"——每条坑都能在前文找到对应的"为什么"。

| 坑 | 现象 |
|----|------|
| 喂狗放中断里 | 主循环死循环照样复位不了/或永远不复位 |
| Stop 醒后没重配时钟 | 串口乱码、延时全错 |
| Flash 擦写时进中断 | 偶发 HardFault（取指失败） |
| 忘等 LSE 起振 | RTC 一直 0 |
| 备份域写保护没解 | 备份寄存器写不进 |

## 7. 章节小结（STM32 阶段毕业）

- 看门狗=定期喂+主循环喂+复位原因记录；WWDG 窗口防"喂狗代码自己飞了"
- 低功耗三级：Sleep 常用、Stop 保现场（醒后重配时钟！）、Standby 最省
- RTC/备份寄存器=VBAT 备份域；Flash 参数=先擦后写+双备份

## 课后思考题

1. 为什么 Stop 模式唤醒后要重配时钟而 Sleep 不用？（Stop 关掉了整个 1.8V 域的时钟源（HSI 除外），PLL/HSE 全断；Sleep 只停 CPU 内核，时钟树完好——模式差异决定恢复成本）
2. 看门狗喂狗点为什么不能放最高优先级中断？（最高优先级中断"永远活着"，喂了狗也证明不了主循环健康——监控要覆盖最容易死的路径）
3. Standby 模式下 RTC 为什么还在走？（RTC 在备份域，独立 VBAT/LSE 供电，不在 1.8V 域关断范围内——备份域的存在意义）
4. 回顾全阶段：如果面试官问"从上电到 main 之间发生了什么"+"时树怎么从 8M 变 72M"+"HardFault 怎么定位"，你能在 5 分钟内说清吗？（01/07 篇——这是本阶段面试的三大标准题）
