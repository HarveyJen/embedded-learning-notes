# 09 · 寄存器方式直操外设（脱掉 HAL 的马甲）

> 路线要求"HAL 上手后用寄存器重学一遍"的落地篇。目标：不依赖任何库，直接查参考手册（RM0008）写 GPIO/USART/TIM 代码——面试与底层排障的底气来源。

**开篇大白话**：HAL 帮你开车，但你不该不知道油门在哪。这一篇把 01~08 篇的每个操作翻译回寄存器本来的样子——你会发现"配置外设"翻来覆去就三步：开时钟、配模式、读写数据寄存器。吃透本篇，换任何一颗 ARM 芯片你都有底。

## 1. 为什么要脱马甲（HAL 不是原罪，但要看穿它）

**这一节说什么/解决什么问题**：回答"库都替我做好了，为什么还要学寄存器"——因为排障、面试、移植三层都需要"看穿封装"的能力。学法也简单：不是背手册，而是"拆函数看它动了谁"。

```c
/* HAL 一行 */
HAL_GPIO_WritePin(GPIOC, GPIO_PIN_13, GPIO_PIN_RESET);
/* 展开后它做的事 */
GPIOC->BSRR = GPIO_PIN_13 << 16;   /* 写复位寄存器，原子操作 */
```

**马甲的价值**：跨芯片移植、快速开发。**看穿的价值**：①读懂启动/中断/DMA 里 HAL 到底动了什么；②HAL 踩坑时能绕开；③面试"HAL 做了什么"一问见真章。
**方法**：Keil 里 Go To Definition 逐层展开 HAL 函数，对照参考手册寄存器定义读——这就是本篇的全部学习方式。

**寄存器名怎么读**（先给一层的"命名语法"，后面全用得上）：`GPIOC->BSRR` 读作"GPIOC 组的 BSRR 寄存器"——`->` 是结构体指针取成员（C 笔记06）；组名 GPIOC 是芯片头文件定义好的结构体指针，它指向 0x40011000 这个"组基地址"，每个成员按手册的偏移排布——**结构体布局=寄存器地图**，这就是"内存映射"的落地。

## 2. GPIO 寄存器版（F103）

**这一节说什么/解决什么问题**：亲手把 02 篇的"配模式+写电平"翻译成寄存器操作——重点理解 CRL/CRH 的 4 位一组编码和 BSRR 的原子性，这两个是 GPIO 的灵魂。

每个 GPIO 组 7 个寄存器（偏移从组基址算，如 GPIOC=0x4001_1000）：

| 寄存器 | 全称 | 作用 |
|--------|------|------|
| CRL/CRH | 配置低/高寄存器（Control Low/High） | 每脚 4 位：CNF[2位]+MODE[2位]，CRL 管 0~7 脚、CRH 管 8~15 脚 |
| IDR | 输入数据寄存器（Input Data） | 读 16 脚电平 |
| ODR | 输出数据寄存器（Output Data） | 写 16 脚电平（读改写） |
| **BSRR** | 置位/复位寄存器（Bit Set/Reset） | 低 16 位置 1，高 16 位复位——**原子操作** |
| BRR | 位复位寄存器（Bit Reset） | BSRR 高半的便捷版 |

**先学会读 CRL/CRH 的编码**（每个引脚占 4 位，格式 = CNF[1:0] + MODE[1:0]）：MODE=00 输入 / 01 输出10MHz / 10 输出2MHz / 11 输出50MHz；CNF 在输出态时 00=推挽、01=开漏。所以"推挽输出 50MHz"这组 4 位 = CNF(00)+MODE(11) = `0011` = 0x3。

**PC13 落在 CRH 哪里（一步步算）**：

```
第1步：13 号脚 ≥ 8 → 归 CRH 管（CRL 只管 0~7）
第2步：偏移 = (13 − 8) × 4 位 = 5 × 4 = 20 位（CRH 里 8 号脚占 [3:0]，9 号 [7:4]……13 号 [23:20]）
第3步：把 0x3 放进 [23:20] → (0x3 << 20)
   顺便验证文件里的掩码：清 4 位用 ~(0xF << 20)——0xF 正好盖住那 4 位
```

**关键认知：BSRR 为什么比 ODR 好**——`GPIOC->ODR ^= pin` 是"读-改-写"三步（中断插队会踩）；`GPIOC->BSRR = pin` 一步原子完成，中断安全。HAL 的 TogglePin 在 F1 上实际用 ODR 异或，高并发场景自己改 BSRR。

**"读改写被踩"是什么场景（走一遍）**：主循环执行 `ODR ^= pin`，刚读完旧值、还没写回——此时中断触发也去改 ODR 并返回；主循环用"旧值"算出的结果写回，把中断的修改覆盖了。单步调试永远复现、全速跑偶发出错——正是这种 bug 让"原子操作"成为刚需。

### 寄存器版流水灯（无 HAL）

**这段代码做什么**：不用任何 HAL 头文件，只用自己宏定义的地址，让 PC13 的 LED 闪烁——"点灯"这件事的最底层形态。

```c
#define RCC_APB2ENR   (*(volatile uint32_t*)0x40021018)  /* 时钟使能寄存器地址 */
#define GPIOC_BASE    0x40011000
#define GPIOC_CRH     (*(volatile uint32_t*)(GPIOC_BASE+0x04))
#define GPIOC_BSRR    (*(volatile uint32_t*)(GPIOC_BASE+0x10))

/* PC13 推挽输出 50MHz：CNF=00(推挽) MODE=11(50M) → 4位=0x3，在 CRH 的 13-8 脚段 */
void LED_Init(void)
{
    RCC_APB2ENR |= (1u << 4);          /* bit4=IOPCEN：先开 GPIOC 时钟！ */
    GPIOC_CRH &= ~(0xFu << 20);        /* 清 13 脚的 4 位 */
    GPIOC_CRH |=  (0x3u << 20);        /* 0011：推挽输出 50MHz */
}

void LED_Toggle(void)
{
    GPIOC_BSRR = (1u << 13) << 16;     /* BR13=1 复位（低电平点亮） */
    for (volatile int i = 0; i < 100000; i++);
    GPIOC_BSRR = (1u << 13);           /* BS13=1 置位 */
}
```

**关键行拆解**：
- `#define RCC_APB2ENR (*(volatile uint32_t*)0x40021018)`——三层结构：`0x40021018`（手册查到的地址）→ `(volatile uint32_t*)`（强转为"指向 32 位无符号数的指针"）→ 外面再 `*(...)`（解引用，从此写这个名字=读写那个地址）。**这就是"给地址起名字"的 C 语言本质**，51 的 `sfr P1 = 0x90` 在 ARM 上的等价物；
- `RCC_APB2ENR |= (1u << 4)`——bit4 是 IOPCEN（I/O Port C Enable，手册 RCC 章节的位分配表）。又是 51 笔记02 的位操作三件套：`|=` 只点亮这一位、不惊动其他位；
- `GPIOC_CRH &= ~(0xFu << 20); GPIOC_CRH |= (0x3u << 20);`——**先清后写**两步式：先把 13 号脚的旧配置 4 位清干净，再填入 0x3。**为什么不能一句 `CRH = ...`**：CRH 同时管 8~15 共 8 个脚，整寄存器赋值会把别的脚配置全部冲掉；
- `GPIOC_BSRR = (1u << 13) << 16;`——BSRR 低 16 位管"置 1"、高 16 位管"清 0"。要清 13 号脚 → 把 1 放进高半区 → 左移 16 位。写这句时读作"BSRR 高半区的 bit13=1"；
- `for (volatile int i = 0; ...)`——volatile 让空循环不被优化掉（不加的话 -O2 直接删成 0 循环，灯不闪）。

**三步走口诀**（所有外设通用）：**开时钟（RCC）→ 配模式（CRL/CRH）→ 用数据寄存器（BSRR/IDR）**。忘开时钟 = 最常见"寄存器写了没反应"。**为什么必须先开时钟**：01 篇时钟树——每个外设的时钟默认是关的（省电），时钟没到，寄存器电路根本没工作，你写的值落进空气里。

## 3. USART 寄存器版（发送一字符）

**这一节说什么/解决什么问题**：把 04 篇的 HAL 串口拆到底层——你会看到"发一个字节"其实就是"查一个标志位+写一个数据寄存器"，波特率计算也在这里手算一遍（BRR 两个域的拆法）。

| 寄存器 | 作用 |
|--------|------|
| USART_SR | 状态：TXE（发送空）/TC（发送完）/RXNE（收到） |
| USART_DR | 数据寄存器（读写同址） |
| USART_BRR | 波特率：72MHz/16/115200=39.0625 → 整数39+小数0.0625×16=1 → BRR=0x271 |
| USART_CR1 | UE 使能、TE/RE、RXNEIE 接收中断 |

**BRR=0x271 怎么算出来的（一步步复算，04 篇公式在此落地）**：

```
第1步：USARTDIV = 72,000,000 ÷ 16 ÷ 115200 = 39.0625
第2步：整数域 = 39 = 0x27
第3步：小数域 = 0.0625 × 16 = 1（低 4 位，满 16 进 1 → 1/16=0.0625）
第4步：拼装 = (39 << 4) | 1 = 0x270 | 0x1 = 0x271
验证：39 + 1/16 = 39.0625 √  写回硬件后实际波特率分毫不差
```

**四个寄存器各管什么**（发字节的完整剧本）：CR1 是"总开关面板"（UE 开外设、TE 开发送机、RE 开接收机）；BRR 是"语速旋钮"（上面算的）；SR 是"状态灯"（TXE 亮=发送寄存器空了可以塞新数据）；DR 是"出货口"（写进去硬件自动移位发出）。

```c
void USART1_Init(void)
{
    RCC_APB2ENR |= (1u<<14) | (1u<<2);     /* USART1EN + IOPAEN（两块时钟都要开） */
    /* PA9=TX 复用推挽 50M：CRH 低 4 位=1011(0xB)；PA10=RX 浮空输入 0100(0x4) */
    GPIOA->CRH = (GPIOA->CRH & ~0xFF) | 0x4B;
    USART1->BRR = 0x271;                    /* 115200@72MHz */
    USART1->CR1 = (1u<<13)|(1u<<3)|(1u<<2); /* UE+TE+RE */
}

void UART_SendByte(uint8_t d)
{
    while (!(USART1->SR & (1u<<7)));        /* 等 TXE：上一次数据已进移位器 */
    USART1->DR = d;                          /* 写 DR 自动启动发送 */
}
```

**关键行拆解**：
- `RCC_APB2ENR |= (1u<<14) | (1u<<2)`——USART1 和 GPIOA 都挂在 APB2（01 篇时钟树），**两块时钟都要开**：串口本体没电不行，TX 引脚（PA9）没电同样不行——头号新手坑"开了串口时钟还是没输出"就栽在第二块；
- `(GPIOA->CRH & ~0xFF) | 0x4B`——PA9/PA10 都 ≥8 归 CRH，低 8 位正是这两个脚的配置（PA9 占 [3:0]、PA10 占 [7:4]）。0x4B = `0100 1011`：低 4 位 1011（复用推挽 50MHz，给 TX）、高 4 位 0100（浮空输入，给 RX）——一个掩码写两个脚；
- `USART1->CR1 = (1u<<13)|(1u<<3)|(1u<<2);`——bit13=UE（USART Enable 总开关）、bit3=TE（Transmitter Enable）、bit2=RE（Receiver Enable）。对照 51 的"SCON 选模式+REN"——思想一脉相承，只是位多了；
- `while (!(USART1->SR & (1u<<7)));`——bit7 是 TXE。**为什么发之前要等**：发送寄存器里上一个字节还没转移进移位器的话，新数据写进去会把旧数据冲掉；TXE=1 才是"出货口空了"；
- `USART1->DR = d;`——写 DR 即启动发送：硬件自动把 8 位按帧格式（起始+数据+停止）移位出去。所谓"串口发送"，底层就是这么两行。

对照 04 篇：HAL_UART_Transmit 内部就是这个 while+写 DR；RXNEIE 置 1 就是 `HAL_UART_Receive_IT` 里做的事。**波特率 39.0625 拆整数小数两个域**——这就是 51 里 TH1 计算的升级版。

## 4. TIM 寄存器版（1ms 中断）

**这一节说什么/解决什么问题**：把 03 篇的定时器模型落到 6 个寄存器上——你会发现 51 笔记04 的"定时器+重装+清标志"全套在这里原样上演，只是换了寄存器名。

**先点名每个寄存器**：PSC（预分频，÷(PSC+1)）、ARR（自动重装终点）、DIER（中断使能，bit0=UIE 允许更新中断）、CR1（控制，bit0=CEN 启动）、SR（状态标志，bit0=UIF 溢出了）、还有 NVIC_EnableIRQ（内核侧的"总闸"，等价 51 的 EA）。

**1ms 参数怎么来（03 篇公式的快算版）**：72MHz ÷(71+1)=1MHz → 粒度 1μs；ARR=999 → 数 1000 拍=1ms。

```c
/* TIM3：72MHz/(71+1)=1MHz，数 1000 → 1ms */
void TIM3_Init(void)
{
    RCC_APB1ENR |= (1u<<1);            /* TIM3EN（APB1 挂 TIM2~7，×2 规则见 01 篇） */
    TIM3->PSC = 71;                     /* 预分频：÷72 */
    TIM3->ARR = 999;                    /* 数 1000 个 1μs */
    TIM3->DIER = (1u<<0);               /* UIE：更新中断使能 */
    TIM3->CR1  = (1u<<0);               /* CEN：启动 */
    NVIC_EnableIRQ(TIM3_IRQn);          /* NVIC 内核函数，等价 HAL NVIC 配置 */
}

void TIM3_IRQHandler(void)              /* 启动文件里登记的固定函数名 */
{
    if (TIM3->SR & (1u<<0)) {           /* UIF：更新标志 */
        TIM3->SR &= ~(1u<<0);           /* 清标志！忘了=退出中断立刻重进（死在中断里） */
        msTicks++;
    }
}
```

**关键行拆解**：
- `RCC_APB1ENR |= (1u<<1)`——TIM3 在 APB1 上（注意不是 APB2！与 GPIO/USART1 不同总线），bit1 是 TIM3EN——"时钟总线挂错"是 09 篇独立坑的来源；
- `PSC=71; ARR=999;`——两个寄存器就是 03 篇公式的两个未知数，直接代入；
- `DIER = (1u<<0)`——更新中断使能（UIE），然后 `NVIC_EnableIRQ` 再开 NVIC 侧——**里外两道闸**：外设自己愿意发（DIER）+ NVIC 愿意转交（NVIC）= 51 的"分闸+总闸"（ET0+EA）翻版；
- `if (TIM3->SR & (1u<<0))`——先确认确实是"更新事件"叫的自己（严谨的 ISR 习惯）；
- `TIM3->SR &= ~(1u<<0);`——**清 UIF 必须软件做**。**为什么忘了会死循环**：标志不清，NVIC 看到"请求还挂着"，ISR 一退出立刻重进——主循环永远得不到执行，现象是"程序像死了一样但其实在中断里打转"。51 的 TF0=0 军规在这里原样复活。

**与 51 的对账**：PSC/ARR = 51 的"重装初值"（硬件自动版）；"清标志"军规从 51 一路传到 STM32（51 是 TF0=0，这里是 SR 的 UIF）。

## 5. volatile 与内存映射的根源（C 笔记兑现）

**这一节说什么/解决什么问题**：解释本篇所有宏定义里的两个"咒语"为什么必须存在——内存映射回答"地址哪来的"，volatile 回答"为什么编译器会坑我"。这是 C 语言笔记与单片机的正式会师。

```c
#define GPIOC_BSRR (*(volatile uint32_t*)0x40011010)
/*                    └─ 强转地址为指针 ─┘└─ volatile 禁止编译器优化读写 ─┘ */
```

- 外设寄存器就是**内存映射的固定地址**——C 笔记06 指针"寄存器映射"模板的全部意义；
- **volatile 必须**：编译器不知道"这个地址的值会被硬件改"，不加 volatile 它可能把 `while(!TXE)` 优化成 `if(!TXE)` 死循环。**优化到底做了什么（走一遍）**：编译器看到循环体里没人改 TXE，就"好心"把读寄存器的动作提出循环只读一次——此后循环条件永远是旧值，硬件再怎么置位程序也看不见。volatile = 贴张条"这个变量背后有硬件，每次都必须真读"；
- 实际工程用芯片头文件（`stm32f103xb.h`）里已定义好的结构体版：`GPIOC->BSRR` = 结构体指针访问，本篇的裸地址写法是"穿透到最底层"的教学版。

## 6. 常见坑

**这一节说什么**：寄存器直操的坑几乎都是"三步走口诀"缺一步——对照口诀逐行自查。

| 坑 | 现象 |
|----|------|
| 忘开 RCC 时钟 | 寄存器写入无任何效果（读回恒 0） |
| 时钟总线挂错 | 在 APB1ENR 开 GPIOC（GPIO 全在 APB2）→ 无效 |
| 不清中断标志 | ISR 死循环（永远进进出出） |
| ODR 读改写被中断踩 | 偶发引脚状态错（改用 BSRR） |
| BRR 算错/时钟源记错 | 波特率偏差 → 乱码 |
| 没加 volatile | Release 版（-O2）死循环 |

## 7. 章节小结

- HAL = 寄存器操作的封装马甲；Go To Definition + 参考手册 = 脱马甲方法
- 外设三步走：**开时钟→配模式→用数据寄存器**；忘开时钟是头号坑
- GPIO：BSRR 原子操作优于 ODR 读改写；USART：SR 查询 + DR 收发 + BRR 分频
- TIM：PSC/ARR 自动重装 + SR 清标志军规；volatile 是寄存器访问的护身符
- 至此"HAL 用过 + 寄存器懂了"双技能达成，05 阶段真正闭环
