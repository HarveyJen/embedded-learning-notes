# 03 · 定时器与 PWM

> 目标：STM32 定时器是外设之王（PWM/捕获/编码器/触发 ADC 全靠它）。目标：吃透"分频+计数+比较"模型，会用 PWM、输入捕获。

**开篇大白话**：51 的定时器是"一个只会加数的计数器"，STM32 的定时器给它配了"分频器（把心跳变粗）+ 比较器（数到指定值就动作）+ 自动重装（数完自动归位）"，于是从"定时"进化成"万能波形发生器"。这一篇的所有计算都围绕两个寄存器：PSC 和 ARR，学会"代入就完事"。

## 1. 定时器家族与统一模型

**这一节说什么/解决什么问题**：先分清"哪款定时器干什么用"，然后学所有定时器共用的一个模型——把模型吃透，PWM/捕获/定时中断全是它的不同用法，不用一个个重新学。

| 家族 | 型号 | 特点 |
|------|------|------|
| 高级定时器 | TIM1/TIM8 | 带死区/刹车——电机驱动用（死区=让上下两个开关管"错峰"开关、防止同时导通短路；刹车=紧急情况立刻封锁输出） |
| 通用定时器 | TIM2~TIM5 | 主力，本阶段全在这里 |
| 基本定时器 | TIM6/TIM7 | 只能定时，常触发 DAC |

**统一模型（所有定时器通用）**——四个寄存器先点名，这是本篇的全部主角：

```
时钟源 → [PSC 预分频器 ÷(PSC+1)] → [CNT 计数器 +1] → [ARR 自动重装载值]
                                        │ CNT==CCR → 事件（PWM 翻转）
                                        │ CNT==ARR → 溢出（中断/复位）
```

- **PSC**（Prescaler，预分频器）：把外设送来的大拍子"切小/放慢"——72MHz ÷(PSC+1)，PSC=71 就是 ÷72，得到 1MHz。作用：把计数粒度调到"好算"的档位；
- **CNT**（Counter，计数器）：干活的本体，每来一个（分频后的）节拍 +1，从 0 数到 ARR；
- **ARR**（Auto-Reload Register，自动重装载值）：计数终点——CNT 数到 ARR 就"溢出"，同时硬件自动把 CNT 归零重新数（51 手动重装的自动化版）；
- **CCR**（Capture/Compare Register，捕获/比较值）：一条"警戒线"——CNT 数到 CCR 的瞬间产生一个事件（比如把引脚电平翻转）。PWM 的占空比就靠它。

**一句话记住分工**：PSC 定"每拍多久"，ARR 定"数多少拍算一轮"，CCR 定"这一轮里在第几拍动手脚"。

对照 51：51 的"手动重装初值"在这里升级为 **ARR 硬件自动重装**；新增 PSC 分频（相当于把"机器周期"变长）。

**定时时间公式（必背会推）**：

```
T = (ARR+1) × (PSC+1) / TIM_CLK
```

**为什么要 +1**：计数从 0 开始（0、1、2…999 共 1000 拍），分频同样是 ÷(n+1)——硬件约定"写 0 = 分频 1 倍"，公式里就得补回 +1。

**完整算例一：定时 1ms（一步步代入）**

```
已知：TIM_CLK = 72MHz（APB1 定时器 ×2 规则，01 篇算过）
目标：溢出周期 T = 1ms
第1步：总拍数 = T × TIM_CLK = 0.001s × 72,000,000 = 72,000 拍
第2步：拆成"分频 × 计数"：72,000 = 72 × 1000
第3步：PSC = 72 − 1 = 71（→ 每 72 个主频拍算 1 个计数拍，粒度 1μs）
第4步：ARR = 1000 − 1 = 999（→ 数 1000 拍溢出，1000 × 1μs = 1ms）
验证：T = (999+1) × (71+1) / 72MHz = 1000 × 72 / 72,000,000 = 1ms √
```

**完整算例二：2kHz PWM（对应第 2 节呼吸灯例程）**

```
目标：PWM 频率 2kHz → 周期 T = 1/2000 = 0.5ms = 500μs
第1步：总拍数 = 500μs × 72MHz = 36,000 拍
第2步：拆分：36,000 = 72 × 500 → PSC = 71（粒度仍 1μs，好算）
第3步：ARR = 500 − 1 = 499
验证：频率 = 72MHz / (499+1) / (71+1) = 72,000,000 / 500 / 72 = 2000Hz √
```

**拆分怎么选**：同一个总拍数有多种"分频×计数"组合（72×1000、1000×72 都行），选法看两个约束——**ARR ≤ 65535**（16 位计数器上限），**粒度别太粗**（影响 PWM 占空比精度/捕获精度）。惯用手：先把 PSC 调到让粒度变成 1μs 或 0.1ms 这类整数，剩下的交给 ARR。

文字拆解：先分频把"心跳"放缓到舒服的粒度（1μs），再数 (ARR+1) 下触发——**PSC 定粒度，ARR 定长度**。

## 2. PWM 输出（定时器第一大用途）

**这一节说什么/解决什么问题**：51 里要"中断+软件计数"才能凑出的 PWM，STM32 全交给硬件——CPU 只改一个数字（CCR），波形源源不断。调光、调速、舵机、蜂鸣器都吃这一套。

**PWM = 用数字信号模拟模拟量**：周期固定，改"高电平占比（占空比 CCR/ARR）"。
回忆 51 笔记04 的软件 PWM——STM32 把它交给硬件：CNT 数到 CCR 拉高、到 ARR 拉低（比较模式），你只改一个寄存器。**占空比怎么算**：占空比 = CCR ÷ (ARR+1)。上节例子里 ARR=499 → 分母 500，若 CCR=250，占空比 = 250÷500 = 50%——灯一半时间亮，视觉亮度约为全亮的一半。

**呼吸灯例程**（CubeMX：TIM3 CH1 → PWM Generation，配 PSC=71、ARR=499 → 72MHz/72/500=2kHz，**为什么是 2kHz**：人眼对 <100Hz 的闪烁敏感，2kHz 远超阈值，呼吸过程丝滑无闪）：

**这段代码做什么**：启动 PWM 输出后，让 CCR 从 0 慢慢加到 499（渐亮）、再减回 0（渐暗），灯就像呼吸一样明暗交替。

```c
HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);        // 启动输出

for (uint16_t d = 0; d <= 499; d++) {             // 渐亮
    __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, d);  // 只改 CCR
    HAL_Delay(2);
}
/* __HAL_TIM_SET_COMPARE 宏 = 直写 CCR1 寄存器——HAL 宏是"寄存器的马甲" */
```

**关键行拆解**：
- `HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1)`——**启动定时器**和**启动 PWM 通道**是两件事：定时器开始数数（CNT 跑起来）≠ 引脚开始输出波形（要把通道接到引脚上）。只 Start TIM 不 Start PWM，引脚永远是平的——高频坑；
- `__HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, d)`——把比较值改成 d。**拆开看本质**：展开后就是 `TIM3->CCR1 = d;` 一句寄存器赋值。改 CCR 不打断计数、不进中断，波形无缝切换——这就是"硬件 PWM"与"软件 PWM"的差距；
- `HAL_Delay(2)`——每 2ms 升一档，0→499 约 1 秒完成一次渐亮。

频率与占空比速记：**频率由 PSC+ARR 定，占空比由 CCR 定**。改频率动前两个，调亮度/转速只动 CCR。

## 3. 输入捕获与测频（定时器第二大用途）

**这一节说什么/解决什么问题**：PWM 是"输出方波"，输入捕获是反过来"量别人的方波"——测频率、测脉宽。超声波测距、红外遥控解码、测转速，全是它的地盘。

**捕获 = 记录边沿到来那一刻 CNT 的值** → 两次捕获值相减 = 脉宽/周期。**为什么不用软件等**：软件 `while(引脚==0)` 死等既占 CPU 又不准（进中断有延迟），硬件捕获是"CNT 打了个快照"，误差只有 1 个计数粒度。

**算例：测 1kHz 方波**（PSC=71 → 粒度 1μs）：

```
第1步：上升沿 A 到来 → 硬件记下 CNT 值 = 1000
第2步：上升沿 B 到来（一个周期后）→ 记下 CNT 值 = 2000
第3步：差值 = 2000 − 1000 = 1000 个粒度 = 1000 × 1μs = 1ms
第4步：频率 = 1 ÷ 1ms = 1kHz √   （若再捕下降沿差值 250 → 高电平 250μs → 占空比 25%）
```

测 1kHz 方波频率例程：

```
① 通道配"上升沿捕获"，先测整个周期 T1
② 同一通道再配"下降沿捕获"测高电平宽 T2
③ 频率 = 1/T1，占空比 = T2/T1
```

用途：超声波 HC-SR04 测距（Echo 脉宽×声速——例如脉宽 580μs × 0.034cm/μs ÷ 2 ≈ 10cm，**为什么要 ÷2**：声波走了个来回）、红外解码、测转速。**精度**：72MHz 计数粒度 14ns（PSC=0）——比 51 软件延时高三个数量级。

### 从模式一瞥（进阶预告）

定时器可"接力"：主定时器触发从定时器（级联 32 位计数）、触发 ADC 采样（**定时采样是 ADC 的标准玩法**，05 篇实做）、触发 DAC 波形输出。CubeMX 里叫 Trigger/Slave Mode。**思想**：多个外设共用一个"节拍发令员"，保证动作严格同步——又是"时序确定性"。

## 4. SysTick 与 HAL_Delay 的真相

**这一节说什么**：揭开 HAL_Delay 的底——它不烧 CPU 空转在"忙等"上吗？是。它靠什么计时？内核自带的 SysTick。搞懂这个，你才能解释 02 篇"ISR 里 HAL_Delay 死锁"实验。

HAL_Delay 基于 **SysTick**（Cortex 内核自带的 24 位滴答定时器，所有 M 核都有）——它每 1ms 中断一次给 HAL 计数（配置：72MHz÷72000=1kHz，SysTick 时基，原理与 TIM 定 1ms 完全同构）。**注意**：HAL_Delay 是"忙等"，靠 SysTick 中断递增计数——这就是 02 篇"ISR 里 HAL_Delay 死锁"的原因（SysTick 被更高优先级堵住，计数永远不涨）。

## 5. 常见坑

**这一节说什么**：定时器的坑九成出在"公式没理解、+1/-1 手滑"。每条坑都值得亲手踩一次再爬出来。

| 坑 | 现象 |
|----|------|
| PSC/ARR 多减或多加 1 | 周期差一拍（都是"÷(n+1)"） |
| APB1 定时器以为 36MHz | 实际 72MHz（×2 规则，01 篇） |
| PWM 频率太低 | LED 呼吸灯"呼吸"变"闪烁"（<100Hz 人眼可见） |
| 只启动了定时器没启动 PWM 通道 | 引脚无波形（Start PWM ≠ Start TIM） |
| 捕获没清标志/没处理溢出 | 高频信号测错（要做溢出补偿，进阶） |

## 6. 章节小结

- 统一模型：PSC 定粒度、CNT 计数、ARR 定周期、CCR 定比较点
- 定时时间 T=(ARR+1)(PSC+1)/CLK；PWM 频率看 PSC/ARR，占空比看 CCR
- 输入捕获=边沿打点测脉宽；从模式=定时器接力/触发 ADC
- SysTick 是内核滴答，HAL_Delay 是忙等（ISR 里禁用）

## 课后思考题

1. 为什么 PSC 和 ARR 都要 +1 才是分频/计数值？（0 也是合法值且要可用，硬件设计约定 ÷(n+1)——"0 不等于没有"）
2. 想要 1Hz PWM、又想要 1% 占空比精度，72MHz 下 PSC/ARR 怎么取？（周期 1s=100 步 → 每步 10ms → PSC=7199（10kHz 计数），ARR=99——粒度与长度匹配的取舍思想）
3. 电机驱动为什么用高级定时器的死区功能？（上下管直通短路——死区让一管关断后另一管延迟开启，H 桥安全根基，对应 05 篇电机场景）
