# 01 · 工程建立、时钟树与启动流程

> 目标：跑通 CubeMX→Keil 的标准工作流；看懂 F103 时钟树；理解"复位之后到 main() 之前发生了什么"。

**开篇大白话**：51 阶段"新建空文件就能写"，STM32 做不到——寄存器多到爆、配置项互相咬合，于是有了三件事要先懂：工具链怎么用（CubeMX 配置→Keil 写码）、芯片的"供电神经网"（时钟树）、程序是怎么从上电跑到 main 的（启动流程）。这三关过了，后面每篇都是"配外设+写逻辑"的重复劳动。

## 1. 开发工作流：CubeMX + Keil

**这一节说什么/解决什么问题**：STM32 有几百个寄存器、每个外设几十个配置位，手查手册手写配置三天起步；CubeMX 把"查手册"变成"点界面"，把结果翻译成 C 代码。先学会这条工作流，后面十篇笔记的配置环节全是它的重复。

**STM32CubeMX**：图形化配置工具——点选引脚功能、配时钟、配外设 → 自动生成初始化 C 代码。它解决的是"寄存器太多、配置项相互纠缠"的问题，让配置工作从查三天手册变成点十分钟界面。

**为什么还要 Keil**：CubeMX 只管"配置"，写业务代码、编译、调试还得靠 IDE——两者分工像"设计师出图纸（CubeMX）+ 工人施工（Keil）"。

标准工作流（每篇笔记都沿用），每步附"为什么"：

```
① CubeMX 选芯片 → 配 RCC/时钟树 → 配外设引脚与参数
   （为什么先选芯片：后面所有的头文件、Flash/RAM 大小、可用外设清单都由它决定，
     选错了整个工程的地基就是歪的）
② Project Manager：选 Keil MDK、生成"外设初始化 .c/.h + main.c 骨架"
   （为什么要在这里选 IDE：CubeMX 按目标 IDE 的工程格式组织文件，
     生成后才好用 Keil 直接打开）
③ Keil 打开工程，在 USER CODE BEGIN/END 区间写业务代码
   （为什么只写在这对注释之间：重新生成代码时 CubeMX 只保留这对标记内的内容，
     写在外面=下次生成时被无声抹掉，白写）
④ 编译 → ST-Link 烧录 → 调试
   （为什么用 ST-Link 而不是串口下载：串口只能"烧进去"，ST-Link 还能"看进去"
     ——断点、看变量、看寄存器，07 篇的主角）
```

**铁律：所有手写代码只写在 `USER CODE BEGIN ... END` 注释对之间**——重新生成代码时其他区域会被覆盖。

工程结构速览（读懂即可，知道"什么在哪"以后排错才不慌）：

```
Core/Src/main.c          ← 你的业务代码主要在这里
Core/Src/stm32f1xx_it.c  ← 所有中断服务函数（ISR）
Drivers/STM32F1xx_HAL_Driver/  ← HAL 库源码（不懂的函数来这里读）
startup_stm32f103xb.s    ← 启动文件（汇编，见第 4 节）
```

## 2. 时钟树（STM32 与 51 最大的分水岭）

**这一节说什么/解决什么问题**：回答"芯片里 72MHz 从哪来、各外设分到多少"。时钟树是所有外设计算（定时器周期、波特率、ADC 采样率）的总源头——这节没搞懂，03/04/05 篇的每个数字你都只能背不能推。

51：晶振直供所有外设，一个频率走天下。
STM32：**时钟像一棵树，从根到叶逐级分频/倍频**——为什么？各外设需要的速度差好几个数量级（CPU 要 72MHz，看门狗只要 40kHz），树形分发才能"该快的快、该省电的省电"。

**公司打卡系统类比**：晶振是公司门口的**标准钟**（只报 8MHz，稳定但慢）；PLL 是一台**把节拍加速的增压器**（×9 后变 72MHz）——总部以此为"标准时间"；AHB 是**行政部**，原速转发给核心部门（CPU）；APB1/APB2 是**各科室**，按需减速（÷2、÷1）；科室里还允许个别设备"特批加倍"（定时器 ×2 规则）。每个外设按自己科室的节拍干活，互不干扰、省电。

**沿途名词先点名**：
- **HSE**（High Speed External，外部高速晶振）：板子上焊的 8MHz 石英晶振——准（误差 ppm 级）但要花钱占板；
- **HSI**（High Speed Internal，内部高速 RC）：芯片内部自带的 8MHz 振荡——免元件但糙（误差约 1%），应急/备用；
- **PLL**（Phase Locked Loop，锁相环倍频器）：把输入频率整数倍放大的硬件，8MHz×9=72MHz；
- **SYSCLK**：系统主时钟，CPU 和总线树的源头；
- **AHB/APB1/APB2**：三级总线，就是给外设"分发烧钟"的三层管道——挂在哪条总线上，就得听哪条总线的频率。

### F103 时钟树主干（必须能画）

```
HSE 8MHz 晶振（外部高速）
   │ ×9 (PLL倍频)
   ▼
SYSCLK 72MHz ──┬─ AHB不分频 72MHz ──┬─ APB1 ÷2 → 36MHz（挂 TIM2~7，但定时器时钟×2=72MHz）
               │                    └─ APB2 不分频 72MHz（挂 GPIO/USART1/TIM1/ADC）
HSI 8MHz 内部RC ─（备用，精度差1%，晶振坏了自动顶上）
LSI 40kHz 内部低速 ── IWDG 看门狗
LSE 32.768kHz ── RTC（与 51 的 RTC 晶振同款！）
```

**这条树怎么算（跟着除一遍）**：

```
① PLL 输入 = HSE = 8MHz
② PLL 输出 = 8MHz × 9 = 72MHz（这就是 SYSCLK，F103 的上限，不许更高）
③ AHB 分频 = 1 → HCLK = 72 ÷ 1 = 72MHz
④ APB1 分频 = 2 → PCLK1 = 72 ÷ 2 = 36MHz（APB1 上限 36MHz——这条总线硬件设计只能跑到 36MHz，所以必须 ÷2，不是随便选的）
⑤ APB2 分频 = 1 → PCLK2 = 72 ÷ 1 = 72MHz
⑥ APB1 分频系数 >1 → 挂在它下面的 TIM2~7 定时器时钟 = 36 × 2 = 72MHz
⑦ ADC 时钟 = PCLK2 ÷ 6 = 72 ÷ 6 = 12MHz（≤14MHz 上限，合规）
```

三个必懂细节：

1. **为什么定时器时钟是 72MHz 而 APB1 只有 36MHz**——硬件规定：APB 分频系数 >1 时，挂在其上的定时器时钟自动 ×2 补偿。**为什么这么设计**：定时器经常和挂在 APB2 上的外设配合（PWM 驱动、触发 ADC），×2 让它们节拍一致。这是笔试高频题；
2. **72MHz 从哪来**：8MHz × PLL9 倍 = 72MHz。PLL 倍频上限决定了"为什么 8MHz 晶振是最常见配置"；
3. **ADC 最大 14MHz**：72÷6=12MHz，分频取 6——"外设有自己的频率上限，树要为它减枝"。**为什么 ADC 上限低**：转换核心是模拟电路，跑太快精度崩。

**一个高频疑问**：为什么不让晶振直接来个 72MHz？——高频晶振贵、难起振、还互相干扰；"低频晶振+片内倍频"是成本与稳定的平衡，这个思路在几乎所有 MCU 上通用。

## 3. 启动流程：复位到 main() 之间的四步

**这一节说什么/解决什么问题**：你以为"程序从 main 开始"，其实 main 之前有一段看不见的准备工作。搞懂它，你才能解释"全局变量为什么自动有初值""栈溢出是怎么回事""中断为什么会跳到对应函数"——这也是面试三巨头题之一。

**为什么需要启动文件**：C 程序运行有个前提——"C 环境"要先搭好：栈能用（函数调用、局部变量的工作台）、全局变量有正确初值。51 时代这些小事编译器顺手就做了，STM32 的启动文件（startup_stm32f103xb.s，一段汇编）把这些活明明白白写出来。

**先认识两个新词**：
- **SP（Stack Pointer，栈指针）**：指向"栈顶"的专用寄存器。栈是 RAM 里一块"后进先出"的工作台——函数的局部变量、调用返回地址都放这。SP 没初始化，第一个函数调用就把系统弄死；
- **向量表**：Flash 最开头的一张"地址清单"，第 0 项是栈顶地址、第 1 项是复位入口、后面是各中断入口——51 笔记04 的"向量表"在这里实体化。

按下复位键到你的 main() 第一行之间，硬件+启动文件干了四件事（面试高频）：

```
① 硬件从地址 0x08000000（Flash起始）取栈顶地址 → 初始化 SP（堆栈指针）
   （为什么第一步是它：万一复位瞬间就来了中断，中断也要用栈——先把工作台搭好）
② 取复位向量 → 跳入启动文件 Reset_Handler（汇编）
③ Reset_Handler：把 .data 段（已初始化全局变量初值）从 Flash 拷到 RAM；
   把 .bss 段（未初始化全局变量）清零；调 SystemInit() 配默认时钟
   （为什么要搬运/清零：全局变量 int a=5 存在 Flash 里（断电不丢的"模板"），
     但程序运行要在 RAM 里改它——开机必须先照模板把 RAM 铺一遍；
     未初始化的变量不能留着随机值，全部清 0，这就是"int b; 保证是 0"的真相）
④ 跳入 main() —— 你的代码从这里开始
```

**两个段的名词拆开**：`.data` = 有初值的全局/静态变量（如 `int a = 5;`）；`.bss` = 没初值的（如 `int b;`）——它们的差异只体现在启动时"拷初值"还是"清零"。

对照 C 语言笔记08（内存五分区）：**.data/.bss 的搬运与清零就是"静态区初始化"的物理实现**——原来"全局变量自动有初值"不是天经地义，是启动文件替你搬的。

**中断向量表也在 Flash 头部**：复位向量、HardFault 向量、各外设中断向量依次排开——中断发生时硬件按"编号×固定间隔"查表跳转，不用软件参与。51 笔记04 的"向量表"概念在这里实体化了（启动文件 .s 里可见）。

## 4. 第一个工程：流水灯（HAL 版）

**这一节说什么**：用最小的工程验证整条链路（配置→生成→编译→烧录→运行）通不通。程序本身很简单，重点是"每一步为什么这么做"。

CubeMX 配置：PA5 设为 GPIO_Output（以 NUCLEO 为例；开发板按原理图选 LED 脚——**为什么要看原理图**：LED 接在哪个脚、是高电平亮还是低电平亮，板子和板子不一样，配置错了代码再对灯也不亮）→ 生成。

**这段代码做什么**：让 LED 每 200ms 翻转一次电平，形成 2.5Hz 的闪烁（亮 200ms 灭 200ms）。

```c
while (1)
{
    HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);  // 电平翻转（|= 的库函数版）
    HAL_Delay(200);                          // HAL 的毫秒延时（基于 SysTick）
}
```

**关键行拆解**：
- `HAL_GPIO_TogglePin(...)`——"翻转"=读到 1 就写 0、读到 0 就写 1（51 里 `P1 ^= 0xFF` 的库函数版）；
- `HAL_Delay(200)`——注意它不是"什么都不干的空延时"，内部基于 **SysTick 中断**计数（详见 03 篇第 4 节）。记住一个伏笔：中断服务函数里调它会死锁，02 篇实验会验证。

HAL 命名规律（读懂名字就会用）：

```
HAL_外设_动作        例：HAL_GPIO_TogglePin / HAL_UART_Transmit / HAL_ADC_Start
外设句柄 huart1      每个外设实例一个结构体句柄，含配置与状态（结构体思想的活用）
```

**"句柄"是什么**：一个代表某个外设实例的结构体（比如 huart1 就代表 USART1，里面装着它的配置参数、当前状态、缓冲指针）。所有 HAL 函数都问你要句柄——"你对哪个外设操作？"——这就是为什么函数第一个参数总是 `&huart1` 这种形式。

## 5. 常见坑

| 坑 | 现象 |
|----|------|
| 代码写在 USER CODE 区外 | 重新生成代码后消失 |
| HSE 没配或晶振没焊 | 时钟回退 HSI，串口波特率偏、主频不对 |
| Flash 未擦除干净/选项字节异常 | 下载报错（用 STM32CubeProgrammer 全片擦除救） |
| 忘配 Debug:Serial Wire | ST-Link 下载失败（SWDIO/SWPA13/14 被 GPIO 占用） |
| 供电不稳/只接 USB 不共地 | 玄学复位 |

## 6. 章节小结

- 工作流：CubeMX 配置 → 生成 → Keil 写 USER CODE 区 → ST-Link 烧录
- 时钟树：HSE×PLL→SYSCLK→AHB→APB1/APB2；APB 分频 >1 时定时器 ×2
- 启动四步：取 SP → Reset_Handler → .data 搬运/.bss 清零 → main()
- HAL 命名有规律，函数细节去 HAL_Driver 源码里读

## 课后思考题

1. 为什么 STM32 要设计复杂的时钟树而 51 不需要？（多外设速度需求差 3 个数量级+低功耗分级+外设频率上限各不同；51 外设少且慢，单时钟够用）
2. 如果 PLL 配置超频到 128MHz 会怎样？（超出 datasheet 绝对最大值：可能能跑但寿命/温度特性恶化、外设时钟超限出错——"参数留裕量"在芯片级同样适用）
3. 中断向量表为什么放在 Flash 最前面？（复位后 PC 固定从 0x08000000 附近取向量，硬件规定的"必经之路"；可以重映射到 RAM 加快向量跳转——进阶）
