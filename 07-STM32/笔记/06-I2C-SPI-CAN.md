# 06 · I2C、SPI、CAN

> 目标：三大总线"什么时候用哪个"的判断力 + 各自的时序理解与实战（OLED/MPU6050 走 I2C，Flash 走 SPI，CAN 了解硬件与帧格式）。

**开篇大白话**：这一篇解决"外设怎么接进单片机"的选型问题——外设多了 IO 不够分，总线协议就是"一线多户"的通信规则。学法上别贪多：先背会第 1 节的选型表（哪个场合用哪条线），再按需深入某一条的时序细节。

## 1. 三总线选型总表（先建立全局判断力）

**这一节说什么/解决什么问题**：拿到一个新外设（OLED、Flash、屏幕、模组），第一件事不是写代码而是选总线——这张表就是你的"选型菜单"，背下口诀能省掉大量犹豫时间。

| | I2C | SPI | UART | CAN |
|---|-----|-----|------|-----|
| 线数 | 2（SCL/SDA，开漏+上拉） | 4（SCK/MOSI/MISO/CS） | 2（TX/RX） | 2（CANH/CANL 差分） |
| 速度 | 标准 100k/快速 400k | 几~几十 MHz | ~115200 典型 | 1Mbps |
| 主从 | 多主多从（地址寻址） | 一主多从（片选线） | 点对点 | **多主仲裁** |
| 优点 | 省脚、可挂多器件 | 快、全双工 | 简单通用 | 可靠、抗干扰、多节点 |
| 典型器件 | OLED/MPU6050/EEPROM/RTC | W25Q Flash/TFT 屏/W5500 | 模组/调试 | 汽车电子/工业节点 |

口诀：**低速省脚 I2C，高速大量 SPI，点对点 UART，车上工地 CAN**。

## 2. I2C：两根线的一百个朋友

**这一节说什么/解决什么问题**：用最少的线挂最多的慢速器件。核心机制就三个：开漏线与（硬件层）、地址寻址（谁在听）、ACK 应答（收到没有）——OLED、MPU6050、温湿度传感器全是它。

### 协议本质（理解时序）

- **两根线点名**：**SCL**=时钟线（主机吹节拍，全车同频）、**SDA**=数据线（双向传数据，SCL 高电平期间必须稳定不许变）；地址寻址=说话前先点名（"7 号器件，你听我说"）；
- **开漏+上拉**（GPIO 笔记02 的线与）：任何设备都能拉低、没人能独自拉高 → 高电平靠上拉电阻（4.7k@3.3V，量级选择的道理见课后思考题 1）；
- **帧格式**：`起始(SDA在SCL高时由高变低) → 7位地址+读写位 → 从机ACK → 数据...ACK... → 停止`；
- 每字节后**从机回 ACK**（第 9 拍拉低）——主机能知道"从机在不在/收没收"。

**类比**：I2C 像"课上老师点名提问"——先喊名字（地址），被点到的学生起立应答（ACK），然后开始对话（传数据）；没人应答（NACK）= 这位同学请假了（器件没接好/地址错）。

**0x3C 与 0x78 的换算（一步步算）**：手册给 OLED 的 7 位地址 0x3C；总线上实际发的是"7 位地址+1 位读写"拼成的 8 位。0x3C = `011 1100` → 左移一位腾出读写位 → `0111 1000` = 0x78（最低位 0=写、1=读，所以读是 0x79）。**资料里一个写 0x3C 一个写 0x78，就是这么来的**——填哪个取决于函数要 7 位还是含读写位的 8 位形式。

### 实战1：软件模拟 vs 硬件外设

**这一节说什么/解决什么问题**：同一个协议可以由硬件外设代劳，也可以拿两个 IO 手搓波形。知道两条路的优劣，才能在不同项目里做正确选择。

| | 软件 I2C（IO 翻转模拟） | 硬件 I2C（外设） |
|---|------------------------|------------------|
| 速度 | 慢（μs 级翻转） | 快 |
| 引脚 | 任意 IO | 固定引脚 |
| 稳定性 | 可控（好写） | F103 的 I2C 外设有历史瑕疵，死锁需复位恢复 |

**工程建议**：F103 上软件 I2C 反而是主流选择（稳定可控）；F4 及以后硬件 I2C 成熟。先用软件 I2C 把协议学透，硬件版再切——**协议懂了，实现只是壳**。

### 实战2：OLED（SSD1306）与 MPU6050

- **OLED**：初始化一串命令字节 → 写显存 RAM（1024 字节页结构）→ 显示字符/数字（字库存在 Flash，SPI 笔记里的 W25Q 或代码数组）；
- **MPU6050**：读 WHO_AM_I 寄存器（应答 0x68，**验证总线连通的第一招**）→ 配量程 → 循环读加速度/陀螺仪寄存器组。I2C 读寄存器套路：`START → 器件地址+W → 寄存器地址 → RESTART → 器件地址+R → 读数据 → NACK → STOP`——**这个套路通吃所有 I2C 传感器**。

## 3. SPI：高速四线

**这一节说什么/解决什么问题**：I2C 100kHz~400kHz 的速度撑不起刷屏、存日志这类大流量——SPI 用四根线换几十 MHz。重点弄懂"主机定节奏+CS 点名"和四种模式，Flash/屏幕就都能接了。

### 协议本质

**四根线各管一摊**（先点名）：**SCK**=时钟（主机吹节拍，速度由它定）；**MOSI**=主出从入（Master Out Slave In，数据从主机流向从机）；**MISO**=从出主入（反向那根）；**CS**=片选（Chip Select，拉低=点名"就你了"）。

- 时钟由主机**产生并决定一切节奏**（没有 ACK、没有地址——用 **CS 片选**点名）；全双工：MOSI/MISO 同时移位，交换式传输；
- **模式 0~3**（CPOL 时钟极性 × CPHA 相位）——**两个参数什么意思**：CPOL 定"空闲时 SCK 是高是低"，CPHA 定"第几个边沿采样"（0=第一个边沿采，1=第二个边沿采）；器件 datasheet 会写"SPI Mode 0"，配错读全 0x00 或全 0xFF（最高频坑——**为什么是这个症状**：采样时刻错位后，主机收到的始终是移位环里"没换出来的旧位"）。

**类比**：SPI 像"二人转手绢"——时钟一响，两边的手绢（数据）同时交换；CS 是"主持人点名谁上台"，没被点名的必须把手绢端平不动（MISO 高阻）。

### 实战：W25Q64 NOR Flash

**这一节说什么/解决什么问题**：SPI 总线的头号应用就是外挂存储。以 W25Q64 为例走一遍"命令集三段式"和"先擦后写"——看懂它，所有 SPI Flash 都是同款。

- 与 LX-750PLUS 的 SST39VF 并行总线 Flash 不同，W25Q 是 SPI 串行——省脚换速度，现代主流；
- 命令集套路：发命令字节 + 地址 → 读写数据（**每条命令先查手册命令表**：0x9F 读 ID、0x06 写使能、0x02 页编程、0x20 扇区擦除）；
- **写使能(WREN) → 扇区擦除(4KB) → 页编程(256B)**——Flash "先擦后写、按扇区擦" 的特性（C 笔记08 Flash 章节落地面）；**页 256B 的坑**：一次连续写不能跨页边界，跨页要拆成两次——写入前先算好"本页还剩多少"；
- 应用：存字库/波形/配置/日志，甚至自己实现简单文件分配表（FAT 思想）。

## 4. CAN：可靠优先的总线（汽车/工业标配）

**这一节说什么/解决什么问题**：现场环境恶劣（电机干扰、线缆几十米、几十个节点同时说话）——UART/I2C 在车上根本活不下来。CAN 用"差分+仲裁+硬件重发"三板斧换来工业级可靠。

- **差分两线**（CANH/CANL，显性/隐性电平）共模抑制强，120Ω 终端电阻匹配（对应电路基础笔记05 RS485/CAN 一节）；**显性/隐性是什么**：显性=两线电压差拉开（对应逻辑 0），隐性=两线电压几乎相等（对应逻辑 1）——显性能"盖住"隐性，这是仲裁的物理基础；
- **多主仲裁**：节点靠 ID 逐位仲裁，低 ID 优先且**不损失数据**（显性覆盖隐性的线与思想放大版）；**为什么不撞车**：多个节点同时开口时逐位比较 ID，发 0（显性）的赢，发 1 的发现被压线立刻闭嘴让贤，下一轮重来——像开会抢话筒，声音小的自动让，且没人听岔；
- **帧结构**：仲裁段(ID)+控制段+数据段(0~8字节)+CRC+ACK——硬件自动重发出错帧，可靠性全在硬件层解决；
- STM32 bxCAN 外设：配波特率+过滤器 → 收发帧中断。**过滤器**：总线是广播的，几百条消息刷屏，过滤器是"只让我关心的 ID 进屋"，省 CPU。**调试工具**：CAN 分析仪（几百元）或双板互发。

## 5. 调试方法论（总线排障通用流程）

**这一节说什么/解决什么问题**：总线不通时的"查案顺序"。从物理层往应用层查，每一层确认了再往上走——倒过来查会浪费一倍时间。

```
波形 → 电平对不对（上拉/终端电阻）→ 协议对不对（逻辑分析仪解码 I2C/SPI/CAN）
     → 寄存器对不对（读 WHO_AM_I/ID 类寄存器验证链路）
     → 软件逻辑（缓冲/状态机）
```

**为什么是这个顺序**：物理层错（没上拉/没终端电阻）会让协议层看起来"全是乱码"，你却对着一堆协议代码调到天亮——先确认"电线是通的、电平是对的"，再查"说的对不对"，最后才查"程序逻辑"。读 WHO_AM_I 是"链路通不通"的一锤定音：能读对 0x68/0xEF，物理层+协议层就都没问题了。

## 6. 常见坑

**这一节说什么**：总线类故障高度模式化——这张表几乎覆盖 90% 的现场问题，出问题时逐行对照。

| 坑 | 现象 |
|----|------|
| I2C 忘上拉 | 总线无高电平，永远 START 失败 |
| I2C 地址用错（7位 vs 8位含读写位） | ACK 收不到（0x3C 与 0x78 之惑） |
| SPI 模式配错 | 读全 0x00/0xFF |
| Flash 忘先擦除 | 写入数据混乱（只能 1→0，擦除才是 0→1） |
| CAN 少终端电阻 | 帧错误率飙升、通信断续 |
| 多器件 I2C 地址冲突 | 只能响应一个（换地址脚或换器件） |

## 7. 章节小结

- 选型口诀：低速省脚 I2C、高速大量 SPI、点对点 UART、抗干扰多主 CAN
- I2C=开漏线与+地址+ACK；读寄存器套路通吃传感器
- SPI=主机定节奏+CS 点名+四模式；Flash 先擦后写
- CAN=差分+仲裁+硬件重发，汽车工业标配
- 排障从物理层往应用层查

## 课后思考题

1. 为什么 I2C 的上拉电阻不能太大也不能太小？（大→RC 上升慢、400kHz 顶不住；小→灌电流超 IO 能力、功耗大；4.7k 是 100~400kHz 的折中——电路基础笔记01 分压思想的频率版）
2. SPI 为什么没有 ACK 机制还能保证可靠？（场景不同：SPI 短距板内高速、CS 点名+时钟确定性已够；I2C 挂多从机需要"在不在"确认——可靠性机制跟着总线拓扑走）
3. CAN 为什么用 8 字节短帧而不是长帧？（短帧仲裁等待时间短、出错重发代价小、实时性可预测——工业实时网络的帧长权衡）
