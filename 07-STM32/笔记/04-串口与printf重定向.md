# 04 · 串口 UART 与 printf 重定向

> 目标：USART 全双工收发 + printf 重定向 + 中断/环形缓冲接收架构——从此拥有调试生命线（本阶段用得最勤的外设）。

**开篇大白话**：帧格式和 51 一模一样（白学了？不——说明知识迁移了），但硬件升级：专用波特率分频器、收发缓冲更强、还能挂 DMA。这一篇的重点是"三档收发姿势"的演进逻辑和 printf 重定向——后者是整个学习阶段用得最多的技能。

## 1. 从 51 到 STM32 的串口升级

**这一节说什么/解决什么问题**：一张表看清"哪些没变（帧格式、交叉接线）、哪些变了（波特率发生器、时钟源）"，然后重点算一遍 STM32 的波特率寄存器 BRR——它比 51 的 TH1 精细，支持小数分频。

帧格式一字不变（51 笔记05），升级点：

| 项 | 51 | STM32 |
|----|----|-------|
| 波特率发生 | T1 兼职 | 专用 BRR 分频器（72MHz÷9600÷16=468.75 → BRR 整数域 0x1D4） |
| 时钟源 | 机器周期 | APB1（USART2/3）或 APB2（USART1）——又是时钟树 |
| 数据缓冲 | 单字节 SBUF | 收发各带 FIFO 思路 + 移位寄存器双缓冲 |
| 额外能力 | 无 | DMA 收发、LIN/SmartCard、硬件流控 RTS/CTS |

**BRR 完整算例（9600bps @72MHz，一步步算）**：

```
第1步：STM32 波特率公式：波特率 = fCK / (16 × USARTDIV)
       （16 是硬件固定过采样率——每 bit 采 16 次投票，抗干扰）
第2步：反求 USARTDIV = 72,000,000 ÷ 16 ÷ 9600 = 468.75
第3步：BRR 是 16 位寄存器，拆两个域：
       整数域（高 12 位）= 468 = 0x1D4
       小数域（低 4 位） = 0.75 × 16 = 12（硬件把 1/16 当"1"，12/16=0.75）
       → 完整 BRR = (468 << 4) | 12 = 0x1D4C
第4步：CubeMX 会自动算好填入；若只写整数域 0x1D4（小数=0），
       实际波特率 = 72MHz/(16×468) ≈ 9615，误差 0.16% < 2% 也能用，
       但 115200 这种高速率必须带小数域才能压住误差
```

对照 09 篇的 115200 算例（39.0625 → BRR=0x271）再看一遍——**整数域+小数域的两段式**就是 51 里 TH1 计算的升级版：51 只有整数一档，算不整就容忍误差；STM32 有小数档，几乎都能凑准。

**注意 TX/RX 交叉 + 共地**的老规矩不变；TTL 电平 3.3V（51 常见 5V）——接 5V 设备要电平转换（02 篇开漏/FT 脚知识）。

## 2. 三种收发姿势（工程演进）

**这一节说什么/解决什么问题**：串口收发的三种实现各有代价——阻塞省心但卡主程序，中断+缓冲不卡但要管理缓冲，DMA 全自动但要配通道。理解演进逻辑，你就知道项目该用哪档。

### 姿势①：阻塞发送（最简单，短调试信息够用）

```c
uint8_t msg[] = "hello\r\n";
HAL_UART_Transmit(&huart1, msg, sizeof(msg)-1, 100);  // 最后参数=超时ms
```

CPU 一直等到发完才返回（阻塞）——发 100 字节 @9600bps 要 100ms，期间啥也干不了。调试信息可以，正式产品里大数据不行。

### 姿势②：中断接收 + 环形缓冲（标准裸机架构）

**这段代码做什么**：让串口每收到 1 字节就自动进一次中断，中断里只干一件事——把字节塞进环形缓冲区；主循环有空时再从缓冲区慢慢取出来解析。数据到达和处理节奏彻底解耦。

```c
/* 初始化后开启单字节接收中断 */
HAL_UART_Receive_IT(&huart1, &rxByte, 1);

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huat)  // 收到 1 字节自动进来
{
    RingBuffer_Push(&rb, rxByte);            // 存入环形缓冲（C 笔记11 那套）
    HAL_UART_Receive_IT(&huart1, &rxByte, 1); // 重新挂接收——每次收完必须重挂！
}
/* 主循环：RingBuffer_Pop 逐字节解析协议（状态机，C 笔记10 模板） */
```

**关键行拆解**：
- `HAL_UART_Receive_IT(&huart1, &rxByte, 1)`——告诉硬件："收 1 个字节到 rxByte，收完叫我"。参数 3 的 1 = 一次接收的字节数（也可配成一帧的长度，收满才中断一次）；
- `HAL_UART_RxCpltCallback`——"接收完成回调"，HAL 中断处理函数链的最末端（中断硬件入口 → HAL_UART_IRQHandler → 你这个回调），51 的 UART_ISR 翻版；
- `HAL_UART_Receive_IT(...)`（回调里再调一次）——**为什么必须重挂**：HAL 收完设定数量后自动关闭本次接收，不重挂=后面的字节全部丢掉。"只能收到一次"是本外设第一坑；
- `RingBuffer_Push`——环形缓冲像一个"首尾相接的传送带"，写指针（ISR 负责推）和读指针（主循环负责取）各走各的，天然免锁。

架构思想：**ISR 只搬砖（入缓冲），主循环慢慢消化**——与 51 综合项目完全同构，只是缓冲区从"1 字节变量"升级为环形缓冲。

### 姿势③：DMA 收发（数据量大时，05 篇细讲）

`HAL_UART_Receive_DMA()` 挂后台搬运，CPU 全程不参与，收完半/全量中断通知——串口屏数据流、GPS NMEA 大流量必用。

## 3. printf 重定向（调试体验质变）

**这一节说什么/解决什么问题**：printf 默认不知道"字符该往哪发"，重定向=告诉它。配好之后 `printf("%d", x)` 直接可用——调试效率的质变，本阶段每个后续项目都靠它。

printf 默认不知道往哪发——把它"接"到串口（重定向）。**Keil 微库版**（MicroLIB 要勾选——**为什么**：标准 C 库的 printf 体积大还依赖半主机模式——即程序借调试器之手用电脑的键盘屏幕做输入输出，脱离调试器就卡死；MicroLIB 是精简库，不玩这套，fputc 才会被真正调用）：

**这段代码做什么**：实现 fputc——printf 打印每个字符时都会调用它，你在这个函数里把字符从串口发出去，printf 就"通"了。

```c
#include <stdio.h>
int fputc(int ch, FILE *f)                 // printf 底层只调这一个函数
{
    HAL_UART_Transmit(&huart1, (uint8_t*)&ch, 1, 10);
    return ch;
}
/* 此后随便用：printf("ADC=%d, temp=%.1f\r\n", adc, temp); */
```

**关键行拆解**：
- `int fputc(int ch, FILE *f)`——函数签名必须一字不差（C 库约定），printf 逐字符调它；
- `HAL_UART_Transmit(..., 1, 10)`——发 1 个字节、超时 10ms。注意这是阻塞发送，每打印一行要等发完（9600bps 下一行 30 字节约 30ms）——高频打印会拖慢主程序，量大的日志走姿势③；
- `(uint8_t*)&ch`——ch 是 int，发的是低 8 位，取地址强转后按 1 字节发。

原理：printf 输出时逐字符调 `fputc`——重定向=告诉它"一个字符怎么发"。CubeIDE 版重写 `_write`，原理相同。

**调试打印心法**：打印处加文件行号宏 `printf("[%s:%d] val=%d\r\n", __FILE__, __LINE__, val)`；生产版本用条件编译关掉——`#define DEBUG_PRINT(...)`（C 笔记09 可变参数宏落地场景）。

## 4. 协议解析实战（把 51 的状态机升级）

**这一节说什么**：串口是字节流，没有"边界"——你得自己定义帧（帧头+长度+校验）并用状态机切分。这是 51 综合项目里"逐字节比较"的正式升级版，也是产品里最常用的串口协议雏形。

上位机发帧 `[0xAA][长度][数据...][校验和]`——固定帧头+状态机解析（C 笔记10 代码直接迁移）。调试三件套：逻辑分析仪抓波形（协议对不对）→ 串口打印中间值（解析哪步丢的）→ 断点看缓冲区内容（07 篇）。

## 5. 常见坑

| 坑 | 现象 |
|----|------|
| 波特率/时钟树不匹配 | 乱码（先打印固定字符串验证发送链路） |
| 忘 MicroLIB | printf 卡死或硬错误 |
| 收完不重挂 Receive_IT | 只能收一次 |
| ISR 里直接 printf | 偶发死锁（阻塞发送在 ISR 里等发送完） |
| TX/RX 不交叉/不共地 | 全无反应或乱码 |
| 3.3V/5V 电平直连 | 读错或损坏（非 FT 脚禁 5V） |

## 6. 章节小结

- 帧格式没变，波特率专用 BRR、时钟源挂 APB
- 三姿势：阻塞（调试）/中断+环形缓冲（裸机标准）/DMA（大数据）
- printf 重定向=实现 fputc；打印带行号、条件编译可关
- 协议解析=状态机+环形缓冲，前面 C 语言积累全部落地

## 课后思考题

1. 为什么 ISR 里禁止 printf？（阻塞发送 100ms 级等待，中断实时性崩塌；且 printf 非重入，可能与主循环的 printf 互相踩——日志要发到缓冲区由主循环或 DMA 出）
2. 环形缓冲的读写指针分别属于谁维护？为什么要这样分？（写指针=接收侧/ISR，读指针=消费侧/主循环——单生产者单消费者无需加锁，指针本身是 volatile（C 笔记09））
3. 115200bps 下阻塞发送 100 字节要多久？值不值得改 DMA？（72MHz 假设 10 位/字节 → 100×10/115200≈8.7ms——看场景：调试可忍，产品数据流必改 DMA）
