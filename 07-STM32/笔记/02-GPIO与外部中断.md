# 02 · GPIO 与外部中断

> 目标：吃透 GPIO 的 8 种工作模式（面试必考）与推挽/开漏本质；掌握 EXTI 外部中断；养成"看原理图定极性"的习惯。

**开篇大白话**：GPIO 就是"引脚的用法说明书"——同样是输出电平，51 只有"准双向口"一种玩法，STM32 给你 8 种模式按场景挑（强的、省电的、能接 5V 的……）。选模式的依据全在"内部开关结构"，看懂结构，8 种模式不用背。

## 1. GPIO 内部结构与 8 种模式

**这一节说什么/解决什么问题**：每个引脚内部是一小坨可配置的电路（开关+驱动管），8 种模式就是这坨电路的 8 种"接线方式"。理解结构，你才能回答"为什么开漏要接上拉""为什么按键要配上拉"这类工程问题。

每个引脚 = **保护二极管对 + 上下拉开关 + 输出驱动管（P-MOS/N-MOS 对）+ 施密特触发输入** 的组合。这些零件先点名：
- **保护二极管对**：引脚电压冲过高/拉过低时把电流泄走——芯片的"保险丝"；
- **上/下拉开关**：软件可开关的内部电阻，给悬空引脚一个"默认电平"；
- **P-MOS/N-MOS 驱动对**：两个开关管，一个负责拉高（P-MOS）、一个负责拉低（N-MOS）——**推挽还是开漏，就看这两个管怎么用**；
- **施密特触发**：输入信号的"整形器"——把缓慢、带毛刺的信号变成干净的 0/1（门槛有两个：升到 2V 才算 1、降到 1.2V 才算 0，中间地带不翻脸，专治抖动信号）。

8 种模式就是这几个开关的不同组合：

### 4 种输出类

| 模式 | 结构 | 特点 | 用途 |
|------|------|------|------|
| **推挽输出**（GPIO_MODE_OUTPUT_PP） | P-MOS+N-MOS 轮流导通 | **强 0 强 1**，双 25mA 驱动 | LED、普通输出首选 |
| **开漏输出**（GPIO_MODE_OUTPUT_OD） | 只用 N-MOS | 强 0，**输出 1 = 高阻**，高电平靠外部上拉 | 见下文"开漏三大用途" |
| 复用推挽（AF_PP） | 输出接到片上外设（TX、PWM） | 同推挽，数据源不是 ODR | 外设信号输出 |
| 复用开漏（AF_OD） | 同上但开漏 | I2C 专用 | 硬件 I2C |

**推挽/开漏类比**：推挽像"双向水泵"——既能往外推水（输出高）也能往回抽水（输出低），两个方向都有劲；开漏像"单向阀门"——只会抽（拉低），想"推"就得外接一根水管（上拉电阻）补水压，推力多大取决于水管（电阻）。

### 4 种输入类

| 模式 | 特点 | 用途 |
|------|------|------|
| **浮空输入** | 无上无下，读引脚真实电平，悬空时读数漂 | 接外部有确定驱动的信号（如另一芯片 TX） |
| **上拉输入** | 默认高，被外部拉低才变 0 | **按键接地的标准配法**（悬空防误读） |
| 下拉输入 | 默认低 | 按键接 VCC 时用 |
| 模拟输入 | 施密特触发断开，直连 ADC | 模拟量采集 |

**"上下拉"到底防什么**：引脚什么都不接时叫"悬空"，电平随环境电磁场漂——像没系绳的气球。上拉/下拉就是一根默认的绳，把气球拴在"高"或"低"上，等外部信号（按键按下）来强行改它。

### 开漏三大用途（为什么离不开它）

1. **电平转换**：开漏+上拉到 5V → 输出可到 5V 而 IO 本身 3.3V 承受？注意：F103 多数 IO 是 **FT（5V tolerant，5V 忍受）脚**，普通脚 3.3V 上限——查引脚表确认；
2. **线与**：多个开漏输出并联（如 I2C 总线），任一拉低总线即低——推挽并联会"强 1 撞强 0"烧管子（两个水泵一个猛推一个猛抽，管子爆）；
3. **单向驱动保护**：不同电压域器件握手信号常用。

> 回望 51：P0 的开漏+上拉、LED 低电平点亮，全是这里概念的雏形；推挽 = "强 0 强 1"，是 51 没有的豪华配置。

## 2. GPIO 常用函数与点灯

**这一节说什么**：三个最常用的 HAL 函数 + 一条保命铁律（先看原理图）。函数极简，真正容易翻车的是"极性"——高电平亮还是低电平亮。

```c
HAL_GPIO_WritePin(GPIOC, GPIO_PIN_13, GPIO_PIN_RESET);  // 写 0（RESET=低）
HAL_GPIO_ReadPin(GPIOA,  GPIO_PIN_0);                    // 读输入电平
HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);                  // 翻转
```

**参数拆解**：第一个参数=哪一组（GPIOC），第二个=组内第几脚（GPIO_PIN_13，一个"只有 bit13 是 1"的掩码值，内部就是去动 BSRR 寄存器——09 篇脱马甲验货）。`GPIO_PIN_SET`=写 1、`GPIO_PIN_RESET`=写 0——**SET/RESET 是"置位/复位"的固定搭配，不是"设置/重置"那么随意**。

**看原理图定极性**（第一步永远是这一步）：LED 一端接 VCC → **低电平点亮**（写 RESET）；接 GND → 高电平点亮。按键一端接 GND → 上拉输入，按下读到 0。开发板差异全在原理图，代码逻辑相同。**为什么强调这个**：代码是死的、电路是活的，"程序没毛病灯不亮"十有八九是极性搞反——先查原理图再改代码，能省两小时。

## 3. 外部中断 EXTI

**这一节说什么/解决什么问题**：让"引脚电平跳变"主动喊 CPU（而不是主循环反复去读）。按键、传感器报警脚、无线模块的 IRQ 全靠它——这是把 51 的 INT0 概念全面升级：更多引脚、更多触发方式、更灵活的优先级。

**EXTI**（External Interrupt/Event Controller，外部中断控制器）是什么：夹在 GPIO 和 NVIC 之间的一层"门铃接线板"——16 条 EXTI 线（0~15）对应引脚号 0~15，每条线可配"上升沿/下降沿/双边沿"触发。

**NVIC**（Nested Vectored Interrupt Controller，嵌套向量中断控制器）是什么：Cortex 内核的"总机接线员"——所有中断请求最后都要经它排队、判优先级、跳向量表。51 的 IE+IP 在这里是它的分身，但优先级从 2 级升到"抢占+响应"双维度。

### 硬件结构两要点

1. **每条 EXTI 线一组，同号引脚二选一**：PA0/PB0/PC0 共用 EXTI0——同组只能选一个，CubeMX 配置冲突多半栽在这（硬件上有个多路选择器，同一时刻只能把一个引脚接到 EXTI0 线上）；
2. **中断号分段**：EXTI0~4 各有独立向量；EXTI5~9、EXTI10~15 各**共用**一个向量 → ISR 里要读标志位分辨具体是谁（类比：1~4 号会议室各有专属门铃，5~9 号共一个门铃——响了得看指示灯才知道是哪间）。

### 配置流程（CubeMX）与代码

CubeMX 三步走，每步为什么：**选引脚设 GPIO_EXTIx**（把引脚接到 EXTI 线上——物理接线）→ **选触发边沿**（定义什么算"响铃"：上升沿/下降沿）→ **NVIC 里使能对应 EXTIx**（向总机登记这个门铃——不登记，响了也没人接）→ 生成。

**这段代码做什么**：按键触发 EXTI 中断后，所有 EXTI 共用这一个回调函数，靠参数 GPIO_Pin 分流——"是 KEY1 按下就立旗"，主循环看到旗子再干活。

```c
/*stm32f1xx_it.c 里 CubeMX 已写好框架，业务写在 HAL 回调里*/
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)   // 所有 EXTI 共用回调，靠 Pin 参数分流
{
    if (GPIO_Pin == KEY1_PIN)
    {
        keyFlag = 1;        // ISR 纪律（51 笔记04）：只立旗，不干活
    }
}
```

**关键行拆解**：
- `HAL_GPIO_EXTI_Callback`——HAL 把"清标志、判来源"的杂活包了，只给你留这一个"业务入口"（51 里 IT0、清 IE 标志这些手动活它全代办了）；
- `if (GPIO_Pin == KEY1_PIN)`——因为 EXTI5~9/10~15 共享向量，一次进中断可能是好几个引脚之一触发，必须用参数甄别；
- `keyFlag = 1;`——51 军规原样沿用：ISR 只立旗。

**按键中断的消抖**：中断方式下不能延时等待（ISR 纪律）。工程做法：**中断里只记录时间戳/立旗，10ms 后的确认交给定时器扫描**——即"中断+定时器状态机"组合（按键状态机模板见 51 笔记03，此处升级为时间戳版）。

## 4. HAL 库初见：读源码的能力

**这一节说什么**：别把 HAL 当黑盒——它就是普通 C 代码，读得懂。这一节给你一个可以吃一辈子习惯：遇到"魔法函数"，右键进去看实现。

HAL 层层回调（EXTI_IRQHandler → HAL_GPIO_EXTI_IRQHandler → 用户 Callback），初学觉得绕。正确姿势：**Keil 里右键 Go To Definition 顺藤摸瓜读一遍**——你会在 HAL_GPIO_EXTI_IRQHandler 里看到"清标志 → 判别 → 调回调"，把中断通用框架看穿：**清标志、判源、处理**三步是所有 MCU 中断的公共骨架。

## 5. 常见坑

| 坑 | 现象 |
|----|------|
| 同号引脚都想做中断 | CubeMX 报错/只有一个生效（EXTI 线二选一） |
| 按键配浮空输入 | 松手时读数乱跳（悬空漂移） |
| 中断里 DelayMs | 系统卡死（ISR 军规失效） |
| 忘使能 NVIC | 引脚配了中断但永远不进 |
| 5V 信号直接进普通 IO | 过流损坏（必须 FT 脚或分压） |
| 开漏输出不接上拉 | 只能输出 0，量不到高电平 |

## 6. 章节小结

- 8 模式本质 = 内部开关组合：推挽强 0 强 1；开漏强 0 高阻 1（线与/电平转换/I2C）
- 输入先看原理图定上下拉；按键 = 上拉输入 + 定时器状态机消抖
- EXTI：同号引脚互斥、5~9/10~15 共享向量；ISR 只立旗
- HAL 读法：Go To Definition 顺藤摸瓜，看穿"清标志判源处理"通用框架

## 课后思考题

1. I2C 的 SDA 为什么必须开漏+上拉而不能推挽？（多设备共享总线必须线与；推挽强 1 与从机强 0 对撞 = 电源对地短路）
2. 为什么浮空输入能被"手摸引脚"干扰？（高阻态，人体感应静电即可改变电平——工业设备输入脚标配上拉/下拉的底层原因）
3. EXTI5~9 共享一个向量，会不会丢中断？（不会丢事件——标志位分开；但 ISR 里必须判清标志逐一处理，漏判=逻辑丢失）
