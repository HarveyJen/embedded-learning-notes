# 07 · 结构体、联合体、枚举

> 嵌入式三大件：寄存器用结构体描述、协议用联合体/位域解析、状态机用枚举。
> 标准库源码（如 `GPIO_TypeDef`）、RTOS API 全是它们。

**这一篇讲什么**：C 语言自带的类型（int、char）只能装"一样东西"，可现实中一个对象往往有多项属性——一个学生有姓名、学号、成绩。**结构体**就是把几样东西打包成一张"登记表"；**联合体**是"一间房轮流住几种人"（省内存）；**枚举**是"给一串状态编号并起名"（防手滑写错数字）。这三样是读懂 STM32 库源码的门票。

## 1. 结构体（struct）

**这是什么**：把若干个（类型可以不同）变量捆成一个整体，起一个名字。类比个人档案表：姓名栏、年龄栏、照片栏印在同一张表上，整张表传阅（整体赋值/传参），也可以按栏位单独改（`p1.x = 10`）。

### 定义与使用

```c
#include <string.h>

typedef struct {              // typedef 后用 Point_t 即可，省去 struct 关键字
    int    x;
    int    y;
    char   name[16];
} Point_t;

Point_t p1 = {3, 5, "origin"};
Point_t p2 = { .x = 1, .y = 2, .name = "pt" };   // 指定初始化（C99，嵌入式常用）

p1.x = 10;                    // 结构体变量用 .
Point_t *pp = &p1;
pp->x = 20;                   // 结构体指针用 ->
```

### 结构体传参：传址优先

**这是什么**：结构体大（几十上百字节）时，传值（拷贝整张表）又慢又费内存；传址（只传 4/8 字节的地址）高效。要改原值必须传址；只想读不想改就"传址 + const"，两全其美。

```c
void print_point(Point_t p);              // 传值：拷贝整个结构体（大结构体开销大）
void move_point(Point_t *p, int dx, int dy);   // 传址：只传4/8字节地址，可修改原值
void show_point(const Point_t *p);        // 只读传址：const 保护，高效又安全（标准库风格）
```

### 结构体嵌套与自引用（链表基础）

```c
typedef struct Node {
    int            data;
    struct Node   *next;      // 自引用必须是"指针"（大小已知），不能是本结构体变量
} Node_t;
```

## 2. 内存对齐（必考，必须会手算）

**这是什么**：结构体成员在内存里不是"一个紧挨一个塞满"，而是各自要站在"规定好的位置"上，中间可能垫空位（**填充 padding**）。为什么？因为 CPU 读内存不是 1 字节 1 字节读的，而是按 2/4/8 字节"整块"读——数据放在整块边界上，一次读完；跨在两块之间，就要读两次再拼接，有的架构干脆报错。**对齐 = 用一点空间换访问速度**。手算 sizeof 是笔试超高频题，规则只有两条半，跟着下面的例子走一遍就会。

### 对齐规则
1. 每个成员的**起始地址必须是 min(自身大小, 默认对齐数) 的整数倍**（gcc 无默认对齐数即自身大小；VS 默认 8）；
2. 结构体**总大小必须是最大成员对齐数的整数倍**（尾部补齐）；
3. 嵌套结构体：按其中最大对齐数对齐。

### 手算示例

**一步步算 struct A 为什么是 12 字节**（char 1 字节、int 4 字节，gcc 规则）：
1. 成员 c（char，对齐数 1）：放偏移 [0]，占 1 字节；
2. 成员 i（int，对齐数 4）：下一个可用位置是偏移 1，但 1 不是 4 的倍数 → 垫 3 个填充字节，i 放 [4..7]；
3. 成员 c2（char）：放 [8]，占 1 字节，目前总长 9；
4. 规则 2：总大小必须是最大对齐数（4）的整数倍 → 9 补到 12。**结论：sizeof(struct A) = 12**。

```c
struct A { char c; int i; char c2; };   // 12 字节
// c 占 [0]；i 需 4 对齐 → 填充 3 字节，占 [4..7]；c2 占 [8]；总 9 → 补到 12

struct B { char c; char c2; int i; };   // 8 字节
// c[0] c2[1] 填充[2,3] i[4..7] —— 成员顺序影响大小！
```

对比 struct B：两个 char 先把 [0]、[1] 占掉，再垫 2 字节，int 放 [4..7]，总长 8，无尾部填充。**同样的成员，换个顺序省了 4 字节**——所以嵌入式里"小成员排前面、大成员排后面"是常见优化口诀（按对齐数从小到大排最省）。

```c
struct C { char c;  double d; };        // gcc: 16；c[0] 填[1..7] d[8..15]
struct D { double d; char c; };         // 16；d[0..7] c[8] 补到16 → 同为16
```

### 为什么要对齐
CPU 按 2/4/8 字节块访问内存，未对齐的数据要读两次再拼接（有的架构直接总线错误）。**空间换速度**。

### 控制对齐（协议/寄存器场景）

```c
#pragma pack(1)          // 1 字节对齐：成员紧密排列，和协议帧/Flash布局完全一致
typedef struct {
    uint8_t  head;       // 1
    uint16_t len;        // 2
    uint32_t addr;       // 4
} Frame_t;               // sizeof = 7（不 pack 则 12）
#pragma pack()           // 恢复默认
```

> 通信协议帧、写 Flash/EEPROM 的记录结构，通常 `pack(1)` 后再用 `sizeof` 做字节数校验。

## 3. 位域（bit-field，寄存器专用）

**这是什么**：有时一个开关只需 1 位，用整个 int（32 位）去存太浪费。**位域**让成员以"位"为单位分配宽度——`:3` 就是只占 3 位。它像是编译器帮你做的"按位打包"，让 `reg.enable = 1;` 这种写法语义一目了然。

把一个整数按**位**拆分成员：

```c
typedef struct {
    uint8_t mode   : 3;     // 3 位
    uint8_t enable : 1;     // 1 位
    uint8_t irq    : 1;
    uint8_t rsv    : 3;     // 保留位凑满 8 位
} CtrlReg_t;                // sizeof = 1
```

- 好处：`reg.enable = 1;` 语义清晰；
- 缺点：**位排列依赖编译器/端序，跨平台不可移植** → 协议数据用位域要谨慎，裸寄存器更常用"位运算宏"（笔记10）。

## 4. 联合体（union）

**这是什么**：所有成员**共享同一块内存**——同一间房，今天住 4 字节的 uint32_t，明天改住 1 字节的 uint8_t[4]，"换人住"时前一个的痕迹还在（数据按新的类型解读）。大小 = 最大成员。核心用途就两个：**换视角看同一份数据**（判断大小端、验证 float 存储）和**省内存**（多个身份同一时刻只用一个）。

所有成员**共享同一块内存**，大小 = 最大成员。

```c
union Data {
    uint32_t u32;
    uint8_t  u8[4];
    float    f;
};
union Data d;
d.u32 = 0x11223344;
printf("%02x %02x\n", d.u8[0], d.u8[1]);  // 小端输出 44 33
```

### 经典应用 1：判断大小端（见笔记02）

### 经典应用 2：寄存器"整体写 / 逐位读"

```c
typedef union {
    uint32_t all;              // 一次性读写整个寄存器
    struct {
        uint32_t mode  : 4;    // 或按位访问
        uint32_t enable: 1;
        uint32_t rsv   : 27;
    } bits;
} GPIO_CR_t;

#define GPIOA_CR (*(volatile GPIO_CR_t *)0x40010800)
GPIOA_CR.all   = 0x44444444;
GPIOA_CR.bits.enable = 1;
```

### 经典应用 3：节省内存（变量同一时刻只用一个身份）
低内存 MCU 上，一块缓冲区既当"接收缓冲"又当"解析后的帧"。

## 5. 枚举（enum）

**这是什么**：把一组相关的整数常量"打包起名"。没有枚举时你写 `state = 2;`——2 是啥？查半天才知是"运行中"；有枚举后写 `state = STATE_RUN;`，一眼看懂，输错名字编译器立刻报错。类比餐厅给菜品编号：点"3 号"（裸数字）容易错，点"宫保鸡丁"（枚举名）不会错，后厨账本上它仍然对应编号（整数值）。

```c
typedef enum {
    STATE_IDLE = 0,     // 不指定则从 0 递增
    STATE_RUN,          // 1
    STATE_ERR  = 100,   // 指定后继续 +1
    STATE_STOP          // 101
} State_t;

State_t state = STATE_IDLE;
```

- vs `#define`：枚举有**类型**，调试器能显示名字，作用域受限，推荐；
- 典型用途 1：**状态机状态**（见第6节）；
- 典型用途 2：返回错误码：

```c
typedef enum {
    OK = 0,
    ERR_PARAM,
    ERR_TIMEOUT,
    ERR_BUSY
} Status_t;

Status_t uart_send(uint8_t *buf, uint16_t len);
```

## 6. 组合实战：switch 状态机 + 结构体 + 枚举

**这是什么**：本篇的"毕业设计"——用枚举定义状态、用结构体保存解析进度、用 switch 驱动状态跳转，写出一个串口协议帧解析器。这是真实项目里每天都见的代码形态，阶段二的"自定义协议"项目就是它的放大版。

**这段代码要做什么**：逐字节喂入串口数据，按 `帧头0x55 | 长度 | 数据 | 校验和` 的格式解析，收到完整合法帧就打印提示。

```c
#include <stdio.h>
#include <stdint.h>

typedef enum { S_IDLE, S_HEAD, S_LEN, S_DATA, S_CHECK } FsmState;

typedef struct {
    FsmState state;
    uint8_t  len;
    uint8_t  cnt;
    uint8_t  sum;
    uint8_t  buf[32];
} Fsm_t;

/* 解析一帧: 0x55 | len | data... | checksum(前所有字节和) */
void fsm_feed(Fsm_t *f, uint8_t byte)
{
    switch (f->state) {
    case S_IDLE:
        if (byte == 0x55) { f->state = S_LEN; f->sum = byte; }
        break;
    case S_LEN:
        f->len = byte; f->cnt = 0; f->sum += byte;
        f->state = (f->len > 0 && f->len <= sizeof(f->buf)) ? S_DATA : S_IDLE;
        break;
    case S_DATA:
        f->buf[f->cnt++] = byte; f->sum += byte;
        if (f->cnt >= f->len) f->state = S_CHECK;
        break;
    case S_CHECK:
        if (f->sum == byte) printf("frame OK, len=%u\n", f->len);
        f->state = S_IDLE;
        break;
    default:
        f->state = S_IDLE;
        break;
    }
}
```
这就是串口协议解析器的标准写法——把这段吃透，阶段二的"自定义协议"项目就稳了。

## 7. 标准库中的寄存器结构体（读懂即通关）

```c
typedef struct {                 // STM32 标准库（节选）
    volatile uint32_t CR1;
    volatile uint32_t CR2;
    volatile uint32_t ODR;
    ...
} GPIO_TypeDef;

#define GPIOA ((GPIO_TypeDef *)GPIOA_BASE)   // 把基址强转为结构体指针

GPIOA->ODR |= (1u << 5);     // 库里的写法 = 笔记06 第9节的手工版
```
原理：**结构体成员地址连续**，正好对应芯片手册的寄存器偏移表——成员按声明顺序依次排列，ODR 在基址 +0x0C 处，编译器把"访问成员"翻译成"读写 基址+偏移"，所以 `GPIOA->ODR` 落到的正是手册里那个寄存器。
