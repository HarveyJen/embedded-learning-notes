# 01 · C 语言概述与环境搭建

## 1. C 语言是什么

**先说大白话**：C 语言就是人和计算机说话用的"语言"之一。计算机只认识 0 和 1，人写不出来也不爱看，所以需要一种"中间语言"——人写起来像英语句子，再由一个叫**编译器**（翻译官，把 C 代码翻译成 0/1 机器码的程序）的软件翻给计算机听。C 语言就是这些语言里最贴近硬件、翻译出来最精简的一种。

- 1972 年由 Dennis Ritchie 在贝尔实验室为开发 UNIX 而设计。
- 标准演进：**K&R C → ANSI C（C89/C90）→ C99 → C11 → C17**。嵌入式编译器常用 `C99`（Keil/GCC 默认兼容）。
- C 是**编译型语言**：源码一次性翻译成机器码；Python 是解释型语言（逐行解释执行）。这是嵌入式选 C 的根本原因——**运行快、占用小、贴近硬件**。

### 为什么嵌入式领域几乎被 C 垄断

1. **直接操作内存和寄存器**（指针）；
2. **运行效率高**，无虚拟机、无 GC；
3. **生成的代码体积小**，适合资源受限的单片机（几 KB RAM 也能跑）；
4. **所有主流芯片工具链（GCC、Keil、IAR）都支持 C**；
5. RTOS、Linux 内核、驱动几乎全部用 C 编写。

## 2. 编译流程（必须理解）

**这是什么**：你写的 `.c` 文件并不是计算机能直接跑的东西，它要经过一条"流水线"加工 4 次才能变成可执行文件（Windows 上的 .exe，或烧进单片机的固件）。理解这条流水线，以后看懂报错信息、看懂 Keil 的编译输出，都不会一头雾水。

一个 `.c` 文件变成可执行文件/固件，经历四步：

```
hello.c ──预处理──> hello.i ──编译──> hello.s ──汇编──> hello.o ──链接──> hello.exe / .bin/.axf
        (gcc -E)            (gcc -S)           (gcc -c)              (gcc / ld)
```

| 步骤 | 做什么 | 关键点 |
|------|--------|--------|
| 预处理 | 展开 `#include`/`#define`、处理条件编译、删除注释 | 只做文本替换，**不检查语法** |
| 编译 | 词法/语法/语义分析，生成汇编代码 | 语法错误在这里报 |
| 汇编 | 汇编代码 → 二进制目标文件（.o） | 单个文件的目标代码 |
| 链接 | 合并多个 .o 和库，分配地址，解析符号 | **未定义引用（undefined reference）在这里报** |

> 嵌入式对应关系：STM32 工程 Build 一次 = 预处理+编译+汇编+链接；生成的 `.axf/.elf` 再转成 `.bin/.hex` 烧录。链接脚本（.ld/.sct）决定代码和变量放在 Flash 还是 RAM。

**生活化类比**：把这 4 步想象成"出版一本书"——预处理是整理素材（把引用的资料都抄进来）；编译是把中文稿翻成英文；汇编是排版成铅字；链接是把所有章节装订成一本书、并做好目录（分配地址）。

### GCC 常用命令

```bash
gcc main.c -o app        # 一步到位编译
gcc -E main.c -o main.i  # 只做预处理（观察宏展开很有用）
gcc -S main.c -o main.s  # 生成汇编
gcc -c main.c            # 只生成 main.o
gcc main.c -o app -g     # -g 带调试信息（gdb 可用）
gcc main.c -o app -Wall  # -Wall 打开全部警告，建议养成习惯
```

## 3. 环境搭建（三选一）

**这是什么**：写代码需要两样工具——**编辑器**（打字的地方，像 Word）和**编译器**（翻译官）。新手可以直接用把它们打包好的软件（IDE，集成开发环境），少折腾配置。下面三个方案选一个装好即可，卡住了先看报错、再搜报错信息，这是程序员的日常。

### 方案 A：VS 2022（Windows 初学者最省心）
- 安装时勾选「使用 C++ 的桌面开发」工作负载；
- 新建「空项目」→ 添加 `main.c` → Ctrl+F5 编译运行；
- 调试器最好用（断点、监视、内存窗口、调用堆栈）。

### 方案 B：VSCode + MinGW-w64（轻量，推荐长期用）
1. 安装 VSCode + 扩展 C/C++；
2. 安装 MinGW-w64（或直接用 MSYS2），把 `bin` 目录加入 PATH；
3. 终端验证：`gcc -v`；
4. 写代码 + Code Runner 插件或手动 `gcc xxx.c -o xxx && ./xxx`。

### 方案 C：Linux / WSL
```bash
sudo apt install build-essential gdb   # gcc + make + gdb
gcc hello.c -o hello && ./hello
```
> 嵌入式 Linux 方向（阶段四）必须熟悉这条路线。

### 嵌入式专属（后续阶段用）
- **Keil MDK**（单片机主流 IDE）、**STM32CubeIDE**（免费，基于 GCC）；
- 它们的编译器本质还是上面那四步，只是加了交叉编译（在 PC 上编译出 ARM 芯片的机器码）。

## 4. 第一个程序逐行解析

**这是什么**：所有程序员的"开学第一课"——让屏幕打印出 Hello World。别小看这 6 行，它包含了 C 程序的基本骨架，以后每写一个程序都是这个框架的扩展。

**这段代码要做什么**：包含一个标准库头文件，定义程序入口 main，打印一句话，正常退出。

```c
#include <stdio.h>          // 预处理指令：包含标准输入输出头文件

int main(void)              // 主函数：程序入口，有且只有一个
{                           // 函数体开始
    printf("Hello World\n"); // 库函数调用：打印字符串，\n 换行
    return 0;               // 返回 0 表示程序正常结束
}                           // 函数体结束
```

要点：

- `#include <stdio.h>` 可以理解为"把官方说明书借来抄一份"——`printf` 的用法写在 stdio.h 这个文件里，不抄进来编译器就不认识 printf；
- `main` 是**程序的入口**，链接器从这里开始；嵌入式里入口之前还有启动文件（startup_xxx.s），那是后话。
- `int main(void)` 是标准写法；`void main()` 不标准（别用）。
- 语句以 `;` 结尾——分号像说话时的句号，少写一句就"语无伦次"（编译报错）；`{}` 界定代码块；注释用 `//`（单行）或 `/* */`（可多行，**不可嵌套**）。
- 字符串里的转义字符：`\n` 换行、`\t` 制表、`\\` 反斜杠、`\"` 双引号、`\0` 字符串结尾标志。

### printf 常用格式符

| 格式符 | 含义 | 示例 |
|--------|------|------|
| `%d` | 有符号十进制 int | `printf("%d", -5);` |
| `%u` | 无符号十进制 | `printf("%u", 4000000000u);` |
| `%f` | 浮点（默认 6 位小数） | `printf("%.2f", 3.14159);` |
| `%c` | 单个字符 | `printf("%c", 'A');` |
| `%s` | 字符串 | `printf("%s", "hello");` |
| `%x` / `%X` | 十六进制（小/大写） | `printf("%#x", 255);` → 0xff |
| `%p` | 指针地址 | `printf("%p", &x);` |
| `%ld` `%lld` `%zu` | long / long long / sizeof 结果 | — |

`scanf` 读入时：`%d` 等要取地址 `&num`，数组名（字符串）不用。为什么：scanf 要把读到的值"写进"变量，必须知道变量住在哪（地址），`&num` 就是门牌号；数组名本身就代表首地址，所以不用再加 `&`。

## 5. 错误的三种类型

**这是什么**：新手最怕报错，其实报错是编译器在"帮你"。错误分三类，认清是哪一类，就知道该去哪里找原因。类比：编译错误像"作文有错别字"（写的时候就发现）；链接错误像"目录里列了第 8 章，但书里根本没写这章"（拼装时发现）；运行时错误像"书印出来了，读者照着做却出了事故"（跑起来才暴露）。

| 类型 | 举例 | 排查 |
|------|------|------|
| 编译错误（error/warning） | 少分号、类型不匹配 | 看第一条报错，别慌 |
| 链接错误 | 只声明没定义：`undefined reference to "fun"` | 检查函数是否实现、.c 是否加入工程 |
| 运行时错误/逻辑错误 | 死循环、数组越界、野指针 | **调试器 + printf + 画内存图** |

## 6. 调试基础（VS / VSCode+gdb 通用思路）

**这是什么**：调试（Debug）= 让程序在半路停下来，像放电影按暂停键，逐帧检查哪里不对。调试器就是干这个的工具。学会调试后，你找 bug 就不用靠"盯着代码猜"，而是亲眼看变量的值怎么变。

- **断点**（F9）：程序停在该行，之后可逐语句（F10/F11）执行；
- **监视窗口**：添加变量实时观察值的变化；
- **内存窗口**：看 `&变量` 开始的原始字节（学指针必备）；
- **调用堆栈**：看函数调用链（递归/回调分析神器）。

> 习惯：写代码先 `-Wall` 消警告；出 bug 先别改代码，先观察内存和变量——这是嵌入式调试（J-Link/ST-Link）的思维雏形。
