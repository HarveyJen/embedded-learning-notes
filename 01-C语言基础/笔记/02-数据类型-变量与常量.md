# 02 · 数据类型、变量与常量

**这一篇讲什么**：写程序先要"装东西"——年龄装一个数，名字装一串字符，温度装一个带小点的数。数据类型就是各种规格的"容器"，变量就是贴了标签的容器，常量是封死不能换内容的容器。这一篇还要解决两个嵌入式绕不开的问题：负数在芯片里怎么存（补码），多字节数据怎么排（大小端）。

## 1. 数据类型总览

**这是什么**：C 语言把数据分成几大类，每类规定了"占几个字节、能表示什么范围的值"。就像买收纳箱要看尺寸——装袜子用小盒，装被子用大箱，选错了要么装不下，要么浪费空间。

```
            ┌── char           （字符型，本质是 1 字节整数）
      ┌─ 整型 ─┼── short / int / long / long long
      │        └── signed / unsigned
C类型 ─┼─ 浮点型：float（4B） / double（8B）
      ├─ 构造类型：数组、结构体 struct、联合体 union、枚举 enum
      └─ 指针类型：与被指向的类型有关（后面专章）
```

### 常见类型大小（32 位单片机 / Windows x64 下的典型值）

| 类型 | 典型字节 | 范围（signed） | 嵌入式备注 |
|------|---------|----------------|-----------|
| `char` | 1 | -128 ~ 127 | 串口收发基本单位 |
| `short` | 2 | -32768 ~ 32767 | 协议字段常用 |
| `int` | 4 | ±21 亿 | 平台相关！16位机上可能是2字节 |
| `long` | 4 (Win) / 8 (Linux64) | — | 平台差异大，跨平台慎用 |
| `long long` | 8 | ±9.2×10^18 | 时间戳/大计数 |
| `float` | 4 | ~7 位有效数字 | 无 FPU 的 MCU 上很慢 |
| `double` | 8 | ~16 位有效数字 | 小型 MCU 尽量避免 |

> 读表说明：**字节（Byte）** 是内存计量的基本单位，1 字节 = 8 个二进制位（bit），每一位只能是 0 或 1。所以 1 字节最多能表示 2^8 = 256 种不同状态——这就是 `char` 的范围 -128~127（有符号）或 0~255（无符号）的来历。**"有效数字"** 指小数点前后一共有几位是可靠的，比如 `~7 位有效数字` 意思是 3.14159265 存进 float 再读出来，大概只有 3.141593 是可信的。

验证大小：

```c
printf("char=%zu int=%zu long=%zu\n", sizeof(char), sizeof(int), sizeof(long));
```

> **嵌入式铁律**：跨平台代码用 `stdint.h` 固定位宽：
> `uint8_t / int16_t / uint32_t / int64_t`。寄存器、协议、Flash 存储一律用它们。
>
> 名字怎么读：`uint8_t` = **u**nsigned（无符号）**int** 整数、**8** 位、**_t** type（类型）。所以 `uint8_t` 是"8 位无符号整数"，`int16_t` 是"16 位有符号整数"。它们的好处是名字里写死了位数，在任何平台都一样大，不像 `int` 可能 2 字节也可能 4 字节。

```c
#include <stdint.h>
uint8_t  raw;          // 0 ~ 255，对应串口一个字节
uint32_t tick;         // 32 位系统滴答计数
```

## 2. 原码、反码、补码（嵌入式重点）

**这是什么**：计算机里只有 0 和 1，没有"+"号"-"号。那负数怎么办？工程师们约定了一套编码规则：用二进制的最高位当**符号位**（0 代表正、1 代表负），其余位表示数值。这套规则经过三代演变——原码（最直观）、反码（过渡方案）、补码（最终方案）。今天**计算机里所有整数实际都是按补码存的**，所以这是必须搞懂的地基。

三个概念一句话：
- **原码**：人最好懂的写法——最高位放符号，其余位放数值本身；
- **反码**：负数求补码的中间步骤——原码的数值部分逐位翻转（0 变 1、1 变 0），符号位不动；
- **补码**：反码 + 1，这才是真正存进内存的东西。

计算机中**整数一律以补码存储**：

- 正数：原码 = 反码 = 补码（三码合一，不用变）；
- 负数：反码 = 原码按位取反（符号位不变），补码 = 反码 + 1。

8 位示例：

| 数值 | 原码 | 补码 |
|------|------|------|
| +5 | 0000 0101 | 0000 0101 |
| -5 | 1000 0101 | 1111 1011 |
| -1 | 1000 0001 | **1111 1111** |
| -128 | 无对应原码 | **1000 0000** |

**一步步算 -5 的补码**（以 8 位为例）：
1. 写出 +5 的原码：`0000 0101`；
2. 把符号位改成 1 得到 -5 的原码：`1000 0101`；
3. 符号位保持 1，其余 7 位逐位取反（000 0101 → 111 1010），得反码：`1111 1010`；
4. 反码加 1：`1111 1010 + 1 = 1111 1011`，这就是 -5 存进内存的真实模样。

为什么用补码：把减法变加法，且 0 只有一种表示，多出一个 -128。

**验证"减法变加法"**：计算 5 - 5，计算机实际算的是 5 + (-5) 的补码相加：
```
  0000 0101   (+5)
+ 1111 1011   (-5 的补码)
-----------
 1 0000 0000   → 9 位，最高位溢出扔掉，剩 0000 0000 = 0 √
```
如果不用补码（比如直接用原码相加），电路还得专门处理"同号相减、异号相加"等一堆情况，硬件更复杂。补码让加法器一套电路通吃加减法——这就是它存在的意义。

**经典坑：无符号回绕**

**这是什么**：`unsigned`（无符号）类型没有负数概念，就像汽车里程表没有"倒退"档——最小值再减 1，不是变负数，而是"绕回"到最大值。这叫**回绕（wrap around）**。

**这段代码要做什么**：演示 0 减 1 在无符号类型下的真实结果，并展示 for 循环里的致命死循环写法。

```c
unsigned char a = 0;
a = a - 1;            // a = 255 ！（-1 的补码 0xFF 按 unsigned 解读）
printf("%d\n", a);    // 255
```

运行逻辑逐段拆解：`a - 1` 按补码算出 8 个 1（`1111 1111`）。这串 0/1 本身没有"正负"属性，全看你声明变量时贴的标签：贴 `signed char` 标签，它被解读为 -1；贴 `unsigned char` 标签，它被解读为 255。内存里同一份数据，读法不同结果不同——这就是回绕的全部秘密。

```c
unsigned int i;
for (i = 10; i >= 0; i--) { ... }   // 死循环！i 永远 >= 0
```

**为什么死循环**：循环条件 `i >= 0` 对无符号数永远成立（无符号数最小是 0，不可能小于 0）。走到 `i = 0` 再减 1，i 回绕成 4294967295（32 位无符号最大值），继续"合法"循环。

> 面试常问：`unsigned char` 存 `-1` 是多少？答：255（0xFF）。

**补码算例（练习清单第 2 题的示范）**：手算 -20 的 8 位补码——
1. +20 原码：`0001 0100`；
2. 符号位置 1：`1001 0100`；
3. 取反：`1110 1011`；
4. 加 1：`1110 1100`，即 0xEC。用 `printf("%d", (char)-20)` 打印仍得 -20，因为存的就是补码 `1110 1100`。

## 3. 变量

**这是什么**：变量就是一块贴了标签的内存空间——标签（变量名）让你不用记地址，规格（类型）决定这块空间多大，里面装的东西（值）可以随时换。

### 定义与初始化

**这段代码要做什么**：声明三个不同类型的变量并给它们赋初值。

```c
int    count = 0;
float  temp  = 36.5f;      // float 字面量加 f
char   ch    = 'A';        // 字符本质是整数 65
```

- `36.5f` 里的 `f` 必须写：不加 f 时编译器默认把小数当 `double`（8 字节）处理，再塞进 4 字节的 float 会多一次转换并可能丢精度；
- `'A'` 本质是数字 65——计算机只认数字，每个字符对应一张编号表（ASCII 码表），'A' 的编号就是 65，所以 `char` 和小整数可以互相赋值。

### 命名规范（养成习惯）

- 只能由字母、数字、下划线组成，不能以数字开头，不能是关键字；
- 见名知意：`uart_baud`、`led_state`、`adc_value`；
- 常用风格：局部变量小驼峰 `maxCount` 或 snake_case `max_count`；宏全大写 `MAX_SIZE`；全局变量加前缀 `g_`。

### 局部变量 vs 全局变量

**这是什么**：局部变量是"函数内部私有的"，函数一结束就销毁；全局变量是"整个程序公用的"，从头活到尾。类比：局部变量像会议室白板——开会（函数运行）时写写画画，散会就擦掉；全局变量像公司公告栏——整栋楼（程序运行期）都能看到、一直挂着。

| | 局部变量 | 全局变量 |
|---|---------|---------|
| 位置 | 函数/代码块内 | 函数外 |
| 存储区 | 栈 | 数据段/BSS段 |
| 未初始化值 | **随机（垃圾值）** | 自动为 0 |
| 生命周期 | 所在代码块运行期间 | 整个程序运行期 |

> 表里的"栈""数据段""BSS 段"是内存中的不同区域（详见笔记08《内存布局与动态内存》）。这里只需记住结论：局部变量住"临时工位"，全局变量住"永久工位"。

> 嵌入式注意：未初始化的局部变量是"栈上的随机值"，有些芯片上电后 RAM 里是特定图案（如 0xA5），别依赖它。

## 4. 常量

**这是什么**：常量就是"不许改的值"。有的写在代码里（字面量），有的起个名字（宏常量、const 常量）。起名字的好处：改一个地方全局生效，且名字比裸数字更说明用途。

**这段代码要做什么**：对比宏常量和 const 常量两种写法。

```c
#define PI 3.14159f            // 宏常量：预处理阶段文本替换，无类型、不占内存
const float pi = 3.14159f;     // const 常量：有类型，编译器检查（推荐）
```

- `#define` 是**预处理阶段的查找替换**：编译前 `PI` 这个词被原地换成 `3.14159f`，之后编译器根本不知道有 PI 存在——所以它无类型、不占内存、也没法调试；
- `const` 是编译器管的：`pi` 是一个真正的 float 变量，只是被贴上"只读"封条，谁改它谁报错。

- **字面量后缀**：`100L`（long）、`100u`（unsigned）、`3.14f`（float）、`3.14`（double 默认）；
- **进制表示**：十进制 `100`、八进制 `0144`、十六进制 `0x64`（嵌入式写寄存器全用 0x）；
- **字符常量**：`'A'` 是 int 类型（ASCII 65）；`"A"` 是字符串（占 2 字节：'A' + '\0'），别混。'A' 为什么按 int 而不是 char 处理：C 标准规定字符常量的类型是 int，与第 6 节"整型提升"同源——CPU 做运算天生按 int 宽度进行。

## 5. 类型转换

**这是什么**：不同类型的数一起运算时，编译器会先统一"口径"再算。就像身高用米、体重用公斤没法直接加减——先统一单位。统一有两种方式：编译器自动转（隐式转换，藏着手脚，有坑）和你手动转（强制转换，明明白白）。

### 隐式转换规则（由低到高）

```
char/short → int → unsigned int → long → ... → float → double
```

规则读法：运算时"小"类型自动升级成"大"类型（好比 5 毛钱和 10 元放一起算，统一按元算不会丢钱；反过来按毛算就可能丢精度）。大问题在下面这一条：

记忆点：**有符号和无符号混合运算时，有符号会被转成无符号**（大坑）。

**这段代码要做什么**：演示 -1 和 1 的比较，结果却"反常识"。

```c
int a = -1;
unsigned int b = 1;
if (a > b)          // 为真！a 被转成 0xFFFFFFFF 巨大的无符号数
    printf("a > b\n");
```

运行逻辑逐段拆解：`a` 和 `b` 类型不同，编译器把 `a` 提升为 `unsigned int`。提升不改内存里的 0/1——`a` 的补码是 `1111 1111 1111 1111 1111 1111 1111 1111`（32 个 1），换成无符号视角解读就是 4294967295。4294967295 > 1 成立，所以打印 `a > b`。记住：**内存数据不变，变的是解读方式**。

### 强制转换

**这段代码要做什么**：演示整数除法怎么变成小数除法，以及嵌入式里"地址转指针"的惯用写法。

```c
int sum = 10, n = 4;
float avg = (float)sum / n;    // 2.5；不转换则是 10/4=2（整型除法截断）

// 嵌入式常见：地址转指针
uint32_t addr = 0x40010800;
volatile uint32_t *pGPIO = (volatile uint32_t *)addr;
```

逐段拆解：
- `(float)sum` 把 10 临时当作 10.0 参与运算，10.0 / 4 = 2.5；如果写成 `sum / n`，两个整数相除直接丢掉小数部分得 2；
- 第二段：`0x40010800` 只是一个 32 位的数字，但在这个工程里它是约定好的**硬件寄存器地址**。`(volatile uint32_t *)` 强制转换等于说"别把这个数字当数，当门牌号用"——之后 `*pGPIO` 就能读写这个地址上的硬件了（详见笔记06 第 9 节）。

## 6. 整型提升（笔试常考）

**这是什么**：CPU 内部的运算器天生按 `int`（4 字节）宽度干活，比 int 窄的 `char`/`short` 参与运算时会被先"升舱"成 int，算完再把结果塞回窄容器——塞的时候多出来的高位被剪掉（截断），坑就出在这里。

表达式中 `char/short` 会被自动提升为 `int` 再运算：

**这段代码要做什么**：100 + 100 明明没超过 255，赋给 char 却变成负数，演示整型提升 + 截断。

```c
char a = 100, b = 100;
char c = a + b;        // a+b 先按 int 算 = 200，赋给 char 截断
printf("%d\n", c);     // -56（200 的补码 11001000 按 signed char 解读）
```

一步步算：
1. `a`、`b` 都被提升为 int，按 int 相加得 200（int 装得下，没问题）；
2. 200 的 8 位低字节补码是 `1100 1000`（因为 200 = 128 + 64 + 8）；
3. 赋值给 `char c` 时只保留这 8 位，而 char 默认有符号，最高位是 1 → 这是负数的补码；
4. 解读负数补码：减 1 得 `1100 0111`，取反得 `0011 1000` = 56，加负号 → **-56**。

结论：单步看每一步都"合法"，合起来就丢了预期。用 `unsigned char` 接就能得到 200（0~255 范围内），或者干脆用 `int` 接。

## 7. sizeof 与 typedef

**这是什么**：`sizeof` 是"量尺寸的尺子"——告诉你某类型/某变量占几个字节；`typedef` 是"起外号"——给长得吓人的类型名起个短名字。

**这段代码要做什么**：测量类型和数组的大小，并演示 typedef 起别名的用法。

```c
sizeof(int);            // 4，是"运算符"不是函数
int arr[10];
sizeof(arr);            // 40（整个数组）；sizeof(arr)/sizeof(arr[0]) = 个数
```

**代入数字算一遍 sizeof 公式**：数组总字节数 = 元素个数 × 单个元素字节数。本例 10 个 int、每个 int 4 字节 → 10 × 4 = 40，与 sizeof 返回一致。反过来求元素个数：`sizeof(arr) / sizeof(arr[0])` = 40 / 4 = 10。这个"总大小 ÷ 单个大小 = 个数"的除法是嵌入式里数组长度的标准算法，笔记09 的 `ARRAY_SIZE` 宏就是它。

```c
typedef unsigned char  u8;        // 给类型起别名（嵌入式风格）
typedef uint32_t       reg_val;
typedef struct Point  Point_t;    // 结构体别名，后面细讲
```

> `typedef` 与 `#define` 区别：`#define` 是文本替换、无作用域；`typedef` 由编译器处理、有作用域、能正确处理指针组合（`typedef char* String;` 定义两个变量都是指针）。用 `#define` 替换指针类型时只有第一个变量是指针，第二个会变成普通 char——这是经典考题。

## 8. 大小端（Endianness，嵌入式高频）

**这是什么**：一个 32 位数占 4 个字节，就要在内存里占 4 个"格子"。先放低字节还是先放高字节？两种流派都有人用，这就是**字节序（大小端）**。类比：写日期，中国人习惯"年月日"（大的在前），美国人习惯"月日年"（小的在前）——同样是那三个数字，顺序不同，别人读起来理解就完全不同。

- **小端（Little-Endian）**：低字节放低地址。x86、**ARM 默认**、STM32；
- **大端（Big-Endian）**：高字节放低地址。网络字节序、部分通信协议。

`0x12345678` 在内存（地址从低到高）：

```
小端：78 56 34 12
大端：12 34 56 78
```

读法提示：`0x12345678` 里 0x78 是最低字节（"个位"），0x12 是最高字节（"万位"）。小端就像"个位放门口"——低字节放在低地址。

经典判断代码：

**这段代码要做什么**：把一个 4 字节数用联合体"换个视角看"——同一块内存，按 4 字节整读、或按单字节逐个读，看最低地址字节是 0x78 还是 0x12。

```c
#include <stdio.h>
#include <stdint.h>

int main(void)
{
    union {
        uint32_t u32;
        uint8_t  u8[4];
    } test;

    test.u32 = 0x12345678;

    if (test.u8[0] == 0x78)
        printf("Little-Endian\n");
    else
        printf("Big-Endian\n");
    return 0;
}
```

指针写法：

**这段代码要做什么**：不用联合体，用指针直接"偷看"这 4 字节的第一个字节。

```c
uint32_t x = 1;
if (*(uint8_t *)&x == 1)   // 取低地址字节
    printf("Little-Endian\n");
```

运行逻辑逐段拆解：`&x` 取出 x 的地址（类型是"指向 4 字节的指针"）；`(uint8_t *)&x` 强转成"指向 1 字节的指针"（骗过类型系统，允许只读 1 个字节）；最外层 `*` 解引用，读出最低地址那 1 个字节。如果机器是小端，x=1 的最低字节就是 1。

> 为什么嵌入式必懂：串口/SPI/CAN 传多字节数据、Flash 存结构体、协议组包，字节序不一致数据就全错。例如设备 A（小端）把 0x12345678 按 `78 56 34 12` 发出去，设备 B（大端）按 `12 34 56 78` 收进来还原，就变成 0x78563412——数值完全不对。跨设备协议通常统一约定"大端"（即网络字节序）。
