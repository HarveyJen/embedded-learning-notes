# 09 · 预处理器与关键字专题

> `#define` / `static` / `const` / `volatile` —— 嵌入式 C 面试的"四大天王"。

**这一篇讲什么**：这几个关键字单看定义都简单，但它们各自"管"程序的一个侧面——`#define` 管编译前的文本、`static` 管生命周期和可见范围、`const` 管只读、`volatile` 管不许偷懒。嵌入式代码里到处是它们的组合拳，面试也盯着问，所以单独开一篇集中讲透。

## 1. 预处理指令一览

**这是什么**：**预处理器（Preprocessor）** 是编译流水线的第一站，只干一件事：**查找替换**——把 `#include` 换成文件内容、把 `#define` 的名字换成内容、按条件保留/删除代码段。它完全不懂 C 语法（不懂变量、不懂类型），就像一个只会 Ctrl+H 的编辑器。理解这一点，宏的各种坑都能解释。

| 指令 | 作用 | 示例 |
|------|------|------|
| `#include` | 头文件包含 | `#include <stdio.h>` / `#include "bsp_led.h"` |
| `#define` | 宏定义 | `#define LED_ON 1` |
| `#undef` | 取消宏 | — |
| `#if / #elif / #else / #endif` | 条件编译 | 版本/平台裁剪 |
| `#ifdef / #ifndef` | 是否已定义 | 头文件守卫 |
| `#error` | 强制报错 | 参数不合法时拦截 |
| `#pragma` | 编译器指令 | `#pragma pack(1)`、`#pragma once` |

预处理器在**编译之前**做纯文本替换——它不懂 C 语法，所以宏的坑全在"替换"上。

## 2. #define 对象宏

**这是什么**：给一个东西起"外号"，编译前全文替换。类比快递单上写"公司前台"而不是完整地址——一处定义（前台在哪），处处使用，搬家只改一处。

**这段代码要做什么**：定义三个典型对象宏：数量、地址、常数。

```c
#define MAX_SIZE    100              // 常量宏
#define GPIOA_BASE  0x40010800UL     // 地址宏（加 UL 后缀防溢出）
#define PI          3.14159f
```

- `UL` 后缀白话：告诉编译器这个数按"unsigned long"（无符号长整型）处理。0x40010800 接近 10 亿，默认按 int（最大约 21 亿）处理勉强够，但一做左移、加法就可能溢出，写地址宏一律带 UL 是保命习惯；
- 宏名全大写是**给人看的约定**，一眼就知道"这是替换出来的常量，不是变量"。

习惯：
- 宏名**全大写**；末尾**不加分号**（会替换进表达式出错）；
  - 为什么不能加分号：`#define LED_ON 1;` 会让 `int s = LED_ON;` 展开成 `int s = 1;;`——多出一个空语句，在 if/else 里会直接语法错误；
- 宏体里的参数和整体**都要加括号**（见下）。

## 3. 函数宏（带参宏）

**这是什么**：长得像函数、本质仍是替换的宏。调用 `MAX(a,b)` 不是真的"跳去执行"，而是把这段文本抄过去、把 a b 填进去。就像快捷短语：手机打"zj"自动展开成"在加班，晚点回"——发送前展开，展开成什么完全取决于模板。

```c
#define SQUARE(x)  ((x) * (x))
#define MAX(a, b)  ((a) > (b) ? (a) : (b))
```

**为什么必须加括号**：

**这段代码要做什么**：复现两个"少写括号导致算错"的宏。

```c
#define SQUARE_BAD(x) x * x
SQUARE_BAD(1 + 2);        // 展开成 1 + 2 * 1 + 2 = 5，而不是 9！

#define MUL(a, b) (a) * (b)
int r = 10 + MUL(2, 3);   // 10 + 2 * 3 = 16；想 (10+2)*3 必须整体也包一层
```

**一步步算**（第一个错例）：预处理只是文本替换，把 `SQUARE_BAD(1 + 2)` 中的 x 换成 `1 + 2`，得到 `1 + 2 * 1 + 2`；按优先级先算乘法：1 + 2 + 2 = 5。参数包上括号后展开是 `(1 + 2) * (1 + 2)` = 9，正确。第二个错例同理：整体不加括号，宏就"接不住"外层的 + 号。

**嵌入式经典宏（必背）**：

```c
#define SET_BIT(reg, bit)      ((reg) |=  (1u << (bit)))   // 置位
#define CLR_BIT(reg, bit)      ((reg) &= ~(1u << (bit)))   // 清零
#define TGL_BIT(reg, bit)      ((reg) ^=  (1u << (bit)))   // 翻转
#define GET_BIT(reg, bit)      (((reg) >> (bit)) & 1u)     // 读某位
#define ARRAY_SIZE(a)          (sizeof(a) / sizeof((a)[0])) // 数组元素个数（库源码标配）
#define ABS(x)                 ((x) > 0 ? (x) : -(x))
```

### 多行宏与 do{}while(0)（库源码常见）

```c
#define LED_TOGGLE()              \
    do {                          \
        GPIOA->ODR ^= (1u << 5);  \
        delay_us(10);             \
    } while (0)
```
为什么套 `do { } while(0)`：让宏在任何 if/else 分支中都表现为"一条语句"，且 `if (x) LED_TOGGLE(); else ...` 不会语法错误。
白话拆解：如果宏体直接写两条语句，展开后 `if (x) 语句1; 语句2; else ...`——语句2 游离在 if 之外，else 就找不到配对的 if，编译报错。套上 `do { ... } while(0)` 后整体算一条语句（do-while 是一条语句），加分号也合法，不加也不多余——这是库源码里多行宏的标准外壳。

### 宏 vs 函数

| | 宏 | 函数 |
|---|----|------|
| 展开 | 预处理文本替换 | 运行时调用 |
| 开销 | 无调用开销，但代码膨胀 | 有栈帧开销 |
| 类型 | 无类型检查 | 有类型检查 |
| 适合 | 短小、位操作、常量 | 逻辑复杂、需调试 |

## 4. 条件编译（嵌入式裁剪利器）

**这是什么**：让一部分代码"有条件地存在"——定义了某个宏才编译它，否则当它不存在（连目标文件里都不会有）。类比手机出厂设置：同一套系统代码，根据机型开关 NFC、红外等功能模块。嵌入式里一份代码适配多块板子全靠它。

**这段代码要做什么**：演示头文件守卫（防重复包含）、调试宏开关、预定义宏三个惯用法。

```c
// 头文件守卫
#ifndef __BSP_LED_H
#define __BSP_LED_H
/* ... */
#endif

// 平台/功能裁剪
#define DEBUG_EN   1

#if DEBUG_EN
    #define DBG(fmt, ...)  printf("[DBG]" fmt "\r\n", ##__VA_ARGS__)
#else
    #define DBG(fmt, ...)              // 发布版直接空宏，零开销
#endif

// 调试信息直接带文件行号
#define TRACE()  printf("%s:%d\n", __FILE__, __LINE__)   // 预定义宏
```

> 嵌入式里一份代码适配多块板子、开关某模块（`#define USE_WIFI`），全靠条件编译；正点原子例程头部的 `#define` 配置区就是这个玩法。

> 头文件守卫原理一句话：第一次 include 时 `__BSP_LED_H` 还没定义 → 定义它、展开内容；第二次 include（往往是多个文件互相 include 导致同一头文件被包含多次）时宏已存在 → 整个文件内容被跳过。没有守卫，重复定义的编译错误会成灾。

## 5. static 专题（三种用法）

**这是什么**：static 一词三用，共同思想是"**收窄**"：修饰局部变量，把"随函数生灭"收窄成"活到程序结束"；修饰全局变量和函数，把"全工程可见"收窄成"本文件可见"。类比：员工卡（全局）换成部门内卡（static）——工位还在（内存还在），但别的部门刷不进你的门了。

**这段代码要做什么**：依次演示 static 修饰局部变量、全局变量、函数三种写法。

```c
// ① 修饰局部变量：改变生命周期（栈 → 数据段），只初始化一次
void counter(void)
{
    static int cnt = 0;     // 函数返回后值保留
    cnt++;
    printf("%d\n", cnt);
}

// ② 修饰全局变量：作用域限制在本 .c 文件内（内部链接）
static int g_private = 0;    // 其他 .c 看不见，防命名冲突

// ③ 修饰函数：函数仅本 .c 可见
static void helper(void) { }
```

| 用法 | 改变 | 不改变 |
|------|------|--------|
| static 局部变量 | 生命周期 → 程序全程；位置 → 数据段 | 作用域仍是本代码块 |
| static 全局变量/函数 | 作用域 → 本文件 | 生命周期、存储位置 |

> 嵌入式实践：每个模块的内部函数/变量都加 static，只把对外 API 暴露在头文件里——模块化的基石。
> 通俗理解：把模块想成一台自动售货机——按键面板（头文件里的 API）人人可用；内部货道、找零机构（static 函数/变量）藏在外壳里，外人碰不到，坏了也只影响这一台。

## 6. const 专题

**这是什么**：const = "只读封条"。贴上封条的东西编译器帮你看着，谁试图改就报错。它不是"放哪"的关键字，但嵌入式里 const 全局数据会被链接器放进 Flash——既有"数据"又能省 RAM，一举两得。

**这段代码要做什么**：演示 const 修饰普通变量、指针三种形态、函数参数、以及嵌入式查表。

```c
const int  a = 10;          // 常量变量（不通过 a 修改；指针可强转但别这么干）
const int *p1;              // 指向常量的 int（*p1 不可改）
int * const p2 = &x;        // 指针本身是常量（p2 不可改）
const int * const p3 = &x;  // 都不可改

// 函数参数：承诺不修改调用者的数据（库函数全是这么写的）
size_t my_strlen(const char *s);

// 嵌入式：查表放 Flash
const uint8_t seg7_code[10] = {0x3F, 0x06, 0x5B, ...};   // 数码管字库
```

`#define` vs `const`：const 有类型、可调试、有作用域 → **能用 const 就用 const**，宏只留给"必须文本替换"的场景（数组长度、条件编译开关）。

## 7. volatile 专题（嵌入式灵魂关键字）

**这是什么**：volatile 告诉编译器："这个变量的值**会瞒着你变**——可能被硬件、中断服务程序、别的任务改掉。你每次用到它，都必须老老实实去内存里现读，不许自作聪明用上次缓存的值。" 类比：普通变量像你抄在便签上的股价（编译器以为不会变，一直用便签值）；volatile 变量像行情软件上的实时价（每次都刷新看最新的）。编译器的"优化"有时会坏事——它看到你连续读一个变量，就自作主张只读一次， volatile 就是禁止这种自作主张。

**含义：告诉编译器"这个变量随时可能被程序之外的力量改变"，禁止优化，每次都老老实实读写内存。**

没有 volatile 会发生什么：

**这段代码要做什么**：演示一个"等待硬件就绪"的轮询循环，被编译器优化后卡死。

```c
uint32_t *reg = (uint32_t *)0x40010800;

// 等待寄存器标志位（无 volatile 时）：
while (*reg & FLAG_READY) { }     // 编译器发现循环体没改 *reg，
                                  // 直接优化成 if (*reg & FLAG_READY) while(1);
                                  // → 死循环卡死！
```

**三大必用场景**：
1. **硬件寄存器**：`*(volatile uint32_t *)0x40010800`；
2. **中断与主程序共享的变量**：

```c
volatile uint8_t rx_done = 0;

void USART1_IRQHandler(void)      // 中断里置位
{
    rx_done = 1;
}

int main(void)
{
    while (!rx_done) { }          // 主循环等待：无 volatile 会被优化成死循环
    /* 处理数据 */
}
```

3. **多任务（RTOS）共享的标志变量**。

第 2 个场景运行逻辑拆解（中断模拟程序，练习清单第 3 题配套）：
- `rx_done` 平时由主循环读、由中断写——中断发生的时机主循环完全无法预知；
- 编译器看 `while (!rx_done)` 的循环体没人改 rx_done，开了 -O2 优化后把它当成"死条件"，只读一次内存：若第一次读到 0，循环体又没有别的退出路径 → 永远转圈，中断里改成 1 它也"看不见"；
- 加 volatile 后，每次判断都强制重新从内存读，中断改的值立刻可见，循环正常退出。

> 面试标准答案：volatile 保证**可见性**（每次都从内存读），但**不保证原子性**——多字节变量被中断/任务并发读写仍需关中断或加临界区。
> 原子性白话：一个操作"要么整个完成、要么整个没发生"，中间不会被打断。`uint32_t` 在 8 位机上要分 4 次搬运，中断可能正好插在两次搬运之间——读到的数一半新一半旧。可见性管"看没看到"，原子性管"看的是不是完整的一幕"，两码事。

const 和 volatile 连用合法：`const volatile uint32_t *p`（只读但会变——典型如只读状态寄存器）。

## 8. extern 与头文件配合

**这是什么**：C 里"定义"和"声明"是两回事：**定义 = 真的分配一块内存造出这个变量**；**声明 = 只告诉编译器"它在别的文件里，你放心用"**。extern 就是声明的标志。类比：定义是"在自家公司注册了一家分店"，声明是"挂出一张指路牌'分店在隔壁楼'"——指路牌可以挂很多张，分店只能有一家。

**这段代码要做什么**：在 .c 里定义全局变量，在 .h 里用 extern 声明，让其他文件也能用。

```c
// bsp_uart.c
volatile uint32_t g_ticks = 0;      // 定义（分配内存）

// bsp_uart.h
extern volatile uint32_t g_ticks;   // 声明（告诉别人存在，不分配内存）
```
规则：**头文件只声明，定义放唯一的 .c**；绝不 `extern` 头文件里同时赋值。
为什么：头文件会被多个 .c 包含，若在头文件里赋值定义，每个包含它的 .c 都会"造一家分店"，链接时报重复定义错误。

## 9. 关键字连问（模拟面试）

1. static 局部变量初始化几次？什么时候初始化？（一次，编译期）
2. const 全局变量放在哪个区？（只读数据段/Flash）
3. volatile 能否保证线程安全？（不能，只保证可见性不保证原子性）
4. 中断里能调用 printf/malloc 吗？（原则：不能——不可重入、耗时、可能重入死锁）
5. 一个指针可以是 volatile 吗？（可以，如中断里修改缓冲区指针）

> 第 4 题的"不可重入"白话：printf 内部用全局缓冲区、malloc/free 操作全局的堆管理数据，若主循环调用到一半被中断打断、中断里又进入同一函数，内部状态就被搅乱——这种"自己还没执行完又被再次进入"的函数叫不可重入函数。且它们耗时不确定，中断处理讲究短平快，所以原则上一律不调。
