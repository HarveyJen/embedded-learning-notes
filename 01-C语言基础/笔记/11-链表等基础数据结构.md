# 11 · 链表等基础数据结构

> 嵌入式离不开链表：FreeRTOS 任务就绪列表、Linux 内核 list_head、协议缓冲队列全是链表。
> 目标：**单链表增删改查 + 反转**手写熟练，理解"内核链表"思想即可。

**这一篇讲什么**：数组是一排连号储物柜（位置固定、数量固定），**链表**则是"寻宝游戏"——每个节点（宝箱）里装着数据和"下一个宝箱在哪"的线索（指针），宝箱散落在内存各处，顺着线索就能走完全程。它牺牲了"报编号直达"的能力，换来"随时插队、随时退场、想伸多长伸多长"的灵活性。

## 1. 为什么数组不够用，要链表

**这是什么**：先想清楚数组的两个痛点：**中间插队要整体搬家**（插入位置后面的元素全部后移）、**容量说死就死**（编译期定死大小）。链表用"指针串珍珠"的方式解决了这两个问题。

| | 数组 | 链表 |
|---|------|------|
| 内存 | 连续 | 分散（节点 + 指针连接） |
| 随机访问 | O(1) 下标直达 | O(n) 顺藤摸瓜 |
| 插入/删除 | O(n) 整体搬移 | O(1) 改指针（找到位置的前提下） |
| 大小 | 编译期固定 / realloc | 运行时按需生长 |

数据量大、频繁增删（任务队列、日志缓冲）→ 链表。

## 2. 单链表定义

**这是什么**：单链表的每个节点是一个结构体，装两样东西：**数据域**（业务数据）和**指针域**（下一个节点的地址）。整条链表的入口是一个叫 head 的指针。类比火车：每节车厢（节点）装货（数据），车厢间的挂钩（next 指针）连成列车，head 是"找到车头的凭证"。

**这段代码要做什么**：定义链表节点类型——注意自引用指针的写法。

```c
#include <stdio.h>
#include <stdlib.h>

typedef int ElemType;

typedef struct Node {
    ElemType         data;     // 数据域
    struct Node     *next;     // 指针域：指向下一个节点
} Node;
```

内存示意（`head -> A -> B -> C -> NULL`）：

```
head ──> [data|next] ──> [data|next] ──> [data|next] ──> NULL
          data=1          data=2          data=3
```

两种风格：
- **带头节点（哨兵）**：head 是不存数据的空节点 → 插入删除不用特判第一个，推荐；
- 不带头节点：head 指向第一个数据节点，首插/首删要改 head，容易出错。

> 哨兵为什么省事：没有哨兵时，"在第一个位置插入"要先改 head，"删除第一个"也要改 head——和其他位置的操作逻辑不同，得写两个分支，新手必错。有了哨兵，第一个数据节点的前驱永远是哨兵，所有位置的插入删除统一成一套逻辑。类比：酒店给每层都安排一个"0 号房"当楼道入口，进任何房间都走同样的路。

## 3. 基本操作（带头节点版，完整可运行）

```c
/* 创建空链表（带头节点） */
Node *list_create(void)
{
    Node *head = (Node *)malloc(sizeof(Node));
    if (head == NULL) return NULL;
    head->data = 0;
    head->next = NULL;
    return head;
}

/* 头插：新节点插到头节点后，O(1)，顺序会倒 */
int list_push_front(Node *head, ElemType x)
{
    Node *node = (Node *)malloc(sizeof(Node));
    if (node == NULL) return -1;
    node->data = x;
    node->next = head->next;      // ① 新节点先接上原来的第一个
    head->next = node;            // ② 头节点再指向新节点
    return 0;                     // 顺序不能反，反了丢链！
}

/* 尾插：保持输入顺序 */
int list_push_back(Node *head, ElemType x)
{
    Node *node = (Node *)malloc(sizeof(Node));
    if (node == NULL) return -1;
    node->data = x;
    node->next = NULL;

    Node *cur = head;
    while (cur->next != NULL)     // 走到最后一个节点
        cur = cur->next;
    cur->next = node;
    return 0;
}

/* 遍历打印 */
void list_print(const Node *head)
{
    for (const Node *cur = head->next; cur != NULL; cur = cur->next)
        printf("%d -> ", cur->data);
    printf("NULL\n");
}

/* 按值查找：返回节点指针，找不到返回 NULL */
Node *list_find(Node *head, ElemType x)
{
    for (Node *cur = head->next; cur != NULL; cur = cur->next)
        if (cur->data == x) return cur;
    return NULL;
}

/* 删除第一个值为 x 的节点：需要"前驱"指针 */
int list_remove(Node *head, ElemType x)
{
    Node *prev = head;
    while (prev->next != NULL) {
        if (prev->next->data == x) {
            Node *victim = prev->next;
            prev->next = victim->next;    // 跨过 victim
            free(victim);                 // 先改链再释放
            return 0;
        }
        prev = prev->next;
    }
    return -1;                            // 没找到
}

/* 按位置插入：在第 pos 个数据节点前插入（pos 从 1 开始） */
int list_insert(Node *head, int pos, ElemType x)
{
    Node *prev = head;
    for (int i = 1; i < pos && prev != NULL; i++) prev = prev->next;
    if (prev == NULL) return -1;

    Node *node = (Node *)malloc(sizeof(Node));
    if (node == NULL) return -1;
    node->data = x;
    node->next = prev->next;
    prev->next = node;
    return 0;
}

/* 销毁：逐个 free，防止内存泄漏 */
void list_destroy(Node *head)
{
    Node *cur = head->next;
    while (cur != NULL) {
        Node *next = cur->next;      // 先记住下一个
        free(cur);                   // 再删当前
        cur = next;
    }
    free(head);
    return;
}

/* 反转（笔试高频）：迭代三指针 */
void list_reverse(Node *head)
{
    Node *prev = NULL;
    Node *cur  = head->next;
    while (cur != NULL) {
        Node *next = cur->next;      // 保存后继
        cur->next  = prev;           // 反向指
        prev       = cur;
        cur        = next;
    }
    head->next = prev;               // 头节点接上新的第一个
}

/* 测试 */
int main(void)
{
    Node *list = list_create();
    for (int i = 1; i <= 5; i++) list_push_back(list, i * 10);
    list_print(list);                // 10 -> 20 -> 30 -> 40 -> 50 -> NULL

    list_reverse(list);
    list_print(list);                // 50 -> 40 -> 30 -> 20 -> 10 -> NULL

    list_remove(list, 30);
    list_print(list);

    list_destroy(list);
    return 0;
}
```

**单链表操作三铁律**：
1. 插入：**先接后断**（新节点先指向后继，前驱再指向新节点）；
2. 删除：**先跨过，再 free**；
3. 遍历删除：**先存 next，再 free**。

> 三铁律的共同思想：**指针是节点唯一的生命线**。free 一个节点前，必须确保还有别的指针指着它的后继（否则后半条链就永远找不回来了）；改链时新线必须先接好，才能拆旧线。顺序一反，"丢链"，后半段节点全部失联且无法 free（内存泄漏）。

**头插函数逻辑重点拆解**（初学最容易翻车的两行）：
```
node->next = head->next;   // ① 新车厢先挂上原来第一节车厢
head->next = node;         // ② 车头再挂钩新车厢
```
若反过来先执行②，`head->next` 被覆盖，原第一节的"地址"就丢了——后半列车失联。这就是"先接后断"。

**list_insert 定位循环说明**：`for (int i = 1; i < pos && prev != NULL; i++) prev = prev->next;` 从哨兵 head 出发走 pos-1 步，正好落在"第 pos 个数据节点的前驱"上——i 从 1 起，是为了 pos=1 时循环一次都不执行、prev 停在哨兵（即插在第一个数据节点之前）。

## 4. 链表经典笔试题

**这是什么**：链表是笔试出题率最高的数据结构，下面 5 题覆盖了 90% 的考法。核心工具是**快慢指针**——两个指针从同一起点出发，速度不同或出发时间不同，利用"路程差"制造位置差。类比操场跑圈：跑得快的人迟早"套圈"追上慢的（判环）；两人同时起跑、快者步长加倍，快者到终点时慢者恰好在半程（找中点）。

1. 反转单链表（上面迭代版；递归版也写一遍）；
2. 找中间节点：**快慢指针**，fast 一次走 2 步，slow 一次 1 步，fast 到尾则 slow 在中间；
3. 找倒数第 k 个：fast 先走 k 步，然后两个一起走到尾；
4. 判断环：快慢指针相遇即有环（Floyd 判圈）；
5. 合并两个有序链表：双指针逐个摘取。

```c
/* 快慢指针找中间节点示例 */
Node *mid_node(Node *head)
{
    Node *slow = head->next, *fast = head->next;
    while (fast != NULL && fast->next != NULL) {
        slow = slow->next;
        fast = fast->next->next;
    }
    return slow;
}
```

## 5. 双向链表（了解 + 会用思想）

**这是什么**：每个节点多一个 `prev` 指针，既知道"下一个是谁"也知道"上一个是"。类比：单链表是只进不退的单行道，双向链表是双行道——走过头能倒回来，但每节车厢多装一个"路标"、过岔口要多操作一次。

```c
typedef struct DNode {
    ElemType        data;
    struct DNode   *prev;     // 指向前驱
    struct DNode   *next;     // 指向后继
} DNode;
```
- 插入删除不用找前驱（直接拿到 prev），代价是每节点多一个指针、操作多一步；
- FreeRTOS 队列项、Linux 链表都是双向循环链表。

## 6. 内核链表思想（嵌入式进阶，开阔思路）

**这是什么**：前面实现的链表把数据"装"在节点里，数据类型一换就得重写一套链表。Linux 内核反过来想：**链表节点只做"纯挂钩"（只有 prev/next），挂到任何业务结构体里面去**。一套链表代码，服务所有数据类型。

Linux 内核的做法：把**指针域做成独立小结构**，嵌入到任何数据里：

```c
struct list_head {                 // 内核/RTOS 通用链表节点
    struct list_head *prev, *next;
};

struct my_task {                   // 业务结构体内嵌链表节点
    int priority;
    struct list_head list;         // 通过它挂到链表上
};

/* 遍历时用 container_of 从 list 成员地址反推 my_task 首地址 */
#define container_of(ptr, type, member) \
    ((type *)((char *)(ptr) - (unsigned long)&((type *)0)->member))
```
好处：**一套链表代码服务所有数据类型**（不是把数据塞进链表，而是把链表塞进数据）。
container_of 的原理一句话：**成员地址减去成员在结构体里的偏移 = 结构体首地址**——知道某个房间在楼里偏移多少，就能反推出整栋楼的大门牌号。
现在只需看懂思想，FreeRTOS 阶段会在 `list.c` 里再见到它。

## 7. 其他常用结构速览

**这是什么**：除链表外还有两个必须认识的"兄弟"——栈和队列。它们不是新存储方式，而是"规定只从哪个口进出"的链表/数组。嵌入式里栈用于函数调用和表达式处理；**环形缓冲区队列是串口收发的行业标准方案**，必须会写。

- **栈**：后进先出，数组 + 栈顶下标即可实现；函数调用、表达式求值、括号匹配；
  - 后进先出白话：像食堂摞盘子——洗好的盘子摞上去，取的时候拿最上面的（最后放的最先取）。笔记04 讲的"函数调用栈"就是这么回事；
- **队列**：先进先出，环形缓冲区（head/tail 下标循环推进）——**串口收发的标准方案**，RTOS 阶段必备：

```c
#define QSIZE 64
typedef struct {
    uint8_t buf[QSIZE];
    volatile uint8_t head, tail;    // 中断写 head，主循环读 tail
} RingBuf;

int rb_push(RingBuf *q, uint8_t b)
{
    uint8_t next = (uint8_t)((q->head + 1) % QSIZE);
    if (next == q->tail) return -1;         // 满
    q->buf[q->head] = b;
    q->head = next;
    return 0;
}

int rb_pop(RingBuf *q, uint8_t *b)
{
    if (q->tail == q->head) return -1;      // 空
    *b = q->buf[q->tail];
    q->tail = (uint8_t)((q->tail + 1) % QSIZE);
    return 0;
}
```

为什么"满"的判断是 `next == tail`：队列故意留一个格子不存数据——若不留，head 追平 tail 时既可能是"满"也可能是"空"，两种状态无法区分；牺牲 1 格换来判断简单，这是环形缓冲区的经典设计。
