# 12 · 文件操作与配置解析

> 路线阶段一"补充项"的落地篇：程序一旦退出，内存里的一切就蒸发——文件是把数据**留下来的唯一手段**。
> 本篇技能直接服务于：PC 上位机工具写配置、产测日志分析、升级文件解析；也是 [11-嵌入式Linux](../../11-嵌入式Linux/笔记/00-目录与学习路线.md) 文件 IO 和 FatFS（单片机文件系统，规划于 [14-进阶专题](../../14-进阶专题/笔记/00-目录与学习路线.md)）的直系前置。

**这一篇讲什么**：到目前为止你写的所有程序，数据都住在**内存**里——变量、数组、链表，全是"断电即失、程序一退就没"的临时数据。想让数据**活得比程序久**（保存设置、记录日志、读出上次的进度），就必须写到**磁盘文件**里。类比：内存是**黑板**，写得快但一擦就没；文件是**笔记本**，合上之后下次翻开还在。学完本篇，你的程序就具备了"记忆"。

## 1. 文件的本质：流（stream）

**这是什么**：C 语言不让你直接"摸"磁盘，而是给你一根**水管**——数据从程序这头流进去/流出来。这根水管的"阀门句柄"就是 `FILE *`。类比：`FILE*` 是水管上的阀门把手，开阀（fopen）→ 放水（读写）→ 关阀（fclose），三步缺一不可。

| 概念 | 大白话 | 类比 |
|------|--------|------|
| 流 stream | 数据进出的通道 | 水管 |
| `FILE *` | 管住这条流的句柄 | 阀门把手 |
| 缓冲区 | 攒一批再流，减少开关次数 | 水塔（攒够一桶冲一次） |
| EOF | 文件结束标志（End Of File） | 水管尽头 |

其实你早就在用流了：`printf` = 往**标准输出流** `stdout` 写；`scanf` = 从**标准输入流** `stdin` 读。文件操作只是把"标准水管"换成"你自己 fopen 出来的水管"，用法一脉相承。

## 2. 打开与关闭：fopen / fclose

**这是什么**：一切文件操作的第一步。`fopen(路径, 模式)` 返回 `FILE*`；**返回 NULL 表示失败**（路径不存在、没权限），必须判空再用——这是本篇第一条纪律。

| 模式 | 含义 | 文件不存在时 | 原有内容 |
|------|------|--------------|----------|
| `"r"` | 只读 | fopen 返回 NULL | 保留 |
| `"w"` | 只写 | 自动新建 | **清空！** |
| `"a"` | 追加 | 自动新建 | 保留，写在其后 |
| `"rb"` / `"wb"` / `"ab"` | 二进制的读/写/追加 | 同上 | 同上 |
| `"r+"` `"w+"` `"a+"` | 可读可写变体 | 见手册 | 见手册 |

记忆口诀：**r 是"读"，w 是"毁"（清空重来），a 是"续"（接着写）**。最常见事故就是想追加日志却开了 `"w"`——每次运行日志都被清空。

**这段代码要做什么**：安全地打开一个文件，失败时打印原因并退出，而不是拿 NULL 硬用导致崩溃。

```c
#include <stdio.h>

int main(void)
{
    FILE *fp = fopen("config.txt", "r");   /* 只读打开 */
    if (fp == NULL) {                       /* 纪律：判空！ */
        perror("打开 config.txt 失败");      /* perror 会附带打印系统错误原因 */
        return 1;                           /* 非零返回值 = 程序异常退出 */
    }
    /* ... 读写操作写在这里 ... */
    fclose(fp);                             /* 用完必须关：冲掉缓冲区 + 释放资源 */
    return 0;
}
```

运行逻辑逐段拆解：
- `fopen("config.txt", "r")`：按"只读"模式开阀，拿到阀门把手 fp；
- `if (fp == NULL)`：文件可能根本不存在（比如没放到程序同级目录），不开判空就是给野地址解引用——直接崩溃，和指针篇的野指针是同一个坑；
- `perror(...)`：把"为什么失败"（如 No such file or directory）人话打印出来，排错第一助手；
- `fclose(fp)`：关阀。**不关的后果**：缓冲区里没写完的数据可能根本没落到磁盘（文件是空的/缺尾部），且文件句柄泄漏。

两个新手必踩的路径坑：① Windows 代码里写路径 `\` 要转义成 `\\`（`"D:\\data\\a.txt"`），或直接用 `/`；② "当前工作目录"不一定是 .c 文件所在目录（IDE 可设置），找不到文件先 `perror` 看原因。

## 3. 文本读写三板斧

**这是什么**：文本文件（人能直接看懂的字符文件）的读写按"颗粒度"分三档，从细到粗：

| 函数 | 颗粒度 | 典型场景 |
|------|--------|----------|
| `fgetc` / `fputc` | 一个字符 | 逐字符扫描、统计 |
| `fgets` / `fputs` | 一行 | **逐行读配置、读日志（最常用）** |
| `fprintf` / `fscanf` | 格式化 | 按格式写/读（类似 printf/scanf） |

`fgets` 是本篇主角，重点讲透：

**这段代码要做什么**：逐行读取文本文件并打印行号——读日志、读配置的标准姿势。

```c
#include <stdio.h>

int main(void)
{
    FILE *fp = fopen("log.txt", "r");
    if (fp == NULL) { perror("打开失败"); return 1; }

    char line[256];             /* 行缓冲区：一行最多 255 字符 + 结尾 '\0' */
    int lineno = 0;
    while (fgets(line, sizeof(line), fp) != NULL) {   /* 每次读一行 */
        lineno++;
        printf("%3d| %s", lineno, line);   /* line 自带换行符，不用再加 \n */
    }
    fclose(fp);
    return 0;
}
```

运行逻辑逐段拆解：
- `fgets(line, sizeof(line), fp)`：从 fp 读**最多 sizeof(line)-1 个字符**（留 1 个位置给 `'\0'`），遇到换行符或文件尾就停。**第二个参数是安全带**——就算某行超长也只会读满缓冲区，绝不溢出。对比 `gets()` 无安全带（已从 C 标准除名，见到就绕道）；
- 返回值：读到内容返回 line，文件读完返回 NULL——所以 `while (... != NULL)` 就是"读完整份文件"的固定写法；
- `line` 里**自带行尾的 `'\n'`**，所以 printf 里不再加 `\n`；如果要去掉（比如拼字符串），`line[strcspn(line, "\n")] = '\0';` 一行搞定。

## 4. 实战一：解析配置文件（key = value）

**这是什么**：上位机工具、产测程序几乎都靠配置文件工作——改波特率不用改代码重新编译，改配置文件就行。格式约定：一行一条 `键 = 值`，`#` 开头是注释。类比：配置文件是**食堂菜单**，程序开工前先照单点菜——菜单换了菜就换了，厨房（程序本身）不动。

测试文件 `config.txt`（放到程序运行目录）：

```
# 设备配置
device_name = line-tester
baudrate = 115200
debug = 1
```

**这段代码要做什么**：逐行读入，拆出键和值，把关心的三项填进配置结构体，最后打印确认——这就是一个迷你配置解析器。

```c
#include <stdio.h>
#include <stdlib.h>   /* atoi：字符串转 int */
#include <string.h>

typedef struct {
    char device_name[32];
    int  baudrate;
    int  debug;         /* 1 开 0 关 */
} Config;

int main(void)
{
    Config cfg = { "", 9600, 0 };            /* 默认值兜底：文件缺失也能跑 */
    FILE *fp = fopen("config.txt", "r");
    if (fp == NULL) { perror("无配置文件，使用默认配置"); }
    else {
        char line[128], key[32], val[80];
        while (fgets(line, sizeof(line), fp) != NULL) {
            if (line[0] == '#' || line[0] == '\n') continue;   /* 跳过注释和空行 */
            /* %31s 读到空白为止装进 key；字面 ' = ' 吃掉等号；%79s 装 val */
            if (sscanf(line, "%31s = %79s", key, val) != 2) continue;
            if      (strcmp(key, "device_name") == 0) strcpy(cfg.device_name, val);
            else if (strcmp(key, "baudrate") == 0)    cfg.baudrate = atoi(val);
            else if (strcmp(key, "debug") == 0)       cfg.debug    = atoi(val);
        }
        fclose(fp);
    }
    printf("device=%s baud=%d debug=%d\n", cfg.device_name, cfg.baudrate, cfg.debug);
    return 0;
}
```

运行逻辑逐段拆解：
- `Config cfg = { "", 9600, 0 }`：先给默认值。工程习惯——**配置文件只是"覆盖默认值"**，缺了哪项就退回默认，程序永不因缺配置而瘫；
- `line[0] == '#'`：注释行直接跳过；`sscanf(...) != 2`：没拆出"键+值"两个东西的行（乱行）也跳过——解析器要**皮实**，遇到脏行跳过而不是崩溃；
- `sscanf(line, "%31s = %79s", key, val)`：`%31s` 最多读 31 个字符进 key（防溢出，和 fgets 的安全带同理）；中间的 `' = '` 用来跳过等号两边的空格；返回值 2 = 成功拆出两项；
- `atoi(val)`：ASCII to integer，字符串 "115200" 变数字 115200（更严谨用 `strtol`，可查错误）；
- 局限声明：`%s` 遇空格就停，所以**值里不能带空格**。要支持带空格的值，用 `strchr(line, '=')` 找到等号后手动截取——留作实操任务。

预期输出：`device=line-tester baud=115200 debug=1`

## 5. 实战二：日志解析（统计与提取）

**这是什么**：产测设备、服务器都吐文本日志；"从几百行日志里数出有几个 ERROR、把温度曲线抠出来"是最常见的自动化小工具。类比：日志是大海，`strstr` 是**渔网**——撒在"关键字"处一捞一个准。

测试文件 `log.txt`：

```
[10:02:11] INFO: start test
[10:02:12] ERROR: ch3 open circuit
[10:02:15] DATA: temp=25.6
[10:02:18] ERROR: ch7 short
[10:02:21] DATA: temp=26.1
```

**这段代码要做什么**：统计 ERROR 出现次数，并把所有 temp= 后面的数字提取出来。

```c
#include <stdio.h>
#include <string.h>

int main(void)
{
    FILE *fp = fopen("log.txt", "r");
    if (fp == NULL) { perror("打开失败"); return 1; }

    char line[256];
    int err_cnt = 0;
    double temp;
    while (fgets(line, sizeof(line), fp) != NULL) {
        if (strstr(line, "ERROR") != NULL)   /* strstr：找子串，返回位置指针，找不到返回 NULL */
            err_cnt++;
        char *p = strstr(line, "temp=");
        if (p != NULL && sscanf(p, "temp=%lf", &temp) == 1)
            printf("读到温度 %.1f\n", temp);  /* 后续可存数组画曲线 */
    }
    printf("ERROR 共 %d 条\n", err_cnt);
    fclose(fp);
    return 0;
}
```

运行逻辑逐段拆解：
- `strstr(line, "ERROR")`：在整行里找"ERROR"这个子串——**比逐字符比对省事得多**，是文本检索第一工具；
- `strstr(line, "temp=")` 找到后返回**指向 "t" 的指针** p；`sscanf(p, ...)` 就地从 p 开始解析（而不是行首）——这个"找到再就地解析"的两段式是日志提取万能模板；
- `%lf` 对应 double（printf 里打 double 用 %f，sscanf 读用 %lf，别混）。

预期输出：`读到温度 25.6` / `读到温度 26.1` / `ERROR 共 2 条`

## 6. 二进制读写：fwrite / fread（嵌入式重点）

**这是什么**：文本文件是"给人看的"（记事本打开能读），**二进制文件是"给程序看的"**（内存里什么样，盘上就什么样）。两类对比：

| | 文本模式 | 二进制模式 |
|---|----------|-----------|
| 存数字 25.6 | '2''5'.'6' 三个字符 | 4 字节 float 原样 |
| 体积 | 大（有格式开销） | 小 |
| 人能看懂 | 能 | 不能（乱码） |
| 速度/步骤 | 要转换 | 直拷贝 |
| 嵌入式对应 | 配置、日志 | **记录仪数据、固件文件、Flash 镜像** |

**这段代码要做什么**：把"采样记录数组"整体写入文件，再整体读回来验证——这就是数据记录仪的雏形，也是单片机上 FatFS / Flash 记录的 C 语言预演。

```c
#include <stdio.h>
#include <stdint.h>

typedef struct {
    uint32_t tick;    /* 采样时刻 */
    float    temp;    /* 温度值 */
} Sample;

int main(void)
{
    Sample a[3] = { {1, 25.6f}, {2, 26.1f}, {3, 26.4f} };

    /* 写：三个 Sample 整块落盘 */
    FILE *fw = fopen("rec.bin", "wb");            /* wb = 二进制写 */
    if (fw == NULL) { perror("写打开失败"); return 1; }
    fwrite(a, sizeof(Sample), 3, fw);             /* 从 a 起，每次 12 字节，写 3 次 */
    fclose(fw);

    /* 读：整块读回并逐条验证 */
    Sample b[3];
    FILE *fr = fopen("rec.bin", "rb");
    if (fr == NULL) { perror("读打开失败"); return 1; }
    size_t n = fread(b, sizeof(Sample), 3, fr);   /* 返回实际读到的条数 */
    fclose(fr);

    printf("读到 %zu 条\n", n);
    for (size_t i = 0; i < n; i++)
        printf("tick=%u temp=%.1f\n", b[i].tick, b[i].temp);
    return 0;
}
```

运行逻辑逐段拆解：
- `fwrite(a, sizeof(Sample), 3, fw)`：四个参数读法——"从 a 地址开始，每次搬 sizeof(Sample)=8 字节（4+4），搬 3 次，搬往 fw"。**结构体数组整块直写**，无需逐字段转换，这就是二进制的爽点；
- `fread` 返回**实际读到的条数**：文件被截断时返回值会小于 3——用返回值判断完整性，别默认一定读够；
- `rec.bin` 用记事本打开是乱码，**这不是 bug**——二进制文件本来就不是给人看的；
- 埋个伏笔：直接把整个结构体写盘，在"同一台电脑读写"没问题；但文件拿到**另一平台**（大小端不同、对齐不同）可能读歪——工程上记录文件用定宽字段+约定端序（详见 [02 数据类型](02-数据类型-变量与常量.md) 大小端、[10-OTA 固件头](../../10-Bootloader与OTA/笔记/00-目录与学习路线.md) 的跨平台约定）。

配套小工具——**算文件大小**：

```c
fseek(fr, 0, SEEK_END);   /* 光标甩到文件末尾 */
long size = ftell(fr);    /* ftell = 当前光标距文件头的字节数 = 文件大小 */
rewind(fr);               /* 光标拉回头，继续正常读 */
```

类比：光标是书签，SEEK_END 是"直接翻到最后页"，ftell 报"你翻到第几字节"。

## 8. 常见坑清单

1. **fopen 不判 NULL**：路径错一个字 → NULL 解引用 → 崩溃。判空 + perror 是铁纪律；
2. **`"w"` 清空陷阱**：想追加日志开了 "w"，每次运行历史全没。追加用 `"a"`；
3. **文本/二进制混用**：二进制文件用文本函数读，或文本文件加 "b"——Windows 下 `\r\n` 处理不同会读出脏数据；
4. **fgets 读进 `'\n'`**：比较字符串前不去掉行尾换行，`strcmp("yes\n","yes")` 永远不等；
5. **写完不 fclose 就去看文件**：数据还在缓冲区没落盘，文件是空的——"我明明写了"九成是这个；
6. **fscanf 读数字后接 fgets**：数字后面的换行残留被 fgets 读成"空行"。统一策略：要么全 fscanf，要么 fgets + sscanf（本篇采用后者，更稳）；
7. **结构体直接写盘跨平台**：对齐、大小端会让同一文件在别的机器读歪——单机练习无妨，产品级要定端序（伏笔见第 6 节）；
8. **路径含中文/空格**：部分终端与工具链编码不一致导致打不开。练习阶段用英文路径最省心。

## 章节小结

- 程序要"记忆"就必须用文件；C 的文件操作 = fopen 开阀 → 读写 → fclose 关阀，**判 NULL 贯穿始终**；
- 文本三板斧：fgetc（字符）、**fgets（行，主力）**、fprintf/fscanf（格式化）；fgets 自带安全带，`while (fgets(...) != NULL)` 是通读全文的固定句式；
- 万能解析模板：**fgets 整行进缓冲区 → strstr 定位 → sscanf 就地拆解**，配置文件和日志解析全适用；
- 二进制：fwrite/fread 按字节直搬，结构体整块进出——数据记录、固件文件的底层形态；
- 缓冲区导致"写了但没落盘"，fclose 才是收尾动作。

## FAQ

**Q1：printf 不 fopen 也能输出，它走的哪个文件？**
标准流 `stdout`（显示器）。stdin/stdout/stderr 是程序启动时自动打开的三根水管，文件操作只是"自开水管"，原理相同。

**Q2：文件几百 MB，fgets 一行行读太慢怎么办？**
用 `fread` 分块读（如每次 4KB 到大缓冲区）再在内存里切行。原则不变：**分块、判返回值**，别试图一次 malloc 文件大小。

**Q3：单片机上也能 fopen 吗？**
FatFS 提供 `f_open/f_read/f_write/f_close`——命名和用法与 stdio 几乎镜像（多了挂载 mount 步骤），本篇的代码思想可整体平移，届时在 [14-进阶专题](../../14-进阶专题/笔记/00-目录与学习路线.md) 会展开。

**Q4：为什么 "w+" 能写能读，读之前要做什么？**
写完想读，光标停在文件尾——先 `fseek(fp, 0, SEEK_SET)`（或 rewind）把光标拨回头部，否则什么都读不到。光标位置意识是文件操作的隐藏主线。
