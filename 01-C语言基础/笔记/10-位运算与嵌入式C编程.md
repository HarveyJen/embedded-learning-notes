# 10 · 位运算与嵌入式 C 编程

> 嵌入式面试权重最高的一章：进制与位运算、寄存器操作、协议解析、函数指针回调、状态机。

**这一篇讲什么**：芯片内部的最小信息单位是"位"（一个 0 或 1），硬件控制、通信协议、校验算法全在"位"的层面打交道。**位运算就是直接对一个整数的各个二进制位做置 1、清 0、翻转、读取**。这一章学完，你就能看懂"点亮一个 LED 的那行神秘代码"，也能写出串口协议解析。

## 1. 进制速查（嵌入式只用二进制和十六进制）

**这是什么**：同一个数有多种写法。十进制给人看，**二进制**是芯片的真实工作方式（每一位对应一根信号线的高低电平），**十六进制**是二进制的"缩写"（1 个十六进制字符 = 4 位二进制，写起来短还不丢位信息）。类比：二进制像电路里的 8 个开关（开/关），十六进制像给每 4 个开关的组合起个单字代号，方便口头沟通。

| 十进制 | 二进制 | 十六进制 |
|--------|--------|----------|
| 0 | 0000 | 0x0 |
| 5 | 0101 | 0x5 |
| 10 | 1010 | 0xA |
| 15 | 1111 | 0xF |
| 255 | 1111 1111 | 0xFF |

- 二进制 ↔ 十六进制：**每 4 位一组**直接映射，`1011 0110` → `0xB6`；
- 嵌入式惯例：寄存器地址、掩码用 `0x`；一位对应一个引脚/一个标志。

## 2. 六大位运算符

**这是什么**：6 个直接对二进制位下手的运算符。每个运算符两边对齐，**一位一位独立地算**（不像加法有进位）——这是位运算和算术运算最本质的区别。

| 运算符 | 名称 | 规则 | 常见用途 |
|--------|------|------|----------|
| `&` | 按位与 | 有 0 则 0 | **清零、读位** |
| `|` | 按位或 | 有 1 则 1 | **置位** |
| `^` | 异或 | 不同为 1 | **翻转、加密、比较** |
| `~` | 按位取反 | 0↔1 | 配合 & 清零 |
| `<<` | 左移 | ×2ⁿ | 移到目标位 |
| `>>` | 右移 | ÷2ⁿ | 读位；无符号高位补0 |

用生活话记规则：`&` 是"一票否决"（任一方是 0，结果就是 0）；`|` 是"一票通过"（任一方是 1，结果就是 1）；`^` 是"不同才响铃"（两位相同得 0，不同得 1）。

**代入数字算一遍**（逐位对齐，无进位）：
```
  1010   (0xA)
& 0110   (0x6)      | 0110          ^ 0110
-------          -------        -------
  0010   → 2          1110 → 14       1100 → 12
```
`&`：逐位看，只有第 2 位两边都是 1 → 0010；`|`：凡是 1 都保留 → 1110；`^`：只有两边不同的位是 1 → 1100。

真值表演示（`0b1010 & 0b0110 = 0b0010`；`0b1010 | 0b0110 = 0b1110`；`0b1010 ^ 0b0110 = 0b1100`）。

**位移注意**：
- 左移右移**不改变原变量**：`a << 1` 结果只是表达式的值，要 `a = a << 1`；
- 负数右移、移动位数 ≥ 位宽是**未定义行为**；位宽常量写 `1u`；
  - `1u` 白话：数字 1 + u 后缀（unsigned）。不加 u 时 1 是有符号 int，`1u << 31` 这类操作在有符号数上可能踩"符号位"的未定义行为；写位运算一律 `1u` 是行业标准习惯；
- 有符号数右移依赖实现（一般补符号位），位运算只对**无符号类型**用。

## 3. 位操作四大基本操作（必背必默写）

**这是什么**：嵌入式每天用的"四则运算"——对一个寄存器/变量的**第 n 位**做：置 1、清 0、翻转、读取。全部围绕一个技巧：先用 `1u << n` 造出一个"只有第 n 位是 1"的**掩码（mask）**——掩码就像一张只挖了一个洞的卡片，贴在数据上，洞的位置露出来、其余全挡住。

```c
/* 对变量 v 的第 n 位（从 0 开始） */
v |=  (1u << n);          // 置 1
v &= ~(1u << n);          // 清 0
v ^=  (1u << n);          // 翻转
bit = (v >> n) & 1u;      // 读取

/* 批量操作：掩码 mask */
v |=  mask;               // 置 1 掩码指定的所有位
v &= ~mask;               // 清 0
v = (v & ~mask) | newval; // 修改某几位为新值（读-改-写，操作寄存器的标准三步）

/* 判断某位是否为 1 */
if (v & (1u << n)) { }
```

例：把 `0xAF` 的高 4 位改成 `0x5`：

```c
uint8_t v = 0xAF;
v = (v & 0x0F) | (0x5 << 4);    // 结果 0x5F
```

**一步步算**（"修改某几位"的实戾示范）：
1. 目标：把 `0xAF`（`1010 1111`）的**高 4 位**换成 0101，低 4 位保持不变；
2. `v & 0x0F`：0x0F 是低 4 位全 1 的掩码，与运算把高 4 位清掉 → `0000 1111`（低 4 位完好保留）；
3. `0x5 << 4`：把 0101 搬到高 4 位的位置 → `0101 0000`；
4. `|` 拼接：`0000 1111 | 0101 0000` = `0101 1111` = 0x5F。低 4 位原样、高 4 位换新——这就是"读-改-写"三步中的"改"。

## 4. 位运算技巧（笔试题）

**这是什么**：笔试最爱考的 7 个位运算小技巧。每个技巧背后的"位规律"比技巧本身更重要，理解一个规律，能自己推导一串技巧。

**这段代码要做什么**：演示异或交换、判奇偶、判 2 的幂、统计 1 的个数等经典技巧。

```c
// ① 交换两数（不用临时变量）：a ^= b; b ^= a; a ^= b;
// ② 判断奇偶：if (x & 1)  → 奇数
// ③ 乘除 2 的幂：x << n; x >> n
// ④ 判断是否 2 的幂：x && !(x & (x - 1))
//    原理：2^n 形如 1000...0，减 1 后 0111...1，与运算为 0
// ⑤ 统计二进制中 1 的个数：
int popcount(uint32_t x)
{
    int n = 0;
    while (x) { x &= (x - 1); n++; }   // 每次消掉最低位的 1
    return n;
}
// ⑥ 取最低位的 1：lowbit = x & (-x)
// ⑦ 掩码构造：低 n 位全 1：((1u << n) - 1)
```

两个最常被追问的原理，一步步算：
- **判断 2 的幂**：2 的幂的二进制形如 `1000...0`（1 后面全是 0）。减 1 后变成 `0111...1`。两者 `&` 必为 0。反之任何非 2 幂（如 6 = `110`）减 1（`101`）后与运算不为 0。例：8 = `1000`，7 = `0111`，`1000 & 0111` = 0 → 是 2 的幂；
- **异或交换为什么成立**：`^` 的规律是"x ^ x = 0、x ^ 0 = x"。设初始 a、b：第一步 `a ^= b` 后 a 存的是 a^b；第二步 `b ^= a` 即 b = b ^ (a^b) = a（b 变成了原来的 a）；第三步 `a ^= b` 即 a = (a^b) ^ a = b。全程无临时变量。

## 5. 寄存器操作实战（模拟 GPIO）

**这是什么**：把第 3 节的四件套用起来——用 PC 上的一个 uint8_t 变量"假装"是单片机的 GPIO 输出寄存器，模拟流水灯。变量 bit0~bit3 就当作 4 个 LED 引脚的电平。这可是阶段一最接近"真硬件"的练习。

**这段代码要做什么**：定义模拟寄存器和四个宏（点亮/熄灭/翻转/读状态），主函数演示点亮、翻转和流水灯。

```c
#include <stdint.h>
#include <stdio.h>

/* 模拟一个 8 位 GPIO 输出寄存器，bit0~bit3 接 LED0~3 */
uint8_t GPIO_ODR = 0x00;

#define LED_SET(n)        (GPIO_ODR |=  (1u << (n)))
#define LED_CLR(n)        (GPIO_ODR &= ~(1u << (n)))
#define LED_TOGGLE(n)     (GPIO_ODR ^=  (1u << (n)))
#define LED_GET(n)        (((GPIO_ODR) >> (n)) & 1u)

int main(void)
{
    LED_SET(0);                 // 点亮 LED0      0000 0001
    LED_SET(2);                 //               0000 0101
    LED_TOGGLE(0);              // 熄灭 LED0      0000 0100

    /* 流水灯：LED0 → LED3 */
    for (int i = 0; i < 4; i++) {
        GPIO_ODR = (uint8_t)(1u << i);      // 每次只亮一个
        printf("ODR=0x%02X\n", GPIO_ODR);
    }
    return 0;
}
```

真实 STM32 对照（看得懂 = 阶段一毕业）：

**这段代码要做什么**：展示真实 STM32 库里操作 GPIO 的三行代码——和上面模拟版思路一致，只是寄存器换成了真地址。

```c
GPIOA->BSRR = (1u << 5);          // 原子置位（Set 寄存器，无需读改写）
GPIOA->BSRR = (1u << (5 + 16));   // 原子清位（Reset 寄存器 = 高16位）
GPIOA->ODR ^= (1u << 5);          // 翻转 PA5
```

"原子置位"白话：`ODR |= (1u<<5)` 是"读→改→写"三步，若两步之间被中断插进来改了其他位，写回去就会把别人的修改覆盖掉。BSRR（置位/复位寄存器）专门设计成"写 1 生效、写 0 无影响"，一条写指令直接完成置位/清零，中间不会被打断——这就是"原子（不可分割）"的含义。

## 6. 多字节数据的拆分与组合（协议基础）

**这是什么**：串口一次只能发 1 个字节，可温度值是 16 位、地址是 32 位——发送前要**拆**成字节序列，接收后要**拼**回来。拆拼的方向（先发高字节还是低字节）就是笔记02讲的"字节序"。这一节是所有通信协议（串口帧、SPI 传输、网络包）的地基。

**这段代码要做什么**：把 32 位数按大端拆成 4 字节，再把 4 字节拼回 32 位，并处理"12 位 ADC 值跨字节"的特殊格式。

```c
#include <stdint.h>

/* 32 位数据按大端（网络序/多数协议）拆成 4 字节 */
uint8_t buf[4];
uint32_t v = 0x12345678;
buf[0] = (uint8_t)(v >> 24);      // 0x12 高字节在前
buf[1] = (uint8_t)(v >> 16);
buf[2] = (uint8_t)(v >> 8);
buf[3] = (uint8_t)(v);

/* 4 字节组回 32 位（大端） */
uint32_t u = ((uint32_t)buf[0] << 24) | ((uint32_t)buf[1] << 16)
           | ((uint32_t)buf[2] << 8)  |  (uint32_t)buf[3];

/* 12 位 ADC 值跨两个字节（低 8 位 + 高 4 位）的常见格式 */
uint16_t adc = (uint16_t)((buf[1] & 0x0F) << 8) | buf[0];   // 12位: 0~4095
```

**一步步算拆包**（v = 0x12345678）：
- `v >> 24`：整体右移 24 位，高 8 位 `0x12` 掉到最低位，buf[0] = 0x12；
- `v >> 16` 后取低 8 位（强转 uint8_t 自动截断）→ buf[1] = 0x34；
- 同理 buf[2] = 0x56，buf[3] = 0x78。大端 = 高字节在先。

**一步步算组包**（拆包的逆操作）：
- buf[0] = 0x12 左移 24 位回到最高 8 位 → 0x12000000；
- buf[1] = 0x34 左移 16 位 → 0x00340000；
- 依次 | 起来（各字节错位占位，互不干扰）→ 0x12345678。

**12 位 ADC 逐位拆解**：ADC 只产生 12 位（0~4095），协议把它拆进两个字节——buf[0] 装低 8 位，buf[1] 的低 4 位装高 4 位。重组时：`buf[1] & 0x0F` 先抹掉 buf[1] 的高 4 位（那里可能是别的字段），左移 8 位升到高位，再 | 低 8 位，拼出完整 12 位数。

### 校验和（Checksum）

**这是什么**：数据在线路上可能因干扰"变脸"（某位 0 变 1）。**校验** = 发送方按规则算出一个"指纹"随数据一起发，接收方用同样规则重算一遍，对不上就判这帧数据坏了、丢弃重传。累加和是最简单的指纹（所有字节加起来取低 8 位），异或校验略强（还能发现字节顺序错误）。

**这段代码要做什么**：实现累加和与异或校验两个函数。

```c
/* 累加和校验：所有字节相加取低 8 位 */
uint8_t checksum(const uint8_t *p, uint8_t len)
{
    uint8_t sum = 0;
    while (len--) sum += *p++;
    return sum;
}

/* 异或校验：所有字节异或（比累加和更能发现连续位错误） */
uint8_t xor_check(const uint8_t *p, uint8_t len)
{
    uint8_t x = 0;
    while (len--) x ^= *p++;
    return x;
}
/* CRC 校验由库/查表完成，原理到 STM32 阶段再学 */
```

## 7. 函数指针与回调（嵌入式架构核心）

**这是什么**：变量有地址，**函数也有地址**（函数的机器码也存在内存里，有起始位置）。存函数地址的指针就叫**函数指针**。它最大的价值是**回调（Callback）**：把自己写的函数"登记"给别人，让别人在合适的时机回头调用你。类比：你把电话号码（函数地址）留给快递柜（框架代码），快递到了**它**打给你——而不是你每隔 5 分钟跑去查一次柜子。

函数也有地址；**函数指针存的是函数入口地址**。

```c
#include <stdio.h>

int add(int a, int b) { return a + b; }
int sub(int a, int b) { return a - b; }

/* 声明：返回类型 (*指针名)(参数列表) */
int (*op)(int, int);

op = add;                       // 函数名就是地址，&add 亦可
printf("%d\n", op(3, 4));       // 7，两种调用等价：(*op)(3,4)
op = sub;
printf("%d\n", op(10, 4));      // 6
```

### 回调函数：把"逻辑"当参数传给别人

```c
/* 数组遍历器：对每个元素执行用户提供的操作 */
void for_each(int *arr, int n, void (*fn)(int))
{
    for (int i = 0; i < n; i++) fn(arr[i]);
}

void print_dec(int v) { printf("%d\n", v); }
void print_hex(int v) { printf("0x%X\n", v); }

for_each(buf, 10, print_dec);   // 同一框架，不同行为 → 解耦
for_each(buf, 10, print_hex);
```

### 典型嵌入式应用 1：命令表（CLI / AT 指令）

**这是什么**：串口收到 "help"、"reboot" 这样的命令字符串，程序要决定执行哪个函数。新手写法是一长串 if-else strcmp；专业写法是**命令表**——名字和函数配好对放进数组（放 Flash），处理时查表调用。加一条新命令只需加一行表项，不用动逻辑代码，这就是"解耦"。

**这段代码要做什么**：定义"命令名 + 处理函数"的结构体数组，cmd_exec 查表执行。

```c
typedef void (*cmd_handler_t)(void);

typedef struct {
    const char    *name;
    cmd_handler_t  fn;
} Command_t;

void cmd_help(void)  { printf("help...\n"); }
void cmd_version(void){ printf("v1.0\n"); }
void cmd_reboot(void){ /* NVIC_SystemReset(); */ }

static const Command_t cmd_table[] = {       // 放 Flash（const）
    { "help",    cmd_help    },
    { "version", cmd_version },
    { "reboot",  cmd_reboot  },
};

void cmd_exec(const char *name)
{
    for (unsigned i = 0; i < sizeof(cmd_table)/sizeof(cmd_table[0]); i++)
        if (strcmp(name, cmd_table[i].name) == 0) {
            cmd_table[i].fn();               // 通过指针调用
            return;
        }
    printf("unknown cmd\n");
}
```

## 8. 用 switch 写状态机（裸机程序骨架）

**这是什么**：**状态机（State Machine）** 是把程序行为建模成"若干状态 + 状态之间的跳转条件"。类比洗衣机：待机→进水→洗涤→脱水→结束，每个状态只干该干的事，条件满足才跳下一个。裸机程序没有操作系统帮忙调度，状态机就是让主循环"每次只专注当前状态"的最佳骨架。

**这段代码要做什么**：用一个枚举变量记当前状态，while(1) 主循环里 switch 分发，各 case 里干活并决定下一个状态。

```c
typedef enum { TASK_IDLE, TASK_SAMPLE, TASK_SEND, TASK_SLEEP } TaskState;

int main(void)
{
    TaskState state = TASK_IDLE;
    while (1) {
        switch (state) {                 // 状态可被中断/事件修改
        case TASK_IDLE:
            if (time_up)      state = TASK_SAMPLE;
            break;
        case TASK_SAMPLE:
            read_sensor();
            state = TASK_SEND;
            break;
        case TASK_SEND:
            upload_data();
            state = TASK_SLEEP;
            break;
        case TASK_SLEEP:
            enter_lowpower();
            state = TASK_IDLE;
            break;
        default:
            state = TASK_IDLE;
            break;
        }
    }
}
```
> 状态机 + 中断标志位 + 位操作 = 裸机工程的全部骨架，先在 PC 上把逻辑跑通，阶段二原样搬到单片机。
>
> 读这段代码的钥匙：`state` 变量是全局剧情的唯一进度条。主循环每圈只执行当前状态对应的 case；中断函数可以随时修改 state（比如收到数据就把 IDLE 掰到 SAMPLE），下一圈主循环就换了剧情——这就是"状态可被中断/事件修改"的含义。
