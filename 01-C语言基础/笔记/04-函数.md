# 04 · 函数

**这一篇讲什么**：函数就是把一段常用代码"打包起名"，以后喊名字就能用，而不用每次重写。类比榨汁机：放进去水果（参数），吐出来果汁（返回值），中间怎么榨的是封装好的内部逻辑。

## 1. 为什么要有函数

**这是什么**：先回答"为什么需要函数"，再学"怎么写"。没有函数的代码像一篇不分段的作文——500 行流水账，改一处要在 500 行里找；有了函数，代码按功能分块，每块有自己的名字。

- 复用：一段逻辑写一次，处处调用；
- 拆解：大问题拆成小问题（模块化是嵌入式代码架构的核心）；
- 维护：出问题定位到具体函数。

嵌入式工程典型分层：
```
main.c        → 主流程调度
bsp_led.c     → 板级：LED 初始化/控制
bsp_uart.c    → 板级：串口收发
protocol.c    → 协议：数据帧解析
每个模块 = 一个 .c + 一个 .h
```

## 2. 函数三要素

**这是什么**：一个函数涉及三件事——**声明**（先告诉编译器"有这么个人，长这样"，像交名片）、**定义**（本人真正干活）、**调用**（喊他干活）。三样缺一不可：只声明不定义，链接时报错（名片上有人，公司里查无此人）；没声明就调用，编译器不认识就报错/乱猜。

**这段代码要做什么**：完整演示"声明 → main 里调用 → 文件末尾定义"的标准顺序。

```c
返回类型 函数名(参数列表);      // 声明（原型）：告诉编译器"存在，长这样"
返回类型 函数名(参数列表) { }   // 定义（实现）：真正干活
函数名(实参);                   // 调用
```

```c
#include <stdio.h>

int Add(int x, int y);          // 声明通常放 .h 头文件里

int main(void)
{
    int sum = Add(3, 5);        // 调用
    printf("%d\n", sum);
    return 0;
}

int Add(int x, int y)           // 定义
{
    return x + y;               // return：返回值 + 结束函数
}
```

要点：
- 先**声明后使用**，否则 C89 下编译器会按 `int` 猜（老编译器警告/错乱）；新建函数统一"先声明、再 main、后定义"或用头文件；
- `void`：无返回值 `void func(...)`；无参数 `int main(void)`；
- return 之后的语句不执行；void 函数可 `return;` 提前结束。

## 3. 形参 vs 实参，传值调用（关键）

**这是什么**：这是函数这一章最重要的一节，搞不懂它，指针就永远学不明白。核心一句话：**C 语言传给函数的永远是"复印件"，不是原件**。函数里怎么改复印件，原件都纹丝不动；想让函数改原件，就得把原件的"地址"（在哪里的门牌号）告诉它。

- **实参**：调用时传进去的真实值；**形参**：定义时的占位变量；
- C 语言**只有传值调用**：形参是实参的**一份拷贝**，修改形参不影响实参。

**这段代码要做什么**：先看一个"看起来交换了、其实没交换"的错误示范，再看正确写法。

```c
void Swap_wrong(int a, int b)   // 错误示范：交换的是拷贝
{
    int t = a; a = b; b = t;
}

void Swap(int *pa, int *pb)     // 正确：传地址，解引用修改原值
{
    int t = *pa;
    *pa = *pb;
    *pb = t;
}
Swap(&x, &y);
```

运行逻辑逐段拆解：
- `Swap_wrong(x, y)`：x、y 的值被**复印**到 a、b。函数内 a、b 确实交换了，但函数一返回，a、b 这两张复印件就被销毁，x、y 原封不动；
- `Swap(&x, &y)`：传的不是值，而是 x、y 的**地址**。`*pa` 意思是"顺着 pa 里存的地址找到 x 本尊"，`*pa = *pb` 改的是本尊，所以真的交换了。

> 记忆：**想改变谁，就传谁的地址**。这是指针的第一个杀手级应用，也是理解后面"结构体传参""回调"的基础。

## 4. 数组作参数（退化为指针）

**这是什么**：数组传参比较特殊——传的不是复印件，而是"首地址"（数组第一个元素住哪）。就像把整个仓库搬过去太费劲，只给对方一张"仓库在几号路几号门"的纸条，对方拿着纸条直接去仓库里翻找、修改。

**这段代码要做什么**：打印数组所有元素；顺带演示新手最经典的 sizeof 误用。

```c
void print_arr(int arr[], int n)   // 等价于 int *arr
{
    int sz = sizeof(arr) / sizeof(arr[0]);   // 错！arr 已退化，得到 8/4=2 或 1
    for (int i = 0; i < n; i++) printf("%d ", arr[i]);
}
```

- `int arr[]` 写在参数位置只是"看起来像数组"，编译器实际按 `int *arr`（一个存地址的指针）处理——这叫**退化**；
- 指针只占 4/8 字节，所以函数内 `sizeof(arr)` 量出来是指针大小，不是数组大小。这就是为什么**长度 n 必须单独传**；
- 数组传参**只传首地址**（不拷贝整个数组，效率高）；
- **长度必须另传**（所以库函数都带 n/len 参数）；
- 函数内通过下标/解引用修改，会**直接影响原数组**（地址共享）——和上一节"复印件"规则不矛盾：传值传的是地址的复印件，但顺着地址找到的还是原件。

## 5. 嵌套调用与链式访问

```c
printf("%d", printf("%d", 43));
// printf 返回打印的字符数：内层打印 "43" 返回 2，外层打印 "2" → 输出 432
```

## 6. 递归

**这是什么**：函数自己调用自己。类比俄罗斯套娃——打开一个娃娃，里面还是娃娃，只是更小；直到最小的那个（不能再打开）为止。递归必须回答两个问题："什么时候停？"（出口）和"每一层比上一层小多少？"（规模递减）。少了任何一个，就是无限套娃，撑爆内存。

函数自己调用自己。两个必要条件：**有出口**（递归终止条件）+ **问题规模递减**。

**这段代码要做什么**：用递归算阶乘（n! = n × (n-1) × ... × 1），并给出斐波那契的迭代写法。

```c
// 阶乘
long long Fact(int n)
{
    if (n <= 1) return 1;          // 出口
    return n * Fact(n - 1);        // 规模减小
}
```

**一步步展开 Fact(4)**（看懂这个展开，递归就通了）：
```
Fact(4) = 4 * Fact(3)
        = 4 * (3 * Fact(2))
        = 4 * (3 * (2 * Fact(1)))
        = 4 * (3 * (2 * 1))      ← Fact(1) 命中出口，开始"往回收"
        = 4 * (3 * 2)
        = 4 * 6
        = 24
```
前半程"一层层往下问"叫递，后半程"一层层往回算"叫归。

```c
// 斐波那契（递归版直观但重复计算多，O(2^n)；迭代版 O(n)）
long long Fib(int n)
{
    long long a = 0, b = 1, c;
    if (n < 2) return n;
    for (int i = 2; i <= n; i++) { c = a + b; a = b; b = c; }
    return c;
}
```

坑：
- 没出口 → 栈溢出（Stack Overflow）；
- 递归太深 → 栈爆。**嵌入式栈很小（几 KB~几十 KB）**，递归慎用，优先写迭代。

## 7. 栈帧简说（理解即可）

**这是什么**：**栈（Stack）** 是内存里一块专门给"函数调用"用的区域，像一摞盘子——每调用一个函数，就往上放一个盘子（这块空间叫**栈帧**，里面装着该函数的形参、局部变量、返回地址）；函数返回，这个盘子就被端走（栈帧销毁，里面的数据作废）。这就是"局部变量函数返回后不能再用"的原因——盘子都没了，上面的东西自然不存在。

每次函数调用，系统在**栈**上开辟一块空间（栈帧）存放：形参、局部变量、返回地址、寄存器现场。函数返回，栈帧销毁 → 所以**局部变量的地址不能返回**：

```c
int *bad(void)
{
    int a = 10;
    return &a;      // 危险！a 所在栈帧已销毁，返回野指针
}
```

## 8. static 与函数（嵌入式常用）

```c
// protocol.c
static int crc16(uint8_t *buf, int len);   // static 函数：仅本 .c 可见（内部链接）
```
- 模块私有函数加 `static`：外部看不到、防命名冲突，相当于面向对象的 private；
- 头文件里**只放声明，不放定义**（static 内联函数除外）。

## 9. 多文件编程与头文件

**这是什么**：代码多了以后，不能全塞在一个 .c 文件里（几千行没法维护）。C 的做法：**.c 文件放实现，.h 头文件放"说明书"**（声明）。别的文件要用你的功能，`#include` 你的头文件即可。类比：.c 是厨房（真做菜的地方），.h 是菜单（告诉顾客有什么菜、怎么点）。

```
project/
├── main.c
├── bsp_led.c
├── bsp_led.h
```

`bsp_led.h`：
```c
#ifndef __BSP_LED_H      // 头文件守卫（或 #pragma once）
#define __BSP_LED_H

#include <stdint.h>

#define LED_PIN   13     // 宏/类型/声明放头文件
typedef enum { LED_OFF, LED_ON } LedState;

void     LED_Init(void);
void     LED_Set(LedState s);

#endif
```

`bsp_led.c`：
```c
#include "bsp_led.h"     // 自己的头文件用 ""，系统头文件用 <>

void LED_Init(void)  { /* ... */ }
void LED_Set(LedState s) { /* ... */ }
```

规则：
- `<>` 找系统目录；`""` 先找当前目录；
- 头文件必须加**守卫**防止重复包含（重复定义错误）；
- 头文件里**不能定义变量**（会被多个 .c 各定义一份），只能声明 `extern int g_flag;`。

## 10. 函数设计好习惯（嵌入式代码规范）

1. 一个函数只做一件事，一般不超过一屏（50~80 行）；
2. 入口参数先检查（对外接口判 NULL / 范围）；
3. 返回值约定：`0` 成功、负数错误码（errno 风格）；
4. 全局变量能不用就不用，必须用时加注释说明共享关系；
5. 中断和主循环共享的变量加 `volatile`（笔记09详讲）。
