# 11-嵌入式Linux · 目录与学习路线

> 定位：**阶段四（约 6~8 周，方向选修）**。目标：从"点灯思维"升级到"系统思维"——Linux 系统编程、交叉编译、U-Boot/内核/根文件系统、设备驱动，能独立把一块板子"从裸板到跑应用"。
> 前置：C 语言（四大件《操作系统》理论边学边对照）；07/08 阶段的启动流程知识在此全面升华（ARM7→Cortex-A 的世界）。

**先说人话**：以前你写 STM32，程序就是全部世界；进了 Linux，世界变成一整座大楼——内核是总管家，你的程序只是楼里的一个住户（进程）。本阶段解决一个核心问题：**怎么让一块裸板子，从上电到稳稳跑起你写的 Linux 应用**。路子是"先在 PC 上学系统编程（01/02），再把系统整个装上板子（03），最后写驱动（04）并集成毕业项目（05）"。

## 阶段验收标准

- [ ] 系统编程：多线程 TCP 服务器（select/poll）、fork+exec 进程管理、信号处理
- [ ] 交叉编译：Makefile 独立手写工程 → CMake 工程 → 板上运行+GDB 远程调试
- [ ] 系统：Buildroot 出整套镜像，U-Boot 环境变量/启动参数能手改
- [ ] 驱动：LED 驱动+按键中断驱动，设备树修改生效，用户态测试程序配套

- [ ] 能讲清"STM32 裸机 vs Linux"架构差异（MMU/进程/驱动分层）

## 裸机 → Linux 概念迁移表（全程最重要的心智升级）

怎么读这张表：左列是你已经掌握的 STM32 世界，中列是 Linux 里的"对应物"，右列是两者最关键的差异——**横向逐行对照**，每读懂一行就完成一次思维迁移。这张表值得打印贴墙上。

| STM32 世界 | Linux 世界 | 关键差异 |
|-----------|-----------|----------|
| 直接写寄存器 | 驱动代理 + open/read/write | 内核独占硬件，用户态只能系统调用 |
| main() 就是全部 | 内核先跑，你的程序是"进程" | 应用随时崩了重启系统不倒 |
| 中断服务函数 | 内核驱动中断处理 + 用户态信号/epoll | 上半部下半部分离彻底 |
| FreeRTOS 任务 | 进程/线程（CFS 调度） | MMU 隔离、虚拟地址 |
| HAL_Delay 忙等 | sleep/usleep/epoll 等待 | 等待不占 CPU 是系统义务 |
| 启动文件 → main | BootROM→U-Boot→Kernel→rootfs→init→应用 | 启动链长但每环可替换 |

## 名词速查表

怎么读这张表：不是让你现在背——它是**全书速查字典**，后面各篇读到陌生黑体词时来这里对号；学完整个阶段再回来通读一遍，应该每一行都能自己讲出来。

| 名词 | 一句话解释 |
|------|-----------|
| **MMU** | 内存管理单元：虚拟地址→物理地址翻译，进程隔离的基石 |
| **系统调用** | 用户态进内核态的唯一正门（open/read/write...） |
| **进程/线程** | 资源分配单位/调度单位；fork 克隆进程，pthread 造线程 |
| **文件描述符** | 一切 I/O 的句柄（文件/socket/串口都是"文件"） |
| **epoll** | 高并发 I/O 多路复用：一个线程盯一千个 socket |
| **信号** | 内核/进程间的"异步通知"（SIGTERM=请你退出） |
| **交叉编译** | 在 x86 电脑上编译出 ARM 可执行文件（arm-linux-gnueabihf-gcc） |
| **U-Boot** | 裸机小系统：初始化 DDR/加载内核，舞台报幕员 |
| **zImage/dtb** | 内核压缩镜像/设备树二进制（描述硬件的"家具清单"） |
| **rootfs** | 根文件系统：/bin /etc /lib 全家桶，应用的"家" |
| **Buildroot/Yocto** | 一键构建整套系统（内核+驱动+rootfs）的框架；Yocto 企业级 |
| **设备树（DTS）** | 描述硬件的数据文件，"硬件说明书"与代码分离 |
| **字符设备驱动** | 内核里实现 file_operations 的模块，用户 open 后走 read/write |
| **insmod/modprobe** | 加载驱动模块（.ko）进内核 |
| **systemd/init.d** | 开机自启服务管理器 |

## FAQ

**这是什么**：开工前最常纠结的三个选择题，先给结论式答案——选好就别反复横跳，跑通一条路比纠结选路重要。

**Q1：学了 STM32 直接学 Linux 还是再学点别的？**
看方向：做 IoT 网关/智能硬件/AI 边缘 → Linux 是必修；深耕汽车电子/工控单片机 → 可缓。**i.MX6ULL 入门成本最低**，学完概念通吃 RK/全志。

**Q2：Buildroot 还是 Yocto？**
学习/中小产品 **Buildroot**（简单直观）；大团队/复杂产品 Yocto（分层可复用，学习曲线陡）。先 Buildroot 读懂全流程，工作需要再上 Yocto。

**Q3：WSL 能全程用吗？**
系统编程/交叉编译/Buildroot 都可以（WSL2）；涉及 USB 烧写和以太网 tftp 的网络配置略折腾，卡住就换 VMware。
