# 05 · 状态机与外设时序衔接

> 定位：本模块的"毕业篇"——把状态机从数电视角重新看一遍，再拿 SPI/I2C 时序图逐段精读，直通 STM32 通信外设和逻辑分析仪实操。

前面学的门电路、触发器、时序图，最终都要服务于两件事：**看懂外设时序**（芯片手册里那些波形图到底在说什么）和**写对通信代码**（为什么 CPOL/CPHA 配错就读全 0x00）。本篇先用大白话讲清 Moore/Mealy 两种状态机，再用"硬件状态机"的视角重新拆解你在 [01-C语言基础/10](../../01-C语言基础/笔记/10-位运算与嵌入式C编程.md) 写过的 switch 状态机；然后是重头戏——把 SPI 四线和 I2C 起始/停止/ACK 的时序图**逐段念出来**；最后落地到一次真实的逻辑分析仪抓波形。学完本篇，[07-STM32/06](../../07-STM32/笔记/06-I2C-SPI-CAN.md) 对你来说就是复习课。

## 一、Moore 与 Mealy："看灯不看路" vs "看路又看灯"

**这是什么**：状态机的两大门派，区别只有一个——**输出从哪来**。**Moore 机**：输出只由当前状态决定（"看灯不看路"：十字路口的红绿灯只按自己的节拍变色，路口有没有车都不影响它的输出）；**Mealy 机**：输出由当前状态和当前输入共同决定（"看路又看灯"：感应门——既知道自己在"营业中"状态，又看"有人靠近吗"这个输入，两者一起决定开不开门）。

| 对比项 | Moore | Mealy |
|--------|-------|-------|
| 输出依赖 | 只看当前状态 | 状态 + 输入 |
| 响应速度 | 输入变化要等下一拍才反映 | 输入一变输出立刻变 |
| 稳定性 | 输出与状态绑定，干净不易毛刺 | 输入线上的毛刺会直接串到输出 |
| 状态数量 | 通常更多（要多设状态表达"条件"） | 通常更少 |
| 类比 | 红绿灯 | 感应门 |

嵌入式里怎么选：**对外输出（控制执行器、驱动总线）优先 Moore**——稳定第一；**对响应速度有极端要求时用 Mealy**——但要给输入先做滤波消抖。这个取舍和"中断 vs 轮询"的取舍同构，本质都是"及时性 vs 确定性"。

一个最小例子感受差别（按键检测）：Moore 版设"等待按下→消抖确认→等待释放→消抖确认"四个状态，输出只在"确认"状态置位；Mealy 版输出 = 状态为等待 且 输入为按下，快但输入毛刺直接出输出。两种写法都合法，工程上按键类基本选 Moore + 定时器消抖（软件侧的完整实现见 [06/03](../../06-51单片机/笔记/03-数码管与按键.md) 按键部分）。

### 状态编码的三种写法（了解即可）

- **二进制编码**：4 个状态用 00/01/10/11——最省触发器，C 语言 enum 默认就是它；
- **格雷码**：相邻状态只差一位（00/01/11/10）——跳变时只有一位翻转，出毛刺的概率小，高速计数常用；
- **独热码（One-hot）**：每个状态独占一位（0001/0010/0100/1000）——译码只需看一根线，FPGA 里速度最快、最常用。

软件里用 enum 的二进制编码足够；记住格雷码和独热码的名字，以后读 FPGA/硬件资料不慌即可。

## 二、硬件状态机视角：重看你的 switch 状态机

**这是什么**：你在 C/10 篇用 `enum + switch + while(1)` 写的裸机状态机，在数电里有一个精确的硬件对应物——**有限状态机（FSM）三件套：状态寄存器 + 次态逻辑 + 输出逻辑**。两边逐件对照：

| 硬件 FSM 部件 | 数电实体 | 你的 C 代码对应 |
|---------------|----------|-----------------|
| 状态寄存器 | 一组 D 触发器（03 篇） | `state` 这个 enum 变量 |
| 次态逻辑 | 组合逻辑门网络 | 每个 case 里的 `if` 跳转判断 |
| 输出逻辑 | 组合逻辑/译码器 | 各 case 里执行的 `read_sensor()` 等 |
| 状态译码 | 译码器（02 篇 138 同思路） | `switch` 本身——按编码值选分支 |
| 时钟节拍 | 全局时钟沿 | `while(1)` 每转一圈 |

逐句拆"为什么一一对应"：`state` 变量的每个位存在内存/寄存器里（触发器阵列）；`switch(state)` 硬件版就是"把状态编码送进译码器，选中唯一一条输出路径"；case 里的 `if (time_up) state = TASK_SAMPLE` 硬件版是"次态组合逻辑根据当前状态和输入算出下一个编码，下个时钟沿写回状态寄存器"。**你写的软件状态机，就是一台用指令解释执行的硬件 FSM**——这层对照让你以后读芯片手册里的"状态图"毫无障碍，也让你理解：为什么状态编码要互斥、为什么每个 case 必须写 break、为什么 default 是安全网（硬件上对应"非法状态强制回 IDLE"的抗跑飞设计）。

一个职业习惯从这里埋下：**画状态图先于写代码**——圆圈是状态、箭头是条件，画完箭头数一数每个圆圈的出箭头是否齐全（漏一个就是死等 bug），再翻译成 switch。这张图在硬件工程师眼里就是 FSM 的标准语言，软硬件通用。

### 动手：Moore 风格的按键长按检测

**这段代码要做什么**：定时器节拍每 10ms 扫一次按键，四状态 Moore 机用状态本身表达"短按/长按"，消抖逻辑藏在状态跳转里而不是延时里。

```c
typedef enum { KEY_IDLE, KEY_DOWN, KEY_LONG, KEY_RELEASE } KeyState;

KeyState key_scan(uint8_t pin_pressed)     /* 每 10ms 调一次 */
{
    static KeyState state = KEY_IDLE;
    static uint16_t cnt = 0;

    switch (state) {
    case KEY_IDLE:                          /* 等按下 */
        if (pin_pressed) { state = KEY_DOWN; cnt = 0; }
        break;
    case KEY_DOWN:                          /* 已确认按下，开始数长按 */
        if (++cnt >= 100)       state = KEY_LONG;   /* 数到 1 秒 = 长按 */
        else if (!pin_pressed)  state = KEY_RELEASE;
        break;
    case KEY_LONG:                          /* 长按保持中 */
        if (!pin_pressed)       state = KEY_RELEASE;
        break;
    case KEY_RELEASE:                       /* 等松手，顺便消抖 */
        if (!pin_pressed)       state = KEY_IDLE;
        break;
    }
    return state;                           /* Moore 输出 = 当前状态本身 */
}
```

对照本文第二节表格自查：`static state` 是状态寄存器；每个 `if` 是次态逻辑；`return state` 是 Moore 输出（调用方按状态值决定"短按/长按"动作）；10ms 节拍是时钟。四个 case 的出口都数过了吗？漏一个就会卡死——这就是"画图先于写码"的回报。

## 三、时序图精读实战一：SPI 四线逐段念

**这是什么**：SPI 时序图（[07/06](../../07-STM32/笔记/06-I2C-SPI-CAN.md) 的前菜现在上正席）表达四根线在一场传输里的分工：**CS**（片选，点名）、**SCK**（时钟，节拍器）、**MOSI**（主机→从机数据）、**MISO**（从机→主机数据）。全双工：同一根时钟下，两根数据线同时移位，一次交换两个字节的内容。

逐段念（SPI 模式 0：CPOL=0、CPHA=0，发 0x55 = 0101 0101）：

1. **CS 拉低**：从机被点名，收听开始。为什么需要 CS？SPI 总线上可能挂多个从机，SCK/MOSI/MISO 是公共线，谁被选中谁才把 MISO 从高阻态里放出来——04 篇三态门"话筒规则"的现场应用；
2. **SCK 空闲电平**：CPOL=0 表示空闲时 SCK 为低。CPOL 只定"不通信时线的姿态"，本身不传输数据——它决定的是数据采样的"基准相位"；
3. **第 1 个 SCK 上升沿**：CPHA=0 表示在**第一个沿**采样。主机把 bit7（0）摆上 MOSI，从机在上升沿把它采走；同时从机把它的 bit7 摆上 MISO，主机同一沿采走——**同一拍，双向各交一位**；
4. **随后 7 个沿**：0101 0101 逐位移过，每个上升沿采样、下降沿翻线（模式 0 的惯例：数据在下降沿更新、上升沿被采）。8 拍后，双方各自拿到了对方的一个字节；
5. **CS 拉高**：本次点名结束，MISO 回高阻，SCK 回空闲电平。

**CPOL/CPHA 四模式为什么长这样**（对 [07/06](../../07-STM32/笔记/06-I2C-SPI-CAN.md)"配错读全 0x00/0xFF"症状的根因解释）：从机芯片内部采样窗口是固定的——它的设计者选了"上升沿采"或"下降沿采"、"第一个沿采"或"第二个沿采"的组合之一，写进了它的数据手册（如"SPI Mode 0"）。主机必须把 CPOL/CPHA 配成和从机**同一个组合**，让"我的采样沿"恰好落在"它的数据稳定窗口"内。配错组合，主机的采样沿正好踩在从机翻线的时刻，采到的永远是刚翻走前的旧位或半截电平——于是读回来清一色 0x00/0xFF，或每位错位的乱码。**主从模式匹配 = 采样沿对准数据稳定窗口**，这就是四模式存在的全部理由。

拿笔把模式 0 画一遍（对照上面逐段念的 5 步）：

```
CS#   ────┐                                  ┌────
          └──────────────────────────────────┘
SCK   ____  ┌─┐_┌─┐_┌─┐_┌─┐_┌─┐_┌─┐_┌─┐_┌─┐  ____
              （8 个上升沿 = 8 个采样快门）
MOSI  ──<b7>──<b6>──<b5>──<b4>──<b3>──<b2>──<b1>──<b0>──
       数据在下降沿换新，上升沿被采（模式 0 惯例）
MISO  ──<s7>──<s6>──<s5>──<s4>──<s3>──<s2>──<s1>──<s0>──
       从机同拍反向交位：8 拍后双方各得一个字节
```

## 四、时序图精读实战二：I2C 起始/停止/ACK 逐段念

**这是什么**：I2C 只有两根线——**SCL**（时钟，主机掌握）和 **SDA**（数据，双向）。两根线要表达"开始说话、传数据、对方收到了、结束说话"，靠的是三条特殊时序规则。念之前先立一条 I2C 宪法：**SCL 高电平期间 SDA 不许变**（那条"唯一的例外"就是起始和停止信号），SDA 只允许在 SCL 低电平期间翻转——否则会被误判成起始/停止。

逐段念：

1. **起始条件（START）**：SCL 保持高电平时，SDA 由高变低。这是全协议唯一允许"SCL 高时 SDA 下降"的时刻，所以所有挂线设备一看到这个动作就全体立正："主机要开始说话了"；
2. **发地址字节**：之后每个 SCL 高电平期间 SDA 保持稳定（代表 1 位），SCL 低电平期间才允许翻线准备下一位。主机发 7 位地址 + 1 位读写位，共 8 拍；
3. **第 9 拍 ACK**：主机放开 SDA（高阻），从机负责把 SDA 拉低——"我在，收到了"。主机第 9 拍读 SDA：低=ACK，高=NACK（设备不在/地址错/数据完）。**为什么设计 ACK**：I2C 是多机共享总线，没有 CS 片选，必须靠"点名应答"确认对面真的存在且在听（对照 SPI：有 CS 点名就不需要 ACK，机制跟着总线拓扑走）；
4. **停止条件（STOP）**：SCL 高电平时 SDA 由低变高——又一个"宪法例外"，全总线看到就散会。

这套逐拍解读直接服务于实操：逻辑分析仪抓 I2C 波形时，软件按上述规则解码出"START → 0x3C+W → ACK → …"，你人工复核的第一件事就是看第 9 拍 SDA 是否被拉低。完整实战语境（OLED、MPU6050）见 [07/06](../../07-STM32/笔记/06-I2C-SPI-CAN.md)。

一图收拢四段（以主机发地址 0x3C+W 为例）：

```
        START        8 位地址+读写位(逐拍)      第9拍        STOP
SCL   ┐_┌─┐_┌─┐_┌─┐_┌─┐_┌─┐_┌─┐_┌─┐_┌─┐_┌─┐_┌───┐_┌─┐_ ...
SDA   ┐____________________________ ... _______________┐____
       （SCL高时SDA下降=起始）            （从机拉低=ACK）└（SCL高时上升=停止）
```

读图要领重申一遍宪法：除 START/STOP 两个"例外动作"，SDA 的一切变化都必须发生在 SCL 低电平期间——逻辑分析仪解码报错的波形，多半是哪根线违反了这条宪法。

## 五、建立/保持违例的后果：毛刺与亚稳态

**这是什么**：03 篇的 t_su（建立时间）/t_h（保持时间）现在收网。当时说"数据必须在时钟沿前后各稳定一小段时间"，违例会怎样？**触发器内部是一场赛跑：数据要通过几级门"赶到"输出，时钟沿是发令枪。数据踩着枪响才起跑（违例），它可能没跑到、跑一半、或跑出个不上不下的结果——输出进入一种既非 0 也非 1、长时间晃荡的状态，叫亚稳态**。

三句话科普就够嵌入式应用层用：

- **症状**：采样值不可预测（同一输入有时对有时错）、输出毛刺、下游电路被这个"半吊子电平"带偏连锁出错；
- **高危场景**：异步信号直接进触发器（按键、外部中断输入不做同步处理）、时钟沿正好撞上数据翻转（SPI 模式配错正是这种情况）；
- **工程对策**：给信号足够的建立/保持窗口（把 SPI 模式配对、降低时钟）、异步输入先过两级触发器同步（STM32 的 GPIO 输入电路内部已做，你配的"滤波/消抖"是在同一思想上的软件延伸）。

## 六、实操：逻辑分析仪抓一次 SPI 波形对照时序图逐位读

**目标**：用几十块的 USB 逻辑分析仪，把 STM32（或 51）发出的一帧 SPI 数据抓下来，人工逐位读出值——这是"看懂时序图"的毕业考，也是 [02/06 测量仪器](../../02-电路基础/笔记/06-测量仪器与调试排障.md)仪器技能的首次实战。

**步骤拆解**：

1. **接线**：分析仪 4 个通道分别夹 CS、SCK、MOSI、MISO（地线就近接板子 GND，否则波形毛刺多）；
2. **配置**：上位机选 SPI 协议解码，按你代码里的配置填参数——CPOL/CPHA/位序/速率，一处配错解码就乱，正好体会"主从模式必须匹配"；
3. **抓取**：运行发送代码（发 0x55 之类特征值），触发一帧完整传输；
4. **人工逐位读**：关掉自动解码（先别偷懒），对照本篇第三节五段法手动读：CS 何时拉低 → 空闲电平验证 CPOL → 找第一个采样沿验证 CPHA → 数 8 个沿逐位记 MOSI 电平 → 拼出 0101 0101 = 0x55 → CS 拉高；
5. **交叉验证**：再打开自动解码对比你的手读结果；故意把软件配置改错一位（如 CPHA 翻转），观察解码乱码——亲手复现"读全 0x00/0xFF"的经典故障。

**这个实验沉淀三样东西**：时序图从"看"变"念"；逻辑分析仪成为你的常规武器（调 I2C/SPI 必备）；建立"配置参数 = 波形长相"的直觉——以后所有通信外设调试都是这套动作的重复。

### 抓波记录表模板（照抄即可用）

| 通道 | 接的线 | 期望看到的 |
|------|--------|------------|
| CH0 | CS | 起始拉低、结束拉高，中间无毛刺 |
| CH1 | SCK | 空闲电平符合 CPOL，恰好 8（或 16）个采样沿 |
| CH2 | MOSI | 逐位电平拼出的字节与代码发送值一致 |
| CH3 | MISO | 从机回位（状态字节或读数） |

人工读数时在表格追加四列：**事件 / 期望 / 实测 / 结论**——每核对一段填一行，这就是工程师的"波形笔记"，排障时它就是证据链。软件配置（CPOL/CPHA/位序/速率）单独记一行，和分析仪设置互相对照，两边都核过才算闭环。

## 常见坑（新手必看）

1. **CPOL/CPHA 背表不理解**：别背"模式 0 是什么"，记住唯一本质——主机采样沿必须落在从机数据稳定窗口内；理解了它，四张模式图自己能推；
2. **把 SDA 当单向线调 I2C**：SDA 双向，从机 ACK 时会主动拉低；主机发完字节立刻又写 SDA 会和从机"抢话筒"，读到 ACK 恒为高（NACK）；
3. **逻辑分析仪地线不接**：只夹信号不共地，波形全是噪声毛刺，解码乱码——先共地再谈抓波；
4. **解码参数抄例程不看自己代码**：分析仪配置要和你代码里 CubeMX/寄存器配置一模一样，"分析仪能解出字"不等于"配置对了"，两边独立核对；
5. **状态机漏 default**：状态编码被干扰跑飞后无处可去，程序假死——default 回安全态是硬件抗跑飞思想的软件翻译；
6. **Mealy 直连机械按键**：输入毛刺直接串到输出，灯乱闪——输入先消抖（硬件 RC 或软件定时）再进 Mealy 逻辑；
7. **把亚稳态当"偶尔出错重试就好"**：亚稳态会向下游传播放大，靠重试掩盖的亚稳态在安全相关场景是事故级 bug，正确姿势是从时序根源上消灭它。

## FAQ

**Q1：Moore/Mealy 和 RTOS 的任务状态（就绪/运行/阻塞）是一回事吗？**
同一思想不同层次。RTOS 调度器内部管理任务状态也是一台（很复杂的）状态机，只是"状态"由内核维护、切换由调度器驱动。你写的业务级 switch 状态机跑在 RTOS 之上，两者共存不打架——08-FreeRTOS 阶段你会同时用到两层。

**Q2：I2C 为什么不像 SPI 那样加一根片选线，非要靠地址+ACK？**
省线是 I2C 的立身之本（两根线挂一串设备）。地址+ACK 的代价是协议复杂、速度上限低；SPI 加 CS 换来协议简单、速度高。机制跟着总线拓扑和目标走——这个判断思路比记住协议本身更重要。

**Q3：逻辑分析仪和示波器怎么分工？**
逻辑分析仪看"数字逻辑对不对"（多位并行、自动协议解码、长时间记录）；示波器看"模拟质量好不好"（幅度、边沿、毛刺、时序余量）。调通信先逻辑分析仪定位协议层错误，波形可疑再上示波器看物理层——详见 [02/06](../../02-电路基础/笔记/06-测量仪器与调试排障.md)。

**Q4：学完本模块，下一步在主线里怎么用？**
直接进主线：51 阶段用 02/04 篇的位选与 595 知识读开发板原理图；STM32 阶段配定时器时回忆 03 篇分频原型，调 SPI/I2C 时用 05 篇的时序精读法和逻辑分析仪流程。本模块此后转为工具书，随用随翻。
