# 02 · 组合逻辑电路

> 定位：把一堆逻辑门组装成"有分工的班组"——译码器、数据选择器、加法器、优先编码器，每个都是单片机里某个外设的思想原型。

**先说人话**：本篇讲什么，学完能做什么——

单个逻辑门只会做一件事（与/或/非），但把十几个门按套路组合起来，就能干"大活"：一片 74HC138 能用 3 根线控制 8 个数码管的位选；一排全加器就是 CPU 里做算术的 ALU 雏形；一片优先编码器就是中断控制器的祖师爷。**组合逻辑电路的定义：输出只由当前输入决定，和"刚才发生过什么"无关**——像自动售货机，你按哪个按钮它立刻对应出货，不记得你上次买了什么。学完本篇，你能看懂 51 开发板上的数码管位选电路、独立完成一次 138 仿真、并提前认识"ALU""中断优先级"这些术语的硬件长相。

## 一、先分清：组合逻辑 vs 时序逻辑

**这是什么**：数字电路的两大门派。**组合逻辑**：输出只看当前输入（现在的题现在答）；**时序逻辑**：输出还参考过去的经历（带记忆）。类比：组合逻辑是计算器——按什么算什么，断电重来不留痕；时序逻辑是游戏存档机——走到哪一步、下一段从哪续，全靠"记得"。

本篇先讲组合逻辑门派，它的两个特点提前记住：

- **没有记忆**：输入撤掉，输出立刻跟着变，不存在"上一次的状态"；
- **传播延迟**：信号穿过每个门都要一点时间（纳秒级），多级串联时输出比输入"晚到"——现在只需知道这个概念，05 篇讲建立/保持时间时会回来收网。

### 组合逻辑的"图纸"：真值表 → 逻辑式 → 电路

设计任何组合逻辑都走三步，回头看 01 篇"两键互锁"正是这么造出来的：**第一步列真值表**——把每种输入组合该有的输出写全（这是"需求"）；**第二步写逻辑式**——从真值表归纳成与/或/非表达式（这是"翻译"）；**第三步选门搭电路**——把逻辑式映射成实际芯片（这是"施工"）。以后看到任何门电路，倒着走一遍（电路→逻辑式→真值表）就能读懂它想干什么——真值表是组合逻辑世界的"通用语言"，芯片手册的功能表本质就是它。

## 二、译码器 74HC138：数码管位选的原理

**这是什么**：3-8 译码器——把 3 位二进制输入"翻译"成 8 根输出线里的一根。输入是 000~111 中的某个值，输出端就只有对应的那一根变低（注意：138 是**低电平有效**输出），其余 7 根保持高。类比：酒店前台给你一把房间号钥匙——你说"305"（3 位输入），全楼 8 个房间只有 305 的门锁打开（1 根输出激活）。

引脚速记（DIP-16）：

| 引脚 | 方向 | 作用 |
|------|------|------|
| A、B、C | 输入 | 3 位选择码，A 是最低位 |
| G1、G2A#、G2B# | 使能 | G1=1 且 G2A#=0 且 G2B#=0 才工作；不满足时所有输出强制为高 |
| Y0#~Y7# | 输出 | 8 根输出，低电平有效：选中的那根变低 |

完整真值表（使能满足时）：

| C | B | A | 唯一变低的输出 |
|---|---|---|----------------|
| 0 | 0 | 0 | Y0# |
| 0 | 0 | 1 | Y1# |
| 0 | 1 | 0 | Y2# |
| 0 | 1 | 1 | Y3# |
| 1 | 0 | 0 | Y4# |
| 1 | 0 | 1 | Y5# |
| 1 | 1 | 0 | Y6# |
| 1 | 1 | 1 | Y7# |

读表方法：把 CBA 三位当成一个 3 位二进制数读出编号（C 是最高位），编号是几、Y 几# 就变低——和 01 篇"位权重"是同一套数学。使能三脚的组合决定芯片"在不在班"，不满足时上表整张作废（8 个输出全高），所以手册真值表里使能列永远排在最前面。

**为什么数码管位选爱用它**：8 位一体数码管要 8 根位选线（控制哪一位亮，概念见 [06-51单片机/03 数码管与按键](../../06-51单片机/笔记/03-数码管与按键.md)）。直接用单片机 IO 占 8 根；换成 138，**3 根 IO（输出 0~7 的编号）就能换 8 根位选**——省下的 5 根 IO 干别的活。这正是"译码"的价值：**用 log₂(N) 根线选中 N 个对象之一**，位数越多省得越狠（4 根选 16 个）。

**使能脚是白送的高级货**：G1/G2A#/G2B# 三脚不满足时，8 根输出全部强制高电平（位选全关）。51 传统开发板利用它做"切换段选/位选总线"的分时复用；你仿真时先把它接死（G1 接 VCC，两个 G2# 接 GND），学会后再玩分时复用的花样。

**低有效输出正好对口共阳数码管**：位选低电平选通 + 138 输出恰好低有效，天然匹配不用反相——这也是它常年霸榜位选电路的原因之一。

### 顺手认识"地址译码"：138 的另一个身份

把 138 的 3 根输入换成"地址线高位"，8 根输出接 8 片存储/外设芯片的片选，就是**地址译码**：CPU 给出一个地址，译码器决定"这地址归哪片芯片管"。51 扩展外部存储器时用 P2 口高位地址译码选片、STM32 外设靠地址映射——都是同一思想（13 模块计算机组成原理里还会重逢）。**"编号选中对象"是数字系统里最通用的分身术，学会一次到处能用。**

### 信号穿门的隐患：竞争与冒险（毛刺）

信号经过不同条数的门到达同一点，路径长短不同导致"快慢不一"——同一时刻本该稳定的输出可能闪一下假电平，这叫**竞争与冒险**，闪出的窄脉冲叫**毛刺**。类比：两条路汇车，一条堵一条畅，路口瞬间反而容易乱。对数码管位选这类慢速场景毛刺无感（扫描周期是毫秒级），但毛刺若闯进时钟或计数输入就会多计数、出乱码。工程对策先记两条：关键信号走同步设计（03 篇）、选通信号加使能窗口（先稳定再开门）。

## 三、数据选择器 74HC151：多路开关

**这是什么**：8 选 1 数据选择器（MUX）——8 路数据输入，由 3 位地址码选出其中 1 路送到唯一输出端。类比：8 台摄像机接一个导播台，导播（地址码）说切 3 号机位，直播画面就是 3 号机的内容。

它和译码器像一对反着干的兄弟：

- **译码器**：1 个地址值 → 展开 N 根输出线（一对多，"分发"）；
- **选择器**：N 路输入 → 收拢到 1 根输出线（多对一，"汇聚"）。

经典 51 没有片上 ADC，增强型 51 通常也只有一路——8 个传感器轮流上报时，硬件层用 MUX 分时复用这唯一的输入口是经典省钱套路；STM32 内部每个 GPIO 的"复用功能选择器"（这一脚到底连通定时器还是串口）本质上就是一个多路选择器——你在数据手册里配的"复用推挽输出"，底层就是在拨这个导播台。本篇认识概念即可，仿真不做它。

### 经典玩法：一片 MUX 实现任意三变量逻辑

MUX 还有个"隐藏技能"：把三个变量中的两个接地址端（如 A、B），第三个变量 C 及其反相按真值表填进 8 路数据端（每路填 C、C#、0、1 之一），输出就是任意想要的三变量逻辑函数——**真值表怎么写，MUX 就怎么配**。这是数电考试常客，工程上是"临时改逻辑不换芯片"的活口，知道有这招即可。

## 四、加法器：ALU 的雏形

**这是什么**：做二进制加法的电路。别小看"加法"——CPU 里的减法（加负数）、乘法（多次加）、地址计算，最后都落回加法器。所以加法器被称为 **ALU（算术逻辑单元）的雏形**。

**半加器**：两个 1 位数相加，输出"本位和"与"进位"：

```
1 + 1 = 10   →  本位 0，进位 1
1 + 0 = 01   →  本位 1，进位 0

规律：本位和 = A XOR B（相同为 0，不同为 1——1+1 进位后本位归 0）
      进位   = A AND B（只有两个都是 1 才进位）
```

为什么恰好是这两个门？想想二进制加法的"逢二进一"：两位都是 1 时 1+1=10，本位清零且进位——"相同才归零"就是异或，"都满才进"就是与。**一个异或门加一个与门 = 半加器**，两颗门解决一位加法。

**全加器**：多位相加时还得算上低位的进位，所以输入变成三个（A、B、低位进位 Cin），输出"本位和"与"向高位进位 Cout"。两个半加器加一个或门 = 全加器。8 个全加器首尾相连（低位 Cout 接高位 Cin），就是 8 位加法器——你写的 `a + b` 编译成指令后，最终就是这条进位链在一拍拍算。

**逐位算例**（5 + 3，5=0101，3=0011）：

```
  0101
+ 0011
------
逐位：bit0: 1+1 → 本位0 进1；bit1: 0+1+进1 → 本位0 进1；
      bit2: 1+0+进1 → 本位0 进1；bit3: 0+0+进1 → 本位1 进0
结果 = 1000 = 8，对上了。
```

### 减法和负数怎么办：补码一句话

CPU 里其实**没有减法器**——减一个数等于加它的补码（按位取反加一），负数也用补码表示，于是减法统一成加法，一套加法器通吃。这也是 [C/10 篇](../../01-C语言基础/笔记/10-位运算与嵌入式C编程.md)讲"有符号数"时补码规则的硬件动机：**补码不是数学游戏，是省硬件的设计**。想深挖到 13 模块计算机组成原理再展开。

## 五、优先编码器：中断控制器的思想原型

**这是什么**：编码器是译码器的逆过程——8 根输入线里某根有效，输出 3 位二进制编号。**优先编码器**（如 74HC148）更进一步：如果同时有多根输入有效，**输出优先级最高的那一个的编号**。类比：医院分诊台——同时来了三个病人，先处理最危重的，其他的排队。

这直接就是**中断系统的思想原型**：多个中断同时来，谁先被响应？看优先级。51 的"自然优先级"、STM32 的 NVIC 抢占优先级，硬件层做的都是"优先编码"这个动作（详见 [06-51单片机/04 中断与定时器](../../06-51单片机/笔记/04-中断与定时器.md)和 [07-STM32/02 GPIO与外部中断](../../07-STM32/笔记/02-GPIO与外部中断.md)）。你以后配 NVIC 优先级分组时可以想：软件填的那张优先级表，最终翻译成硬件里一片"优先编码器"的判决逻辑。

### 中断嵌套：优先编码器的"加时赛"

高级中断打断低级中断的处理、办完事再回去，就是**中断嵌套**。硬件上相当于优先编码器多了一步"比较"：新申请的级别和"当前正在处理的级别"比一比，赢了才能插队。你配 STM32 NVIC 抢占优先级时填的数字，就是在给这场比较登记规则——数电原型的价值就在这：配置项背后都有电路在干活，不是纯软件约定。

优先编码器和普通编码器的一字之差要记牢：普通编码器**只允许一根输入有效**，两根同时来输出就乱了；优先编码器**天生处理竞争**，来几根都只认优先级最高的——"并发场景必须有仲裁规则"，这个思想比芯片本身重要得多。

## 六、实操：Proteus 仿真 138 驱动 8 位数码管位选

**目标**：不用一根根数 IO，用 3 根控制线轮流点亮 8 位数码管中的任意一位。

**步骤拆解**（仿真软件用法见 [05/03 Proteus 电路仿真](../../05-EDA与生产工具/笔记/03-Proteus电路仿真.md)）：

1. **摆器件**：74HC138 一片、共阳数码管一个（或 8 个 LED 代表位选线更简单，建议先用 LED）、逻辑状态源 3 个（当 A/B/C 输入）、逻辑探针 8 个（挂 Y0#~Y7# 观察输出）；
2. **接使能**：G1 接 +5V，G2A#、G2B# 接 GND——让芯片常开，排除使能干扰；
3. **接输入输出**：逻辑状态源接 A/B/C；Y0#~Y7# 各串一个 470Ω 电阻接 LED 到 +5V（Y 输出低时 LED 亮，直观模拟"位选选中"）；
4. **拨表验证**：把 A/B/C 拨成 000→001→010→…→111，观察 LED 亮的位置是否逐一右移；故意断开 G1，验证 8 个输出全部失效（全部为高）；
5. **进阶（可选）**：换真数码管——Y0#~Y7# 接 8 位共阳数码管的位选公共端（低选通），A/B/C 接 51 三个 IO，跑一段逐位循环代码，让 8 位轮流显示各自数字，就还原了 [06/03](../../06-51单片机/笔记/03-数码管与按键.md) 里"动态扫描"的位选半边。

**现象背后的三句话**：A/B/C 是"房间号"，Y# 是"门锁"，使能是"前台在不在班"。位选的本质是"选通哪一位通电"，138 只是把"3 位编号"翻译成"8 选 1"的自动化门卫。

### 仿真排障三板斧（现象不对先过这三关）

1. **完全不工作**：先查供电和使能——VCC/GND 接没接、G1 是不是高、G2# 是不是低（对应 01 篇"芯片没电/输入悬空"两大悬案）；
2. **现象和预期相反**：十有八九忘了输出低有效——LED 该接 Y#→电阻→VCC 而不是接 GND；
3. **顺序乱跳但不规律**：查 A/B/C 高低位有没有接反（C 是最高位），再查是不是多个输入脚悬空在飘。

## 七、四种组合逻辑器件一张表总结

| 器件 | 方向 | 一句话职责 | 单片机里的对应 |
|------|------|-----------|----------------|
| 译码器 74HC138 | 1 入 → N 出 | 编号选中一路（分发） | 数码管位选、地址译码、片选 |
| 选择器 74HC151 | N 入 → 1 出 | 多路择一（汇聚） | GPIO 复用选择、多传感器分时复用 |
| 加法器 | 多位并行 | 二进制算术 | ALU：加减乘除与地址计算的地基 |
| 优先编码器 74HC148 | N 入 → 1 编号 | 多路竞争按级别裁决 | 中断控制器（NVIC）的优先级判决 |

共同点：**全是组合逻辑，没有记忆**——输出只由当前输入决定；它们的"有记忆版本"，就是下一篇的主角（触发器与时序逻辑）。

### 带着问题进下一篇

这四种器件都"过目就忘"：输入一撤，输出就变。可数码管要"记住"当前亮的是第几位、CPU 要"记住"算到哪一步、通信要"记住"传到第几位——**记忆是谁管的？**下一篇触发器登场，时序逻辑开工。

## 常见坑（新手必看）

1. **忘了 138 输出是低有效**：拿输出高电平去点灯，怎么拨都没反应——LED 应接 Y#→电阻→VCC，输出变低才亮；
2. **使能脚悬空**：G1 悬空不保证是 1，G2# 悬空不保证是 0，芯片随机不工作——使能脚必须接死（01 篇"CMOS 输入不悬空"铁律的续集）；
3. **A/B/C 高低位接反**：C 是最高位，接反后"选中 Y1"实际选中 Y4，现象是"灯的顺序乱跳但不规律"；
4. **以为 MUX 和译码器是同一个东西**：一个一对多、一个多对一，方向相反；面试常拿这个混淆出题；
5. **仿真跑通了却说不清为什么**：能拨出结果只是第一步，能对着真值表逐行解释才算懂——这是本模块所有实操的共同验收标准；
6. **把优先编码器的"优先"理解成"时间上先来先服务"**：它判的是"同时出现时谁级别高"，和时间无关；时间上的先后调度是软件/中断控制器更上层的事；
7. **把仿真当实物**：仿真里手动拨开关不会暴露竞争冒险和建立时间问题，信号都是理想化跳变——仿真验证逻辑对不对，实物才验证时序好不好，两关都要过。

## FAQ

**Q1：我的 51 开发板数码管位选为什么有时用 74HC573 锁存器而不是 138？**
两种方案并存：138 解决"IO 不够"（3 换 8）；573 是锁存器（时序逻辑，03 篇的主角），解决"P0 口分时复用"——段选和位选共用 P0 总线时，用两片 573 分别锁存两路数据。开发板用哪种取决于设计者的省钱思路，读原理图时先认芯片型号再判断套路（04 篇速查表里有 573）。

**Q2：STM32 有几十个 IO，还需要 138 这种省 IO 的芯片吗？**
看场景。STM32 本身 IO 多，但"3 根线选 8 路"的思路在工业上依然常见（继电器阵列、LED 屏行选），而且 138 的硬件译码不占 CPU——软件一次写 3 位，其余全自动。学会的是思路，不是死记芯片。

**Q3：加法器和我的编程有什么关系？我又不写加法器。**
关系在"位运算的理解深度"：`x ^ y` 做无进位加法、`(x & y) << 1` 算进位、循环直到进位为 0——这段面试经典题就是半加器原理的软件复刻。懂了全加器，这段代码一眼看穿；不懂就只能背。

**Q4：传播延迟在什么时候开始真正影响我？**
两级门之间纳秒级延迟在低速电路（数码管扫描）完全无感；到高速总线（几十 MHz 的 SPI、SDRAM 接线）就要认真算了。本模块建立概念，量化计算留给 05 篇的建立/保持时间和以后的信号完整性专题。

**Q5：两片 138 能不能扩成 4-16 译码？**
能，这正是使能三脚的用武之地：最高位地址接两片互斥的使能、低位地址共用 A/B/C——任一时刻只有一片在工作，16 路位选拼出来。看懂这个级联套路，比多背十种芯片都值。
