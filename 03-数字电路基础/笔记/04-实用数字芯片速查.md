# 04 · 实用数字芯片速查

> 定位：74 家族的"芯片身份证速查册"——看懂原理图上的 74xxx 不再发怵，并用一场 74HC595 驱动数码管的完整实战，把"三根线扩展八个口"的串转并套路打穿。

**先说人话**：本篇讲什么，学完能做什么——

拆开任何一块老工业设备或 51 开发板，都能看到印着 74 开头型号的小芯片：它们就是"标准件逻辑门/逻辑功能块"的封装体——就像建材市场的标准角钢，谁家都买来搭自己的架子。本篇前半是速查表：常用型号各自是干嘛的、电平怎么兼容、使用注意什么；后半是一场重头戏实战：用 74HC595 只花单片机 3 根 IO，就扩展出 8 个输出口去驱动数码管段选——这正是 [06-51单片机/03](../../06-51单片机/笔记/03-数码管与按键.md) 里"IO 不够用"的经典解法，也是 FPGA 普及之前人类最爱的"串转并"手法。学完你还能看懂三态门和总线：多设备共用一根线为什么不打架。

## 一、74 家族速查：型号前缀里的门道

**这是什么**：74 开头的编号是"标准逻辑芯片"的通用命名：前缀定工艺家族（决定供电和电平），后两位数字定功能（00 与非门、04 反相器……各家族通用）。类比：手机型号——"Pro/Max"定档次（家族），"13/14"定代际功能（编号）。

| 家族 | 全称 | 供电范围 | 输入阈值特点 | 什么时候见到它 |
|------|------|----------|--------------|----------------|
| 74LS | TTL 低功耗肖特基（老） | 5V±0.25V 左右 | TTL 门槛（约 2V 算高） | 老设备、老教材 |
| 74HC | CMOS 高速（主流） | 2~6V | 与供电成正比（约 0.7VCC 算高） | 现代设计首选 |
| 74HCT | CMOS 但按 TTL 门槛设计 | 5V | 输入门槛兼容 TTL | 5V 系统里混接 TTL 输出 |
| 74LVC | 低压 CMOS | 1.65~3.6V | 3.3V 系统；多数型号输入耐 5V | 3.3V 的 STM32 系统外围 |

电平兼容判断三句话：**看供电、看门槛、看耐压**——3.3V 单片机接 5V 芯片输出：74HC 输出 5V 对 3.3V 引脚可能超压，要选"LVC"（耐 5V 输入）或加电平转换；5V 单片机接 74HC（供 5V）无压力；74HCT 专门为"TTL 输出喂 CMOS 输入"的混搭而生。新手原则：一个系统尽量全家统一，混用前查数据手册。

## 二、主力芯片逐片说

**74HC00 / 74HC04：门级万金油**。功能就是 01 篇讲的与非门/非门的标准封装。典型应用除了搭逻辑，还有：复位信号取反（有的芯片低复位、有的高复位，中间靠 04 转个向）、把"按键按下=低"翻成"按下=高"。注意点一个：**输出脚不能并联硬怼**——两个门的输出一个推高一个推低，相当于电源对地短路。

**74HC14：施密特触发器，信号整形大师**。它是带"迟滞"的反相器：从低往高翻要过上门槛（约 0.7VCC 量级），从高往低翻要破下门槛（约 0.3VCC 量级），两个门槛之间的"回差"就是免疫力。类比：空调温控设 26 开 25 关——温度在 25~26 之间晃时压缩机不会反复启停。典型应用：**按键消抖**（机械触点抖动产生的毛刺幅度在回差内，输出纹丝不动）和**慢变化信号整形**（RC 延时后的斜坡波形被削成干净方波）。迟滞比较的思想与模拟电路同源，想深挖见 [04-模拟电路基础/04 比较器与波形产生](../../04-模拟电路基础/笔记/04-比较器与波形产生.md)。注意：它和 74HC04 引脚兼容但行为不同（迟滞），画板时别顺手换料。

**74HC245：总线缓冲/驱动**。8 位双向收发器——A 口 8 根、B 口 8 根，方向由 DIR 脚定（高=A→B，低=B→A），OE# 低电平时才导通（高时全部高阻）。它不改变逻辑，只"加油门"：51 的 P0 口驱动能力弱，带 8 位数码管段选电流吃紧时，中间插一片 245 做功率中转——[02/08 真机 BOM 案例](../../02-电路基础/笔记/08-真实工业产品BOM案例-LX750PLUS线材测试仪.md)里"逻辑 IC"一栏它常年在岗。记忆点：**245 管"力气"，573 管"时机"，595 管"省线"**。

**74HC573：八 D 锁存器**。03 篇讲的电平触发锁存器标准封装：LE（锁存使能）为高时输出透明跟随输入，LE 拉低瞬间定格。51 板用它做"P0 分时复用"：P0 先送段码，段选 573 的 LE 给个高脉冲锁住；P0 再送位选码，位选 573 再锁——一根总线两用，靠"先透明后定格"的时间差分账。坑：LE 是电平触发，给"长高"不给"脉冲"就锁不住。

## 三、重头实战：74HC595 三根线驱动数码管段选

**这是什么**：8 位移位寄存器 + 输出锁存器的组合体。工作方式像"传水桶队列"：数据一位一位从 DS 脚挤进去，每来一个移位时钟（SHCP 上升沿），队列整体向前挪一格；8 位装满后，给锁存时钟（STCP）一个上升沿，队列内容**整体**搬到输出脚 Q0~Q7。类比：银行柜台办业务——客户（数据位）排队进队叫号（SHCP），一批到齐后经理喊"放行"（STCP），8 个窗口同时开闸。

**为什么它是传奇**：单片机只出 3 根线（数据+2 个时钟），换来 8 个并行输出；还能串级——第一片的 Q7# 接第二片的 DS，16 位、24 位随便扩。LED 点阵屏、老式 LED 显示屏全是 595 阵列。这就是"串行转并行"（串转并）的标准姿势。

**接线表**（51 驱动共阳数码管段选为例）：

| 595 引脚 | 接到 | 说明 |
|----------|------|------|
| VCC / GND | 5V / 地 | 供电（2~6V） |
| DS | 单片机 P1.0 | 串行数据入口 |
| SHCP | 单片机 P1.1 | 移位时钟，上升沿移位 |
| STCP | 单片机 P1.2 | 锁存时钟，上升沿输出更新 |
| OE# | 接 GND | 输出常开（要调亮度/闪烁时接 PWM） |
| MR#（复位） | 接 VCC | 不用复位功能就拉高 |
| Q0~Q7 | 数码管段 a~g + dp | 段选输出，每段串 470Ω 限流 |
| Q7# | （级联时）下一片 DS | 串行级联专用输出，不是段输出；不级联就空着，别接数码管 |

**驱动时序文字拆解**（以显示段码 0xFE 为例，逐位为什么）：

```
void seg595_send(uint8_t seg)
{
    uint8_t i;
    for (i = 0; i < 8; i++) {
        /* 1. 先发最高位：0xFE 最高位是 1 */
        DS = (seg & 0x80) ? 1 : 0;
        /* 2. SHCP 给上升沿：595 在这一瞬把 DS 当前电平采进移位队列头
              —— 为什么先放数据再给沿：沿是"快门"，先摆好姿势再拍 */
        SHCP = 0; SHCP = 1;    /* 低→高 = 上升沿 */
        /* 3. 数据左移一位，准备发下一位 */
        seg <<= 1;
    }
    /* 4. 8 位全部进队后，STCP 给上升沿：队列内容整体搬到 Q0~Q7
          —— 为什么单独一个锁存沿：移位过程中输出保持旧值不变，
             段码"整帧更新"，中间毛刺不会上屏（不会闪出鬼影） */
    STCP = 0; STCP = 1;
}
```

时序要点三连：**数据在 SHCP 上升沿之前摆稳**（这就是 03 篇"建立时间"的现实版）；**先移位后锁存**（移位是搬运，锁存才是上屏）；**先发高位还是低位看段码表对应关系**——Q0 对应段 a 的话，先发的位最终落在 Q7（队列先进后到），对照位序取反或调整发送顺序即可，实测一次就明白。

**和 [06/03](../../06-51单片机/笔记/03-数码管与按键.md) 的动态扫描合体**：段选走 595（3 根线），位选走 138（3 根线）——原来 8+8=16 根 IO 的活，7 根线全包了，还剩富余。这套"595 段选 + 138 位选"是 51 大屏显示的经典架构。

### 完整代码：0~9 轮播（51 风格）

**这段代码要做什么**：定义段码表和三根控制线，seg595_send 按时序发一个字节，主循环轮播数字 0~9，每个数字都走"移位 8 拍 + 锁存 1 拍"。

```c
#include <reg52.h>

typedef unsigned char u8;

sbit DS   = P1^0;    /* 串行数据 */
sbit SHCP = P1^1;    /* 移位时钟 */
sbit STCP = P1^2;    /* 锁存时钟 */

/* 共阳段码表 0~9（低电平点亮的段，按你的接线上下核对） */
u8 code segTable[10] = {
    0xC0, 0xF9, 0xA4, 0xB0, 0x99,
    0x92, 0x82, 0xF8, 0x80, 0x90
};

void seg595_send(u8 seg)
{
    u8 i;
    for (i = 0; i < 8; i++) {
        DS = (seg & 0x80) ? 1 : 0;   /* 1. 先摆数据（建立时间的软件体现） */
        SHCP = 0;
        SHCP = 1;                    /* 2. 上升沿：这一位被采进移位队列 */
        seg <<= 1;                   /* 3. 左移，准备发下一位 */
    }
    STCP = 0;
    STCP = 1;                        /* 4. 上升沿：8 位整体搬到输出脚 */
}

void delay_ms(u16 t)                 /* 粗略延时，仅演示用 */
{
    u16 i;
    while (t--) for (i = 0; i < 120; i++);
}

void main(void)
{
    u8 i;
    while (1) {
        for (i = 0; i < 10; i++) {
            seg595_send(segTable[i]);
            delay_ms(500);           /* 每个数字停半秒 */
        }
    }
}
```

代码三处与正文互证：`seg & 0x80` 配 `seg <<= 1` 是"从高位到低位逐位剥"（[C/10 篇](../../01-C语言基础/笔记/10-位运算与嵌入式C编程.md)位运算实战）；先摆 DS 再打 SHCP 是建立时间的软件体现；先移位完再打 STCP 是"整帧更新"的关键——试着把 STCP 那两行挪进 for 循环，数码管会闪出移位过程的"鬼影"，改一次试试，现象比道理更说服人。

## 四、三态门与总线：多设备共用一条线不打架的秘密

**这是什么**：普通门输出只有 0 和 1 两态；**三态门**多一个"高阻态"（High-Z）——使能无效时，输出脚像被"拔掉"一样，既不输出高也不输出低，彻底让出线路。类比：圆桌会议只有拿着话筒的人能说话，没话筒的人闭嘴（高阻），话筒一次只给一个人——这条"话筒规则"就是总线不冲突的全部秘密。

**总线的工作模式**：N 个设备的数据脚并联挂在一组线上（如 51 的 P0 既接 RAM 又接外设芯片），任何时刻**只能有一个设备处于输出态**，其他全部高阻监听；由片选信号（常来自 02 篇讲的译码器）决定谁拿话筒。两个设备同时输出且电平相顶，就是"总线冲突"——轻则数据错乱，重则芯片发热损坏。

**为什么这个思想无处不在**：

- **I2C 的开漏线与**：每个设备只能"拉低"或"放手"（放手=高阻，靠上拉电阻回高），天生没有"推高打架"的可能——详见 [05/06 I2C-SPI-CAN](../../07-STM32/笔记/06-I2C-SPI-CAN.md)，那是三态思想的总线级应用；
- **STM32 的 GPIO**：配置成输入时引脚呈高阻（不干扰外部电路），复用时切给片上外设——每根 GPIO 内部就藏着输出使能这类开关；
- **74HC245 的 OE#**：让整片 8 位从总线上"消失"，就是给一片芯片发"把话筒放下"的指令。

一句话沉淀：**并联可以，但输出权必须独占；靠使能/片选轮流发话筒。** 以后看到原理图上一根线接了五个芯片的同一脚，先找它们的使能/片选是谁在管。

### 一个总线冲突的实物剧本

想象两台老 51 共享一片 RAM：如果地址译码设计马虎，同一地址甲乙两机的输出同时使能——甲推高、乙拉低，线上出现"非 0 非 1 的中间电平"，两机各读各的错，严重时电流对灌芯片发热。正确设计正是本篇两大件的合用：**138 译码器保证任一时刻只有一片被片选（话筒唯一），245 缓冲器负责驱动能力（嗓门够大）**。I2C 把这个问题解决得更彻底——干脆用开漏加拉电阻，物理上杜绝"推高打架"（详见 [07/06](../../07-STM32/笔记/06-I2C-SPI-CAN.md)）。

## 五、如何读一份 74 数据手册（五步法）

拿到陌生 74 芯片，手册按这个顺序读，五步定位：

1. **首页特性栏**：确认功能描述、家族（HC/HCT/LVC）、供电范围——30 秒判断"是不是我要的那颗"；
2. **引脚图（Pin Configuration）**：对照实物缺口方向数脚位，标出 VCC/GND/输入/输出/使能；
3. **功能表（Function table）**：这就是真值表，逐行读出每种输入组合下的输出行为——使能列永远先看；
4. **推荐工作条件（Recommended operating conditions）**：供电范围、输入高/低电平门槛——和你的系统电平逐项对照；
5. **时序图与开关特性（Timing）**：需要高速或严格时序时才精读，看建立/保持时间和最大时钟频率。

一个提醒：手册里的"**绝对最大额定值（Absolute Maximum Ratings）**"不是"可以长期工作的条件"，而是"超过就可能损坏的极限"——日常设计要看第 4 步那张"推荐工作条件"表，两者千万别混。

## 常见坑（新手必看）

1. **OE#、MR# 忘接**：595 的 OE# 悬空可能导致输出半开半闭（LED 微亮或不亮），MR# 悬空随时可能复位——这两个脚必须接死（GND/VCC），是 595 排障第一查；
2. **移位和锁存混为一谈**：只打 SHCP 不打 STCP，数据在队列里转但输出纹丝不动；新手常以为"送完数据就该亮"，其实差最后一拍锁存；
3. **位序发反**：先发高位还是低位没和 Q0~Q7 的对应关系核对，显示字符镜面对称的乱码——发一次 0x01 的"单点测试"即可定位位序；
4. **三态门当普通门用**：OE# 没拉低就以为输出坏了；总线上两个输出同时使能造成冲突发热——先查"话筒"在谁手里；
5. **74HC 供电超压或极性反**：家族供电 2~6V，接 12V 或反接直接阵亡；上电前万用表量一遍供电是铁纪律；
6. **595 直接驱动大电流负载**：每个输出脚的灌/拉电流有限（几十 mA 量级，以手册为准），带继电器/大功率 LED 要加三极管或专用驱动（ULN2003 等），别让 595 硬扛；
7. **把施密特整形当万能消抖**：74HC14 吃掉的是幅度小的抖动毛刺，抖动幅度大时仍需 RC 配合；软件消抖（[06/03](../../06-51单片机/笔记/03-数码管与按键.md)）依然是必会项。

## FAQ

**Q1：595 和 573 都能"扩展输出"，选哪个？**
看线预算：573 是 8 进 8 出并行锁存（不省线，省的是"P0 分时复用"的调度）；595 是 3 线串入 8 出（省线，代价是发送要 8 个时钟拍）。IO 紧张选 595，IO 富余要速度选 573——两者还常在同一块板上各司其职。

**Q2：74HC595 的"595"和"74HC"分别什么意思？**
74 是标准逻辑系列代号；HC 是工艺家族（高速 CMOS）；595 是功能编号（8 位移位寄存器+存储锁存）。同功能不同家族叫 74LS595、74HCT595，引脚相同但电平参数有差——这就是家族前缀的价值：改工艺不改功能。

**Q3：三态门和开漏输出是同一个东西吗？**
不是，但解决同类问题（共享线路）。三态门：使能关=高阻，使能开=能推高也能拉低（推挽）；开漏：永远只会拉低或放手，高电平靠上拉电阻补。I2C 用开漏（还能顺带做线与仲裁），总线缓冲用三态（要全双工推挽速度）。对比表见 [07/06](../../07-STM32/笔记/06-I2C-SPI-CAN.md)。

**Q4：怎么查一片陌生 74 芯片是干嘛的？**
三步：型号后两位数字去 04 篇速查表或搜"74HCxxx 功能"；数据手册重点读第一页的功能描述 + 真值表 + 引脚图；ti.com 或 nexperia.com 官网按型号搜索最稳。别背型号，练"三步定位"的手感。
