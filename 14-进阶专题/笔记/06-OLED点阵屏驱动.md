# 06 · OLED 点阵屏驱动（SSD1306）

> 定位：主线 [07-STM32/06 通信外设](../../07-STM32/笔记/06-I2C-SPI-CAN.md) 教你"会用 I2C/SPI 收发字节"，本篇教你"用这些字节点亮一块屏"——菜单、仪表、波形显示的工程主战篇。触发点：学完 07-STM32/06 之后，手里正要做（或已做）一个带屏项目，屏不亮、乱码、花屏、不知道字库怎么来。

**先说人话**：本篇讲什么，学完能做什么——

以最常见的 128×64 SSD1306 OLED 模块为例（I2C/SPI 两种接法都讲，主线用 I2C），把"显存长什么样、字节怎么变成像素、字库怎么生成、刷新怎么不花屏"一条链讲透：显存地图代入算例（1024 字节怎么来的）、驱动代码逐段拆解（写命令/写数据/帧缓冲/画点/刷屏）、8×16 字符显示与取模要点、总线带宽代入算例（决定刷新率上限）、双缓冲防撕裂。学完你能从零点亮一块 OLED 并跑通"字符 + 图形"显示，遇到不亮/花屏/颠倒乱码能按坑表三招定位。

约定：示例按 F103 + HAL + I2C 版写；SPI 版只讲差异（第 4 节），其余逻辑完全一致。

## 1. 从数码管到点阵屏：为什么它"自由"

> **这是什么**：数码管每个字位只有 7 段固定笔画，只能显示预定字形；点阵屏是 128×64 = 8192 个独立像素，**想显示什么就点亮哪些格子**——字符、汉字、图标、曲线都行。

类比：数码管是**七段荧光灯牌**（工厂预制的字形，只能亮那几笔）；点阵屏是**一面格子墙**（每格一个灯泡，你说了算）。

OLED 与 LCD 的区别一句话：OLED（有机发光二极管）**像素自发光**，无需背光，黑色像素完全不耗电（真黑）；LCD 靠液晶挡光 + 背光源。对本篇驱动逻辑无影响——无论 OLED 还是 LCD，MCU 侧打交道的都是那颗**驱动 IC 的显存**，学会 SSD1306 一通百通（SPI 屏 ST7735/ILI9341 是彩色版思路：1 像素从 1 bit 变 16 bit）。

主线项目里你已见过的显示链路：[03-数码管与按键](../../06-51单片机/笔记/03-数码管与按键.md)（74HC595 段码）→ 本篇点阵屏（显存+字库）→ 进阶彩色屏（深入资料提及 LVGL）。

## 2. 显存地图：1024 字节怎么来

> **这是什么**：SSD1306 内置 128×64 位显存（GDDRAM），每个 bit 对应一个像素。MCU 干的事本质就一件：**往正确位置写 bit**。

代入算例（显存大小）：

```
128 列 × 64 行 = 8192 个像素，每像素 1 bit
8192 bit ÷ 8 = 1024 字节 = 1 KB
```

**页（PAGE）结构**——显存按 8 行一组切成 8 页：

```
PAGE0  ← 第 0~7 行     每页 128 列 × 1 字节（纵向取模）
PAGE1  ← 第 8~15 行    1 个字节的 8 个 bit 对应该页同一列的 8 行
 ...                 bit0（最低位）在上，bit7 在下
PAGE7  ← 第 56~63 行
```

为什么要懂页：显存按"页地址 + 列地址"定位，后面所有代码（画点、刷屏、字库取模）都绕着"页"转。新手直接把显存想成 `uint8_t fb[8][128]` 二维数组——[页][列]，**bit 竖着排**，这是本篇帧缓冲的原型。

## 3. 总线选型：I2C vs SPI，带宽先算账

> **这是什么**：两种接法引脚数与速度不同——屏是"纯写"设备，选型核心问题就一个：**总线带宽够不够我想要的刷新率**。

| 维度 | I2C 版（4 线） | SPI 版（4~7 线） |
|------|----------------|-------------------|
| 信号线 | SCL、SDA（+VCC/GND） | SCLK、MOSI、CS、D/C（+可选 RES） |
| 速度 | 100k/400kHz | 数 MHz 起步，轻松 8MHz+ |
| 硬件占用 | 复用一条总线（可挂其他 I2C 器件） | 独占 SPI（或 CS 分片选） |
| 典型场景 | 低速 UI、菜单仪表 | 波形滚动、动效多 |

带宽代入算例（全屏刷一帧要多久）：

```
一帧数据量 = 1024 字节
I2C 每字节占 9 个时钟（8 数据 + 1 应答）
→ I2C：1024 × 9 ≈ 9216 时钟
   @100kHz：9216 ÷ 100000 ≈ 92ms/帧 → 上限约 10 fps
   @400kHz：9216 ÷ 400000 ≈ 23ms/帧 → 上限约 43 fps（还没算命令开销）
→ SPI：每字节 8 时钟 = 8192 时钟
   @8MHz：8192 ÷ 8000000 ≈ 1.0ms/帧 → 总线已不是瓶颈（上限由屏内部刷新帧率决定，查 datasheet）
```

结论（经验值口径）：菜单仪表类 UI 20~30fps 足够，I2C@400kHz 够用且省引脚——**主线默认 I2C**；要刷波形/动效再上 SPI。注意这只算了总线，没算 CPU 构帧时间（第 7 节刷新策略）。

## 4. SSD1306 怎么"说话"：控制字节与命令速查

> **这是什么**：总线传的字节分两类——**命令**（配置屏的行为）与**数据**（显存内容）。区分方式 I2C 靠控制字节、SPI 靠 D/C 引脚。

**I2C 版协议**（SSD1306 datasheet 标准内容）：

- 从机地址：7 位 `0x3C`（SA0 接地，市面模块默认；个别为 0x3D）。HAL 用 8 位写地址 = `0x3C << 1 = 0x78`；
- **控制字节**：每笔传输紧跟地址的首字节——`0x00` 表示后面全是命令，`0x40` 表示后面全是显存数据。

**SPI 版差异**：没有控制字节，靠 **D/C 引脚电平**区分——低 = 命令，高 = 数据；CS 片选拉低有效；时序上 SCLK 空闲电平高低均可工作（常见配 Mode 0 或 Mode 3），**以 datasheet 时序图为准**。其余驱动逻辑与 I2C 版完全相同。

核心命令速查表（均为 SSD1306 标准命令；完整表查 datasheet，通用初始化序列以上游开源库为准）：

| 命令 | 参数 | 作用 |
|------|------|------|
| 0xAE / 0xAF | — | 显示关 / 显示开（初始化末尾再开） |
| 0x8D | 0x14 / 0x10 | **充电泵开 / 关**（OLED 需内部升压，不开屏全黑——头号坑） |
| 0x81 | 0x00~0xFF | 对比度（跟随参数字节，越大越亮） |
| 0xA0 / 0xA1 | — | 段重映射：左右正常 / 左右翻转 |
| 0xC0 / 0xC8 | — | COM 扫描方向：上下正常 / 上下翻转 |
| 0xB0~0xB7 | — | 页地址（页寻址模式下选当前页） |
| 0x00~0x0F | — | 列地址低 4 位 |
| 0x10~0x1F | — | 列地址高 4 位 |
| 0xA8 | 0x3F | 复用率（128×64 用 0x3F；128×32 屏用 0x1F，引脚配置配 0x02） |
| 0xDA | 0x12 | COM 引脚硬件配置（128×64 用 0x12） |
| 0xA6 / 0xA7 | — | 正常显示 / 反色显示 |

记住 A1/C8 这对"翻转"命令——屏装反方向时它们就是调试神器（第 6 节取模调试三招）。

## 5. 驱动代码逐段拆解（I2C + HAL）

> **这是什么**：最小可用驱动的四件套——写命令、刷帧、画点、初始化。每段拆"为什么这么写"。

```c
/* ---------- 帧缓冲：显存在 RAM 里的镜像，[页][列]，bit0 在上 ---------- */
static uint8_t oled_fb[8][128];                 /* 1KB，占 F103C8T6 的 20KB RAM 的 5% */

/* ---------- 写命令：控制字节 0x00 + 命令 ---------- */
static void OLED_WriteCmd(uint8_t cmd)
{
    uint8_t buf[2] = {0x00, cmd};               /* 0x00 = 后面跟命令 */
    HAL_I2C_Master_Transmit(&hi2c1, 0x78, buf, 2, 10);   /* 0x78 = 0x3C<<1 */
}

/* ---------- 刷屏：逐页搬运（页寻址模式写满一页不会自动跨页！） ---------- */
void OLED_Flush(void)
{
    for (uint8_t page = 0; page < 8; page++) {
        OLED_WriteCmd(0xB0 + page);             /* 选页 */
        OLED_WriteCmd(0x00);                    /* 列地址低 4 位 = 0 */
        OLED_WriteCmd(0x10);                    /* 列地址高 4 位 = 0 */
        /* Mem_Write 技巧：首字节 0x40 当"内存地址"发出（=控制字节·数据流），
           其后 128 字节连续写进本页显存——一页一事务 */
        HAL_I2C_Mem_Write(&hi2c1, 0x78, 0x40, I2C_MEMADD_SIZE_8BIT,
                          oled_fb[page], 128, 20);
    }
}

/* ---------- 画点：y>>3 定页、y&7 定页内行位 ---------- */
void OLED_DrawPixel(int x, int y, int on)
{
    if (x < 0 || x >= 128 || y < 0 || y >= 64) return;   /* 越界保护 */
    uint8_t mask = (uint8_t)(1u << (y & 7));             /* 1 << (y%8)：页内第几位 */
    if (on) oled_fb[y >> 3][x] |= mask;                  /* 亮：置 1 */
    else    oled_fb[y >> 3][x] &= (uint8_t)~mask;        /* 灭：清 0 */
}
```

逐段为什么：

- **帧缓冲先行**：不直接往屏写——先在 RAM 改，改完一次 Flush。原因：① 页寻址下随机画点要反复设地址，RAM 里随便改；② 整帧连续传输带宽利用率高；③ 双缓冲防撕裂的地基（第 7 节）；
- **y >> 3 与 y & 7**：除以 8 和取余 8 的位运算写法（等价于 y/8、y%8）——y=13 的点落在 PAGE1（13/8=1）第 5 位（13%8=5），代入走一遍就懂；
- **Flush 逐页写**：页寻址模式下列地址写满一页**不会自动跳下一页**（这是和"一枪刷 1024 字节"直觉相反的地方）。想一枪刷完需先用 0x20 命令切到水平/垂直寻址模式——开源库里两种实现都有，本篇用逐页（模式零配置，行为最直观）；
- **边界检查别省**：y=64 会写到 PAGE8——越出 fb 数组，内存越界。

**初始化要点序列**（顺序即流程；每条命令的含义查第 4 节速查表，完整序列以上游库/datasheet 为准）：

```c
void OLED_Init(void)
{
    /* 若模块 RES 引脚接了 MCU：拉低数 µs 再拉高并延时——复位时序以 datasheet 为准 */
    OLED_WriteCmd(0xAE);        /* 先关显示，配参数时不闪花屏 */
    OLED_WriteCmd(0xA8); OLED_WriteCmd(0x3F);   /* 复用率：64 行 */
    OLED_WriteCmd(0xDA); OLED_WriteCmd(0x12);   /* COM 引脚配置 */
    OLED_WriteCmd(0xA1);        /* 段重映射（方向不对就换 A0/A1） */
    OLED_WriteCmd(0xC8);        /* COM 扫描方向（上下反了就换 C0） */
    OLED_WriteCmd(0x8D); OLED_WriteCmd(0x14);   /* 充电泵开——忘这条屏全黑 */
    OLED_WriteCmd(0x81); OLED_WriteCmd(0xCF);   /* 对比度 0~255 自调 */
    OLED_Flush();               /* 清一帧（fb 已是 0）避免上电雪花 */
    OLED_WriteCmd(0xAF);        /* 最后开显示 */
}
```

## 6. 字符显示与取模：字库怎么来

> **这是什么**：画点画不出字——字符靠**字库**（预先取模好的点阵数据表）批量搬运。取模 = 把字形翻译成"显存字节"。

**8×16 ASCII 字库的结构**（F8X16 的组织方式，开源库通用口径）：

```
每个字符 16 字节：前 8 字节 = 上半（PAGE y/8 的 8 列），后 8 字节 = 下半（PAGE y/8+1 的 8 列）
数组下标：F8X16[(ch - ' ') * 16] —— 从空格(0x20)起，可打印字符共 95 个 → 95×16 ≈ 1.5KB Flash
```

```c
void OLED_PutChar8x16(int x, int y, char ch)     /* 要求 y 是 8 的倍数（页对齐） */
{
    const uint8_t *p = &F8X16[(ch - ' ') * 16];
    for (int i = 0; i < 8; i++) {
        oled_fb[y / 8][x + i]     = p[i];        /* 上半 8 列直接覆盖页 */
        oled_fb[y / 8 + 1][x + i] = p[8 + i];    /* 下半 8 列 */
    }
}

void OLED_PutString8x16(int x, int y, const char *s)
{
    while (*s) { OLED_PutChar8x16(x, y, *s++); x += 8; if (x > 120) break; }
}
```

（工程版给 x/y 补上边界判断；这里为聚焦取模结构做了精简。字库数组 `F8X16` 本体**不手打**——用取模软件生成。）

**取模要点**（生成 8×16 字库的设置口径）：

| 设置项 | 取值 | 对应显存的什么 |
|--------|------|----------------|
| 取模方向 | 纵向/列行式（每 8 行一节，从上到下） | 页结构：1 字节 = 1 列的 8 行 |
| 字节内位序 | bit0 在上（低位在上） | 显存 bit0 对应该节最上行 |
| 输出 | 阴码/阳码与"亮点为 1"口径按软件预览校验 | 亮点 = 1 |

常用取模软件如 PCtoLCD2002；**不同软件选项名不同，别背选项名——刷一帧校验**：显示上下颠倒或左右镜像，就是取模方向/位序口径与屏不匹配（下一条教你怎么调）。

**方向不对的三招调试**（按序试，多数在第一招就解决）：

1. 命令翻转：0xA0↔0xA1（左右）、0xC0↔0xC8（上下）——改驱动不改字库；
2. 换取模方向：纵向↔横向、顺向↔倒序——重新生成字库；
3. 都不对：大概率初始化序列抄漏（0xA1/0xC8 这两条被删了），回第 5 节对清单。

**中文怎么显示**：16×16 点阵汉字每字 32 字节（16 列 × 2 字节/列，两页高）。Flash 账代入算例：常用 100 字 × 32B = 3.2KB——F103C8T6 的 64/128KB Flash 放得下，**但字库按项目实际用字生成**（全字库几 MB 放不下，除非外挂 SPI Flash 存字库文件）。

## 7. 刷新策略：全屏、局部、双缓冲与节拍

> **这是什么**：驱动跑通后的工程问题——什么时候刷、刷多少、怎么不花屏。

| 策略 | 做法 | 适用 | 代价 |
|------|------|------|------|
| 全屏定时刷 | 固定节拍整帧 Flush | 菜单/仪表（内容全变也无所谓） | 带宽占用大（I2C 一帧 23ms，第 3 节算例） |
| 有变化才刷 | 内容改了置脏标志，下个节拍 Flush | 低频 UI（省带宽省电） | 需要维护脏标志 |
| 局部刷新 | 只 Flush 变化的页（记录哪页脏） | 波形/进度条等区域更新 | 逻辑最复杂，收益最大 |
| 双缓冲 | RAM 开两份 fb，画完互换再刷背板 | 动效/波形防撕裂 | RAM ×2（2KB），F103C8T6 仍可承受 |

**节拍怎么定**（经验值口径）：UI 类 20~30fps 足够——FreeRTOS 周期任务 33~50ms 一次 Flush 即可；别在中断里刷屏（毫秒级传输压死实时性，ISR 纪律见 [05-内存管理与中断处理](../../08-FreeRTOS/笔记/05-内存管理与中断处理.md)）。

**多任务共享总线**：I2C 上若还挂了传感器（如 [02-传感器应用专题](02-传感器应用专题.md) 的 SHT30），屏任务与采集任务并发使用同一 I2C 会互踩——**用互斥量把"一笔完整传输"保护成原子段**（毫秒级长临界区，用互斥量而非关中断，语义辨析见 [03-信号量与互斥量](../../08-FreeRTOS/笔记/03-信号量与互斥量.md)）。

**花屏/撕裂的根因**：单缓冲下，Flush 写到一半，屏的内部扫描正扫到那几行——半新半旧。全屏定时刷对低速 UI 可接受；不能接受就双缓冲（背板画完一帧再整帧搬）。**撕裂是"显示时序"问题，不是"代码写错"**——别在驱动层瞎找 bug。

## 8. 核心 API 三要素速查

| API | 是否阻塞 | 时间单位 | 能否在 ISR 中用 |
|-----|----------|----------|-----------------|
| HAL_I2C_Master_Transmit（写命令用） | 阻塞（至完成或超时） | 超时参数 ms | 不能 |
| HAL_I2C_Mem_Write（刷页用） | 阻塞（至完成或超时） | 超时参数 ms | 不能 |
| HAL_I2C_Mem_Write_IT / _DMA | 非阻塞，完成回调 I2C_MemTxCpltCallback | — | 启动可，回调在 I2C 中断上下文 |
| OLED_Flush（本篇，内部 8 笔阻塞传输） | 阻塞约 23ms（I2C@400kHz，第 3 节算例） | ms | 不能——放任务节拍里 |

主线建议：先把阻塞版跑通理解全链，确有实时性需求再换 DMA 版——"能用阻塞版讲清原理"比"一上来就 DMA"学得扎实。

## 常见坑（新手必看）

1. **上电全黑**：按序排查——I2C 地址错（0x3C/0x3D、HAL 要 0x78/0x7A）、**充电泵 0x8D 0x14 没发**、最后忘了 0xAF、初始化顺序乱（AF 要在末尾）——九成全黑是这四个；
2. **字库镜像/颠倒**：取模方向、位序、初始化里的 A1/C8 三处口径不一致——第 6 节三招，先命令后字库；
3. **Flush 假设"写满自动跨页"**：页寻址模式一页写满停在页末，必须逐页设地址——想跨页连续写要 0x20 切水平寻址模式；
4. **总线挂死（SDA 被拉死）**：屏或传感器在传输中途复位/受扰，从机卡死等待位——I2C 复位后先做 9 个 SCL 时钟 + STOP 的总线恢复流程再重连（恢复流程见 09-通信协议 I2C 相关篇）；
5. **多任务互踩总线**：屏与传感器并发用 I2C 出"偶发乱码/设备无响应"——互斥量保护整笔传输（第 7 节）；
6. **中断里刷屏**：23ms 的阻塞传输放 ISR，系统实时性直接报废——刷屏永远放任务节拍（ISR 纪律见 [05-内存管理与中断处理](../../08-FreeRTOS/笔记/05-内存管理与中断处理.md)）；
7. **电平与供电想当然**：模块逻辑 3.3V 口径，5V 单片机直连 IO 前确认模块是否 5V 容忍——不确定就上电平转换，模块供电电压以模块规格为准（不编造具体型号参数）。

## FAQ

**Q：屏只亮背光/全黑但 I2C 有 ACK，命令都发了怎么不显示？**
A：ACK 只说明地址通了。按坑 1 四项过一遍，最常见是充电泵参数（0x8D 后必须跟 0x14）漏发或顺序错。

**Q：为什么我抄的开源库初始化命令和你的不一样？**
A：SSD1306 初始化序列存在多种"都能亮"的写法（时钟分频、对比度、显示偏移等参数各家取值不同）——只要覆盖第 4 节核心命令且顺序合理即可，以 datasheet 完整命令表为最终依据，不迷信某一份序列。

**Q：一枪 1024 字节刷全屏行不行？**
A：可以——先发 0x20 0x00（水平寻址模式）再连续写，省 7 笔事务开销；但页寻址模式（本篇主线）行为最直观、移植性最好。两种都对，看你的库选了哪条路。

**Q：OLED 会不会烧屏/寿命问题？**
A：OLED 有像素老化特性（长时间高对比度静态画面留残影），工程上用屏保/降对比度/定时休眠缓解——具体寿命与使用条件以厂商规格为准【待查证：不同厂商差异大，无统一数值】。这也是低功耗项目让屏"该睡就睡"的另一个理由（见 [03-低功耗设计实战](03-低功耗设计实战.md)）。
