# 03 · 低功耗设计实战

> 定位：主线 [07-STM32](../../07-STM32/笔记/00-目录与学习路线.md) 教你"把外设跑起来"，本篇教你"把电流降下去"——电池供电项目的工程主战篇。触发点：学完 07-STM32 的时钟树（/01）、定时器 PWM（/03）、系统功能（/08）之后，手里正要做或已做一个电池供电设备。

**先说人话**：本篇讲什么，学完能做什么——

STM32 有三种"睡觉姿势"：Sleep（打盹）、Stop（关灯睡觉）、Standby（断电假死）。本篇把这三种姿势的"关了什么、保了什么、怎么叫醒、代价是什么"一次讲透，配上可直接抄的 Stop 进出代码、一套"睡→醒→采→发→睡"的标准工作流，最后用代入算例算清一块 500mAh 电池能撑多久，并教你怎么用万用表实测静态电流。学完你能独立做出"周期唤醒采集器"级别的低功耗设计：续航估算有理有据，实测验证不掉链子。

联动分工：LDO/DC-DC 怎么选（含静态电流 Iq）在 [01-电源设计进阶](01-电源设计进阶.md)；传感器怎么挑、ADC 怎么采在 [02-传感器应用专题](02-传感器应用专题.md)；本篇只管"睡觉的艺术"。

## 1. 低功耗设计到底在设计什么

> **这是什么**：低功耗设计 = 让电池设备"该干活时全力干活，不该干活时立刻睡觉"，把每一毫安时都花在刀刃上。

类比：把设备想成一家 24 小时便利店——营业额（有效工作）只集中在几个客峰时段，其余时间开着全部灯和冰柜就是纯烧钱。低功耗设计的核心动作就两个：

1. **没人时关灯**（睡眠模式 + 时钟门控 + 外设掉电）；
2. **客人来了快速服务完继续关灯**（缩短"醒着的工作时间"）。

先立一个反面认知：低功耗不是"全程慢速跑"——一直以 8MHz 慢跑 24 小时，往往不如"72MHz 全速干 0.5 秒 + Stop 睡 29.5 秒"省电。**平均电流才是续航唯一的账**（第 7 节正式算给你看）。

## 2. 功耗从哪来：一个公式看清两条路

> **这是什么**：数字电路功耗分两块——**动态功耗**（信号翻转时的充放电）和**静态功耗**（漏电流，芯片"睡着"也在漏）。

动态功耗近似公式：

```
P ≈ C × V² × f
C：被充放电的等效负载电容；V：供电电压；f：翻转频率
```

代入算例（理论示意）：单个等效负载 C = 20pF、V = 3.3V、f = 72MHz：

```
P = 20×10⁻¹² × 3.3² × 72×10⁶ = 20×10⁻¹² × 10.89 × 72×10⁶ ≈ 15.7 mW
```

（这是"单个等效翻转节点"的量级示意，不等于整颗芯片功耗；整芯片数值一律以 datasheet 为准。）

从公式能直接读出三条省电路径，狠程度排序：

| 手段 | 对公式的效果 | 直觉 |
|------|-------------|------|
| 降电压 | V² 项：电压减半，功耗变 1/4 | 最狠，但受工艺与外设约束 |
| 降频率 | f 项：频率减半，功耗减半 | 但活也干得慢，只适合持续型负载 |
| 睡觉（停时钟） | f → 0，动态功耗归零 | 只剩静态漏电，µA 级——本篇主角 |

**结论**：对突发型负载（采集一下、发包一下），"睡"永远比"慢"划算；"慢"只对持续型负载有意义。

## 3. STM32 的三种睡觉姿势（模式选型）

> **这是什么**：以 F103 为例（其他系列逻辑相同、数值各异，一律以对应参考手册 PWR 章节与 datasheet 电源特性表为准），三种模式逐级"关得更狠、丢得更多"。

| 模式 | 关掉什么 | 保住什么 | 典型唤醒方式 | 醒来后从哪继续 | 功耗量级 |
|------|----------|----------|--------------|----------------|----------|
| Sleep 睡眠 | 只停 CPU 内核时钟 | 全部外设、SRAM、寄存器 | 任意中断 | 入睡处的下一条指令 | mA 级 |
| Stop 停止 | 1.8V 域全部时钟（HSI/HSE/PLL 全停） | SRAM、寄存器全部内容 | EXTI 线：GPIO 外部中断、RTC 闹钟等 | 入睡处的下一条指令，**但时钟要重配** | µA 级（个位~几十 µA 量级，以 datasheet 为准【待查证】） |
| Standby 待机 | 1.8V 域整体断电 | 仅备份域（RTC、备份寄存器） | WKUP 引脚（F103 为 PA0）上升沿、RTC 闹钟、IWDG、NRST | **等于复位重启**，SRAM/寄存器全丢 | 更低（µA 以下量级，以 datasheet 为准） |

一句话记忆：**Sleep 是打盹（谁都能叫醒），Stop 是关灯睡（留了记忆，醒来要重新开灯），Standby 是假死（只留纸条，醒来当新的一天）。**

选型决策表（按"多久醒一次 + 醒来要不要接着跑"）：

| 场景 | 选型 | 理由 |
|------|------|------|
| 闲不住，亚秒级就要响应（按键扫描、短间隔广播） | Sleep 或浅 Stop | 唤醒代价要低，Sleep 醒来直接续跑 |
| 周期性干活，秒~分钟级一次（定时采集上报） | Stop + RTC 闹钟 | 主角场景，第 5 节标准工作流 |
| 一睡几分钟~几小时，醒来从头上电初始化无所谓 | Standby | 最省，代价是"失忆" + 重启耗时 |

唤醒时间定性排序：**Sleep < Stop < Standby**（Sleep 随叫随到；Stop 要等时钟重新起振稳定，µs~ms 量级；Standby 走完整复位启动流程，最长）——具体数值查所用型号 datasheet 时序特性表，不背数字。

## 4. Stop 模式代码拆解（HAL 版）

> **这是什么**：进入/退出 Stop 的标准三段式：睡前收尾 → WFI 入睡 → 醒后重配时钟。逐段拆为什么。

```c
/* ---------- ① 睡前收尾：处理掉"会吵醒你"和"会漏电"的 ---------- */
PWR_EnterStop_PrepareGpio();              /* 自写函数：未用 GPIO 配模拟输入防漏电（见坑 2） */

/* ---------- ② 入睡 ---------- */
HAL_SuspendTick();                        /* SysTick 停发中断——它不停，WFI 会 1ms 被叫一次，白睡 */
HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, PWR_STOPENTRY_WFI);
/* CPU 在 WFI 指令处挂起，直到 EXTI 线上有中断/事件…… */

/* ---------- ③ 醒来：第一件事是重配时钟！ ---------- */
SystemClock_Config();                     /* Stop 醒来后系统时钟回落到 HSI，必须重配！ */
HAL_ResumeTick();                         /* 恢复 SysTick，HAL_Delay 才能正常工作 */
if (__HAL_PWR_GET_FLAG(PWR_FLAG_WU)) {
    __HAL_PWR_CLEAR_FLAG(PWR_FLAG_WU);    /* 清唤醒标志，为下一次入睡做准备 */
}
/* 代码从这里继续往下跑——SRAM/寄存器都还在，现场没丢 */
```

逐段为什么：

- `HAL_SuspendTick()`——SysTick 每 1ms 一次中断；不停它，刚 WFI 就被叫醒，睡了等于没睡；
- `PWR_STOPENTRY_WFI`——用 WFI（等待中断）进入；另有 WFE（等待事件）变体，本篇主线用 WFI 即可；
- `SystemClock_Config()`——**最容易漏的一行**：Stop 把 PLL 全停了，醒来后芯片跑在默认 HSI 上，波特率、定时器周期全错位（坑 1）；
- 唤醒标志——区分"正常唤醒"与"复位启动"，在 Standby 流程里它就是"我是被闹钟叫醒的还是上电的"判据。

API 三要素（本篇两个核心调用）：

| API | 是否阻塞 | 时间单位 | 能否在 ISR 里用 |
|-----|----------|----------|-----------------|
| HAL_PWR_EnterSTOPMode | 阻塞（睡到被唤醒为止） | 无单位（时长由唤醒源决定） | 不能（ISR 里"睡觉"没有意义） |
| HAL_PWR_EnterSTANDBYMode | 阻塞（调用后等待复位唤醒） | 无单位 | 不能 |

## 5. 周期唤醒的标准工作流（RTC + Stop）

> **这是什么**：电池采集器的骨架流程——用 RTC 闹钟当"闹钟人"，设备绝大部分时间睡在 Stop 里，到点醒来把活干完接着睡。

RTC 闹钟事件在 F103 上挂在 EXTI Line 17 上，因此能在 Stop 中唤醒芯片。标准一拍（一轮"醒着"）：

```
RTC 闹钟到点 → EXTI 唤醒（Stop 退出） → 重配系统时钟
→ 打开传感器电源（MOS 高边开关） → 等传感器稳定 → ADC 采集
→ 打包数据 → 打开无线模块 → 发送 → 全部关掉
→ 设下一次闹钟 → HAL_SuspendTick + EnterSTOPMode → 睡
```

代码骨架（任务级，可移植）：

```c
for (;;) {
    work_once();                         /* 采数 + 发送（醒着的全部工作） */
    RTC_SetNextAlarm(10);                /* 10 秒后叫醒我 */
    HAL_SuspendTick();
    HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, PWR_STOPENTRY_WFI);
    SystemClock_Config();                /* 醒来第一件事 */
    HAL_ResumeTick();
}
```

**这条流水线的总账**：醒着多久（工作电流 × 时间）+ 睡着多久（睡眠电流 × 时间），摊到整个周期上就是平均电流——第 7 节正式算。

## 6. 省电组合拳：睡觉之外的五件事

1. **降主频**：轻负载阶段切到低速时钟源，干完再切回来——切频后所有依赖时钟的外设参数（波特率、定时器周期）要联动重算，联动关系见 [01-工程建立与时钟树](../../07-STM32/笔记/01-工程建立与时钟树.md)；
2. **关外设时钟**：RCC 的 AHB/APB 时钟门控——不用就关，外设时钟开着即使"没干活"也在漏；
3. **GPIO 防漏电**：未用引脚配成**模拟输入**（防漏电标准做法）；已用引脚按外接电路决定拉死电平——悬空引脚在 Stop 下可能被外部电路倒灌出 mA 级电流（坑 2）；
4. **外设掉电**：传感器有 PD/EN 引脚就接 GPIO 拉低断电；没有就用 MOS 管高边开关直接切断电源轨（选型见 [07-工业常用元器件速查手册](../../02-电路基础/笔记/07-工业常用元器件速查手册.md) 的 MOS 行）；
5. **电源器件本身**：LDO 的静态电流 Iq 24 小时都在吃电池——电池设备选低 Iq 的 LDO（µA 级），对比与计算在 [01-电源设计进阶](01-电源设计进阶.md)。

## 7. 电池续航代入算例（三档对比）

> **这是什么**：低功耗设计的"总账公式"——平均电流法。一阶估算足够指导选型方向，正式设计再留余量。

**平均电流 =（工作电流 × 工作时间 + 睡眠电流 × 睡眠时间）÷ 周期；续航 = 可用电量 ÷ 平均电流。**

设定（经验假设，已注明）：500mAh 标称锂电池，考虑 LDO 压差与保护板损耗按 80% 可用 → **400mAh 可用**（经验值）；工作电流 100mA（采集 + 无线发送），工作时长 0.5 秒；睡眠电流 20µA（Stop 模式实测口径，以实测为准）。

三档对比：

| 策略 | 每周期耗电（工作 + 睡眠） | 平均电流 | 400mAh 续航 |
|------|---------------------------|----------|-------------|
| A：全程不睡（基准） | — | 100mA | 400÷100 = **4 小时** |
| B：每 10 秒醒一次，睡 9.5s | 100mA×0.5s + 0.02mA×9.5s = 50.19 mA·s | 50.19÷10 ≈ **5.02mA** | 400÷5.02 ≈ 80h ≈ **3.3 天** |
| C：每 30 秒醒一次，睡 29.5s | 100mA×0.5s + 0.02mA×29.5s = 50.59 mA·s | 50.59÷30 ≈ **1.69mA** | 400÷1.69 ≈ 237h ≈ **9.9 天** |
| D：10 秒周期不变，工作电流减半 | 50mA×0.5s + 0.02mA×9.5s = 25.19 mA·s | 25.19÷10 ≈ **2.52mA** | 400÷2.52 ≈ 159h ≈ **6.6 天** |

读表三条工程结论（以本工况为例）：

1. **拉长唤醒周期 > 降低工作电流 > 降低睡眠电流**：周期×3（B→C）续航约×3；工作电流减半（B→D）续航仅约×2；而睡眠电流从 20µA 压到 10µA 对总账影响微乎其微（50.19→50.095 mA·s）；
2. **睡眠电流是"地板"不是"天花板"**：它决定下限，但真正拉开差距的是"多久醒一次、醒了干多久"；
3. **一阶估算要留余量**：无线峰值、电池内阻、低温衰减都没算——正式产品按算得的 1/2 余量做预算（经验值）。

## 8. 静态电流怎么测

| 测什么 | 怎么测 | 注意 |
|--------|--------|------|
| 睡眠电流（µA 级） | 万用表 µA/mA 档串进电源回路，设备进入 Stop 后读数 | µA 档内阻大，量程选错会把设备"拉欠压复位"——从 mA 档逐步降档 |
| 动态平均电流 | 采样电阻（如 1~10Ω）串入 + 示波器测压降，或电流采样型功耗分析仪 | 捕捉"醒着的 0.5 秒"电流形状，比只看平均值更有诊断价值 |
| 分段排查 | 先测"纯 MCU 睡"的板子，再逐个装回外设，看谁漏电 | 9 成情况漏电大头在板级（上拉电阻、LED、传感器没掉电），不在芯片本体 |

对照基准：datasheet 电源特性表里"芯片本体"的典型电流只是**守门员线**——整机实测比它大是常态，要查的是板级链路。

## 常见坑（新手必看）

1. **醒来不重配时钟**：Stop 醒来系统时钟回落 HSI，波特率/定时器全错位、串口乱码——唤醒后第一行代码永远是 `SystemClock_Config()`；
2. **GPIO 悬空漏电**：未用引脚浮空，或外部电路经引脚倒灌，Stop 电流从 µA 级飙到 mA 级——睡前统一处理 GPIO；
3. **调试器插着测不准/进不去**：DBGMCU 调试位会阻止时钟停止——测静态电流必须断开 SWD 脱机测；
4. **忘 HAL_SuspendTick/ResumeTick**：SysTick 把 WFI 秒叫醒（白睡），或醒来后 HAL_Delay 永远卡死；
5. **Standby 醒来变量"清零"**：SRAM 已丢——跨 Standby 存数据只能用备份域（RTC 备份寄存器）；设计期就决定"醒来从头上电"是否可接受；
6. **中断标志没清就睡**：pending 标志会让 WFI 立刻返回——睡前清干净；
7. **拿 datasheet 典型值当整机电流**：芯片本体 ≠ 整机，上拉电阻、LED、LDO 的 Iq、传感器静态功耗都是"隐藏食客"——以整机实测为准。

## FAQ

**Q：Stop 模式下串口还能收数据吗？**
A：不能——Stop 把 1.8V 域时钟全停，UART 不工作。要"睡着也能收"，要么周期唤醒轮询，要么换用支持低功耗唤醒特性的串口（新系列才有），要么退回 Sleep。

**Q：FreeRTOS 下怎么睡觉？**
A：内核的 Tickless Idle：空闲任务发现下次唤醒还早，自动停 SysTick 进低功耗并补偿 tick——原理仍是 Stop+WFI，只是由内核代管（调度原理见 [01-裸机到RTOS任务与调度](../../08-FreeRTOS/笔记/01-裸机到RTOS任务与调度.md)）。

**Q：睡眠电流实测比 datasheet 大一个量级，芯片坏了？**
A：先查板级：上拉电阻的常通电流、LED、传感器没掉电、LDO 的 Iq、GPIO 倒灌——按第 8 节"分段排查"走一遍，9 成能抓到。

**Q：续航估算要不要考虑电池自放电？**
A：一阶估算不用（天~周级续航影响小）；做月~年级续航的产品要计入，按电池规格书自放电率另算【具体数值以电池 datasheet 为准】。
