## 学习节奏（约 3 周）

节奏设计的逻辑：先用"看得见的线"（串口/485）把协议设计吃透，再上"看不见的网"（以太网/WiFi）——线上的问题能用逻辑分析仪亲眼验证，是学协议最好的脚手架。

```
第1周前半：01 总论 + 02 串口协议设计（逻辑分析仪抓帧 + 状态机解析实操）
第1周中段：03 Modbus（用 USB 转 485 模块 + Modbus Poll 仿真器实操）
第1周末  ：04 USB CDC（让开发板变成免驱虚拟串口）
第2周    ：05 LwIP（W5500 或 STM32F407 以太网口，ping 通 → TCP 回显 → HTTP）
第3周    ：06 WiFi 模组 AT 流 → 07 MQTT 对接 EMQX 公共服务器，毕业项目收尾
```

## 协议选型速查（嵌入式工程师的"点菜单"）

选型心法一句话：**距离和节点数决定物理层，业务复杂度决定应用层，可靠性要求决定校验与重传**——按这三问从上往下扫这张表，答案基本唯一。

| 场景 | 选什么 | 一句话理由 |
|------|--------|-----------|
| 板间/板→PC 调试 | UART/TTL + 自定义帧 | 简单直白 |
| 工业现场远距离、抗干扰 | RS485 + Modbus RTU | 差分抗噪 + 行业事实标准 |
| 即插即用上电脑 | USB CDC 虚拟串口 | 免驱、快 |
| 板→路由器/局域网 | 以太网（LwIP/W5500） | 稳定、带宽大 |
| 无线物联网、家庭场景 | WiFi（ESP 模组） | 便宜普及 |
| 低功耗可穿戴、手机互联 | BLE 蓝牙低功耗 | 省电 |
| 万物互联云端标准 | MQTT over TCP/TLS | 发布订阅、轻量、断线友好 |

## 名词速查表

用法：背不下来没关系，学到对应篇章时回来对照，读完七篇后这张表应该能"看词说人话"。

| 名词 | 一句话解释 |
|------|-----------|
| **UART** | 异步串行通信规则：起始位+LSB 数据+校验+停止位，无时钟线靠约定波特率对表 |
| **波特率** | 每秒传的符号数（9600/115200）；两端偏差超 ±2.5% 必乱码 |
| **8N1** | 8 数据位、无校验、1 停止位——串口配置默认三字诀 |
| **起始位/停止位** | 低电平开场"对表信号" / 高电平收尾"帧结束哨" |
| **转义（透明传输）** | 数据里出现定界符时换成转义序列（0xDB 法），保证帧边界不被污染 |
| **SEQ 序号** | 帧里带流水号：应答配对、重发去重、丢包检测（TCP 序号微缩版） |
| **TTL 电平** | 芯片引脚直出的 0V/3.3V(5V) 串口电平，只能板内短距传 |
| **RS232** | ±12V 电平的 legacy 串口，点对点，电脑老 COM 口 |
| **RS485** | 差分双线（A/B），32 节点、1200 米，工业总线物理层王者 |
| **差分信号** | 用两线电压"差"表示逻辑，共模噪声被抵消。类比：双人抬杠的平衡木 |
| **半双工** | 同一时刻只能一方说（RS485 方向切换 = DE/RE 引脚控制） |
| **CRC** | 循环冗余校验：数学除法算出的"指纹"，检错率极高 |
| **Modbus** | 工业协议老大哥：主从问答式，读写"寄存器"地图 |
| **保持寄存器/线圈** | Modbus 四张表：线圈(开关量写)、离散输入(开关量读)、输入寄存器(模拟量读)、保持寄存器(模拟量读写) |
| **AT 指令** | 模组的"遥控命令行"：AT+XXX 格式，串口发文本命令控模组 |
| **透传模式** | 模组变身"网线"：串口进 WiFi 出，MCU 无感联网 |
| **LwIP** | 嵌入式轻量 TCP/IP 协议栈（Lightweight IP） |
| **Socket** | 网络编程抽象句柄：IP+端口 定位一个"对话" |
| **TCP/UDP** | 可靠有序（打电话）/ 快而不可靠（寄平信） |
| **MQTT** | 发布/订阅消息协议：设备把话题发 Broker，订阅者自动收 |
| **QoS** | MQTT 质量等级：0 至多一次 / 1 至少一次 / 2 恰好一次 |
| **遗嘱消息（LWT）** | 客户端异常掉线时 Broker 代发的"讣告" |
| **枚举（USB）** | 插入后主机问"你是谁"→设备报身份→分配地址的全过程 |
| **CDC** | USB 通信设备类：让板子冒充"虚拟串口"免驱 |
| **BLE** | 蓝牙低功耗：广播+连接两态，秒连省电 |

## FAQ

**Q1：为什么先学 Modbus 而不是先学联网？**
Modbus 是"协议怎么设计"的最佳教材（帧结构/CRC/超时/主从模型一应俱全），且工业岗位几乎必考；学会了它，再理解 MQTT/HTTP 的协议设计会非常顺。

**Q2：LwIP 用哪个 API 入门？**
**Socket API** 入门（与 Linux 网络编程同构，四大件理论直接对接）；raw API 性能最高但回调地狱，进阶再看。

**Q3：模组方案和自带 WiFi 的芯片（ESP32 当主控）怎么选？**
现有 STM32 工程加联网 → AT 模组方案（本路线主线）；新项目且联网是核心 → ESP32 直接当主控（它本身就能跑 FreeRTOS）。
