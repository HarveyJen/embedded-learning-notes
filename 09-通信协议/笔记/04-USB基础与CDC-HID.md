# 04 · USB 基础与 CDC/HID：让电脑"即插即认"

> 目标：理解 USB 主从架构与枚举流程，用 STM32 USB 设备库实现 CDC 虚拟串口（免驱）与 HID（免驱键鼠），看懂"插上就亮"背后的握手大戏。

## 1. USB 是什么：严格的"主仆社会"

这是什么：串口世界人人平等、随时说话；USB 世界恰恰相反——**主机永远先开口，设备永远等点名**。这套看似霸道的规矩换来的是即插即用：插上就认、自动配驱动、统一供电。本篇就是看懂"插上就亮"背后的握手大戏。

**USB = Universal Serial Bus**，核心规则：**永远一个主机（Host）多个设备（Device）**。

- 主机独掌大权：分配地址、发起一切传输、供电（5V/500mA 起步）；
- 设备只能"被问才答"（**轮询式**，与 UART 设备随时插话完全不同）；
- 类比：**公司前台总机**——所有电话（数据）都由总机（主机）主动拨出转接，分机（设备）不能直接互拨。

| 版本 | 速率 | 嵌入式用途 |
|------|------|-----------|
| USB 1.1 Full-Speed | 12 Mbps | STM32F103/F407 设备口，CDC/HID 主战场 |
| USB 2.0 High-Speed | 480 Mbps | STM32F4 HS 内置 PHY / F105-107 + 外部 PHY |
| USB 3.x | 5~20 Gbps | 嵌入式设备侧少见，了解即可 |

**四线制**：VBUS(5V)、D+、D−（差分对，又是差分！01 篇抗干扰思想复用）、GND。

**速度自协商的小心机**：设备在上 D+（全速）或 D−（低速）接 1.5kΩ 上拉电阻——主机看哪根线被拉高就知道你是谁，这就是"插入瞬间"主机感知你的方式。

这是硬件面试小考点：同一颗芯片想报"全速"还是"低速"，取决于**软件把上拉接到哪个引脚**（STM32 内置收发器已自动处理，但画板/排查时要知道"D+ 上拉=全速"的约定；全速/高速的进一步协商发生在复位期间，学 CDC/HID 阶段不用深究）。

## 2. 枚举：插上电脑后 1 秒内的对话剧本

枚举（Enumeration）= 主机认亲全过程，**面试与调试的关键知识点**：

```
① 检测插入：主机发现 D+ 被拉高 → "有新设备！"
② 复位设备：主机把总线拉 SE0（D+D- 同时低）>10ms → 设备回到默认地址 0
③ GetDescriptor(设备描述符)：主机问"你是谁？"→ 设备报 VID/PID/版本
④ 分配地址：SetAddress(5) → 设备从今往后叫"5号"
⑤ GetDescriptor(配置/字符串...)：主机翻你的"简历"——有几个接口、什么类、要多少电流
⑥ SetConfiguration(1)：主机说"就按 1 号配置上岗"→ 设备点亮工作指示
⑦ 完事：设备管理器里出现"USB 串行设备"或"自定义 HID 设备"
```

**按时间线逐句拆**（每步一句话：谁在做什么）：

```
① 主机：发现 D+ 被 1.5kΩ 上拉 → 触发中断 → "有人插进来了"
② 主机：把 D+/D− 同时拉低超过 10ms（SE0 复位信号）→ 设备：恢复出厂设置（回默认地址 0）
③ 主机：对地址 0 问"你是谁"（GetDescriptor）→ 设备：交出设备描述符（VID/PID/版本）
④ 主机：发一个编号（SetAddress 5）→ 设备：从这一刻起只应答"5 号"的呼唤
⑤ 主机：继续问"你会干什么"（读配置/接口/字符串描述符）→ 设备：交简历（几个接口、什么类、耗电多少）
⑥ 主机：拍板"按 1 号配置上岗"（SetConfiguration）→ 设备：点亮端点、进入工作状态
⑦ 主机：加载对应驱动 → 电脑上冒出"USB 串行设备 (COMx)"
```

一句话总结：**复位认亲 → 报身份 → 领工牌 → 交简历 → 正式上岗**。任何一步答错或答慢，枚举失败——设备管理器只会给你一个冷冰冰的"未知设备"。

**描述符（Descriptor）= 设备的自我介绍文档**，从大到小：设备→配置→接口→端点（EP）。CDC 虚拟串口要两个接口（控制+数据），HID 还要一份"报告描述符"（后面讲）。

类比：把枚举想成**新员工入职**——交身份证（设备描述符）→ 发工牌（SetAddress）→ 交简历定岗位（配置/接口描述符）→ 正式上岗（SetConfiguration）。描述符一层套一层（设备里含配置、配置里含接口、接口里含端点），主机像 HR 一样逐层翻阅。

**调试利器**：Windows 上用 **USBlyzer / Bus Hound**（或 Linux `lsusb -v`）看枚举全过程——枚举卡在哪一步，问题就在哪个描述符。

## 3. 端点与四种传输类型

这是什么：过了"枚举面试"，主机得知道**往哪儿投递数据、用什么方式投**。端点就是设备里一个个编号的收发窗口（EP0 是面试专用窗口，其余 EP 是干活的窗口），传输类型则是四种"快递方式"——有的要稳、有的要快、有的要保时效。

端点（Endpoint）= 设备里的"收发窗口"，每个有方向和类型：

| 类型 | 特点 | 典型用途 |
|------|------|----------|
| **控制传输 EP0** | 枚举+配置专用，所有设备必有 | 描述符读写、SetAddress |
| **批量传输 Bulk** | 大数据、无超时保证、错误重发 | CDC 虚拟串口、U 盘 |
| **中断传输 Interrupt** | 主机周期轮询、保证延迟 | HID 键鼠、传感器小包 |
| 等时传输 Isochronous | 保带宽不重传（丢就丢） | 音频/摄像头流 |

记忆：**控制管身份、批量搬大货、中断保时效、等时弃重传**。

## 4. CDC：把 STM32 变成免驱虚拟串口

这是什么：CDC 是 USB 官方定义的"通信设备"角色扮演模板——照着模板填描述符，电脑就把你的 STM32 当成一根虚拟串口线，老软件（串口助手、上位机）零改动直接用，还不用装驱动。

CDC（Communications Device Class）= USB 委员会定义的"通信设备"类。CDC-ACM 方案让 Win10+/Win11/macOS/Linux **免驱**识别为虚拟 COM 口——替代 CH340 芯片的板载方案（LX-750PLUS BOM 里的 CH340 就是干这个的外置芯片，板载 USB 设备口可以自己实现）。

**结构**：两个接口——通信接口（EP0 控制类请求）+ 数据接口（EP1 IN / EP1 OUT 两个 Bulk 端点）。

**CubeMX 步骤**（F103/F407 通用）：
```
① Connectivity → USB → 勾 Device(FS)
② Middleware → USB_DEVICE → Class 选 Communication Device Class (CDC/Virtual Port)
③ 时钟树确认 48MHz 给 USB（F103 必须精确 48MHz！HSE 8M×9=72MHz 经 1.5 分频（USBPRE=0）得到 48MHz USB 时钟）
④ 生成代码 → 插电脑 → 设备管理器出现"USB 串行设备(COMx)"
```

为什么揪着 48MHz 不放：USB 全速引擎按 48MHz 的节拍采样和发位，时钟偏一点采位就错、枚举必挂——这颗时钟必须精确分频得到，不能"差不多就行"。

**收发 API**（CDC 类的入口都在 `usbd_cdc_if.c`）：

```c
/* 电脑→板子：USB 中断里自动回调，buf 里是收到的数据 */
static int8_t CDC_Receive_FS(uint8_t* buf, uint32_t *len)
{
    RingBuffer_Push(&usbRb, buf, *len);        /* 塞环形缓冲（C 笔记11 的家伙什） */
    osSemaphoreRelease(usbSem);                /* 通知任务处理（中断委托，见 08-FreeRTOS 05 篇纪律） */
    USBD_CDC_ReceivePacket(&hUsbDeviceFS);     /* 重新武装接收！忘了=只收一包 */
    return USBD_OK;
}

/* 板子→电脑：业务代码里主动发 */
CDC_Transmit_FS((uint8_t*)"hello pc\r\n", 10);   /* 返回 USBD_BUSY=上一包没发完，稍后再试 */
```

关键行拆解（收包回调的每一行在干嘛）：
- `CDC_Receive_FS`：这是"快递员按门铃"——USB 硬件收到一包，中断里把包裹（buf/len）递给你；
- `RingBuffer_Push`：先把包裹塞进货架（环形缓冲），不在中断里拆包干重活；
- `osSemaphoreRelease`：摇铃通知业务任务"货架上有新货"（中断委托纪律）；
- `USBD_CDC_ReceivePacket`：把空托盘还回去——**不还，快递员就没托盘装下一包**，这就是"只收一包"坑的本质。

**CDC 两大坑**：
1. `CDC_Transmit_FS` 返回 BUSY 就丢数据——要检查返回值重试（批量传输也是一包一包走的，全速下 64 字节/包）；
2. 收包后必须再调 `USBD_CDC_ReceivePacket` 重新武装，否则第二包永远不来。

## 5. HID：免驱的"人形外设"

这是什么：HID 是 USB 给"输入设备"定的模板——电脑天生认识这类设备，所以自制键盘/手柄/旋钮插上就被当成"正经外设"，零驱动。玩法的核心：把你想发的数据伪装成"按键报告"。

HID（Human Interface Device）= 键鼠手柄类。**杀手锏：任何 OS 免驱 + 可自定义报告**——不良心厂商的"USB 小键盘攻击器"、自造的宏键盘、自制游戏手柄全是 HID。

**报告描述符（Report Descriptor）**：一份"自述数据格式"的二进制说明书——告诉主机"我每包 8 字节：第 0 字节修饰键、第 1 字节保留恒 0、第 2~7 字节是键码区（一次最多报 6 个键）"。

类比：CDC 上岗交的是"岗位简历"（配置描述符），HID 还要多交一份**数据格式说明书**——相当于跟主机约好："我每次递的纸条都是 8 个格子：第 0 格写修饰键、第 1 格保留、第 2 格起写按了哪个键"——主机照单拆包，一个字节都不能错位。

```c
/* 最小键盘 HID：发送一次 "按 A 键" */
uint8_t report[8] = {0, 0, 0x04, 0, 0, 0, 0, 0};   /* [0]修饰键=0 [1]保留 [2]键码=KeyA(0x04) */
USBD_HID_SendReport(&hUsbDeviceHID, report, 8);
osDelay(50);
memset(report, 0, 8);                                /* 松键（不松=长按） */
USBD_HID_SendReport(&hUsbDeviceHID, report, 8);
```

拆一下这 8 字节纸条：修饰键是 Ctrl/Shift/Alt 这类组合键的按位图（每位对应一个键，不按填 0）；0x04 是 HID 键值表里字母 A 的编号——每个格子什么含义，报告描述符早已跟主机约死。

HID vs CDC 选型：**当"串口工具"用 → CDC；当"输入设备/免驱小数据"用 → HID**。HID 无重传保证，批量大数据别用。

## 6. 常见坑

USB 调试的特殊性：现象（识别失败）与病因（时钟/上拉/描述符）隔着一整个枚举流程——下表按"从插入到可用"的链路顺序排，排查时从上往下对。

| 坑 | 现象 |
|----|------|
| USB 时钟不是精确 48MHz | 枚举失败或"无法识别的设备"（F103 高频坑） |
| D+ 上拉电阻缺失（硬件非内置） | 电脑根本发现不了设备 |
| VBUS 检测脚未处理 | 插入无反应 |
| CDC 收包忘重新武装 | 只收到第一包 |
| 发送不查 BUSY | 数据静默丢失 |
| 描述符里 bMaxPower 虚报 | 主机拒绝配置（自报电流要真实） |
| ESD 无保护热插拔 | 端口/设备损坏（TVS 阵列保护 D+/D−） |

## 7. 章节小结

- USB=主从轮询社会；枚举七步剧本（复位→报身份→分地址→上岗）
- 四传输类型：控制/批量/中断/等时；CDC 用批量、HID 用中断
- CDC=免驱虚拟串口（两接口+双 Bulk 端点）；HID=免驱输入设备（报告描述符定格式）
- CDC 两大坑：BUSY 检查、收包再武装；48MHz 时钟是枚举的生命线

## 课后思考题

1. 为什么 USB 设备"不能主动发数据"，而中断传输却能"及时"送出键值？（中断传输=主机按固定间隔（如 10ms）轮询，设备攒数据等被问——"伪主动"；本质仍是主机驱动，轮询间隔决定延迟下限）
2. CDC 虚拟串口和 CH340 芯片方案，工程上怎么选？（板载 USB 设备口+固件 CDC=省一颗芯片+BOM 成本，但要占 USB 外设与开发量；CH340=零固件成本、任何 MCU 品牌通用——量产降本选前者，快速出样/通用板选后者）
3. 枚举失败时你的排障三板斧是什么？（①示波器/逻辑分析仪看 D+ 上拉与复位波形；②确认 USB 48MHz 时钟与 VBUS；③Bus Hound 看卡在哪个 GetDescriptor——按"物理层→时钟→协议层"分层排查，01 篇心法再兑现）
