# 01 · 通信协议总论与物理层：从 TTL 到 RS485

> 目标：建立"分层"世界观；搞清 UART/TTL/RS232/RS485 四兄弟的关系；掌握 RS485 方向切换与帧设计两大实战技能。
> 大白话版目标：学完本篇你能回答——"两个芯片隔着一根线说话，怎么喊才不喊错？"答案分三层：线怎么连（物理层）、句子怎么断（数据链路层）、内容什么意思（应用层）。

## 1. 协议分层：为什么要把"说话"拆成三层

这是什么：两个芯片要"对话"，光有电压变化不够——还得说好"谁先开口、一句多长、说错了怎么办"。分层就是把这三件事拆给不同角色管，各管一摊、互不添乱，换哪一摊都不影响另外两摊。

一次可靠的板间通信要解决三类问题：

| 层 | 解决什么 | 类比（快递寄信） |
|----|----------|------------------|
| **物理层** | 电压怎么表示 0/1、传多远、抗不抗干扰 | 公路和货车 |
| **数据链路层** | 一帧数据从哪开始到哪结束、错了怎么办 | 包裹打包+运单+签收核对 |
| **应用层** | 数据代表什么业务含义（"开灯""设温度"） | 收件人拆包后读的信 |

**分层的好处**：每层独立进化——485 只换"公路"（物理层），信的内容不变（应用层帧原样跑）。这就是"同一份 Modbus 帧可以跑在 485/TCP 上"的原因（03 篇 Modbus RTU vs TCP）。

**嵌入式三件套心法**：拿到任何协议，先问三句——①物理层是什么（电平/线缆/速率）？②帧格式什么样（帧头/长度/校验/帧尾）？③出错谁负责（校验/重传/超时）？

## 2. UART 家族四兄弟：一个协议、三种"公路"

这是什么：同一套"怎么排字节"的规矩（UART），配上三种不同的"电压方言"，就长出了 TTL、RS232、RS485 三种接口。新人最容易把它们当成三种协议——其实协议只有一份，变的只是公路。

UART 是"数据链路层规则"（起始位+数据位+校验位+停止位，STM32 篇 04 已学），配不同物理层就变成不同接口：

| | TTL | RS232 | RS485 |
|---|-----|-------|-------|
| 电平 | 0V/3.3V，高=1 | ±3~15V，**负电平=1** | 差分 A-B：+200mV~+6V=1 |
| 距离 | <30cm（板内） | ~15 米 | **1200 米** |
| 节点 | 1 对 1 | 1 对 1 | **32~256 个** |
| 双工 | 全双工 | 全双工 | **半双工**（两线版） |
| 用途 | 芯片间、调试 | 电脑老 COM 口 | 工业现场 |

**常见坑：TTL/RS232 电平互接**——RS232 的"负电压=1"与 TTL 相反且电压超限，直连烧口（MAX3232 转换芯片就是干这个的，LX-750PLUS BOM 里的 MAX3232 就是上位机调试用）。

记忆钩子：**UART 是"语法"，TTL/232/485 是"声带"**。同一句话（0x55）用 TTL 的 3.3V 方波说、用 RS232 的负电压说、用 485 的差分说，波形完全不同，但"内容"一字不差——这就是第 1 节分层思想的第一次落地。

## 3. RS485：工业现场的物理层之王

### 3.1 差分为什么抗干扰（核心原理）

这是什么：普通信号线被干扰咬一口就出错，485 却能跑 1200 米——秘密是它不传"电压本身"，只传"两根线的电压差"，干扰一视同仁地加在两根线上，一减就没了。

两根线 A/B，接收方只看**电压差**：

```
发送 1：A 比 B 高 2V     发送 0：A 比 B 低 2V
干扰来袭：两根线同时被抬 +1V（共模）→ 差值不变 → 数据无恙
```

类比：**双人抬杠的平衡木**——无论两人一起被地震晃多高，"高低差"不变，裁判只看差值。这就是它跑 1200 米的底气。

### 3.2 半双工与方向切换（485 的最大坑）

这是什么：两个人共用一支话筒，就必须约定"我说完递给你"。485 所有节点共用 A/B 两根线，收发器芯片得知道现在该"说"还是该"听"——方向切换就是抢话筒/还话筒的动作，切早切晚都出事。

两线制 485 同一时刻只能一方发（所有人共用 A/B 总线）。收发器（如 MAX485）的 DE/RE 引脚控制方向：

```c
/* STM32 控制 SP3485 类收发器 */
#define RS485_TX_EN()  HAL_GPIO_WritePin(DE_GPIO, DE_PIN, GPIO_PIN_SET)    /* 发声 */
#define RS485_RX_EN()  HAL_GPIO_WritePin(DE_GPIO, DE_PIN, GPIO_PIN_RESET)  /* 闭嘴收听 */

void RS485_SendFrame(uint8_t *buf, uint16_t len)
{
    RS485_TX_EN();                     /* 1. 先抢占话筒 */
    HAL_UART_Transmit(&huart2, buf, len, 100);
    while (__HAL_UART_GET_FLAG(&huart2, UART_FLAG_TC) == RESET);  /* 2. 等移位器彻底发完！ */
    RS485_RX_EN();                     /* 3. 再还话筒 */
}
```

发一帧的完整时间线（每步一句话：谁在做什么）：

```
T0  CPU：把整帧塞进发送寄存器，拉高 DE（抢话筒）
T1  移位器：把字节一位一位推上线（TXE 变 1 只说明"寄存器空了"，不代表线上发完）
T2  移位器：最后一位也移出上线（TC 变 1，才是真正"话说完了"）
T3  CPU：确认 TC → 拉低 DE（还话筒），总线交还给大家
```

**头号坑：切回接收太早**——只等 TXE 不够（数据还在移位器里没上线），必须等 **TC（Transmission Complete）** 再切方向，否则最后一个字节被腰斩。接收端 CRC 必错，且"偶发"（最后字节正好是校验位时）——典型低概率高伤害 bug。

### 3.3 总线拓扑规矩

这是什么：485 总线像一条共用的自来水管——接线方式、终端处理不对，水流会"撞墙回弹"（信号反射）。下面三条规矩全是为了"让信号平稳到站"。

- **手拉手菊花链**：从主站到从站一节节串下去，**禁止星形/树形分叉**（反射导致信号畸变）；
- **两端各接 120Ω 终端电阻**（匹配线缆特征阻抗，吸收反射波）——LX-750PLUS BOM 的 RS485 接口同理；
- 偏置电阻让总线空闲时呈确定电平（防"悬空乱跳"产生幽灵字节）。

## 4. 帧设计：自定义协议的规范模板

这是什么：线上跑的是一串裸字节，接收方怎么知道"从哪开始、到哪算一句话、这句话干什么、有没有说错"？答案是把字节组织成固定结构的"帧"——就像**寄快递：帧头是纸箱+面单抬头，长度域是面单上的件数，命令是收件部门，数据是货物本身，CRC 是箱子上的封条**。封条完好 = 货物没被半路动过。

裸机/RTOS 项目里自己定协议，按此模板（C 笔记10 状态机解析的帧格式基础）：

```
| 帧头 0xAA 0x55 | 长度 LEN | 命令 CMD | 数据 PAYLOAD(n) | 校验 CRC16 |
|      2B        |    1B    |    1B    |       nB        |     2B     |
```

**逐字节念一遍（完整报文实例）**——"1 号板发命令 0x01=设亮度，数据 0x01 0x64（通道 1 亮度 100）"，本例约定 LEN = CMD+DATA 的字节数（1+2=3）：

```
AA 55 03 01 01 64 xx xx
│  │  │  │  └──┘ └──┴── CRC16（对 01 01 64 计算，低字节在前）
│  │  │  │   └ 数据：通道 1（0x01）+ 亮度 100（0x64）
│  │  │  └ CMD = 0x01（"设亮度"命令）
│  │  └ LEN = 0x03（本例口径：命令+数据共 3 字节）
│  └ 帧头第 2 字节 0x55
└ 帧头第 1 字节 0xAA
```

念帧口诀：**先看箱子（帧头对上 AA 55 才拆）→ 再看面单件数（LEN）→ 看收件部门（CMD）→ 卸货（DATA）→ 验封条（CRC 对上才算签收）**。

设计要点：
1. **帧头用两字节且避开数据可能值**（0xAA55 不是巧合——位型交错，抗误同步）；
2. **必须带长度域**：变长帧靠它知道"数据段到哪结束"；
3. **CRC 而非累加和**：累加和漏检率高（两个错位抵消就漏），CRC16-MODBUS 检错能力是工业级；
4. 解析永远用**状态机**（等帧头→收长度→收数据→验 CRC），不可以用"find + memcpy 拼运气"；
5. **超时复位**：收了半个帧卡住 >100ms，状态机回"等帧头"——否则一个坏字节卡死整条链路。

## 5. 差错控制三境界（面试常问）

这是什么：数据在线上跑，被干扰咬一口是常态——问题只是"你愿意花多大代价发现它"。校验就是给每个包裹贴封条：便宜的封条只能防"明显破损"，贵的封条能防"任何动过手脚"。

| 方式 | 能力 | 成本 | 用在哪 |
|------|------|------|--------|
| 奇偶校验 | 只能查 1 位错 | 1 位 | UART 可选位 |
| 累加和 | 查大多数错，漏双位抵消 | 1 字节 | 简单传感器 |
| **CRC16/CRC32** | 查 99.998%+ 错误 | 2~4 字节 | Modbus/以太网/USB 全在用 |
| 重传（ACK/超时） | 查出后还能救回 | 时间+复杂度 | TCP、可靠帧层 |

表里两行补句白话：奇偶校验=数一遍字节里 1 的个数、凑成奇/偶，任何 1 位翻转都会打破奇偶性（但同时错 2 位又"凑平"了，所以只查得住 1 位错）；累加和=各字节加总取尾数，两个错误恰好一加一减就互相抵消——这就是"漏双位抵消"。

嵌入式结论：**帧内 CRC 查错 + 应用层应答重传纠错** = 工业可靠通信的标准姿势。

## 6. 常见坑

这一节是"事故预案库"：每行都是真实项目里赔过时间的地方，排障时按表对症状，别凭感觉乱改代码。

| 坑 | 现象 |
|----|------|
| TTL/RS232 直连 | 电平反相+超压 → 烧口 |
| 485 切方向早于 TC | 最后字节丢失，CRC 偶发错 |
| 总线星形接线 | 边沿畸变，高速率下误码 |
| 忘终端电阻 | 反射振铃，长线高速误码；电阻过多则负载过重 |
| 收发同帧应答 | 半双工"自发自收"（发的时候自己也收到了） |
| 无超时复位 | 半帧状态机永久卡死 |
| 共地缺失 | 两板各自参考地，差分也得共地（长线通信 A/B 之外的 GND 参考仍要连） |

## 7. 章节小结

- 分层三问心法：物理层/帧格式/差错控制——分析任何协议的万能起手式
- UART 是规则，TTL/232/485 是三种公路；485 靠差分抗噪跑远路
- 485 实战三件事：等 TC 再切方向、菊花链+两端 120Ω、半双工自发自收要过滤
- 自定义帧模板：AA55 + 长度 + CRC16 + 状态机解析 + 超时复位

## 课后思考题

1. 为什么 0xAA55 当帧头抗误同步能力比 0x00 强？（0x00 数据段极易出现→误同步；0xAA55 位型 1010/0101 交错且连续两字节，随机数据撞上的概率极低）
2. 485 总线上一从站损坏"拉死"A/B 线，其他从站还能用吗？（不能——总线共享物理层，一处短路全瘫；工程上加 PTC/TVS 保护和隔离芯片（ADIM2490 类）把故障域切小——呼应 BOM 篇的"隔离"思想）
3. 为什么 Modbus RTU 帧间静默要求 3.5 字符时间？（半双工共享总线没有帧头帧尾分隔符，靠"静默期"分帧——这是 RS485 物理特性对协议设计的直接塑造，03 篇展开）
