## 裸机 → RTOS 概念迁移表（衔接 51/STM32 前后台架构）

| 裸机（51/STM32 学过） | RTOS 对应 | 说明 |
|------------------------|-----------|------|
| while(1) 大轮询 | 多任务并行 | 每个 while(1) 变成一个任务 |
| 定时器时基 + 标志位 | vTaskDelay 阻塞 | 任务主动睡，调度器唤醒 |
| volatile 标志位通信 | 队列/信号量 | 从"碰运气读标志"到"确定性通信" |
| 关中断保护临界区 | taskENTER_CRITICAL | 更精细：关调度不关中断（尽量） |
| 环形缓冲区 | 内置 Queue | 内核自带线程安全缓冲 |
| IWDG 喂狗 | 看门狗任务监控多任务 | 每个任务打卡，一任务饿死即复位 |

## 名词速查表

| 名词 | 一句话解释 |
|------|-----------|
| **任务（Task）** | 有独立栈和优先级的 while(1) 函数，RTOS 调度的基本单位。类比：公司里的员工 |
| **调度器（Scheduler）** | 决定"哪个任务现在用 CPU"的裁判，每滴答一次可换人 |
| **Tick（滴答）** | RTOS 的心跳中断（常用 1ms），时间片与时延的度量单位 |
| **就绪/运行/阻塞/挂起** | 四状态：能跑没轮到 / 正在跑 / 主动等事件 / 被暂停且不参与调度 |
| **抢占式调度** | 高优先级任务就绪立刻夺走 CPU，无需等低优先级让位 |
| **时间片轮转** | 同优先级任务轮流用 CPU（一个 tick 一换） |
| **空闲任务（Idle）** | 优先级最低的系统任务，没人干活时兜底，钩子函数可低功耗 |
| **队列（Queue）** | 线程安全的 FIFO 信箱：拷贝进出、可带阻塞超时 |
| **信号量（Semaphore）** | "事件发生计数器"：二值（事件旗）、计数（资源池） |
| **互斥量（Mutex）** | 带优先级继承的"锁"：保护独占资源，谁拿谁解锁 |
| **优先级反转** | 低优先级持锁 → 高优先级干等 → 中优先级插队捣乱的悲喜剧 |
| **事件组（Event Group）** | 一组事件位，支持"与/或"等待多事件齐活 |
| **任务通知（Task Notify）** | 直发某任务 mailbox 的轻量通信，比信号量快 45% 左右 |
| **软件定时器** | 内核管理的定时回调（跑在定时器服务任务里，回调必须短） |
| **heap_1~5** | 五种内存方案：只分不收 → 分块回收 → 合并回收 → 拆分块 → 多池 |
| **FromISR 后缀** | 中断版 API：不阻塞、用 xHigherPriorityTaskWoken 请求切换 |
| **临界区** | 不许被打断的代码段：taskENTER_CRITICAL / exit 成对 |
| **栈水位（uxTaskGetStackHighWaterMark）** | 栈历史最少剩余量，排查溢出的标尺 |

## FAQ

**Q1：小项目还需要 RTOS 吗？**
不需要就别用。逻辑简单、实时性靠定时器中断就能摆平的项目，裸机更省资源更好调试。**触发条件**：任务间强实时性冲突（通信 10ms 一次 + 屏幕刷新要 100ms 但偶尔卡）、逻辑分支爆炸难维护、要用中间件（LwIP/文件系统）。

**Q2：FreeRTOS / RT-Thread / RTX 怎么选？**
面试与招聘市场 **FreeRTOS 占绝对主流**，本路线以它为主线；RT-Thread 国产、组件丰富，学有余力二刷；概念完全互通，学一个等于通三个。

**Q3：要不要读内核源码？**
先会用（本阶段），再读源码（野火书步骤式带你实现一个迷你内核）。读源码前至少要写过一个"任务间通信+中断委托"的完整项目，否则读不动。
