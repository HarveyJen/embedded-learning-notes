# 02 · 消息队列：任务间的信箱

> 目标：掌握队列这一 RTOS 通信的"万能积木"，用三任务链替换掉所有 volatile 全局标志位。

## 1. 为什么需要队列（裸机标志位的三宗罪）

这一节回答"队列解决什么问题"。一句话：**给任务之间修一条安全、不丢、不吵架的传话通道**——先看没有它有多惨。

裸机里任务间通信 = volatile 标志位 + 全局缓冲：

1. **竞态**：ISR 写一半、任务来读——数据撕裂；
2. **丢事件**：标志只有 0/1，事件连续来两次只记一次；
3. **无节奏解耦**：生产快消费慢时只能覆盖旧数据，没有缓冲排队。

**队列 = 线程安全的环形缓冲 + 唤醒机制**（C 笔记11 环形缓冲的内核版，还附赠"空时消费者睡眠、满时生产者睡眠"）。

类比：**医院叫号系统**——病人（数据）取号排队（入队），医生（任务）没病人时在休息室睡觉（阻塞），广播叫号立刻醒来。不丢号、不撕病历、双方节奏不同也不吵架。

把画面钉牢，对应关系如下：

- 取号机吐号 = 入队拷贝：号码（数据副本）归了队列，之后病人去哪不影响叫号（拷贝语义）；
- 休息室 = Blocked 状态：医生睡觉期间不占诊室（CPU），医院照常运转；
- 叫号广播 = 内核唤醒：有号进来才喊人，没号绝不空喊（睡眠唤醒机制）；
- 号池容量 = 队列长度：号池满了新病人取不到号（队满 Send 失败/阻塞）——所以容量要按客流峰值估。

## 2. 队列核心 API 与语义

```c
QueueHandle_t xQueueCreate(ulen, isize);        /* 建队列：长度×单元大小 */

xQueueSend(q, &data, ticks);                    /* 入队（队满等 ticks）*/
xQueueReceive(q, &buf, ticks);                  /* 出队（队空等 ticks）*/
xQueuePeek(q, &buf, ticks);                     /* 偷看不取 */
xQueueSendToFront(q, &data, ticks);             /* 插队（紧急数据）*/
uxQueueMessagesWaiting(q);                      /* 现有几个 */
```

三个关键语义（理解了就不用背）：

1. **拷贝语义**：入队是把数据**整个复制**进去（值传递）——小数据直接传值；大数据传**指针**（配合 05 篇内存管理，"发邮件不发家具"）；
2. **阻塞超时**：队空 Receive 时任务进 Blocked，来数据即醒——**零 CPU 消耗等待**（对比裸机 while 轮询标志）；
3. **超时值**：`portMAX_DELAY`=无限等；具体 tick 数=限时等，用于"等不到就降级处理"。

把上面三点浓缩成 API 三问（以 xQueueSend / xQueueReceive 为例）：**会阻塞吗？** 会——队满 Send、队空 Receive 时任务进 Blocked，这是设计意图不是 bug；**超时是什么单位？** 第三个参数是 tick 数（用 `pdMS_TO_TICKS(毫秒)` 换算），portMAX_DELAY = 死等；**ISR 里能不能用？** 普通版不能，必须换 `xQueueSendToBackFromISR` / `xQueueReceiveFromISR`（不阻塞、不直接切调度，见 05 篇）。

## 3. 标准架构：三任务链（本篇核心实战）

这一节把队列用到最经典的架构上：中断、解析、执行三段各自独立，靠队列接力——这是 RTOS 工程里出场率最高的骨架，值得手抄一遍。

把 STM32 毕业项目的"串口接收→解析→显示"改成队列衔接：

```
[串口 ISR] ──字节──▶ [rxQueue] ──▶ [解析任务] ──命令──▶ [cmdQueue] ──▶ [执行任务]
   只搬字节            拼帧状态机        校验/分发          干活/回 ACK
```

下面的代码做什么：展示三任务链的两端——ISR 端只管送字节，解析任务端只管取字节，中间全靠 rxQueue 接力。

```c
/* ISR：只收一个字节入队（05 篇 FromISR 详述，此处先看结构） */
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *hu)
{
    BaseType_t woken = pdFALSE;
    xQueueSendToBackFromISR(rxQueue, &rxByte, &woken);   /* 入队 */
    portYIELD_FROM_ISR(woken);                            /* 唤醒解析任务 */
    HAL_UART_Receive_IT(&huart1, &rxByte, 1);             /* 重挂接收 */
}

/* 解析任务：从队列拿字节喂状态机（C 笔记10 帧解析模板直接复用） */
void ParserTask(void *arg)
{
    uint8_t b;
    for (;;) {
        if (xQueueReceive(rxQueue, &b, portMAX_DELAY) == pdTRUE)  /* 没字节就睡 */
            FrameFeed(b);       /* 状态机：拼帧→校验→完整命令入 cmdQueue */
    }
}
```

关键行拆解：

- `xQueueSendToBackFromISR(rxQueue, &rxByte, &woken)`——FromISR 版入队：不阻塞（队满立即返回失败）、第三参数 woken 用来"带话"给内核（05 篇展开）；
- `portYIELD_FROM_ISR(woken)`——把"该切换了"递给内核：若唤醒的解析任务优先级更高，中断退出直接切过去，不用等下一个 tick；
- `xQueueReceive(rxQueue, &b, portMAX_DELAY)`——解析任务的"待命姿势"：没字节就睡死等，来一个处理一个，CPU 零空转。

**一帧命令的时间线**（把架构图走成故事）：

- 第 1 步：串口中断到达，ISR 把这 1 个字节塞进 rxQueue 就退（全程微秒级）——此刻解析任务多半正 Blocked 在 xQueueReceive 上睡着；
- 第 2 步：入队动作把解析任务标为 Ready，中断退出后它被调度上台，取走字节喂状态机；字节不够一帧？继续阻塞等下一个；
- 第 3 步：状态机攒齐一帧、校验通过 → 命令入 cmdQueue → 执行任务（原本也在睡）被唤醒，干活、回 ACK；
- 第 4 步：三段各自回到阻塞位，系统 CPU 占用趋近零，安静等下一帧。

对比裸机版"主循环挨个轮询"：队列版没有任何人在轮询，所有等待都是睡眠——"零 CPU 消耗等待"从此有了实感。

**架构收益自查**：三个模块只认识队列不认识彼此——换掉任何一段不影响别人（C 笔记04 模块分层在 RTOS 下的落地）；中断 0 耗时处理；解析慢了队列自动缓冲。

## 4. 设计要点与陷阱

这一节是"选型参数表"：建队列之前，每个格子都值得先想清楚再动手。

| 话题 | 结论 |
|------|------|
| 单元大小 | 小数据（传感器值、命令码）直接传结构体；>32 字节传指针+内存池 |
| 队列长度 | 按"生产峰值×容忍延时"估，宁大勿小；监控 `uxQueueMessagesWaiting` 水位 |
| 多消费者 | 一条数据只被一个消费者拿走——广播用**队列集或事件组**，别用队列凑合 |
| 优先级联动 | 队列唤醒自带优先级抢占：解析任务优先级高于显示任务时，数据一到立刻插队 |
| 结构体传队列 | 传值安全的前提是**无指针成员**（拷贝后指针指向别人的栈=悬空） |

## 5. 队列集（Queue Set，多队列等一）

这一节解决"一个任务想同时等多个队列"的小众需求——知道有这个工具即可。

任务要同时等"串口命令"和"按键事件"两个队列 → 不用轮询，建 Queue Set 把两队列注册进去，`xQueueReceiveFromSet()` 谁先来拿谁。**实际工程更常用任务通知或事件组替代**（04 篇），了解即可。

## 6. 常见坑

| 坑 | 现象 |
|----|------|
| 在 ISR 用 xQueueSend（无 FromISR） | 断言死机/调度错乱 |
| 队列长度 1 还当缓冲用 | 高速数据大量丢失 |
| 结构体内含指针传值拷贝 | 消费者读到悬空指针（野指针排查经典现场） |
| 发送侧 portMAX_DELAY 且队列满 | 生产任务永久卡死（要评估"满了怎么办"策略：覆盖/丢弃/报错） |
| Peek 与 Receive 混用乱序 | 多任务抢同一队列时序难控 |

## 7. 章节小结

- 队列=线程安全环形缓冲+睡眠唤醒；拷贝语义、阻塞超时是两大支柱
- 标准架构：ISR 只入队、解析任务喂状态机、执行任务出活——全局标志位清零
- 大数据传指针（配内存池），小数据传值；队满策略要预先想好
- 队列自带优先级联动：数据到达即抢占唤醒，实时性有保证

## 课后思考题

1. 队列在内核里本质是什么数据结构？和 C 笔记11 环形缓冲差在哪？（环形缓冲+两个等待列表；差在"拷贝互斥由内核保证"+"空/满自动睡眠唤醒"）
2. 为什么"队列满时生产者阻塞"可能造成系统连锁卡死？（生产者若是高优先级任务被堵 → 它等待的消费动作无人执行 → 死锁链；策略：告警+丢弃旧数据，保系统活性）
3. ISR 为什么必须用 FromISR 版本？（普通版可能阻塞/请求调度，而中断上下文不能睡、切换请求要延后到中断退出——API 分族是"上下文"概念在 RTOS 的体现）
